# 02-1 点亮一个 LED

> [!abstract] 这一集只解决一个问题
> **怎么用程序点亮一颗 LED？**
>
> 答：LED 是低电平点亮，直接给对应引脚输出 0 即可。本集用 `sbit` 把单个引脚命名，再给引脚赋值，建立"程序控制电平"的最小模型。
>
> 下一集 [[江协51 02-2 LED闪烁]] ｜ 章索引 [[江协51 02 LED（章索引）]]

## 1 LED 与点亮原理

LED（发光二极管）有正负极，**正向导通**才会亮。开发板上的接法是：

```text
   +5V ──[限流电阻]──►|── IO 引脚（P1.2 等）
                    LED
```

- **阳极（正）**经限流电阻接 +5V，**阴极（负）**接 IO 引脚。
- IO 输出 **0（低电平，0V）**：电流从 5V 流过 LED 到引脚 → LED 亮。
- IO 输出 **1（高电平，5V）**：LED 两端都是 5V，无压差 → LED 灭。

> [!note] 为什么"低电平点亮"而不接反
> 让 IO 口"灌电流"（电流流入引脚）比"拉电流"（电流从引脚流出）驱动能力更强，所以经典做法是低电平点亮。这是嵌入式里非常常见的接法。

## 2 sbit 位定义

要控制单个引脚，需要先给引脚起个名。`sbit` 是 Keil C51 扩展的关键字，用来**定义某一位**：

```c
sbit LED = P1^2;   // 把 P1 口的第 2 位命名为 LED
```

- `P1^2` 表示 P1 口的第 2 位（P1.2 引脚），`^` 是位选择符号，不是异或。
- 定义后就能像变量一样赋值：`LED = 0;` 就是让 P1.2 输出低电平。

> [!warning] `P1^2` 里的 `^` 不是异或
> 在 sbit 定义里 `^` 是"取第几位"的语法，`P1^2` 就是 P1.2。别把它当成位运算里的异或运算符。

## 3 完整代码

```c
#include <REGX52.H>   // 51 单片机寄存器定义头文件

void main()
{
	P1_2 = 1;    // P1.2 输出高电平（这路 LED 灭）
	P1_3 = 0;    // P1.3 输出低电平（这路 LED 亮）
}
```

> [!note] 本集用的是 P1_2 / P1_3
> 官方源码 2-1 用 `P1_2=1; P1_3=0;` 演示，说明早期点灯接在 P1 口的第 2、3 位。`P1_2`、`P1_3` 是 `REGX52.H` 头文件里已经定义好的位变量（等价于 `sbit P1_2 = P1^2`），所以这里不用自己再写 sbit。从 2-2 起改用 P2 整组 LED。

### 3.1 关于 `#include <REGX52.H>`

- 这个头文件里定义了 P0~P3 端口、以及 `P1_0`~`P1_7` 这类**位变量**，还有各特殊功能寄存器（SFR）。
- 不包含它，`P1`、`P1_2` 这些符号编译器就不认识。

### 3.2 为什么没有 while(1)

本集程序很短，执行完 `main` 就结束。实际开发板上下载后，LED 会保持最后一次赋值的状态（引脚电平保持），所以能看到现象。但**严谨做法**是加 `while(1)` 让程序停住，后面各集都会补上。

## 4 易错点

- [ ] 点亮电平搞反 → 本开发板低电平点亮，`=0` 亮、`=1` 灭。
- [ ] 忘了 `#include <REGX52.H>` → `P1`、`P1_2` 未定义，编译报错。
- [ ] `sbit` 里的 `^` 当成异或 → 它只是位选择语法。
- [ ] 位编号从 0 开始 → `P1^2` 是第 3 个引脚（P1.0、P1.1、P1.2），别当成第 2 个。
- [ ] 主函数没有死循环 → 严谨起见应加 `while(1)`，否则程序结束后的行为不确定。

## 5 自测

1. 为什么本开发板的 LED 是低电平点亮？
2. `sbit LED = P1^2;` 里的 `^` 是什么意思？
3. `P1_2` 和 `P1^2` 是什么关系？

> [!success]- 参考答案
> 1. 因为 LED 阳极经限流电阻接 +5V、阴极接 IO 引脚，IO 输出 0（0V）时才有压差、电流流过 LED 点亮；输出 1（5V）时两端等电位熄灭。
> 2. `^` 是 Keil C51 位选择语法，`P1^2` 表示 P1 口的第 2 位（P1.2），不是异或运算。
> 3. 两者等价：`P1_2` 是 `REGX52.H` 里已经用 `sbit P1_2 = P1^2` 定义好的现成位变量。
