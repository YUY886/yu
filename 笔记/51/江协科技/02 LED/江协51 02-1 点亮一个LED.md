# 02-1 点亮一个 LED

> [!abstract] 这一集只解决一个问题
> **怎么用程序点亮一颗 LED？**
>
> 一句话：LED 是**低电平点亮**（阳极接 5V、阴极接 IO），所以给对应引脚输出 **0** 就能点亮。用 `sbit` 给引脚起个名，然后 `LED = 0;` 就完事。
>
> 但这一集真正值钱的是背后的三件事：**① IO 端口的电路结构（准双向口）**、**② `sbit` 的位寻址本质**、**③ 读引脚 vs 读锁存器的坑**。这三样，后面第 3 章按键、第 4 章数码管、乃至所有 IO 操作都在用。
>
> 下一集 [[江协51 02-2 LED闪烁]] ｜ 章索引 [[江协51 02 LED（章索引）]]

## 1 LED 是什么、怎么亮

**LED（Light Emitting Diode，发光二极管）** 是一种有极性的元件，只有**正向导通**（电流从阳极流向阴极）时才发光。

```text
      阳极（正极，长脚）         阴极（负极，短脚，有缺口）
         ────────►|────────
    +5V ──[限流电阻]──►|── IO 引脚
                     LED
```

- **二极管单向导电**：电流只能从阳极 → 阴极，反向几乎不导通。
- **必须限流**：LED 两端电压超过导通压降（约 1.7~2V）后，电流会急剧增大，不加限流电阻会烧掉 LED。所以电路里串联一个**限流电阻**（开发板上已焊好，通常几百欧）。

### 1.1 开发板的接法：低电平点亮

本开发板（普中 HC6800-ES V2.0）的 LED 是这样接的：

```text
   +5V ──[限流电阻]──►|── IO 引脚（P2.0 等）
                     LED（阳极经电阻接 5V，阴极接 IO）
```

- IO 输出 **0（低电平，0V）**：电流从 5V → 限流电阻 → LED → IO 引脚（0V），形成回路 → **LED 亮**。
- IO 输出 **1（高电平，5V）**：LED 两端都是 5V，**无压差、无电流** → LED 灭。

所以**本开发板是"低电平点亮"**：写 0 亮，写 1 灭。

> [!note] 为什么经典做法是"低电平点亮"（灌电流）
> 51 的 IO 口在**输出低电平时"灌电流"**（电流从外部流入引脚）能力较强，通常能到十几 mA；而**输出高电平时"拉电流"**（电流从引脚流出）能力弱，因为高电平靠内部弱上拉电阻，电流很小。
>
> 所以驱动 LED 这类需要一定电流的负载，经典接法是**低电平点亮**——让 IO 口"灌电流"而非"拉电流"。这是嵌入式里非常普遍的接法，STM32 里也一样常见。

## 2 51 的 IO 端口电路结构（准双向口）

在理解"sbit 为什么能控制单个引脚"之前，先看 P2 端口**一位**的电路结构。这是本集最容易忽略、却最重要的底层知识。

### 2.1 准双向口（Quasi-bidirectional）

51 的 P1/P2/P3 端口是**准双向口**，每个引脚内部大致是这样的：

```text
                         VCC（5V）
                          │
                        ┌─┴─┐
                 内部上拉电阻（弱上拉，几十 kΩ）
                        └─┬─┘
                          │
      ┌───────────────────┼────────────────────┐
      │                   │                    │
      │  输出锁存器        │                    │  读引脚缓冲器
      │  ┌──────────┐     │                    │  （三态门）
      │  │   D Q    │     │                    │      ▲
      │  │  锁存器   │─────┼──► 输出驱动 ────────┼──────┤
      │  │  (1位)   │     │    (强下拉 MOS)      │      │
      │  └────▲─────┘     │                    │  读引脚(Read Pin)
      │       │           │                    │
      │  写锁存器(Write)   │                    │
      │                   │                    │
      └───────────────────┼────────────────────┘
                          │
                         IO 引脚（P2.x）
```

关键点（把这张图看懂，51 的 IO 就懂了一半）：

- **输出 0**：锁存器存 0 → 输出驱动器的**强下拉 MOS 管导通**，把引脚强力拉到 0V。这就是"低电平点亮"时电流的来源——电流从 5V 灌进引脚。
- **输出 1**：锁存器存 1 → 强下拉 MOS 管**截止**，引脚靠**内部弱上拉电阻**拉到 5V。因为上拉电阻阻值大（几十 kΩ），所以**输出高电平时"拉电流"能力很弱**。
- **读引脚前先输出 1**：当你想把这个引脚当**输入**用时，必须先给它写 1，让强下拉 MOS 截止、引脚"释放"，这样外部信号才能改变引脚电平。否则如果之前写过 0，强下拉一直拉着，外部信号拉不动。

> [!warning] 准双向口 vs 推挽口（提前了解，对比 STM32）
> - **51 的准双向口**：输出高电平靠弱上拉（拉电流弱），输出低电平靠强下拉（灌电流强）。
> - **STM32 的推挽输出**：高低电平都由 MOS 管主动驱动（拉/灌电流都强），没有"弱上拉"这个限制。
>
> 这是 51 和 STM32 在 IO 结构上的核心区别，理解了它，后面看 STM32 笔记的"推挽 vs 开漏"会更轻松。

### 2.2 读引脚 vs 读锁存器（重要坑）

51 的 IO 端口**读数据有两条路径**，这是新手最容易踩的坑：

| 读取方式 | 读的是什么 | 对应 C 语句 |
| --- | --- | --- |
| **读引脚**（Read Pin） | 引脚上**真实的电平**（受外部电路影响） | `if(P2_0 == 0)` 判断外部按键 |
| **读锁存器**（Read Latch） | 锁存器里**上次写入的值** | `P2 = P2 | 0x01` 这类"读-改-写" |

- **读引脚**：读的是引脚物理电平。用于判断外部输入（第 3 章按键就用这个）。
- **读锁存器**：读的是你之前写进去的值。用于"读-改-写"操作（如 `P2 |= 0x01` 把某位置 1，要先把 P2 读回来再改）。

> [!tip] 一个经典的"读-改-写"陷阱
> 写 `P2 = P2 | 0x01;` 时，编译器读的是**锁存器**（你上次写的值），而不是引脚电平。但如果用 `if(P2_0==0)` 判断按键，读的是**引脚**。
>
> 为什么这个区别重要？假设 P2.0 接了按键且外部把它拉低了，但锁存器里存的还是 1。此时：
> - 读引脚 → 得到 0（外部按键拉低）
> - 读锁存器 → 得到 1（你上次写的值）
>
> 两种读法结果不同！所以"读-改-写"和"判断外部电平"要分清自己到底在读哪个。

## 3 sbit 位定义：为什么能操作单个引脚

要控制单个引脚，需要先给引脚起个名。`sbit` 是 **Keil C51 扩展的关键字**，用来**定义某一位（bit）**：

```c
sbit LED = P2^0;   // 把 P2 口的第 0 位（P2.0 引脚）命名为 LED
```

### 3.1 `^` 是"位选择"，不是异或

```c
sbit LED = P2^0;   // P2 口的第 0 位
sbit K1  = P3^1;   // P3 口的第 1 位
```

- `P2^0` 里的 `^` 是 Keil C51 的**位选择语法**，表示"P2 口的第 0 位"，**不是** C 语言里的按位异或运算符 `^`。
- 定义后就能像普通变量一样赋值：`LED = 0;` 就是让 P2.0 输出低电平。

> [!warning] 别把 sbit 的 `^` 和异或 `^` 搞混
> 在 `sbit LED = P2^0;` 里，`^` 是"取第几位"的语法；但在 `a = b ^ c;` 里，`^` 是异或运算。两者长得一样、含义完全不同，取决于上下文。

### 3.2 sbit 的底层：位地址

`sbit` 的本质是**给某个"位地址"起别名**。51 的可位寻址 SFR（如 P0~P3、TCON、SCON 等）每一位都有一个独立的**位地址**，`sbit` 就是把这些位地址和名字绑定。

```text
  sbit P2_0 = P2^0;   →  P2_0 是 P2 端口位 0 的别名
  P2_0 = 0;           →  编译器翻译成"把 P2 的位 0 清 0"
```

### 3.3 REGX52.H 里已经定义好了，多数情况不用自己写 sbit

注意：`REGX52.H` 头文件里**已经预定义了** `P1_0`~`P1_7`、`P2_0`~`P2_7` 等位变量：

```c
// REGX52.H 里大致有这些（等价于帮你写好了 sbit）：
// sbit P1_0 = P1^0;  ...  sbit P1_7 = P1^7;
// sbit P2_0 = P2^0;  ...  sbit P2_7 = P2^7;
```

所以：

- 用 `P2_0 = 0;` 时，**不用自己写 sbit**（头文件已定义）。
- 只有当你想起一个**更有意义的名字**时（如 `sbit LED1 = P2^0;`），才需要自己写 sbit。

### 3.4 三种控制单个引脚/端口的方式对照

同样一件事——控制引脚电平——有三种写法，层次不同：

| 写法 | 例子 | 粒度 | 适用 |
| --- | --- | --- | --- |
| **整体赋值** | `P2 = 0xFE;` | 8 位一起改 | 同时控制整个端口的 8 个引脚 |
| **预定义位变量** | `P2_0 = 0;` | 单引脚 | 头文件已定义好位名，直接单引脚操作 |
| **自定义 sbit** | `sbit LED = P2^0; LED = 0;` | 单引脚 | 想起有意义的名字，提高可读性 |

> [!tip] 什么时候用哪种
> - 只改一个引脚，且头文件有现成位名 → 用 `P2_0 = 0;`。
> - 只改一个引脚，想起语义化名字 → `sbit LED1 = P2^0;` 然后 `LED1 = 0;`。
> - 一次改多个引脚 → `P2 = 0xFE;`（整体赋值）。
>
> 第 3 章按键、第 7 章流水灯会大量用到整体赋值和 `sbit` 的组合。

## 4 完整代码（官方源码 2-1）

```c
#include <REGX52.H>   // 51 单片机寄存器定义头文件（含 P1_2、P1_3 位变量）

void main()
{
	P1_2 = 1;    // P1.2 输出高电平（这路 LED 灭）
	P1_3 = 0;    // P1.3 输出低电平（这路 LED 亮）
}
```

> [!note] 本集用的是 P1_2 / P1_3，不是 P2
> 官方源码 2-1 用 `P1_2=1; P1_3=0;` 演示，说明早期点灯接在 **P1 口的第 2、3 位**。`P1_2`、`P1_3` 是 `REGX52.H` 头文件里已经定义好的位变量（等价于 `sbit P1_2 = P1^2`），所以这里不用自己写 sbit。
>
> **注意**：从 2-2 起，官方改用 **P2 端口整组 LED**（`P2=0xFE`），两集引脚不同，别混为一谈。

### 4.1 关于 `#include <REGX52.H>`

- 这个头文件里定义了 P0~P3 端口、`P1_0`~`P1_7` 这类**位变量**，还有各特殊功能寄存器（SFR）。
- 不包含它，`P1`、`P1_2` 这些符号编译器就不认识，报"未定义标识符"。

### 4.2 为什么没有 while(1)

本集程序很短，执行完 `main` 就结束。实际下载后，LED 会保持最后一次赋值的状态（引脚电平保持），所以能看到现象。

但**严谨做法**是加 `while(1)` 让程序停住：

```c
void main()
{
	P1_2 = 1;
	P1_3 = 0;
	while(1)   // 让程序停在这里，不"跑飞"
	{
	}
}
```

> [!warning] 为什么不加 while(1) 是隐患
> 没有 `while(1)` 时，`main` 返回后 CPU 会继续取址执行"未知的代码"（越过你程序的末尾），可能导致不可预知的行为。点灯这种简单场景碰巧没事，但好习惯是**永远用 `while(1)` 兜底**。从 2-2 开始官方源码都加了 `while(1)`。

## 5 易错点

- [ ] 点亮电平搞反 → 本开发板**低电平点亮**，`=0` 亮、`=1` 灭。
- [ ] 忘了 `#include <REGX52.H>` → `P1`、`P1_2` 未定义，编译报错。
- [ ] `sbit` 里的 `^` 当成异或 → 它只是位选择语法。
- [ ] 位编号从 0 开始 → `P1^2` 是第 3 个引脚（P1.0、P1.1、P1.2），别当成第 2 个。
- [ ] 2-1 和 2-2 引脚混淆 → 2-1 用 P1_2/P1_3，2-2 起用 P2 端口。
- [ ] 主函数没有死循环 → 严谨起见应加 `while(1)`。
- [ ] 读引脚和读锁存器不分 → 判断外部电平用"读引脚"，读-改-写用"读锁存器"。
- [ ] 忘了 LED 要限流 → 直接 5V 接 LED 不串电阻会烧 LED（开发板已焊好电阻，自行搭电路要注意）。

## 6 自测

1. 为什么本开发板的 LED 是低电平点亮？低电平点亮的电气原因是什么？
2. `sbit LED = P2^0;` 里的 `^` 是什么意思？sbit 的本质是什么？
3. `P1_2` 和 `P1^2` 是什么关系？
4. 51 的准双向口，输出高电平和输出低电平的驱动能力有什么不同？
5. "读引脚"和"读锁存器"有什么区别？各在什么场景用？

> [!success]- 参考答案
> 1. 因为 LED 阳极经限流电阻接 +5V、阴极接 IO 引脚，IO 输出 0（0V）时才有压差、电流流过 LED 点亮；输出 1（5V）时两端等电位熄灭。电气原因是：51 的 IO 口**灌电流（低电平）能力远强于拉电流（高电平）**，低电平点亮更可靠。
> 2. `^` 是 Keil C51 位选择语法，`P2^0` 表示 P2 口的第 0 位（P2.0），不是异或运算。sbit 的本质是**给某个"位地址"起别名**。
> 3. 两者等价：`P1_2` 是 `REGX52.H` 里已经用 `sbit P1_2 = P1^2` 定义好的现成位变量。
> 4. 输出**低电平**靠强下拉 MOS 管，**灌电流能力强**（能到十几 mA）；输出**高电平**靠内部弱上拉电阻（几十 kΩ），**拉电流能力弱**。所以驱动 LED 用低电平点亮。
> 5. **读引脚**读的是引脚真实的物理电平（受外部电路影响），用于判断外部输入（如按键）；**读锁存器**读的是你上次写入的值，用于"读-改-写"操作（如 `P2 |= 0x01`）。
