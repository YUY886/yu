# 02-2 LED 闪烁

> [!abstract] 这一集只解决一个问题
> **怎么让 LED 一闪一闪？**
>
> 答：交替给端口赋值（`P2=0xFE` 亮、`P2=0xFF` 灭），中间插入**软件延时函数** `Delay500ms()`，用 `while(1)` 让这两步无限循环。
>
> 上一集 [[江协51 02-1 点亮一个LED]] ｜ 下一集 [[江协51 02-3 LED流水灯]] ｜ 章索引 [[江协51 02 LED（章索引）]]

## 1 从"点亮"到"闪烁"

点亮只是给一次赋值；要闪烁，就是**亮 → 等一会儿 → 灭 → 等一会儿 → 循环**：

```text
 while(1) 里：
    P2 = 0xFE;      // 亮（最低位为 0）
    Delay500ms();   // 保持 500ms
    P2 = 0xFF;      // 灭（全 1）
    Delay500ms();   // 保持 500ms
```

- `0xFE = 1111 1110`：最低位（P2.0）为 0 → 第 1 颗 LED 亮，其余灭。
- `0xFF = 1111 1111`：全为 1 → 全部灭。

## 2 软件延时函数

"等一会儿"需要延时。51 没有内置 sleep，最朴素的办法是**让 CPU 空转一段时间**，这叫"软件延时"：

```c
void Delay500ms()		//@12.000MHz
{
	unsigned char i, j, k;

	_nop_();
	i = 4;
	j = 205;
	k = 187;
	do
	{
		do
		{
			while (--k);
		} while (--j);
	} while (--i);
}
```

- 原理：嵌套三层循环让 CPU 反复执行空操作，消耗约 500ms 时间。
- `_nop_()` 是空操作指令，来自 `#include <INTRINS.H>`。
- **关键点**：这个 500ms 是**按 12MHz 晶振**算出来的（`//@12.000MHz` 注释）。晶振变了，i/j/k 的初值就要重算，否则时长不对。

> [!warning] 软件延时的代价
> 软件延时会**完全占用 CPU**——在 Delay 期间，CPU 做不了别的事。所以后面第 7 章引入定时器中断来"解放 CPU"。这一章先理解"延时"这件事本身即可。

## 3 完整代码

```c
#include <REGX52.H>
#include <INTRINS.H>

void Delay500ms()		//@12.000MHz
{
	unsigned char i, j, k;

	_nop_();
	i = 4;
	j = 205;
	k = 187;
	do
	{
		do
		{
			while (--k);
		} while (--j);
	} while (--i);
}


void main()
{
	while(1)
	{
		P2=0xFE;	//1111 1110，第 1 颗 LED 亮
		Delay500ms();
		P2=0xFF;	//1111 1111，全灭
		Delay500ms();
	}
}
```

## 4 易错点

- [ ] 忘了 `#include <INTRINS.H>` → `_nop_()` 未定义，编译报错。
- [ ] 主循环没写 `while(1)` → 只闪一次就结束。
- [ ] `0xFE` 和 `0xFF` 搞混 → `0xFE` 最低位是 0（亮），`0xFF` 全 1（灭）。
- [ ] 以为 500ms 是精确值 → 它是按 12MHz 估算的近似值，且软件延时受编译优化影响。
- [ ] 改晶振后不重算延时初值 → 闪烁速度不对。

## 5 自测

1. `P2=0xFE` 时哪颗 LED 亮？为什么？
2. 软件延时函数的本质是什么？它有什么缺点？
3. 为什么延时函数要 `#include <INTRINS.H>`？

> [!success]- 参考答案
> 1. 第 1 颗（P2.0）亮。因为 `0xFE=1111 1110`，只有最低位为 0，低电平点亮对应的 P2.0。
> 2. 本质是让 CPU 空转（嵌套循环反复执行空操作）来消耗时间。缺点是**占用 CPU**，延时期间无法做其他事。
> 3. 因为函数里用了 `_nop_()` 空操作指令，它定义在 `INTRINS.H` 头文件里。
