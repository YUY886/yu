# 02-2 LED 闪烁

> [!abstract] 这一集只解决一个问题
> **怎么让 LED 一闪一闪？**
>
> 一句话：交替给端口赋值（`P2=0xFE` 亮、`P2=0xFF` 灭），中间插入**软件延时函数** `Delay500ms()`，再用 `while(1)` 让这两步无限循环。
>
> 这一集真正的知识点是**软件延时**——它背后是"机器周期"和"指令周期"的概念，这直接关系到第 7 章定时器为什么比软件延时好。
>
> 上一集 [[江协51 02-1 点亮一个LED]] ｜ 下一集 [[江协51 02-3 LED流水灯]] ｜ 章索引 [[江协51 02 LED（章索引）]]

## 1 从"点亮"到"闪烁"

点亮只是给一次赋值；要闪烁，就是**亮 → 等一会儿 → 灭 → 等一会儿 → 循环**：

```text
 while(1) 里：
    P2 = 0xFE;      // 亮（最低位为 0）
    Delay500ms();   // 保持 500ms
    P2 = 0xFF;      // 灭（全 1）
    Delay500ms();   // 保持 500ms
```

- `0xFE = 1111 1110`：最低位（P2.0）为 0 → 第 1 颗 LED 亮，其余灭。
- `0xFF = 1111 1111`：全为 1 → 全部灭。

### 1.1 为什么要 while(1)

`while(1)` 是一个**死循环**，让"亮-灭"这两个动作无限重复：

```c
void main()
{
	while(1)          // 死循环，永远执行下去
	{
		P2 = 0xFE;     // 亮
		Delay500ms();  // 保持
		P2 = 0xFF;     // 灭
		Delay500ms();  // 保持
	}
}
```

> [!note] 嵌入式程序的主循环模式
> 几乎所有嵌入式程序的主函数都是 `while(1){...}` 的结构——**初始化一次，然后无限循环做任务**。这是和桌面程序（跑完就退出）最大的不同。后面每章的主函数都是这个骨架。

## 2 软件延时：让 CPU"空转"

"等一会儿"需要延时。51 没有内置 sleep，最朴素的办法是**让 CPU 空转一段时间**，这叫"软件延时"。

### 2.1 机器周期和指令周期（理解延时的前提）

在第 1 章提过：51 的 CPU 靠晶振产生时钟节拍，指令执行以**机器周期**为单位。

```text
  晶振 12MHz → 振荡周期 = 1/12MHz = 1/12 μs
  1 个机器周期 = 12 个振荡周期 = 1 μs（12MHz 时）
  1 条指令 = 1 ~ 4 个机器周期（不同指令不同）
```

- **振荡周期**：晶振每振动一次的时间，12MHz 时是 1/12 μs。
- **机器周期**：51 里 12 个振荡周期算一个机器周期，12MHz 时**恰好是 1μs**（这就是为什么选 12MHz 好算）。
- **指令周期**：执行一条指令需要的机器周期数，不同指令不同（1~4 个）。

### 2.2 软件延时的本质

软件延时的本质是**执行大量空操作的指令，让 CPU 白白消耗时间**：

```c
void Delay500ms()		//@12.000MHz
{
	unsigned char i, j, k;

	_nop_();        // 空操作，消耗 1 个机器周期
	i = 4;
	j = 205;
	k = 187;
	do
	{
		do
		{
			while (--k);   // k 从 187 减到 0
		} while (--j);     // j 从 205 减到 0
	} while (--i);         // i 从 4 减到 0
}
```

- 三层嵌套循环，总循环次数 ≈ `4 × 205 × 187` ≈ 15 万次，加上每次循环内几条指令的机器周期，累计约 500ms。
- `_nop_()` 是**空操作指令**，来自 `#include <INTRINS.H>`，消耗 1 个机器周期。
- `while(--k)` 是"先自减再判断"，当 k 减到 0 时循环结束。

> [!warning] 软件延时的两大代价
> 1. **完全占用 CPU**：Delay 期间，CPU 一直在空转，做不了任何其他事。如果后面要"同时"做多个任务（比如边闪灯边响应按键），软件延时会拖垮整个程序。
> 2. **不精确、不可移植**：500ms 是**按 12MHz 晶振 + 特定编译选项**估算的近似值。换晶振、换编译器、开优化，时长都会变。
>
> 这正是第 7 章引入**定时器中断**的原因——用硬件定时，CPU 就能"边定时边干别的"。这一章先理解"延时"这件事本身即可。

### 2.3 为什么不直接用 Sleep 函数

- 51 没有标准库的 `sleep()`。
- 即使有，软件延时和 sleep 一样都会"阻塞"当前执行流，区别只是 sleep 可能省电。对于学习，先用最直观的循环空转理解"延时"。

## 3 完整代码

```c
#include <REGX52.H>
#include <INTRINS.H>

void Delay500ms()		//@12.000MHz
{
	unsigned char i, j, k;

	_nop_();
	i = 4;
	j = 205;
	k = 187;
	do
	{
		do
		{
			while (--k);
		} while (--j);
	} while (--i);
}


void main()
{
	while(1)
	{
		P2=0xFE;	//1111 1110，第 1 颗 LED 亮
		Delay500ms();
		P2=0xFF;	//1111 1111，全灭
		Delay500ms();
	}
}
```

> [!tip] 延时函数是怎么"算"出 500ms 的
> 你可以用 STC-ISP 自带的**延时计算器**（STC 官方工具）自动生成延时函数：输入晶振频率（12MHz）和目标延时（500ms），工具自动算出 i/j/k 的初值。这样就不用自己手算了。实际开发中没人手算这个，都是工具生成。

## 4 易错点

- [ ] 忘了 `#include <INTRINS.H>` → `_nop_()` 未定义，编译报错。
- [ ] 主循环没写 `while(1)` → 只闪一次就结束（或行为异常）。
- [ ] `0xFE` 和 `0xFF` 搞混 → `0xFE` 最低位是 0（亮），`0xFF` 全 1（灭）。
- [ ] 以为 500ms 是精确值 → 它是按 12MHz 估算的近似值，且受编译优化影响。
- [ ] 改晶振后不重算延时初值 → 闪烁速度不对。
- [ ] 不知道"机器周期=1μs@12MHz" → 无法理解延时和后面定时器的计算。

## 5 自测

1. `P2=0xFE` 时哪颗 LED 亮？为什么？
2. 软件延时函数的本质是什么？它有什么缺点？
3. 为什么延时函数要 `#include <INTRINS.H>`？
4. 12MHz 晶振下，一个机器周期是多少？为什么选 12MHz 好算？
5. 为什么第 7 章要用定时器代替软件延时？

> [!success]- 参考答案
> 1. 第 1 颗（P2.0）亮。因为 `0xFE=1111 1110`，只有最低位为 0，低电平点亮对应的 P2.0。
> 2. 本质是让 CPU 空转（嵌套循环反复执行空操作）来消耗时间。缺点是**占用 CPU**（延时期间无法做其他事）且**不精确、不可移植**。
> 3. 因为函数里用了 `_nop_()` 空操作指令，它定义在 `INTRINS.H` 头文件里。
> 4. 一个机器周期 = 12 个振荡周期 = 12 × (1/12MHz) = **1μs**。12MHz 让机器周期恰好是整数 1μs，延时/定时初值好算。
> 5. 因为软件延时完全占用 CPU、无法"边定时边干别的"，而定时器是硬件定时，能在定时期间让 CPU 做其他事（还能触发中断），更精确、更灵活。
