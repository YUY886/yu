# 03-1 独立按键控制 LED 亮灭

> [!abstract] 这一集只解决一个问题
> **怎么读按键的状态（输入）？**
>
> 一句话：按键一端接 IO 引脚、另一端接 GND，按下时引脚被拉低。所以 `if(P3_1==0)` 就是"K1 被按下"。按下时给 LED 输出 0 点亮，松开输出 1 熄灭。
>
> 这一集是**从"输出"到"输入"的转折点**。真正值得理解的是：51 的准双向口**既是输出也是输入**，读引脚之前要理解它为什么能读到外部电平。
>
> 下一集 [[江协51 03-2 独立按键控制LED状态]] ｜ 章索引 [[江协51 03 独立按键（章索引）]]

## 1 输出与输入：同一根线的两个方向

前面第 2 章只做"输出"（程序写引脚电平）。这一章第一次做"**输入**"——程序读取外界（按键）的状态：

```text
  输出：程序 ──写──► 引脚 ──► 控制 LED（第 2 章）
  输入：按键 ──► 引脚 ──读──► 程序判断（本章）
```

关键认知：**51 的 IO 引脚是双向的**，既能输出（写），也能输入（读），甚至同一个引脚在不同时刻分别做输出和输入。

### 1.1 读引脚的 C 语法

读引脚电平，就是**直接把位变量当值用**：

```c
if(P3_1 == 0)   // 读 P3.1 引脚的电平，判断是否为 0（低电平）
{
    // 引脚是低电平
}
```

- `P3_1` 用在"读"的语境时，它代表的是**引脚当前的物理电平**（不是上次写的值）。
- 为 0 表示低电平，为 1 表示高电平。

## 2 按键电路：为什么按下是 0

```text
   +5V ──[上拉电阻]──┬── IO 引脚（P3.1）
                     │
                  ┌──┴──┐
                  │按键 K1│
                  └──┬──┘
                     │
                    GND
```

- **没按下**：按键断开，引脚被**上拉电阻拉到高电平**（5V），读 `P3_1` 得 1。
- **按下**：按键闭合，引脚直接接 GND，被**拉低到 0V**，读 `P3_1` 得 0。

所以 **"按下" = 读到的值是 0**。

> [!note] 为什么按键要接上拉电阻 + GND，而不是反过来
> 也可以反过来接（按键接 5V、引脚接下拉电阻），那样"按下 = 1"。但 51 的 P1/P2/P3 端口**内部自带弱上拉电阻**，所以"引脚接 GND、按下拉低"这种接法最自然——内部上拉已经提供了"松开时为高"的默认状态，不用外接上拉电阻。
>
> 实际上本开发板按键的"上拉"就是靠 P3 口的**内部弱上拉**实现的，外部可能没有额外上拉电阻。这是 51 准双向口带来的便利。

## 3 准双向口作为输入的关键：为什么复位后能直接读

第 2 章讲过，51 的 P1/P2/P3 是**准双向口**，输出高电平靠内部弱上拉、输出低电平靠强下拉。这里有一个重要细节：

```text
  准双向口作为输入的前提：引脚必须先处于"释放"状态（锁存器为 1）
  - 锁存器为 1 → 强下拉 MOS 截止 → 引脚由外部信号（按键）决定
  - 锁存器为 0 → 强下拉 MOS 导通 → 引脚被死死拉在 0，外部按键拉不动
```

- **复位后，P0~P3 的锁存器默认都是 1**（51 复位时端口寄存器置 0xFF）。所以强下拉 MOS 截止，引脚处于"释放"状态，外部按键能正常拉低引脚。
- 这就是为什么**复位后可以直接 `if(P3_1==0)` 读按键**，不用额外配置——因为复位已经帮你"写好了 1"。

> [!warning] 一个容易忽略的坑：写过 0 之后再读
> 如果你之前把某个引脚**输出过 0**（比如用 P2 点过灯），锁存器就存了 0，强下拉一直拉着。此时再把这个引脚当**输入**用，外部信号是拉不动的（引脚被内部强下拉锁死在 0）。
>
> 所以规范做法是：**要用某个端口做输入前，先写 `Px = 0xFF;`**（全部输出 1，释放引脚）。本集因为复位后默认就是 1，且 P3 只做输入没被写过 0，所以没显式写这句——但这是一个要记住的底层原则。

## 4 完整代码

```c
#include <REGX52.H>

void main()
{
	while(1)
	{
		if(P3_1==0 || P3_0==0)	//如果K1按键或K2按键按下
		{
			P2_0=0;		//LED1输出0，点亮
		}
		else
		{
			P2_0=1;		//LED1输出1，熄灭
		}
	}
}
```

- `P3_1==0 || P3_0==0`：K1 或 K2 任意一个按下（逻辑或 `||`）。
- 按下 → `P2_0=0` 点亮 LED1；松开 → `P2_0=1` 熄灭。

> [!note] 这是"按住亮、松开灭"
> 本集是**最简单**的按键读取，没有消抖、没有松手检测——所以效果是"按住就一直亮、松开就灭"。要"每按一次切换一次状态"，得看 3-2 的消抖三件套。

### 4.1 `==` 和 `=` 别写混

```c
if(P3_1 == 0)   // 正确：判断 P3_1 是否等于 0
if(P3_1 = 0)    // 错误：把 0 赋给 P3_1，条件恒为假
```

- `==` 是比较（相等），`=` 是赋值。判断里写 `=` 是新手最常见的 bug 之一，编译可能不报错但逻辑全错。

## 5 易错点

- [ ] 判断"按下"写成 `==1` → 本板按下是 0，应写 `==0`。
- [ ] 把 `||`（或）写成 `&&`（与）→ 会变成"两个都按下才亮"。
- [ ] 引脚名写错 → 按键是 P3_1/P3_0，LED 是 P2_0。
- [ ] `==` 写成 `=` → 赋值而非比较，条件恒为假。
- [ ] 以为读引脚前要复杂配置 → 51 复位后端口默认输出 1，直接读即可（但若之前写过 0 则需先写 1 释放）。

## 6 自测

1. 为什么判断"按下"要写 `P3_1==0` 而不是 `==1`？
2. `if(P3_1==0 || P3_0==0)` 中 `||` 的作用是什么？
3. 本集代码没有消抖，会有什么现象？
4. 为什么复位后能直接读按键，不需要额外配置？
5. 如果之前把 P3 口输出过 0，再读按键会有什么问题？怎么解决？

> [!success]- 参考答案
> 1. 因为按键一端接 GND，按下时引脚被拉低为 0，所以"按下"对应读到的值是 0。
> 2. `||` 是逻辑或，表示"K1 按下**或** K2 按下"任意一个成立就执行。
> 3. 按住就一直亮、松开就灭；且按键瞬间的机械抖动可能造成短暂的误判（本集未处理，3-2 才消抖）。
> 4. 因为 51 复位后端口锁存器默认都是 1（强下拉 MOS 截止），引脚处于"释放"状态，外部按键能正常拉低引脚，所以可直接读。
> 5. 如果锁存器存了 0，强下拉 MOS 会一直把引脚拉在 0，外部按键拉不动，读不到按键。解决：做输入前先写 `P3 = 0xFF;` 释放引脚。
