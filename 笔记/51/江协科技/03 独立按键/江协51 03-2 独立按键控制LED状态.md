# 03-2 独立按键控制 LED 状态

> [!abstract] 这一集只解决一个问题
> **怎么让"每按一次按键、LED 状态切换一次"（而不是按住才亮）？**
>
> 一句话：引入两个关键技术——**延时消抖**（滤掉按下瞬间的抖动）和**松手检测**（按住不松就不重复触发），然后在动作里用 `P2_0=~P2_0` 取反。
>
> 这一集是**按键处理的完整范式**，后面矩阵键盘、定时器按键、红外按键全是这套"消抖 + 松手检测"逻辑的变体，务必吃透。
>

## 1 为什么要消抖：机械按键的抖动

机械按键按下/松开时，金属触点会**弹跳**，电平不是干净地"高→低"，而是"高→低→高→低→低"这样抖几下（持续约 5~20ms）。

```text
理想（无抖动）：   高 ────────┐                    ┌─────
                            └────────────────────┘
                             按下              松开

实际（有抖动）：   高 ────┐  ┌┐┌┐┌┐  ┌──────┐┌┐┌┐┌┐
                         └──┘└┘└┘└┘──┘      └┘└┘└┘└──  ← 按下/松开瞬间的抖动毛刺
                          抖动期(5~20ms)    抖动期
```

- 抖动期通常 **5~20ms**（不同按键不同）。
- 如果不消抖，程序在抖动期里会**多次读到"按下"**，误判成"按了好几次"。

> [!note] 抖动是什么造成的
> 按键内部是**金属簧片 + 触点**。按下时簧片接触触点后还会弹几下（类似弹簧），产生一串断续的通断。这是机械结构的固有特性，不是故障。

## 2 消抖方案：软件延时 vs 硬件 RC

消抖有两条路：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **软件延时消抖**（本课用） | 检测到按下后延时 20ms，跳过抖动期再确认 | 无需额外硬件，改代码即可 | 占用 CPU（延时期间不能干别的） |
| **硬件 RC 消抖** | 按键并联电容/RC 滤波，从物理上滤掉毛刺 | 不占 CPU | 增加元件、成本 |

本课采用**软件延时消抖**——最简单、最通用。

> [!tip] 为什么延时 20ms
> 抖动期最多约 20ms，所以延时 20ms 能保证"抖动已经结束"。延时太短（如 1ms）可能还没跳出抖动期；太长则按键响应变迟钝。20ms 是经验上的平衡点。

## 3 消抖三件套（本课核心范式）

```c
if(P3_1==0)         // ① 检测到按下
{
    Delay(20);      // ② 延时消抖（避开按下时的抖动）
    while(P3_1==0); // ③ 松手检测：按住不松就一直卡在这里
    Delay(20);      // ④ 松手再消抖（避开松开时的抖动）

    P2_0=~P2_0;     // ⑤ 动作：LED 取反
}
```

逐步拆解：

- **① 检测按下**：`if(P3_1==0)` 读到低电平，认为"可能按下了"。
- **② 延时消抖**：`Delay(20)` 等 20ms，让按下时的抖动过去。
- **③ 松手检测**：`while(P3_1==0);` —— 只要还按着（P3_1 还是 0）就**空转等待**，直到松手（P3_1 变 1）才继续。这保证**按一次只动作一次**，不会因为按住不放而反复触发。
- **④ 再消抖**：`Delay(20)` 让松开时的抖动也过去。
- **⑤ 动作**：真正要执行的操作。

> [!warning] ② 和 ④ 两个 Delay 都不能省
> - 省了 ②：按下时的抖动会导致"按一次触发多次"。
> - 省了 ④：松开时的抖动可能导致下一次按键判断异常。
>
> 两个延时一个管"按下抖"、一个管"松开抖"，配合中间的松手检测，才构成完整的消抖逻辑。

## 4 完整代码

```c
#include <REGX52.H>

void Delay(unsigned int xms)
{
	unsigned char i, j;
	while(xms)
	{
		i = 2;
		j = 239;
		do
		{
			while (--j);
		} while (--i);
		xms--;
	}
}

void main()
{
	while(1)
	{
		if(P3_1==0)			//如果K1按键按下
		{
			Delay(20);		//延时消抖
			while(P3_1==0);	//松手检测
			Delay(20);		//延时消抖
			
			P2_0=~P2_0;		//LED1取反
		}
	}
}
```

> [!note] 这里的 Delay 是带参数的
> 从本集开始，延时函数升级为 `Delay(unsigned int xms)`——想延时多少 ms 就传多少，比 2-2 的写死 500ms 灵活。它内部 i=2/j=239 对应约 1ms@12MHz，`Delay(20)` 就是约 20ms。这个函数是后面所有章节的通用延时函数原型。

### 4.1 `P2_0 = ~P2_0` 位取反

```c
P2_0 = ~P2_0;   // 位取反：0 变 1，1 变 0
```

- `~` 是**按位取反**运算符（注意这里是"位取反"，用在位变量上就是 0↔1）。
- 效果：LED 亮 → 灭、灭 → 亮，实现"每按一次切换一次"。

> [!tip] 状态取反是"开关"类功能的通用技巧
> `状态 = ~状态` 或 `状态 = !状态` 是嵌入式里实现"按一下开、再按一下关"的经典写法。它比"用 if/else 判断当前状态再翻转"更简洁。

## 5 易错点

- [ ] 只消抖、不松手检测 → 按住不松会连续触发多次。
- [ ] 只松手检测、不消抖 → 抖动导致按一次触发多次。
- [ ] `~P2_0` 理解错 → `~` 是取反，不是"取低电平"，效果是亮灭切换。
- [ ] 两个 Delay(20) 漏一个 → 消抖不充分（一个管按下抖、一个管松开抖）。
- [ ] `while(P3_1==0);` 漏了分号 → 语法错误，或逻辑变成空循环后继续执行（语义不对）。
- [ ] 消抖延时太长 → 按键响应迟钝。

## 6 自测

1. 消抖和松手检测分别解决什么问题？
2. `P2_0=~P2_0` 实现的效果是什么？
3. 为什么 `while(P3_1==0);` 后面有个分号？
4. 为什么消抖延时选 20ms 而不是 1ms 或 1s？
5. 软件消抖和硬件 RC 消抖各有什么优缺点？

> [!success]- 参考答案
> 1. 消抖解决"机械抖动导致按一次被误判成多次"；松手检测解决"按住不松被反复触发"。
> 2. 每按一次按键，LED 状态取反一次（亮↔灭切换）。
> 3. 因为 `while(P3_1==0);` 是一个空循环体（循环体为空语句），分号是空语句；它表示"只要还按着就原地等待"。
> 4. 抖动期最多约 20ms，延时 20ms 能保证跳出抖动期；1ms 太短可能仍在抖动中，1s 太长导致按键响应迟钝。
> 5. 软件消抖：无需额外硬件、改代码即可，但延时期间占用 CPU；硬件 RC 消抖：不占 CPU，但增加元件和成本。
