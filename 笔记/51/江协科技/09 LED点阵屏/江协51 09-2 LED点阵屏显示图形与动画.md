# 09-2 LED 点阵屏显示图形 & 动画

> [!abstract] 这一集只解决一个问题
> **怎么让点阵屏动起来（显示动画）？**
>
> 答：把**多帧**图形数据连续存在一个数组里，用一个**偏移量 Offset** 每次取其中 8 列（一帧）显示，每隔一段时间偏移 +8 切换到下一帧，形成动画。
>
> 上一集 [[江协51 09-1 LED点阵屏]] ｜ 章索引 [[江协51 09 LED点阵屏（章索引）]]

## 1 动画的本质

动画 = 多张静态画面快速切换。点阵屏动画就是：把好几帧（每帧 8 列）数据依次存放，用**偏移**选中当前帧显示。

```text
Animation[] 数组：
  帧1: 8 列数据（第 0~7 个元素）
  帧2: 8 列数据（第 8~15 个元素）
  帧3: 8 列数据（第 16~23 个元素）
```

用 `Offset`（偏移）表示当前帧的起点，`Animation[i+Offset]` 取当前帧的第 i 列。

## 2 动画数据数组

```c
unsigned char code Animation[]={
	0x3C,0x42,0xA9,0x85,0x85,0xA9,0x42,0x3C,   // 帧1
	0x3C,0x42,0xA1,0x85,0x85,0xA1,0x42,0x3C,   // 帧2
	0x3C,0x42,0xA5,0x89,0x89,0xA5,0x42,0x3C,   // 帧3
};
```

- 3 帧，每帧 8 列，共 24 个元素。
- 每帧的笑脸"嘴巴"位置略有不同，切换起来像在说话/眨眼。

> [!note] `code` 关键字
> `unsigned char code Animation[]` 里的 `code` 是 Keil C51 关键字，表示把数组存到**程序存储器（ROM/Flash）**而不是 RAM。因为 51 的 RAM 很小（256B），大数组要放 code 区省 RAM。

## 3 完整代码

```c
#include <REGX52.H>
#include "Delay.h"
#include "MatrixLED.h"

unsigned char code Animation[]={
	0x3C,0x42,0xA9,0x85,0x85,0xA9,0x42,0x3C,
	0x3C,0x42,0xA1,0x85,0x85,0xA1,0x42,0x3C,
	0x3C,0x42,0xA5,0x89,0x89,0xA5,0x42,0x3C,
};

void main()
{
	unsigned char i,Offset=0,Count=0;
	MatrixLED_Init();
	while(1)
	{
		for(i=0;i<8;i++)	//循环8次，显示8列数据
		{
			MatrixLED_ShowColumn(i,Animation[i+Offset]);
		}
		Count++;			//计次延时
		if(Count>15)       // 约每 15 次扫描切一帧
		{
			Count=0;
			Offset+=8;		//偏移+8，切换下一帧画面
			if(Offset>16)   // 超出最后一帧（24 元素，起点最大 16）
			{
				Offset=0;
			}
		}
	}
}
```

- `for(i=0;i<8;i++)`：显示当前帧的 8 列。
- `Count>15`：每扫 15 次切一帧（控制动画速度）。
- `Offset+=8`：跳到下一帧；`Offset>16` 归 0（3 帧的起点是 0、8、16）。

## 4 易错点

- [ ] 大数组没加 `code` → RAM 不够（51 RAM 只有 256B）。
- [ ] 偏移越界没归 0 → 读到数组外，显示乱码。
- [ ] 动画速度不对 → `Count>15` 这个阈值控制速度，改它调快慢。
- [ ] 帧的起点算错 → 3 帧起点是 0/8/16，`Offset>16` 归 0。

## 5 自测

1. 点阵屏动画的本质是什么？
2. `code` 关键字的作用？
3. `Offset` 和 `Offset>16` 分别是什么意思？

> [!success]- 参考答案
> 1. 多帧静态画面快速切换，用偏移量选中当前帧显示。
> 2. 把数组存到程序存储器（ROM）而非 RAM，节省 51 有限的 RAM（256B）。
> 3. Offset 是当前帧的起点（0/8/16），`Offset>16` 表示超出最后一帧，要归 0 循环。
