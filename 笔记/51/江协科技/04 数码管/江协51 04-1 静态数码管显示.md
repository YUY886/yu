# 04-1 静态数码管显示

> [!abstract] 这一集只解决一个问题
> **怎么让数码管在指定位置显示一个数字？**
>
> 一句话：分两步——**位码**（P2_2/P2_3/P2_4 经 74HC138 译码）选"第几位"，**段码**（P0 输出段码表里的值）决定"显示什么数字"。
>
> 这一集第一次引入**译码器（74HC138）**这个"用 3 根线控制 8 个输出"的经典技巧，以及"段码表"这个查表思维，后面点阵屏、LCD 都会用到类似思想。
>
> 下一集 [[江协51 04-2 动态数码管显示]] ｜ 章索引 [[江协51 04 数码管（章索引）]]

## 1 数码管是什么：8 个 LED 的排列

数码管（七段数码管，Seven-Segment Display）本质就是**把 8 个 LED 段按固定形状排列**，通过点亮不同的段来显示数字。

```text
         a
        ───
     f │   │ b
        ───  ← g（中间横杠）
     e │   │ c
        ───
         d    · dp（小数点）
```

- **a、b、c、d、e、f、g** 七段组成数字轮廓，**dp** 是小数点，共 8 段。
- 显示"1"：点亮 b、c 两段；显示"8"：a~g 全亮；显示"0"：除 g 外全亮。

### 1.1 共阴极 vs 共阳极

8 个 LED 段的阴极或阳极连在一起，形成两种类型：

| 类型 | 公共端接法 | 点亮条件 | 段码特点 |
| --- | --- | --- | --- |
| **共阴极**（本板用） | 所有阴极接一起，接 GND | 给某段阳极高电平（=1）点亮 | "1"点亮 |
| **共阳极** | 所有阳极接一起，接 VCC | 给某段阴极低电平（=0）点亮 | "0"点亮 |

```text
  共阴极：                   共阳极：
     VCC→a段→公共阴极→GND       VCC→公共阳极→a段→GND
    a 段 =1 时点亮             a 段 =0 时点亮
```

> [!warning] 共阴/共阳段码互为反码
> 同一个数字，共阴和共阳的段码是**按位取反**的关系。比如数字"0"：共阴是 `0x3F`，共阳是 `0xC0`（= ~0x3F）。用错段码表，数字会显示成"反"的（亮灭颠倒）。本开发板是**共阴极**，段码位为 1 点亮。

## 2 段码表：8 段 → 一个字节

每一段的亮灭对应一个二进制位，8 段拼成一个字节，这就是**段码**。位和段的对应关系（共阴，1=亮）：

```text
  位：   7    6    5    4    3    2    1    0
  段：   dp   g    f    e    d    c    b    a
```

| 数字 | 段码（共阴） | 二进制（dp g f e d c b a） | 亮的段 |
| --- | --- | --- | --- |
| 0 | 0x3F | 0011 1111 | a b c d e f |
| 1 | 0x06 | 0000 0110 | b c |
| 2 | 0x5B | 0101 1011 | a b g e d |
| 3 | 0x4F | 0100 1111 | a b c d g |
| 4 | 0x66 | 0110 0110 | f g b c |
| 5 | 0x6D | 0110 1101 | a f g c d |
| 6 | 0x7D | 0111 1101 | a f g e c d |
| 7 | 0x07 | 0000 0111 | a b c |
| 8 | 0x7F | 0111 1111 | a b c d e f g |
| 9 | 0x6F | 0110 1111 | a b c d f g |

```c
unsigned char NixieTable[]={0x3F,0x06,0x5B,0x4F,0x66,0x6D,0x7D,0x07,0x7F,0x6F};
// 下标 0~9 对应数字 0~9 的段码
```

> [!tip] 段码不用死记，理解就能推
> 记住位对应关系：**a=第0位、b=第1位、c=第2位、d=第3位、e=第4位、f=第5位、g=第6位、dp=第7位**。
>
> 想显示"2"，就是 a、b、g、e、d 五段亮 → 位 0、1、6、4、3 为 1 → `0101 1011 = 0x5B`。理解了就能自己算，不用背表。

### 2.1 为什么要用数组（查表）

`NixieTable[]` 是一个**查表数组**：`NixieTable[数字]` 直接得到该数字的段码。

- 好处：显示任意数字只需 `P0 = NixieTable[3]`，不用写一堆 if/switch。
- 这是嵌入式里最常见的"**查表法**"——用数组下标当索引，避免大量条件分支。后面点阵屏字模、音乐频率表都用这个套路。

## 3 位码与 74HC138 译码器

开发板有 8 个数码管位（8 个独立数码管），需要 8 根线选位。但为了节省 IO，用 **74HC138（3-8 译码器）** 把 3 根 IO 译码成 8 个位选。

### 3.1 74HC138 是什么：3 线选 8 线

74HC138 是一个 **3-8 译码器**：

```text
        ┌─────────────┐
  A ────►│             │──► Y0（选第1位）
  B ────►│  74HC138    │──► Y1（选第2位）
  C ────►│  (3-8译码器) │──► Y2 ... Y7
        └─────────────┘
  3 个输入 → 8 个输出，每次只有一个输出有效（低电平）
```

- 输入 A/B/C 的 3 位二进制值（000~111）决定哪一个输出有效。
- **用 3 根 IO 代替 8 根 IO** 来选位，这是典型的"**译码复用**"技巧，省 IO 口。

> [!note] 为什么能省 IO
> 8 个位选需要 8 根线，但同一时刻只需要"1 个位被选中"，而"选第几个"这个信息只需要 3 位二进制（2³=8）就能表达。所以用 3 根线 + 译码器，就能实现 8 选 1。这是信息论里的"编码"思想在硬件上的应用。

### 3.2 位码表

本开发板把 74HC138 的 A/B/C 接到 **P2_2 / P2_3 / P2_4**：

| Location | P2_4（C） | P2_3（B） | P2_2（A） | 选中的位 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 1 | 第 1 位 |
| 2 | 1 | 1 | 0 | 第 2 位 |
| 3 | 1 | 0 | 1 | 第 3 位 |
| 4 | 1 | 0 | 0 | 第 4 位 |
| 5 | 0 | 1 | 1 | 第 5 位 |
| 6 | 0 | 1 | 0 | 第 6 位 |
| 7 | 0 | 0 | 1 | 第 7 位 |
| 8 | 0 | 0 | 0 | 第 8 位 |

> [!tip] 位码规律的记忆法
> 注意 P2_4/P2_3/P2_2 的取值其实就是 **8 减 Location 的二进制**（1→7=111、2→6=110...8→0=000），倒着排。这个"倒序"是 74HC138 低电平有效的特性决定的，理解即可，不必深究，抄表用就行。

## 4 完整代码

```c
#include <REGX52.H>

//数码管段码表
unsigned char NixieTable[]={0x3F,0x06,0x5B,0x4F,0x66,0x6D,0x7D,0x07,0x7F,0x6F};

//数码管显示子函数
void Nixie(unsigned char Location,Number)
{
	switch(Location)		//位码输出
	{
		case 1:P2_4=1;P2_3=1;P2_2=1;break;
		case 2:P2_4=1;P2_3=1;P2_2=0;break;
		case 3:P2_4=1;P2_3=0;P2_2=1;break;
		case 4:P2_4=1;P2_3=0;P2_2=0;break;
		case 5:P2_4=0;P2_3=1;P2_2=1;break;
		case 6:P2_4=0;P2_3=1;P2_2=0;break;
		case 7:P2_4=0;P2_3=0;P2_2=1;break;
		case 8:P2_4=0;P2_3=0;P2_2=0;break;
	}
	P0=NixieTable[Number];	//段码输出
}

void main()
{
	Nixie(2,3);	//在数码管的第2位置显示3
	while(1)
	{
		
	}
}
```

逐步拆解：

- `Nixie(Location, Number)`：在 **Location 位**显示 **Number 数字**。
- `switch(Location)`：根据位数选**位码**（写 P2_4/P2_3/P2_2）。
- `P0=NixieTable[Number]`：查表得到段码，输出到 **P0**。

> [!note] 函数原型里 Number 的类型
> 官方源码写的是 `void Nixie(unsigned char Location, Number)`，其中 `Number` 没写类型（隐含 int）。更规范应写 `void Nixie(unsigned char Location, unsigned char Number)`。这是老师源码里的一个笔误/简写，学习时知道即可。

## 5 易错点

- [ ] 段码表索引和数字对不上 → `NixieTable[3]` 是显示"3"（0x4F），不是第 3 位。
- [ ] 位码/段码顺序反了 → 先选位（Location）再送段码（Number）。
- [ ] 段码 0x3F 等记错 → 共阴数码管"0"是 0x3F，不是 0xC0（那是共阳）。
- [ ] Location 范围 1~8 → 传 0 或 9 会没 case 匹配，位码不确定。
- [ ] 共阴共阳搞反 → 本板共阴，段码位为 1 点亮；用成共阳段码会亮灭颠倒。

## 6 自测

1. 显示数字"5"的段码是多少？为什么？
2. 位码和段码分别由哪些引脚控制？
3. `Nixie(2,3)` 实现什么效果？
4. 74HC138 的作用是什么？为什么能"省 IO"？
5. 共阴极和共阳极数码管的段码是什么关系？

> [!success]- 参考答案
> 1. 0x6D（0110 1101），即 a、c、d、f、g 五段点亮（位 0、2、3、5、6 为 1）。
> 2. 位码由 P2_2/P2_3/P2_4（经 74HC138 译码）控制，段码由 P0 输出。
> 3. 在数码管第 2 位显示数字 3。
> 4. 74HC138 是 3-8 译码器，用 3 根线译出 8 个位选。能省 IO 是因为"选第几位"只需 3 位二进制（2³=8），用译码器把 3 根线扩展成 8 根选位线。
> 5. 互为**按位取反**（反码）：同一数字共阴是 0x3F，共阳就是 ~0x3F=0xC0。
