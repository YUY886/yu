# 17-1 红外遥控

> [!abstract] 这一集只解决一个问题
> **怎么解析红外遥控器发出的数据？**
>
> 答：用**外部中断（INT0）+ 定时器计时 + 状态机**解析 **NEC 红外协议**。红外接收头把遥控信号转成脉冲，程序测脉冲宽度区分 0/1，逐步解出地址码和命令码。
>

## 1 红外遥控原理

- 遥控器发出 **38kHz 载波调制**的红外信号，接收头解调成电平脉冲。
- **NEC 协议**：一帧数据 = 引导码 + 地址码 + 地址反码 + 命令码 + 命令反码。
- 逻辑 0 和 1 由**脉冲间隔**区分（1 的间隔比 0 长）。

```text
  引导码(9ms+4.5ms) | 地址码 8 位 | 地址反码 8 位 | 命令码 8 位 | 命令反码 8 位
```

### 1.1 为什么要有 38kHz 载波

红外遥控不是简单"亮红外灯"，而是用 **38kHz 的载波**调制信号：

```text
  无载波（不行）：   直接高低电平 → 环境光（太阳、灯）全是红外，会严重干扰
  有载波（正确）：   信号 × 38kHz 载波 → 接收头只认 38kHz，滤掉环境干扰
```

- **38kHz 载波**：信号"有"时发出 38kHz 脉冲，接收头专门检测这个频率。
- **抗干扰**：环境光是"直流"或低频，没有 38kHz 成分，接收头能自动滤掉，只认遥控器的信号。
- 接收头（一体化红外接收头）内部完成解调，输出给单片机的已经是干净的**基带电平**（高/低）。

> [!note] 红外接收头输出是"反相"的
> 常见红外接收头（如 HS0038）输出是**反相**的：有信号时输出低电平，无信号时输出高电平。所以程序里检测到的电平和高低，和"发光/不发光"是反的，理解协议时要注意这一点。

### 1.2 NEC 协议的数据帧结构

NEC 协议一帧由几部分组成：

```text
  引导码          地址码     地址反码    命令码     命令反码
  ┌──────────┐  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
  │9ms低+4.5ms高│ 8位      │ 8位(反码) │ 8位      │ 8位(反码) │
  └──────────┘  └────────┘ └────────┘ └────────┘ └────────┘
```

- **引导码**：9ms 低 + 4.5ms 高，标志"一帧开始"。
- **地址码**：8 位，标识是哪类设备/遥控器。
- **地址反码**：地址码的按位取反，用于**校验**（防止误码）。
- **命令码**：8 位，具体按键（如音量+、音量-）。
- **命令反码**：命令码的取反，也用于校验。

### 1.3 逻辑 0 和 1 怎么区分

NEC 协议里，逻辑 0 和 1 都"先低后高"，区别在**高电平持续的时间**：

```text
  逻辑 0：  低 560us + 高 560us   （高电平短）
  逻辑 1：  低 560us + 高 1680us  （高电平长，约 3 倍）
```

- 程序用定时器测"高电平持续多久"，短的是 0，长的是 1。
- 这就是为什么红外解析需要**定时器计时**（测脉宽）。

> [!tip] 红外解析 = 测脉宽 + 状态机
> 红外解码的核心就是两件事：
> 1. **测脉宽**（定时器计时，区分引导码、0、1）。
> 2. **状态机**（按顺序：等引导码 → 收 32 位 → 完成）。
>
> 理解了这两点，红外解码的逻辑就通了。

## 2 三个关键模块

| 模块 | 作用 |
| --- | --- |
| **Int0（外部中断）** | 红外接收头信号跳变触发中断 |
| **Timer0** | 计时，测量脉冲宽度 |
| **IR 状态机** | 按状态依次解析引导码、地址、命令 |

```c
#include "Timer0.h"
#include "Int0.h"

void IR_Init(void)
{
	Timer0_Init();   // 定时器计时
	Int0_Init();     // 外部中断 0 检测信号
}
```

## 3 数据解析流程

用状态机逐步解析：

```c
unsigned char IR_Data[4];    // 存 4 字节（地址、地址反码、命令、命令反码）
unsigned char IR_State;      // 状态机当前状态
unsigned char IR_pData;      // 数据指针

// 外部中断里（Int0）：
// ① 状态 0：检测引导码（9ms 低 + 4.5ms 高）
// ② 状态 1：接收 32 位数据（用定时器测每位时长，区分 0/1）
// ③ 收到完整一帧 → 置 IR_DataFlag
```

- 引导码确认后，逐位接收 32 位（地址 8 + 地址反码 8 + 命令 8 + 命令反码 8）。
- 每位的 0/1 由定时器测得的脉冲宽度判断。

## 4 获取解析结果

```c
unsigned char IR_GetDataFlag(void);    // 是否收到数据帧
unsigned char IR_GetAddress(void);     // 地址码
unsigned char IR_GetCommand(void);     // 命令码
```

main 里轮询数据帧标志，收到后读地址码和命令码：

```c
if(IR_GetDataFlag() || IR_GetRepeatFlag())   // 收到数据帧或连发帧
{
	Address=IR_GetAddress();
	Command=IR_GetCommand();
	// 显示或处理
}
```

## 5 完整代码（main.c）

```c
#include <REGX52.H>
#include "Delay.h"
#include "LCD1602.h"
#include "IR.h"

unsigned char Num;
unsigned char Address;
unsigned char Command;

void main()
{
	LCD_Init();
	LCD_ShowString(1,1,"ADDR  CMD  NUM");
	LCD_ShowString(2,1,"00    00   000");
	
	IR_Init();
	
	while(1)
	{
		if(IR_GetDataFlag() || IR_GetRepeatFlag())
		{
			Address=IR_GetAddress();
			Command=IR_GetCommand();
			
			LCD_ShowHexNum(2,1,Address,2);
			LCD_ShowHexNum(2,7,Command,2);
			
			if(Command==IR_VOL_MINUS)   // VOL- 键
			{
				Num--;
			}
			if(Command==IR_VOL_ADD)     // VOL+ 键
			{
				Num++;
			}
			
			LCD_ShowNum(2,12,Num,3);
		}
	}
}
```

## 6 易错点

- [ ] 晶振影响时序 → 红外时序敏感，12MHz 和 11.0592MHz 有不同版本。
- [ ] 状态机顺序错 → 引导码 → 32 位数据，顺序不能乱。
- [ ] 地址码/命令码搞反 → 两个都要读，别混淆。
- [ ] 连发帧没处理 → 长按遥控器会有重复帧（RepeatFlag）。
