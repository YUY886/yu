# 08-2 串口向电脑发送数据 & 电脑通过串口控制 LED

> [!abstract] 这一集只解决一个问题
> **怎么接收电脑发来的数据，并用它控制硬件？**
>
> 答：用**串口接收中断**（`interrupt 4`）。收到数据时 RI 置 1 触发中断，在中断里读 SBUF 得到数据，取反后输出到 LED，再回发给电脑。
>
> 上一集 [[江协51 08-1 串口通信]] ｜ 章索引 [[江协51 08 串口通信（章索引）]]

## 1 接收中断

串口收/发共用中断号 **4**（`interrupt 4`）。收到一个字节时，硬件把 **RI（接收标志）** 置 1，进入中断：

```c
void UART_Routine() interrupt 4
{
	if(RI==1)          // 收到数据
	{
		P2=~SBUF;          // 读 SBUF，取反输出到 LED
		UART_SendByte(SBUF);// 把收到的数据回发
		RI=0;              // 清接收标志
	}
}
```

- **RI=1**：表示接收完成，SBUF 里是收到的数据。
- **读 SBUF** 得到数据（这里是取反后给 P2，因为 LED 低电平点亮）。
- **清 RI**：必须手动清 0，否则一直认为有新数据。

## 2 收发标志对比

| 标志 | 含义 | 何时置 1 | 谁清 |
| --- | --- | --- | --- |
| `TI` | 发送完成 | 发完一帧 | 软件清 0 |
| `RI` | 接收完成 | 收到一帧 | 软件清 0 |

> [!tip] TI 和 RI 别搞混
> TI = Transmit（发送）完成，RI = Receive（接收）完成。发送用 `while(TI==0)` 等，接收在中断里查 `if(RI==1)`。

## 3 完整代码

```c
#include <REGX52.H>
#include "Delay.h"
#include "UART.h"

void main()
{
	UART_Init();		//串口初始化
	while(1)
	{
		
	}
}

void UART_Routine() interrupt 4
{
	if(RI==1)					//如果接收标志位为1，接收到了数据
	{
		P2=~SBUF;				//读取数据，取反后输出到LED
		UART_SendByte(SBUF);	//将收到的数据发回串口
		RI=0;					//接收标志位清0
	}
}
```

- main 是空的，所有工作在中断里完成。
- 效果：串口助手发一个字节，LED 显示它的取反值，同时电脑收到回发的原值。

## 4 易错点

- [ ] 忘了清 RI → 中断反复触发，收不到后续数据。
- [ ] 中断号写错 → 串口是 interrupt 4（T0 是 1，T1 是 3）。
- [ ] TI/RI 混淆 → 接收查 RI，发送等 TI。
- [ ] 直接 `P2=SBUF` 没取反 → LED 亮灭和预期相反（低电平点亮）。

## 5 自测

1. 串口收发中断号是几？TI 和 RI 分别代表什么？
2. 为什么收到数据后要清 RI？
3. `P2=~SBUF` 为什么取反？

> [!success]- 参考答案
> 1. 中断号 4。TI=发送完成标志，RI=接收完成标志。
> 2. RI 是硬件置 1 的，必须软件清 0，否则程序会一直认为有新数据到达，反复进中断。
> 3. 因为 LED 低电平点亮，收到的数据取反后，为 1 的位变 0 对应 LED 亮，使灯亮灭和数据的 0/1 对应。
