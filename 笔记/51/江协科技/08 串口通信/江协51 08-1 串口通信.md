# 08-1 串口通信

> [!abstract] 这一集只解决一个问题
> **单片机怎么和电脑"对话"（收发数据）？**
>
> 一句话：用**串口（UART，异步串行通信）**。核心是配置好**波特率**（两端一致），然后用 SCON/PCON/定时器 1 配置串口，通过 SBUF 收发数据。
>
> 这一集引入"串行通信"这个全新的通信范式——和前面"并行 8 位"完全不同，它用**一根线按位串行**传送数据。理解了串口，后面 I2C、单总线、红外这些"串行协议"都更好上手。
>
> 下一集 [[江协51 08-2 串口向电脑发送数据与电脑通过串口控制LED]] ｜ 章索引 [[江协51 08 串口通信（章索引）]]

## 1 串口通信是什么：串行 vs 并行

前面用 P0~P3 控制 LED/数码管，是**并行**通信——8 根线同时传 8 位。串口是**串行**通信——数据一位一位地在一根线上传。

```text
  并行（8位，8根线）：        串行（1位，1根线）：
   ──► bit7                   时间 →
   ──► bit6            ┌─┬─┬─┬─┬─┬─┬─┬─┐
   ──► bit5            │1│0│1│1│0│0│1│0│  按位依次发送
   ──► bit4            └─┴─┴─┴─┴─┴─┴─┴─┘
   ... 8 根线同时发 8 位
```

- **并行**：快，但线多（8 位要 8 根线）。
- **串行**：慢，但只用 1~2 根线，适合远距离、省 IO 的通信。

UART 用**两根线**通信：

```text
  单片机 ──TXD──► RXD── 电脑   （单片机发、电脑收）
         ◄──RXD── TXD──        （电脑发、单片机收）
```

> [!note] 为什么叫"异步"（Asynchronous）
> UART = Universal **Asynchronous** Receiver/Transmitter，通用**异步**收发器。"异步"的意思是**没有时钟线**——发送方和接收方不共享时钟，而是靠双方事先约定好的**波特率**（传输速度）来同步。
>
> 对比：I2C/SPI 有专门的时钟线（同步），串口没有（异步）。

## 2 串口的数据帧格式

串口一帧数据（一个字节）由几部分组成：

```text
        ┌ 空闲 ┬─ 起始位 ─┬──── 8 位数据位 ────┬─ 停止位 ─┐
  电平  ────────┐          ┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐
  高(1) 空闲      │          │ │ │ │ │ │ │ │ │              ─── 空闲
  低(0)           └──────────┘ └─┘└─┘└─┘└─┘└─┘└─┘└─┘
                   起始位(1bit)   数据位(8bit)        停止位(1bit)
```

- **起始位**：1 位低电平（0），标志"开始传输"。
- **数据位**：8 位数据（先发最低位 LSB）。
- **停止位**：1 位高电平（1），标志"传输结束"。

> [!note] 先发低位（LSB）
> 串口发数据是**先发最低位**（LSB-first）。比如要发 `0x41`（0100 0001），实际按位发的顺序是 1→0→0→0→0→0→1→0（从 bit0 到 bit7）。

> [!warning] 波特率必须两端一致
> 波特率（bps，bits per second）是收发双方"说话的速度"。两端波特率不一致，收到的就是乱码。串口助手和单片机要设成同一个值（本课用 4800）。

## 3 波特率的产生：定时器 1

串口波特率由**定时器 1（T1）**产生。这里用 T1 的**模式 2（8 位自动重装）**，因为模式 2 溢出后自动重装初值，不需要手动干预，最适合做波特率发生器。

### 3.1 51 的波特率计算公式（方式1）

串口方式 1 的波特率公式：

```text
波特率 = (2^SMOD / 32) × (定时器1溢出率)
      = (2^SMOD / 32) × (晶振频率 / 12 / (256 - TH1))
```

- `SMOD`：PCON 的最高位，0 或 1。SMOD=1 时波特率加倍（所以叫"波特率倍频位"）。
- `TH1`：定时器 1 的重装值（模式 2 下 TH1 就是计数初值）。
- 本课设 `SMOD=1`，用 12MHz 晶振，要 4800bps，反推 TH1 ≈ 0xF3。

### 3.2 本课配置（4800bps@12MHz）

```c
void UART_Init()
{
	SCON=0x40;        // 方式 1（8 位 UART），允许接收
	PCON |= 0x80;     // SMOD=1（波特率加倍）
	TMOD &= 0x0F;     // 清 T1 的高 4 位
	TMOD |= 0x20;     // T1 模式 2（8 位自动重装）
	TL1 = 0xF3;       // 定时初值
	TH1 = 0xF3;       // 自动重装值
	ET1 = 0;          // 禁止 T1 中断（只做波特率，不中断）
	TR1 = 1;          // 启动 T1
}
```

### 3.3 关键寄存器

| 寄存器/位 | 作用 |
| --- | --- |
| `SCON` | 串口控制寄存器（方式、允许接收等） |
| `PCON` 的 SMOD 位 | 波特率加倍位（SMOD=1 加倍） |
| `TMOD` | T1 设为模式 2 |
| `TL1`/`TH1` | 波特率初值/重装值 |
| `TR1` | 启动 T1 |

> [!note] 12MHz 波特率的"不完美"
> 12MHz 晶振下有些波特率（如 9600）误差较大，所以课程选 **4800bps**（误差小）。更常见的是用 **11.0592MHz** 晶振，它能精确产生 9600、19200 等标准波特率（因为 11059200 = 9600 × 1152，能被标准波特率整除）。
>
> 这就是为什么第 17 章红外遥控有"11.0592MHz 版本"——红外解码和串口都要精确的时序，11.0592MHz 更好算。

### 3.4 SCON 寄存器逐位

SCON（串口控制寄存器，可位寻址）：

| 位 | 名称 | 作用 |
| --- | --- | --- |
| SM0 SM1 | 串口方式 | 00=方式0、**01=方式1（8位UART）**、10=方式2、11=方式3 |
| SM2 | 多机通信 | 方式1下一般清 0 |
| REN | 允许接收 | 1=允许接收（本课 SCON=0x40 里 REN=1） |
| TB8/RB8 | 第 9 位 | 方式2/3 用，方式1 不用 |
| **TI** | 发送完成标志 | 发完一帧硬件置 1，软件清 0 |
| **RI** | 接收完成标志 | 收到一帧硬件置 1，软件清 0 |

> [!note] 为什么 SCON=0x40
> `0x40 = 0100 0000`：
> - SM0=0、SM1=1 → 方式 1（8 位 UART）
> - REN=1 → 允许接收
> - 其余位（含 TI/RI）为 0。
>
> 注意 TI/RI 也在 SCON 里，所以操作 SCON 时要小心别误清这两个标志。

## 4 发送一个字节

```c
void UART_SendByte(unsigned char Byte)
{
	SBUF=Byte;        // 写 SBUF 触发发送
	while(TI==0);     // 等发送完成（TI 置 1）
	TI=0;             // 清发送完成标志
}
```

- `SBUF`：串口数据缓冲寄存器（**写 SBUF = 发送，读 SBUF = 接收**，同一个名字两个用途）。
- `TI`：发送完成标志，硬件在发完一帧后置 1，软件要手动清 0。
- `while(TI==0)`：等待发送完成，确保上一个字节发完再发下一个。

> [!tip] SBUF 的双重身份
> SBUF 这个寄存器很特殊：**写它启动发送，读它得到接收数据**。虽然同名，但内部是**两个独立的物理寄存器**（发送缓冲和接收缓冲），硬件根据"读还是写"自动区分。所以 `SBUF=x` 和 `y=SBUF` 操作的是不同寄存器。

## 5 完整代码（8-1 发送数据）

```c
#include <REGX52.H>
#include "Delay.h"
#include "UART.h"

unsigned char Sec;

void main()
{
	UART_Init();			//串口初始化
	while(1)
	{
		UART_SendByte(Sec);	//串口发送一个字节
		Sec++;				//Sec自增
		Delay(1000);		//延时1秒
	}
}
```

- 效果：每秒往电脑发一个递增的字节，串口助手里能看到数据。
- 注意 `Sec` 是 `unsigned char`，加到 255 会回绕到 0，是正常现象。

## 6 易错点

- [ ] 波特率两端不一致 → 乱码。
- [ ] 发送后没等 `while(TI==0)` → 数据未发完被覆盖。
- [ ] 忘了清 TI → 只发一次就卡住（TI 一直是 1）。
- [ ] 晶振 12MHz 却设 9600 标准波特率 → 误差大，可能乱码（12MHz 用 4800 更稳）。
- [ ] `TMOD &= 0x0F; TMOD |= 0x20;` 写成 `TMOD=0x20` → 覆盖了 T0 的配置。
- [ ] 忘了 `PCON |= 0x80`（SMOD=1）→ 波特率减半，和串口助手对不上。

## 7 自测

1. 串口通信为什么叫"异步"？
2. 一帧串口数据由哪几部分组成？
3. 串口波特率由谁产生？用什么模式？
4. `UART_SendByte` 里 `while(TI==0)` 的作用？
5. 为什么 12MHz 下选 4800bps 而不是 9600bps？

> [!success]- 参考答案
> 1. 因为没有独立时钟线，靠双方约定好的波特率来同步收发节奏。
> 2. 起始位（1 位 0）+ 数据位（8 位）+ 停止位（1 位 1）。
> 3. 由定时器 1（T1）产生，用 T1 的模式 2（8 位自动重装）。
> 4. 等待发送完成（TI 置 1），确保上一个字节发完再发下一个，避免数据覆盖丢失。
> 5. 12MHz 晶振下 9600bps 误差较大，4800bps 误差小、更稳定；11.0592MHz 才能精确产生 9600 等标准波特率。
