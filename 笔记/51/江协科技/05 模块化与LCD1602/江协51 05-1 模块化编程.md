# 05-1 模块化编程

> [!abstract] 这一集只解决一个问题
> **怎么把越来越长的代码组织成多个文件，方便复用和维护？**
>
> 答：把功能拆成"模块"——每个模块一个 `.c`（实现）+ 一个 `.h`（声明），用 `#ifndef` 防止重复包含。这样 Delay、Nixie 等通用功能写一次，后面每章直接 `#include` 复用。
>
> 下一集 [[江协51 05-2 LCD1602调试工具]] ｜ 章索引 [[江协51 05 模块化与LCD1602（章索引）]]

## 1 为什么要模块化

到第 4 章为止，所有代码都塞在一个 main.c 里。随着功能变多（延时、数码管、按键、液晶……），main.c 会越来越乱，而且**每做一个新工程都要重抄一遍**延时函数、数码管函数。

模块化 = 把通用功能抽出来单独放，以后直接"拿来用"：

```text
  单个 main.c（旧）              多个模块（新）
  ┌──────────────┐         ┌──────────┐ ┌──────────┐ ┌──────────┐
  │ main.c        │         │ Delay.c/h │ │ Nixie.c/h │ │ main.c    │
  │ + 延时函数     │   →     │ 延时模块   │ │ 数码管模块 │ │ 主程序    │
  │ + 数码管函数   │         └──────────┘ └──────────┘ └──────────┘
  └──────────────┘
```

## 2 模块的组成

每个模块由两个文件组成：

| 文件 | 内容 | 作用 |
| --- | --- | --- |
| `Delay.h` | 函数**声明** | 告诉别人"这个模块提供哪些函数" |
| `Delay.c` | 函数**实现** | 具体怎么干 |

### Delay.h（声明）

```c
#ifndef __DELAY_H__
#define __DELAY_H__

void Delay(unsigned int xms);   // 只声明，不实现

#endif
```

### Delay.c（实现）

```c
//延时子函数
void Delay(unsigned int xms)
{
	unsigned char i, j;
	while(xms--)
	{
		i = 2;
		j = 239;
		do
		{
			while (--j);
		} while (--i);
	}
}
```

## 3 头文件保护（#ifndef）

`#ifndef __DELAY_H__ / #define __DELAY_H__ / #endif` 这套叫**头文件保护**，防止同一个头文件被多次包含导致"重复定义"：

```c
#ifndef __DELAY_H__   // 如果没有定义过 __DELAY_H__
#define __DELAY_H__   // 就定义它

void Delay(unsigned int xms);

#endif                // 结束
```

- 第一次包含：`__DELAY_H__` 没定义 → 定义它，内容生效。
- 第二次包含：`__DELAY_H__` 已定义 → 整个内容被跳过。

> [!tip] 保护宏的命名习惯
> 一般用"模块名大写 + 前后下划线"，如 `__DELAY_H__`、`__NIXIE_H__`。只要唯一即可。

## 4 怎么用模块

在 main.c 里 `#include` 模块头文件：

```c
#include <REGX52.H>
#include "Delay.h"	//包含Delay头文件
#include "Nixie.h"	//包含数码管头文件

void main()
{
	while(1)
	{
		Nixie(1,1);
		Nixie(2,2);
		Nixie(3,3);
		Nixie(4,4);
		Nixie(5,5);
		Nixie(6,6);
	}
}
```

> [!note] 双引号 vs 尖括号
> `#include "Delay.h"`（双引号）→ 先在当前目录找，用于**自己的模块**；`#include <REGX52.H>`（尖括号）→ 在系统库目录找，用于**系统头文件**。

## 5 完整模块清单（本集）

本集把第 4 章的延时和数码管拆成了两个模块：

- `Delay.h` / `Delay.c`：延时函数 `Delay(xms)`。
- `Nixie.h` / `Nixie.c`：数码管显示 `Nixie(Location, Number)`（内含段码表和位码）。

Nixie.c 的内容和第 4 章一样，只是抽到了独立文件里，main.c 只负责调用。

## 6 易错点

- [ ] `.c` 忘了 `#include` 自己的 `.h` → 声明和实现可能不一致。
- [ ] 头文件没加 `#ifndef` 保护 → 重复包含报"重复定义"错误。
- [ ] 用 `<>` 包含自己的模块 → 找不到，应改用 `""`。
- [ ] 在 `.h` 里写函数实现（而非声明）→ 被多个文件包含时会重复定义（除非加 static/inline）。
- [ ] 改了模块但没重新编译 → Keil 未检测到变化，现象没更新。

## 7 自测

1. 模块化的两个文件分别放什么？
2. 头文件保护 `#ifndef` 解决什么问题？
3. 包含自己的模块用 `""` 还是 `<>`？为什么？

> [!success]- 参考答案
> 1. `.h` 放函数声明（接口），`.c` 放函数实现（具体逻辑）。
> 2. 防止同一个头文件被多次包含导致"重复定义"错误。
> 3. 用 `""`（双引号），因为它会先在当前目录查找；`<>` 只在系统库目录查找。
