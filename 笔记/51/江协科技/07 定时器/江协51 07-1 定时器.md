# 07-1 定时器

> [!abstract] 这一集只解决一个问题
> **怎么不占用 CPU 地精确计时？**
>
> 一句话：用**硬件定时器**。定时器独立于 CPU 后台计数，到点触发**中断**。只需配置 TMOD（模式）、TL0/TH0（初值）、ET0/EA（开中断），再写一个 `interrupt 1` 中断函数即可。
>
> 这一集是整门课的**分水岭**：从"软件延时死等"进化到"硬件定时 + 中断"。它第一次引入**中断**这个概念，后面串口中断、外部中断、红外解码全都是同一个模型。
>
> 下一集 [[江协51 07-2 按键控制LED流水灯模式与定时器时钟]] ｜ 章索引 [[江协51 07 定时器（章索引）]]

## 1 定时器 vs 软件延时

| | 软件延时（Delay） | 硬件定时器 |
| --- | --- | --- |
| 实现 | CPU 空转数循环 | 独立硬件计数器 |
| 是否占 CPU | 占满（延时期间干不了别的） | 不占（后台计数） |
| 精度 | 粗略、受编译影响 | 精确 |
| 适用 | 短延时 | 精确定时、多任务 |

> [!tip] 为什么需要定时器（核心动机）
> 软件延时期间 CPU 被"锁死"，什么也做不了——你在 Delay(500ms) 里，按键、显示全部停摆。定时器把"计时"交给硬件，CPU 可以**同时**处理按键、显示等其他事。这是从"单任务"走向"多任务"的关键一步，也是后面做"数码管时钟 + 按键可调"这类组合功能的必要前提。

## 2 定时器的硬件结构

STC89C52 有 T0、T1 两个定时器（本课主要用 T0）。定时器本质是一个**计数器**，核心结构：

```text
        晶振 12MHz
           │
      ┌────▼────┐
      │ 12 分频  │  → 每 1 个机器周期（1μs）产生一个计数脉冲
      └────┬────┘
           │ 计数脉冲
      ┌────▼──────────────┐
      │ 计数器 TH0:TL0     │  16 位，每来一个脉冲加 1
      │  (初值 0xFC18)     │
      └────┬──────────────┘
           │ 加到 0xFFFF → 再加 1 → 溢出
      ┌────▼────┐
      │ TF0=1    │  溢出标志置 1
      └────┬────┘
           │ 如果 ET0=1 且 EA=1
      ┌────▼────┐
      │ 触发中断  │  → CPU 暂停当前程序，跳去执行中断函数
      └─────────┘
```

关键流程：

1. 晶振 12MHz → 12 分频 → 每个**机器周期 = 1μs** 产生一个计数脉冲。
2. 计数器（TH0:TL0 拼成的 16 位）每来一个脉冲加 1。
3. 从初值开始加，加到 0xFFFF 再 +1 就**溢出**，TF0 标志置 1。
4. 若中断已使能（ET0=1、EA=1），溢出就触发**中断**，CPU 暂停当前任务，跳到中断函数执行。
5. 中断函数里重装初值，重新开始下一轮计时。

> [!note] 定时 vs 计数
> 51 的定时器既能"定时"也能"计数"：
> - **定时模式**：计数脉冲来自内部晶振（每机器周期一个），用于精确延时。
> - **计数模式**：计数脉冲来自外部引脚（T0=P3.4/T1=P3.5 的下降沿），用于统计外部事件次数。
>
> 本课只用定时模式。计数模式由 TMOD 的 C/T 位选择。

## 3 定时初值的计算（本集核心公式）

要定时 1ms，需要算初值。核心逻辑：**让计数器从"初值"加到"溢出"，恰好经历 1000 个脉冲（1000μs = 1ms）**。

```text
机器周期 = 12 / 晶振频率 = 12 / 12MHz = 1μs
定时 1ms = 1000μs → 需要计 1000 个数

16 位计数器满值 = 65536（0x0000 ~ 0xFFFF）
初值 = 65536 - 计数个数 = 65536 - 1000 = 64536 = 0xFC18
   高 8 位 TH0 = 0xFC
   低 8 位 TL0 = 0x18
```

拆解 `64536 = 0xFC18`：

```text
  64536 / 256 = 252 余 24
  252 = 0xFC → TH0（高 8 位）
  24  = 0x18 → TL0（低 8 位）
```

> [!tip] 通用初值公式（背这个）
> ```
> 初值 = 65536 - 定时时间(μs)
> TH0 = 初值 / 256
> TL0 = 初值 % 256
> ```
> 例：定时 50ms → 初值 = 65536 - 50000 = 15536 = 0x3CB0 → TH0=0x3C, TL0=0xB0。

> [!warning] 初值和晶振绑定
> 0xFC18 是按 **12MHz 晶振**算的（机器周期=1μs）。换晶振（如 11.0592MHz，机器周期≈1.085μs），初值就要重算。这是第 8 章串口波特率、第 17 章红外两个晶振版本共存的根本原因——**初值、波特率都依赖晶振频率**。

## 4 定时器相关寄存器详解

### 4.1 TMOD：定时器工作方式寄存器（不可位寻址）

TMOD 是 8 位，**低 4 位控制 T0，高 4 位控制 T1**，结构对称：

```text
  TMOD ：
   高4位(管T1)            低4位(管T0)
  GATE C/T  M1 M0      GATE C/T  M1 M0
   │    │   └─┴─┐        │    │   └─┴─┐
   │    │    工作方式     │    │    工作方式
   │    └─ 计数/定时      │    └─ 计数/定时
   └─ 门控位              └─ 门控位
```

| 位 | 名称 | 作用 |
| --- | --- | --- |
| GATE | 门控位 | 0=软件启动（TR0 控制）；1=需外部引脚也配合（本课用 0） |
| C/T | 计数/定时 | 0=**定时**（内部晶振）；1=计数（外部引脚） |
| M1 M0 | 工作方式 | 00=方式0、01=**方式1（16位）**、10=方式2（8位自动重装）、11=方式3 |

四种工作方式：

| 方式 | M1 M0 | 位数 | 特点 |
| --- | --- | --- | --- |
| 方式0 | 0 0 | 13 位 | 兼容老 8051，少用 |
| **方式1** | 0 1 | **16 位** | **本课用**：计数范围 0~65535，溢出后需手动重装 |
| 方式2 | 1 0 | 8 位自动重装 | 8 位计数，溢出后自动重装（常做串口波特率发生器） |
| 方式3 | 1 1 | 拆分 | T0 拆成两个 8 位，少用 |

```c
TMOD &= 0xF0;	// 清 T0 的低 4 位（保留 T1 的高 4 位不动）
TMOD |= 0x01;	// 设 T0 = 方式1（M1M0=01，C/T=0 定时，GATE=0）
```

> [!note] 为什么用 `&= 0xF0` 再 `|= 0x01`
> 这是"只改 T0 不影响 T1"的标准写法：
> - `&= 0xF0`：把低 4 位清零（高 4 位 = T1 的配置保留）。
> - `|= 0x01`：把低 4 位设为 0001（方式1）。
>
> 如果直接 `TMOD = 0x01`，会把高 4 位（T1 的配置）也覆盖掉。若后面同时用 T1（如串口波特率），就会出问题。所以养成"先清后设"的习惯。

### 4.2 TCON：定时器控制寄存器（可位寻址）

TCON 的每一位都是独立的控制/标志位，可位寻址（能用 `TR0=1` 这种写法）：

| 位 | 名称 | 作用 |
| --- | --- | --- |
| `TF0` | T0 溢出标志 | 溢出自动置 1；查询/进入中断后清 0 |
| `TR0` | T0 启动位 | 1=启动定时器，0=停止 |
| `TF1`/`TR1` | T1 对应位 | 同 T0 |
| `IE0/IT0`、`IE1/IT1` | 外部中断相关 | 第 5 章外部中断（本课不用） |

```c
TF0 = 0;	// 清溢出标志（防止上电残留误触发）
TR0 = 1;	// 启动定时器 0（开始计时）
```

### 4.3 中断使能：IE 和 IP

定时器要能触发中断，还要开两个开关：

| 位 | 名称 | 作用 |
| --- | --- | --- |
| `EA` | 总中断开关 | **总闸**，=1 才允许任何中断 |
| `ET0` | T0 中断使能 | 分闸，=1 允许 T0 中断 |
| `PT0` | T0 优先级 | =1 高优先级，=0 低（默认） |

```c
ET0 = 1;	// 允许定时器 0 中断
EA  = 1;	// 允许总中断（总闸）
PT0 = 0;	// 优先级（默认低）
```

> [!warning] EA 总中断别忘
> 即使 ET0=1，只要 EA=0，中断仍然进不来。**EA 是所有中断的"总闸"**，这是新手最常漏的一行。类比：EA 是家里总电闸，ET0 是某个房间的分闸——总闸关了，分闸全开也没电。

## 5 中断是什么、怎么响应

### 5.1 中断的基本概念

**中断（Interrupt）** = CPU 正在执行主程序时，硬件事件（如定时器溢出）"打断"它，让它先去处理紧急事件，处理完再回来。

```text
  正常执行：  主程序 ──────► 主程序 ──────► 主程序
                              ▲ 打断
  发生中断：  主程序 ──────► 中断服务函数 ──► 主程序（继续）
                             （处理定时事件）
```

- **中断源**：触发中断的事件（定时器溢出、串口收到数据、外部引脚跳变……）。
- **中断服务函数（ISR）**：中断触发后要执行的函数。
- **中断向量/中断号**：每个中断源有固定的编号，51 里用 `interrupt n` 指定。

### 5.2 51 的中断源和中断号

| 中断源 | 中断号（interrupt n） | 触发条件 |
| --- | --- | --- |
| 外部中断 0（INT0） | 0 | P3.2 引脚跳变 |
| **定时器 0** | **1** | T0 溢出 |
| 外部中断 1（INT1） | 2 | P3.3 引脚跳变 |
| 定时器 1 | 3 | T1 溢出 |
| 串口 | 4 | 串口收发 |

> [!warning] 中断号要写对
> 定时器 0 是 `interrupt 1`，定时器 1 是 `interrupt 3`。写错中断号，中断函数不会被正确调用。这是新手常见错误。

### 5.3 中断函数（ISR）的写法

```c
void Timer0_Routine() interrupt 1   // interrupt 1 = 定时器 0 中断
{
	static unsigned int T0Count;
	TL0 = 0x18;		// 重装初值（方式1 要手动重装）
	TH0 = 0xFC;
	T0Count++;		// 每 1ms 进来一次
	// ... 用 T0Count 分频做具体事
}
```

- `interrupt 1`：中断号，声明这是"定时器 0 的中断服务函数"。
- **中断函数不能有参数、不能有返回值**（`void ... interrupt n`），由硬件自动调用，不能手动调用。
- **16 位模式（方式1）要手动重装初值**：因为方式1 溢出后计数器归 0，不复位到初值，所以每次进中断都要重新 `TL0=0x18; TH0=0xFC;`。

> [!note] 为什么用 static
> 普通局部变量每次进函数都会重新初始化，累加结果会丢失。`static` 让变量"记住"上次的值（只初始化一次），这样 `T0Count++` 才能持续累加实现分频。

## 6 完整初始化与中断函数

### 6.1 Timer0Init（官方源码）

```c
#include <REGX52.H>

void Timer0Init(void)
{
	TMOD &= 0xF0;		//设置定时器模式（清 T0）
	TMOD |= 0x01;		//设置定时器模式（方式1，16位）
	TL0 = 0x18;		//设置定时初值（低8位）
	TH0 = 0xFC;		//设置定时初值（高8位）
	TF0 = 0;		//清除TF0标志
	TR0 = 1;		//定时器0开始计时
	ET0=1;			//允许定时器0中断
	EA=1;			//允许总中断
	PT0=0;			//定时器0优先级（默认低）
}
```

### 6.2 中断函数模板（官方给的注释模板）

```c
void Timer0_Routine() interrupt 1
{
	static unsigned int T0Count;
	TL0 = 0x18;		//设置定时初值
	TH0 = 0xFC;		//设置定时初值
	T0Count++;
	if(T0Count>=1000)   // 1s（1000 次 1ms）
	{
		T0Count=0;
		// 你的代码（每 1 秒执行一次）
	}
}
```

> [!tip] 配置顺序总结（背这个 5 步）
> 1. `TMOD` 选方式（`&=0xF0; |=0x01`）
> 2. `TL0/TH0` 装初值
> 3. `TF0=0; TR0=1` 清标志、启动
> 4. `ET0=1; EA=1` 开中断
> 5. 写 `void xxx() interrupt 1` 中断函数

## 7 易错点

- [ ] 忘了 `EA=1` → 中断进不来（总闸没开）。
- [ ] 忘了重装 TL0/TH0 → 第一次中断后定时就不准（方式1 不自动重装）。
- [ ] 分频变量没加 static → 累加无效，任务永不触发。
- [ ] 初值 0xFC18 记反（TH0=0x18/TL0=0xFC）→ 定时错乱。
- [ ] 中断号写错 → T0 是 interrupt 1，T1 是 interrupt 3。
- [ ] 直接用 `TMOD=0x01` 而不是 `&=0xF0;|=0x01` → 覆盖了 T1 配置。
- [ ] 中断函数里写了 return 或参数 → 中断函数不允许，编译报错。

## 8 自测

1. 定时器比软件延时好在哪里？
2. 为什么 12MHz 下 1ms 定时初值是 0xFC18？
3. `EA` 和 `ET0` 分别是什么？为什么都要开？
4. TMOD 的低 4 位和高 4 位分别控制什么？`M1M0` 有哪些工作方式？
5. 方式 1（16 位）为什么要在中断里重装初值？
6. 定时器 0 的中断号是多少？中断函数有什么书写限制？

> [!success]- 参考答案
> 1. 定时器后台独立计数，不占用 CPU（软件延时占满 CPU）；精度更高，还能配合中断实现"边计时边干别的"。
> 2. 机器周期=12/12MHz=1μs，1ms 要数 1000 次，初值=65536-1000=64536=0xFC18，高 8 位 0xFC、低 8 位 0x18。
> 3. EA 是总中断开关（总闸），ET0 是定时器 0 中断使能（分闸）。两个都要开，中断才能生效。
> 4. 低 4 位管 T0、高 4 位管 T1。M1M0 有 4 种方式：00=方式0（13位）、01=方式1（16位）、10=方式2（8位自动重装）、11=方式3（拆分）。
> 5. 方式 1 溢出后计数器归 0，不会自动恢复到初值，所以每次进中断都要手动重装 TL0/TH0，否则定时就不准。
> 6. 中断号是 1（interrupt 1）。中断函数不能有参数、不能有返回值（`void xxx() interrupt n`），由硬件自动调用。
