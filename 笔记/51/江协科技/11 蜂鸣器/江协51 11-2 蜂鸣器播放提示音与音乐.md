# 11-2 蜂鸣器播放提示音 & 音乐

> [!abstract] 这一集只解决一个问题
> **怎么让蜂鸣器播放一整段音乐？**
>
> 答：用**频率表 + 乐谱**。频率表把每个音符映射成定时器初值（决定音调），乐谱用"音符索引 + 时值"描述旋律。定时器中断按乐谱逐个改变频率，就播出了音乐。
>
> 上一集 [[江协51 11-1 蜂鸣器]] ｜ 章索引 [[江协51 11 蜂鸣器（章索引）]]

## 1 音乐的两个要素

一段音乐 = **音调**（每个音多高）+ **时值**（每个音多久）：

- **音调** → 频率 → 定时器重装值（频率高 = 翻转快）。
- **时值** → 播放时长 → 用"四分音符的时长"为单位。

```c
#define SPEED 500   // 四分音符的时长(ms)
```

## 2 音符与频率表

把音符（低音/中音/高音）编成索引，对应一个频率表：

```c
// 索引与频率对照表（定时器重装值，12MHz）
unsigned int FreqTable[]={
	0,
	63628,63731,63835,63928,64021,64103,64185,64260,64331,64400,64463,64528,  // 低音 1~7
	64580,64633,64684,64732,64777,64820,64860,64898,64934,64968,65000,65030,  // 中音 1~7
	65058,65085,65110,65134,65157,65178,65198,65217,65235,65252,65268,65283,  // 高音 1~7
};
```

- 每个值是一个"定时器初值"（重装到 TL0/TH0），频率越高初值越大（计数越少、翻转越快）。
- 音符索引：`P`(休止)=0，`L1`~`L7`(低音)、`M1`~`M7`(中音)、`H1`~`H7`(高音)，带 `_` 是升半音。

## 3 乐谱

乐谱用"音符, 时值"成对存放：

```c
unsigned char code Music[]={
	P,	4,    // 休止，4 拍
	P,	4,
	M6,	2,    // 中音 6，2 拍
	M7,	2,
	H1,	4+2,  // 高音 1，4+2 拍
	// ...
};
```

- 偶数位（0,2,4…）是音符索引，奇数位（1,3,5…）是时值（拍数）。
- 播放时成对读取：取音符 → 取时值 → 设频率 → 延时对应拍数。

## 4 定时器中断播放

用 Timer0 1ms 中断，配合频率表改变重装值来产生不同频率：

```c

{
	// 根据当前音符，从 FreqTable 取初值重装 TL0/TH0
	// 每半周期翻转一次 Buzzer，产生对应频率的方波
}
```

> [!note] 播放音乐靠"定时器 + 频率表"
> 核心思想：定时器中断里按当前音符查 `FreqTable` 得到重装值，控制翻转频率；主循环按乐谱推进音符、控制每个音的时长。这样就能用一颗蜂鸣器播出旋律。

## 6 易错点

- [ ] 频率表初值算错 → 音调不准（按 12MHz 算）。
- [ ] 乐谱"音符/时值"错位 → 要两个一组读（i+=2）。
- [ ] 休止符没处理 → P=0 时要静音（不翻转）。
- [ ] 定时初值没重装 → 一个音之后频率就乱了。

## 7 自测

1. 音乐的两个要素是什么？分别由什么决定？
2. FreqTable 里存的是什么？为什么音越高值越大？
3. 乐谱数组为什么两个一组？

> [!success]- 参考答案
> 1. 音调（由频率/定时初值决定）和时值（由播放时长决定）。
> 2. 存的是定时器重装值。音越高频率越高，计数越少、初值越大（重装值越接近 65536）。
> 3. 因为一个音符需要两个信息：音符索引 + 时值，所以成对存放（i+=2）。
