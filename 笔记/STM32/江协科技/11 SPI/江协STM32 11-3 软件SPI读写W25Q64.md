# 11-3 软件 SPI 读写 W25Q64

> [!abstract] 这一集只解决一个问题
> **协议讲完了，怎么用 4 个普通 GPIO 把 SPI 时序一位一位翻出来，让 W25Q64 真的能读能写？**
>
> 答：把代码分成两层——**引脚配置层**（`MySPI_W_SS / W_SCK / W_MOSI / R_MISO`）只负责把某根线拉高拉低或读电平，**协议层**（`MySPI_Start / Stop / SwapByte`）只负责按模式 0 的时序调用它们。上层的 `W25Q64.c` 完全不关心底下是 GPIO 还是 SPI 外设，它只会调 `MySPI_SwapByte()`。
>
> 上一集 [[江协STM32 11-2 W25Q64简介]] ｜ 下一集 [[江协STM32 11-4 SPI通信外设]] ｜ 章索引 [[江协STM32 11 SPI（章索引）]]

## 1 这一集要做的三件事

| 顺序 | 做什么 | 依据 |
| --- | --- | --- |
| ① | 写 `MySPI.c`：用 GPIO 手动翻出模式 0 的 SPI 时序 | 官方 `11-1 软件SPI读写W25Q64\Hardware\MySPI.c` |
| ② | 写 `W25Q64.c`：在 `MySPI_*` 之上拼出 W25Q64 的指令时序 | 官方 `11-1 软件SPI读写W25Q64\Hardware\W25Q64.c` |
| ③ | 写 `main.c`：读 ID → 擦除 → 写 → 读回 → OLED 显示 | 官方 `11-1 软件SPI读写W25Q64\User\main.c` |

> [!note] 官方工程目录号与视频集号差 2
> 视频 **11-3** 对应的官方工程目录是 **`11-1 软件SPI读写W25Q64`**，视频 **11-5** 对应 **`11-2 硬件SPI读写W25Q64`**。`README.md` 的对照表已注明「工程目录与视频集号不是一一对应」，第 11 章同样如此。**视频 11-1（SPI 通信协议）、11-2（W25Q64 简介）、11-4（SPI 通信外设）都是理论集，官方没有独立工程目录。**

## 2 分层：谁调谁

```text
User\main.c
   └── W25Q64_Init / ReadID / SectorErase / PageProgram / ReadData   ← W25Q64 指令层
          └── MySPI_Start / Stop / SwapByte                          ← SPI 协议层（模式 0）
                 └── MySPI_W_SS / W_SCK / W_MOSI / R_MISO            ← 引脚配置层（翻 GPIO）
```

官方 `MySPI.c` 里就直接用两行注释把这条分界线画出来了：第 3 行 `/*引脚配置层*/`、第 77 行 `/*协议层*/`。

**分层的意义**：下一集（11-4）讲完 SPI 外设后，11-5 只把 `MySPI.c` 换掉，`W25Q64.c` 一个字都不用改。这一点有官方源码的硬证据——见 11-5 的实测对比。

## 3 引脚与接线

四个信号全部落在 **PA4~PA7**。依据是官方源码 `11-1 软件SPI读写W25Q64\Hardware\MySPI.c`（第 13、24、35、46 行）与引脚定义表第 16~19 行：

| SPI 信号 | STM32 引脚 | 官方源码 | 引脚定义表里的默认复用功能 |
| --- | --- | --- | --- |
| **SS**（片选） | **PA4** | `GPIO_Pin_4` | `SPI1_NSS`（第 14 脚） |
| **SCK**（时钟） | **PA5** | `GPIO_Pin_5` | `SPI1_SCK`（第 15 脚） |
| **MISO**（主机输入） | **PA6** | `GPIO_Pin_6` | `SPI1_MISO`（第 16 脚） |
| **MOSI**（主机输出） | **PA7** | `GPIO_Pin_7` | `SPI1_MOSI`（第 17 脚） |

W25Q64 模块一侧的丝印与 STM32 一侧的对照（模块引脚名出自课件 Slide 158，模块实际接线见 11-2）：

| 模块丝印 | 功能 | 接到 |
| --- | --- | --- |
| `CS` | 片选 | PA4 |
| `CLK` | 时钟 | PA5 |
| `DO` | 从机输出 → 主机输入 | PA6 |
| `DI` | 主机输出 → 从机输入 | PA7 |
| `VCC` | 电源 | 3.3 V |
| `GND` | 地 | GND |

> [!note] 11-3 与 11-5 用的是同一张接线图，这是正常的
> `ground-truth\接线图\11-1 软件SPI读写W25Q64.png` 与 `11-2 硬件SPI读写W25Q64.png` **是同一张图**（同为 552009 字节，SHA-256 均为 `752058c2…a796`）。
>
> 原因很直接：**软件 SPI 与硬件 SPI 用的是同一组引脚 PA4（SS）/ PA5（SCK）/ PA6（MISO）/ PA7（MOSI）**，接线本来就完全一致，课程作者于是复用了同一张图。官方 `1-1 接线图\` 里这种「接线相同就复用」的重复图共有 9 组，例如 `7-2 AD多通道` 与 `8-2 DMA+AD多通道`、`6-6 输入捕获模式测频率` 与 `6-7 PWMI模式测频率占空比`、`14-1 独立看门狗` 与 `14-2 窗口看门狗`。
>
> **两版唯一的差别在 GPIO 模式，不在接线**：软件版 PA4/PA5/PA7 是 `GPIO_Mode_Out_PP`、PA6 是 `GPIO_Mode_IPU`；硬件版把 PA5/PA7 换成 `GPIO_Mode_AF_PP`，**PA4 仍然是 `GPIO_Mode_Out_PP`**（片选继续靠软件翻 GPIO），PA6 仍是上拉输入。详见 11-5 的逐函数对照表。

## 4 MySPI.c 引脚配置层

### 4.1 参数表：初始化时每一脚配成什么

| 引脚 | 主机侧方向 | `GPIO_Mode` | 官方源码行 | 为什么 |
| --- | --- | --- | --- | --- |
| PA4（SS） | 输出 | `GPIO_Mode_Out_PP` | 第 62 行 | 片选由主机发，是输出信号 |
| PA5（SCK） | 输出 | `GPIO_Mode_Out_PP` | 第 63 行 | 时钟由主机发，是输出信号 |
| PA7（MOSI） | 输出 | `GPIO_Mode_Out_PP` | 第 63 行 | 数据由主机发，是输出信号 |
| PA6（MISO） | **输入** | `GPIO_Mode_IPU`（上拉输入） | 第 67 行 | 数据由从机发，主机只能读 |

三个输出脚用同一句 `GPIO_Init()` 配置（`GPIO_Pin_4 \| GPIO_Pin_5 \| GPIO_Pin_7`），输入脚单独配一次。四脚速度都写 `GPIO_Speed_50MHz`。

这与课件 Slide 147 的要求一致：「**输出引脚配置为推挽输出，输入引脚配置为浮空或上拉输入**」——本课输入脚取的是「上拉输入」这一档。

初始化最后还设了两个默认电平：`MySPI_W_SS(1)`（片选默认高 = 不选中）和 `MySPI_W_SCK(0)`（**SCK 默认低电平**）。后者正是模式 0 的标志：课件 Slide 150「模式 0，CPOL=0：空闲状态时 SCK 为低电平」。

### 4.2 官方原文

```c
#include "stm32f10x.h"                  // Device header

/*引脚配置层*/

/**
  * 函    数：SPI写SS引脚电平
  * 参    数：BitValue 协议层传入的当前需要写入SS的电平，范围0~1
  * 返 回 值：无
  * 注意事项：此函数需要用户实现内容，当BitValue为0时，需要置SS为低电平，当BitValue为1时，需要置SS为高电平
  */
void MySPI_W_SS(uint8_t BitValue)
{
	GPIO_WriteBit(GPIOA, GPIO_Pin_4, (BitAction)BitValue);		//根据BitValue，设置SS引脚的电平
}

/**
  * 函    数：SPI写SCK引脚电平
  * 参    数：BitValue 协议层传入的当前需要写入SCK的电平，范围0~1
  * 返 回 值：无
  * 注意事项：此函数需要用户实现内容，当BitValue为0时，需要置SCK为低电平，当BitValue为1时，需要置SCK为高电平
  */
void MySPI_W_SCK(uint8_t BitValue)
{
	GPIO_WriteBit(GPIOA, GPIO_Pin_5, (BitAction)BitValue);		//根据BitValue，设置SCK引脚的电平
}

/**
  * 函    数：SPI写MOSI引脚电平
  * 参    数：BitValue 协议层传入的当前需要写入MOSI的电平，范围0~1
  * 返 回 值：无
  * 注意事项：此函数需要用户实现内容，当BitValue为0时，需要置MOSI为低电平，当BitValue为1时，需要置MOSI为高电平
  */
void MySPI_W_MOSI(uint8_t BitValue)
{
	GPIO_WriteBit(GPIOA, GPIO_Pin_7, (BitAction)BitValue);		//根据BitValue，设置MOSI引脚的电平，BitValue要实现非0即1的特性
}

/**
  * 函    数：SPI读MISO引脚电平
  * 参    数：无
  * 返 回 值：协议层需要得到的当前MISO的电平，范围0~1
  * 注意事项：此函数需要用户实现内容，当前MISO为低电平时，返回0，当前MISO为高电平时，返回1
  */
uint8_t MySPI_R_MISO(void)
{
	return GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_6);			//读取MISO电平并返回
}

/**
  * 函    数：SPI初始化
  * 参    数：无
  * 返 回 值：无
  * 注意事项：此函数需要用户实现内容，实现SS、SCK、MOSI和MISO引脚的初始化
  */
void MySPI_Init(void)
{
	/*开启时钟*/
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);	//开启GPIOA的时钟
	
	/*GPIO初始化*/
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_4 | GPIO_Pin_5 | GPIO_Pin_7;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);					//将PA4、PA5和PA7引脚初始化为推挽输出
	
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_6;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);					//将PA6引脚初始化为上拉输入
	
	/*设置默认电平*/
	MySPI_W_SS(1);											//SS默认高电平
	MySPI_W_SCK(0);											//SCK默认低电平
}
```

## 5 MySPI.c 协议层

```c
/*协议层*/

/**
  * 函    数：SPI起始
  * 参    数：无
  * 返 回 值：无
  */
void MySPI_Start(void)
{
	MySPI_W_SS(0);				//拉低SS，开始时序
}

/**
  * 函    数：SPI终止
  * 参    数：无
  * 返 回 值：无
  */
void MySPI_Stop(void)
{
	MySPI_W_SS(1);				//拉高SS，终止时序
}

/**
  * 函    数：SPI交换传输一个字节，使用SPI模式0
  * 参    数：ByteSend 要发送的一个字节
  * 返 回 值：接收的一个字节
  */
uint8_t MySPI_SwapByte(uint8_t ByteSend)
{
	uint8_t i, ByteReceive = 0x00;					//定义接收的数据，并赋初值0x00，此处必须赋初值0x00，后面会用到
	
	for (i = 0; i < 8; i ++)						//循环8次，依次交换每一位数据
	{
		/*两个!可以对数据进行两次逻辑取反，作用是把非0值统一转换为1，即：!!(0) = 0，!!(非0) = 1*/
		MySPI_W_MOSI(!!(ByteSend & (0x80 >> i)));	//使用掩码的方式取出ByteSend的指定一位数据并写入到MOSI线
		MySPI_W_SCK(1);								//拉高SCK，上升沿移出数据
		if (MySPI_R_MISO()){ByteReceive |= (0x80 >> i);}	//读取MISO数据，并存储到Byte变量
															//当MISO为1时，置变量指定位为1，当MISO为0时，不做处理，指定位为默认的初值0
		MySPI_W_SCK(0);								//拉低SCK，下降沿移入数据
	}
	
	return ByteReceive;								//返回接收到的一个字节数据
}
```

### 5.1 `MySPI_SwapByte` 每一次循环到底做了什么

| 步 | 代码 | 动作 | 对应课件 |
| --- | --- | --- | --- |
| ① | `MySPI_W_MOSI(!!(ByteSend & (0x80 >> i)))` | 取出第 `i` 位（`0x80 >> i` 依次是 `0x80`…`0x01`），**在 SCK 还是低电平的时候**就摆到 MOSI 上 | Slide 150「数据要在第一个边沿前摆好」（见 11-1 第 4 节） |
| ② | `MySPI_W_SCK(1)` | 把 SCK 从低拉到高，产生**第一个（上升）边沿** | Slide 150 |
| ③ | `if (MySPI_R_MISO()) {…}` | 就在这个上升沿之后**读 MISO**，写进 `ByteReceive` 的同一位 | Slide 150 |
| ④ | `MySPI_W_SCK(0)` | 把 SCK 拉回低，产生第二个（下降）边沿 | Slide 150 |

**所以：采样（读 MISO）发生在上升沿，也就是模式 0 的第一个边沿；8 位走完 = 8 个 SCK 脉冲。** 这与函数头注释「使用SPI模式0」一致，也与 11-1 第 4.1 节列出的三条依据一致。

数据位是 **`0x80 >> i`**，即从 `B7` 到 `B0` ——**高位先行**。硬件版对应 `SPI_FirstBit_MSB`（见 11-4 / 11-5）。

### 5.2 两个容易忽略的细节

- **`ByteReceive` 必须初值 `0x00`**：循环里只做「置 1」（`|=`），从不做「清 0」。若初值是别的数，那些该是 0 的位就永远错。官方注释专门写了「此处必须赋初值0x00，后面会用到」。
- **`!!` 是必需的**：`MySPI_W_MOSI` 的注释要求「BitValue 要实现非 0 即 1 的特性」，因为函数里要把它强转成 `(BitAction)`，而 `BitAction` 只有 `Bit_RESET = 0` 和 `Bit_SET = 1` 两个合法值。`ByteSend & (0x80 >> i)` 的结果可能是 `0x80`、`0x40` 这种「非 0 非 1」的值，两次逻辑取反 `!!` 把它归一成 0 或 1，正好满足要求。

> [!warning] 官方注释里「移出 / 移入」的措辞与课件定义正好相反
> `MySPI_SwapByte` 里写的是「拉高 SCK，**上升沿移出数据**」「拉低 SCK，**下降沿移入数据**」。
> 而课件 Slide 150 对模式 0 的定义是「CPHA=0：SCK **第一个边沿移入数据，第二个边沿移出数据**」——两处说法互换。
> **本页保留官方注释原文，不下结论**（11-1 第 4 节已把这条冲突记入「待核对」）。要判断时序，只看代码实际行为：**MOSI 在 SCK 低电平期间就已摆好，主机在上升沿读 MISO**，这就是模式 0（`SPI_CPOL_Low` + `SPI_CPHA_1Edge`，见 `11-2 硬件SPI读写W25Q64\Hardware\MySPI.c` 第 49~50 行）。

## 6 W25Q64.c：在协议层之上拼指令

### 6.1 指令表：每条指令后面跟什么（逐个对着源码数）

| 函数 | 指令 | 值 | 指令后跟的字节 | 源码行 |
| --- | --- | --- | --- | --- |
| `W25Q64_ReadID` | `W25Q64_JEDEC_ID` | `0x9F` | 连发 **3 个 dummy**，收 MID + DID 高 8 位 + DID 低 8 位 | 23~29 |
| `W25Q64_WriteEnable` | `W25Q64_WRITE_ENABLE` | `0x06` | **0 个**，发完直接 `Stop` | 39~41 |
| `W25Q64_WaitBusy` | `W25Q64_READ_STATUS_REGISTER_1` | `0x05` | 反复发 dummy 读状态，判 **bit0** | 52~64 |
| `W25Q64_PageProgram` | `W25Q64_PAGE_PROGRAM` | `0x02` | **3 个地址字节**（A23~16 / A15~8 / A7~0）+ `Count` 个数据字节 | 81~90 |
| `W25Q64_SectorErase` | `W25Q64_SECTOR_ERASE_4KB` | `0x20` | **3 个地址字节** | 104~109 |
| `W25Q64_ReadData` | `W25Q64_READ_DATA` | `0x03` | **3 个地址字节** + 反复发 dummy 收数据 | 124~133 |

指令宏全部来自官方 `Hardware\W25Q64_Ins.h`（该文件共定义 26 条指令宏 + 1 条 `W25Q64_DUMMY_BYTE`，完整清单见 11-2 第 4.4 节）。

> [!tip] 三个地址字节为什么这样写
> `MySPI_SwapByte` 的形参是 `uint8_t`，传进去的 `uint32_t` 会被**隐式截断成低 8 位**。所以
> `Address >> 16` 取出 A23~A16、`Address >> 8` 取出 A15~A8、`Address` 取出 A7~A0。
> 这也是「地址是 24 位」在代码里的落地方式：**一次发一个字节，发三次**。

### 6.2 官方原文

```c
#include "stm32f10x.h"                  // Device header
#include "MySPI.h"
#include "W25Q64_Ins.h"

/**
  * 函    数：W25Q64初始化
  * 参    数：无
  * 返 回 值：无
  */
void W25Q64_Init(void)
{
	MySPI_Init();					//先初始化底层的SPI
}

/**
  * 函    数：W25Q64读取ID号
  * 参    数：MID 工厂ID，使用输出参数的形式返回
  * 参    数：DID 设备ID，使用输出参数的形式返回
  * 返 回 值：无
  */
void W25Q64_ReadID(uint8_t *MID, uint16_t *DID)
{
	MySPI_Start();								//SPI起始
	MySPI_SwapByte(W25Q64_JEDEC_ID);			//交换发送读取ID的指令
	*MID = MySPI_SwapByte(W25Q64_DUMMY_BYTE);	//交换接收MID，通过输出参数返回
	*DID = MySPI_SwapByte(W25Q64_DUMMY_BYTE);	//交换接收DID高8位
	*DID <<= 8;									//高8位移到高位
	*DID |= MySPI_SwapByte(W25Q64_DUMMY_BYTE);	//或上交换接收DID的低8位，通过输出参数返回
	MySPI_Stop();								//SPI终止
}

/**
  * 函    数：W25Q64写使能
  * 参    数：无
  * 返 回 值：无
  */
void W25Q64_WriteEnable(void)
{
	MySPI_Start();								//SPI起始
	MySPI_SwapByte(W25Q64_WRITE_ENABLE);		//交换发送写使能的指令
	MySPI_Stop();								//SPI终止
}

/**
  * 函    数：W25Q64等待忙
  * 参    数：无
  * 返 回 值：无
  */
void W25Q64_WaitBusy(void)
{
	uint32_t Timeout;
	MySPI_Start();								//SPI起始
	MySPI_SwapByte(W25Q64_READ_STATUS_REGISTER_1);				//交换发送读状态寄存器1的指令
	Timeout = 100000;							//给定超时计数时间
	while ((MySPI_SwapByte(W25Q64_DUMMY_BYTE) & 0x01) == 0x01)	//循环等待忙标志位
	{
		Timeout --;								//等待时，计数值自减
		if (Timeout == 0)						//自减到0后，等待超时
		{
			/*超时的错误处理代码，可以添加到此处*/
			break;								//跳出等待，不等了
		}
	}
	MySPI_Stop();								//SPI终止
}

/**
  * 函    数：W25Q64页编程
  * 参    数：Address 页编程的起始地址，范围：0x000000~0x7FFFFF
  * 参    数：DataArray	用于写入数据的数组
  * 参    数：Count 要写入数据的数量，范围：0~256
  * 返 回 值：无
  * 注意事项：写入的地址范围不能跨页
  */
void W25Q64_PageProgram(uint32_t Address, uint8_t *DataArray, uint16_t Count)
{
	uint16_t i;
	
	W25Q64_WriteEnable();						//写使能
	
	MySPI_Start();								//SPI起始
	MySPI_SwapByte(W25Q64_PAGE_PROGRAM);		//交换发送页编程的指令
	MySPI_SwapByte(Address >> 16);				//交换发送地址23~16位
	MySPI_SwapByte(Address >> 8);				//交换发送地址15~8位
	MySPI_SwapByte(Address);					//交换发送地址7~0位
	for (i = 0; i < Count; i ++)				//循环Count次
	{
		MySPI_SwapByte(DataArray[i]);			//依次在起始地址后写入数据
	}
	MySPI_Stop();								//SPI终止
	
	W25Q64_WaitBusy();							//等待忙
}

/**
  * 函    数：W25Q64扇区擦除（4KB）
  * 参    数：Address 指定扇区的地址，范围：0x000000~0x7FFFFF
  * 返 回 值：无
  */
void W25Q64_SectorErase(uint32_t Address)
{
	W25Q64_WriteEnable();						//写使能
	
	MySPI_Start();								//SPI起始
	MySPI_SwapByte(W25Q64_SECTOR_ERASE_4KB);	//交换发送扇区擦除的指令
	MySPI_SwapByte(Address >> 16);				//交换发送地址23~16位
	MySPI_SwapByte(Address >> 8);				//交换发送地址15~8位
	MySPI_SwapByte(Address);					//交换发送地址7~0位
	MySPI_Stop();								//SPI终止
	
	W25Q64_WaitBusy();							//等待忙
}

/**
  * 函    数：W25Q64读取数据
  * 参    数：Address 读取数据的起始地址，范围：0x000000~0x7FFFFF
  * 参    数：DataArray 用于接收读取数据的数组，通过输出参数返回
  * 参    数：Count 要读取数据的数量，范围：0~0x800000
  * 返 回 值：无
  */
void W25Q64_ReadData(uint32_t Address, uint8_t *DataArray, uint32_t Count)
{
	uint32_t i;
	MySPI_Start();								//SPI起始
	MySPI_SwapByte(W25Q64_READ_DATA);			//交换发送读取数据的指令
	MySPI_SwapByte(Address >> 16);				//交换发送地址23~16位
	MySPI_SwapByte(Address >> 8);				//交换发送地址15~8位
	MySPI_SwapByte(Address);					//交换发送地址7~0位
	for (i = 0; i < Count; i ++)				//循环Count次
	{
		DataArray[i] = MySPI_SwapByte(W25Q64_DUMMY_BYTE);	//依次在起始地址后读取数据
	}
	MySPI_Stop();								//SPI终止
}
```

### 6.3 几个必须留意的点

| 观察 | 说明 |
| --- | --- |
| `W25Q64_WriteEnable()` 是**独立的一次通信** | 它内部自己 `Start` / `Stop`，不能被并进 `PageProgram` 的同一次 SS 里（见下面的原文） |
| `WaitBusy` 在 `while` 条件里 **每轮重新发一次 dummy** | 不是只读一次状态，而是「发一个 dummy、收回一个状态字节、判 bit0、再发下一个」 |
| `PageProgram` / `SectorErase` 末尾**都**调 `W25Q64_WaitBusy()` | 写完、擦完芯片会进入忙状态 |
| `ReadData` 末尾**没有**调 `WaitBusy()` | 课件 Slide 160：读取操作「结束后不会进入忙状态」 |
| `PageProgram` 先 `WriteEnable`、`SectorErase` 先 `WriteEnable` | 课件 Slide 160 第 1 条：写入操作前必须先写使能 |
| `ReadData` 与 `ReadID` 里**没有** `WriteEnable` | 读操作「无需使能，无需额外操作」 |

### 7.2 执行顺序与现象

```text
W25Q64_ReadID(0x9F)                          读操作：不需要写使能、不需要擦除
W25Q64_SectorErase(0x000000)                 擦除：内部先 0x06 写使能 → 0x20 + 3 字节地址 → 等忙
W25Q64_PageProgram(0x000000, ArrayWrite, 4)  写入：内部先 0x06 → 0x02 + 3 字节地址 + 4 个数据 → 等忙
W25Q64_ReadData(0x000000, ArrayRead, 4)      读回：0x03 + 3 字节地址 + 4 个 dummy
```

现象：OLED 第 1 行显示 `MID:   DID:` 与两个 ID，第 2 行 `W:` 显示 `01 02 03 04`，第 3 行 `R:` 显示 `01 02 03 04`——**两行一样就说明读写成功**。

> 课件与源码都没有给出 W25Q64 的 MID / DID 具体值，本机资料包里也**没有 W25Q64 数据手册**（`参考文档\` 只有 STM32F103 的手册）。本页因此**不写**「MID 应为 `0xEF`」这类数值，视频里 OLED 上显示的具体数字需要看视频或实机确认（11-2 已记入「待核对」）。

## 8 写入规则：为什么必须先擦除、跨页又会怎样

这两条都是课件 Slide 160 的原文，直接决定了 `main.c` 为什么按这个顺序写。

### 8.1 为什么写之前必须先擦除

| 步骤 | 规则 | 出处 |
| --- | --- | --- |
| ① | 每个数据位**只能由 1 改写为 0**，不能由 0 改写为 1 | Slide 160 第 2 条 |
| ② | 所以要写入「1」，只能先把那一片**擦成全 1** | Slide 160 第 3 条 |
| ③ | 擦除的最小单元是**扇区（4 KB）**，不能只擦一个字节 | Slide 160 第 4 条 |

合起来就是：**`PageProgram` 之前必须先 `SectorErase`**，`main.c` 里第 29 行擦除、第 30 行才写入，顺序不能颠倒。代价也很直白——只写 4 个字节，却要擦掉整个 4 KB 扇区。

### 8.2 跨页写会怎样

课件 Slide 160 第 5 条原文：**连续写入多字节时，最多写入一页的数据，超过页尾位置的数据，会回到页首覆盖写入。**

```text
假设从 0x0000F0 开始连写 32 字节（页边界在 0x0000FF）：

  0x0000F0 ~ 0x0000FF  16 字节  → 正常落在本页
  接下来 16 字节               → 不会进下一页 0x000100
                                 而是绕回本页页首 0x0000F0 覆盖写入！
```

**它不会报错**，只是悄悄把刚写进去的数据盖掉——这类错误极难查。官方源码因此在 `W25Q64_PageProgram` 的函数头注释里专门写了一行「**注意事项：写入的地址范围不能跨页**」（第 73 行），`Count` 的范围也标注为 `0~256`（第 71 行）。

> [!danger] 本课例程正好是安全的
> `W25Q64_PageProgram(0x000000, ArrayWrite, 4)`：起始地址 `0x000000` 是页边界，`Count = 4` 远小于 256，不会跨页。**但这是「刚好安全」，不是「这样写就永远安全」**——要写超过一页的数据，必须自己按 256 字节切分、分段调用。

## 9 易错点

- [ ] `ByteReceive` 忘了赋初值 `0x00` → 该是 0 的位全错（官方注释专门强调过）。
- [ ] `MySPI_W_MOSI` 的参数没做 `!!` 归一 → 传进 `0x80` 这种值再强转 `(BitAction)` 就不是合法枚举值了。
- [ ] `MySPI_Init()` 末尾忘了 `MySPI_W_SS(1)` / `MySPI_W_SCK(0)` → 上电就踩着片选、或 SCK 停在非模式 0 的电平上。
- [ ] 把 MISO（PA6）也配成输出 → 主机和从机同时驱动同一根线；本课 PA6 是 `GPIO_Mode_IPU` 上拉**输入**。
- [ ] 写之前忘了擦除 → 想写 1 的地方写不进去，读回来一看是旧数据。
- [ ] 以为擦除可以按字节 → 最小擦除单元是 **4 KB 扇区**。
- [ ] 跨页写 → 数据绕回页首覆盖，**不报错**。
- [ ] 忘了 `W25Q64_WriteEnable()`，或把它并进 `PageProgram` 的同一次 SS 里 → 芯片静默忽略本次写入（它是独立的一次 Start/Stop）。
- [ ] 写完/擦完不等 `W25Q64_WaitBusy()` 就去读 → 读到旧数据（`main.c` 里靠函数内部自动等待，手写时序时容易漏）。
- [ ] 地址当成 16 位只发两个字节 → 地址是 **24 位**，必须发 3 个字节。
- [ ] 读数据时发 `0x00` 而不是 dummy → 虽然理论上发什么都行，但源码统一用 `W25Q64_DUMMY_BYTE`（`0xFF`），照官方写就对了。
- [ ] 把 `CS` / `CLK` / `DI` / `DO` 和 `SS` / `SCK` / `MOSI` / `MISO` 配错 → 名字不同、功能一一对应，配错一根就完全没反应。

## 10 自测

1. `MySPI_SwapByte()` 里，主机是在 SCK 的哪个边沿读 MISO？这对应 SPI 的哪一种模式？
2. 为什么 `MySPI_W_MOSI()` 的实参要写成 `!!(ByteSend & (0x80 >> i))`，直接传 `ByteSend & (0x80 >> i)` 行不行？
3. `MySPI_Init()` 里 PA4、PA5、PA6、PA7 各自配成了什么模式？为什么 PA6 不一样？
4. `W25Q64_PageProgram()` 内部一共发了哪些字节？其中哪一步是「另外一次独立的通信」？
5. `W25Q64_ReadData()` 末尾为什么不需要 `W25Q64_WaitBusy()`，而 `PageProgram()` 末尾需要？

> [!success]- 参考答案
> 1. 在**上升沿**（`MySPI_W_SCK(1)` 之后立刻 `MySPI_R_MISO()`）读 MISO；上升沿是模式 0 的**第一个边沿**，所以对应**模式 0**（`SPI_CPOL_Low` + `SPI_CPHA_1Edge`，SCK 空闲为低）。
> 2. 不行。`MySPI_W_MOSI` 里要把参数强转成 `BitAction`，而它只有 0 和 1 两个合法值；`ByteSend & (0x80 >> i)` 可能是 `0x80` 这类非 0 非 1 的值。`!!` 把非 0 统一变成 1，正好满足「BitValue 要实现非 0 即 1 的特性」。
> 3. PA4、PA5、PA7 是 `GPIO_Mode_Out_PP`（推挽输出），PA6 是 `GPIO_Mode_IPU`（上拉输入）。因为 SS / SCK / MOSI 都是主机发出的信号，而 MISO 是从机发出的、主机只能读——课件 Slide 147：「输出引脚配置为推挽输出，输入引脚配置为浮空或上拉输入」。
> 4. 先由 `W25Q64_WriteEnable()` 发出 `0x06`，这是**独立的一次通信**（它自己 Start/Stop）；然后在同一次 SS 内发 `0x02` + 3 个地址字节 + `Count` 个数据字节，最后 Stop 并等忙。
> 5. 课件 Slide 160：**读操作「不会进入忙状态」**，所以读完整片都不需要等；而写和擦会让芯片进入忙状态，`PageProgram` / `SectorErase` 必须等 `W25Q64_WaitBusy()` 才能进行下一步。
