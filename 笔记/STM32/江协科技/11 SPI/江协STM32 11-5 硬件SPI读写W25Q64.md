# 11-5 硬件 SPI 读写 W25Q64

> [!abstract] 这一集只解决一个问题
> **11-4 讲的那套 SPI 外设，怎么接到 11-3 的 W25Q64 代码上？**
>
> 答：**只换 `MySPI.c` 一个文件**。`W25Q64.c`、`W25Q64.h`、`W25Q64_Ins.h`、`MySPI.h`、`main.c` **一个字节都没有改**——这一条有 SHA-256 实证（见第 5 节）。软件版的 8 个函数缩成硬件版的 5 个，`SwapByte` 里那个 8 次循环变成了「等 TXE → 写 → 等 RXNE → 读」。
>
> 上一集 [[江协STM32 11-4 SPI通信外设]] ｜ 下一章 [[江协STM32 12 Unix时间戳与RTC（章索引）]] ｜ 章索引 [[江协STM32 11 SPI（章索引）]]

## 1 这一集要做的只有一件事

| | 11-3 软件 SPI | 11-5 硬件 SPI |
| --- | --- | --- |
| 工程目录 | `11-1 软件SPI读写W25Q64\` | `11-2 硬件SPI读写W25Q64\` |
| 改动范围 | — | **只有 `Hardware\MySPI.c`** |
| `MySPI.c` 行数 | 119 行 | 96 行 |
| `MySPI.c` 里的函数个数 | **8 个** | **5 个** |
| 主程序 / `W25Q64.c` 行为 | — | **完全一样** |

> [!note] 官方工程目录号与视频集号差 2（再提醒一次）
> 视频 **11-5** 对应的官方工程目录是 **`11-2 硬件SPI读写W25Q64`**，视频 11-3 对应 **`11-1 软件SPI读写W25Q64`**。视频 11-1 / 11-2 / 11-4 是理论集，官方没有独立工程目录。

## 2 引脚：还是 PA4~PA7

**接线没有变**，因为硬件 SPI 用的就是 SPI1 的默认引脚组合：

| SPI 信号 | STM32 引脚 | 引脚定义表里的默认复用功能 | 11-5 的 GPIO 模式 |
| --- | --- | --- | --- |
| **SS**（片选） | **PA4** | `SPI1_NSS`（第 14 脚） | `GPIO_Mode_Out_PP`（**普通**推挽，仍由软件翻） |
| **SCK**（时钟） | **PA5** | `SPI1_SCK`（第 15 脚） | `GPIO_Mode_AF_PP`（复用推挽） |
| **MISO**（主机输入） | **PA6** | `SPI1_MISO`（第 16 脚） | `GPIO_Mode_IPU`（上拉输入） |
| **MOSI**（主机输出） | **PA7** | `SPI1_MOSI`（第 17 脚） | `GPIO_Mode_AF_PP`（复用推挽） |

依据：官方 `11-2 硬件SPI读写W25Q64\Hardware\MySPI.c` 第 27~40 行 + `ground-truth\引脚定义_xlsx原文.txt` 第 16~19 行。W25Q64 模块一侧仍然是 `CS / CLK / DO / DI / VCC / GND` 分别接到 PA4 / PA5 / PA6 / PA7 / 3.3 V / GND。

> [!note] 两集共用同一张接线图，这是正常的
> `ground-truth\接线图\11-1 软件SPI读写W25Q64.png` 与 `11-2 硬件SPI读写W25Q64.png` 是**同一张图**（同为 552009 字节，SHA-256 均为 `752058c2…a796`）。因为软件 SPI 与硬件 SPI 用的是同一组引脚，接线本来就完全一致——官方 `1-1 接线图\` 里「接线相同就复用同一张图」的例子共有 9 组（如 `7-2 AD多通道` 与 `8-2 DMA+AD多通道`、`14-1 独立看门狗` 与 `14-2 窗口看门狗`）。
> **两版唯一的差别是 GPIO 模式，不是接线。**

## 3 硬件版 MySPI.c 官方原文

```c
#include "stm32f10x.h"                  // Device header

/**
  * 函    数：SPI写SS引脚电平，SS仍由软件模拟
  * 参    数：BitValue 协议层传入的当前需要写入SS的电平，范围0~1
  * 返 回 值：无
  * 注意事项：此函数需要用户实现内容，当BitValue为0时，需要置SS为低电平，当BitValue为1时，需要置SS为高电平
  */
void MySPI_W_SS(uint8_t BitValue)
{
	GPIO_WriteBit(GPIOA, GPIO_Pin_4, (BitAction)BitValue);		//根据BitValue，设置SS引脚的电平
}

/**
  * 函    数：SPI初始化
  * 参    数：无
  * 返 回 值：无
  */
void MySPI_Init(void)
{
	/*开启时钟*/
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);	//开启GPIOA的时钟
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_SPI1, ENABLE);	//开启SPI1的时钟
	
	/*GPIO初始化*/
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_4;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);					//将PA4引脚初始化为推挽输出
	
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_5 | GPIO_Pin_7;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);					//将PA5和PA7引脚初始化为复用推挽输出
	
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_6;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);					//将PA6引脚初始化为上拉输入
	
	/*SPI初始化*/
	SPI_InitTypeDef SPI_InitStructure;						//定义结构体变量
	SPI_InitStructure.SPI_Mode = SPI_Mode_Master;			//模式，选择为SPI主模式
	SPI_InitStructure.SPI_Direction = SPI_Direction_2Lines_FullDuplex;	//方向，选择2线全双工
	SPI_InitStructure.SPI_DataSize = SPI_DataSize_8b;		//数据宽度，选择为8位
	SPI_InitStructure.SPI_FirstBit = SPI_FirstBit_MSB;		//先行位，选择高位先行
	SPI_InitStructure.SPI_BaudRatePrescaler = SPI_BaudRatePrescaler_128;	//波特率分频，选择128分频
	SPI_InitStructure.SPI_CPOL = SPI_CPOL_Low;				//SPI极性，选择低极性
	SPI_InitStructure.SPI_CPHA = SPI_CPHA_1Edge;			//SPI相位，选择第一个时钟边沿采样，极性和相位决定选择SPI模式0
	SPI_InitStructure.SPI_NSS = SPI_NSS_Soft;				//NSS，选择由软件控制
	SPI_InitStructure.SPI_CRCPolynomial = 7;				//CRC多项式，暂时用不到，给默认值7
	SPI_Init(SPI1, &SPI_InitStructure);						//将结构体变量交给SPI_Init，配置SPI1
	
	/*SPI使能*/
	SPI_Cmd(SPI1, ENABLE);									//使能SPI1，开始运行
	
	/*设置默认电平*/
	MySPI_W_SS(1);											//SS默认高电平
}

/**
  * 函    数：SPI起始
  * 参    数：无
  * 返 回 值：无
  */
void MySPI_Start(void)
{
	MySPI_W_SS(0);				//拉低SS，开始时序
}

/**
  * 函    数：SPI终止
  * 参    数：无
  * 返 回 值：无
  */
void MySPI_Stop(void)
{
	MySPI_W_SS(1);				//拉高SS，终止时序
}

/**
  * 函    数：SPI交换传输一个字节，使用SPI模式0
  * 参    数：ByteSend 要发送的一个字节
  * 返 回 值：接收的一个字节
  */
uint8_t MySPI_SwapByte(uint8_t ByteSend)
{
	while (SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_TXE) != SET);	//等待发送数据寄存器空
	
	SPI_I2S_SendData(SPI1, ByteSend);								//写入数据到发送数据寄存器，开始产生时序
	
	while (SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_RXNE) != SET);	//等待接收数据寄存器非空
	
	return SPI_I2S_ReceiveData(SPI1);								//读取接收到的数据并返回
}
```

（全文 96 行，与官方文件逐字一致。）

### 3.1 初始化顺序

```text
① 开 GPIOA 时钟
② 开 SPI1 时钟                     ← 软件版没有这一步
③ PA4 配 Out_PP（片选，普通 GPIO）
④ PA5 / PA7 配 AF_PP（复用推挽）   ← 软件版这里配的是 Out_PP
⑤ PA6 配 IPU（上拉输入）
⑥ SPI_InitTypeDef 九项配置 + SPI_Init(SPI1, …)
⑦ SPI_Cmd(SPI1, ENABLE)            ← 使能外设，对应框图里 SPI_CR1 的 SPE 位
⑧ MySPI_W_SS(1) 片选默认高
```

**注意第 ⑧ 步只有 SS，没有 SCK。** 软件版末尾那一行 `MySPI_W_SCK(0)` 被删掉了——因为 SCK 的空闲电平现在由 `SPI_CPOL_Low` 决定，不再需要软件去摆（对比见第 4 节）。

### 3.2 `MySPI_SwapByte` 的四步

| 步 | 代码 | 在等什么 |
| --- | --- | --- |
| ① | `while (SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_TXE) != SET);` | 发送缓冲区空（`!= SET` = 一直循环到置位） |
| ② | `SPI_I2S_SendData(SPI1, ByteSend);` | 官方注释：「写入数据到发送数据寄存器，**开始产生时序**」 |
| ③ | `while (SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_RXNE) != SET);` | 接收缓冲区非空 |
| ④ | `return SPI_I2S_ReceiveData(SPI1);` | 取走收到的字节 |

标志含义、顺序理由、以及「为什么读的时候要发 dummy」已在 11-4 第 6、7 节讲清；`SPI_I2S_FLAG_TXE` = `0x0002`、`SPI_I2S_FLAG_RXNE` = `0x0001`（`stm32f10x_spi.h` 第 404~405 行），`SPI_I2S_GetFlagStatus` / `SPI_I2S_SendData` / `SPI_I2S_ReceiveData` 的原型在同一文件第 465、455、456 行。

## 4 逐函数对照：软件版 ↔ 硬件版（本集最有价值的一张表）

**两版 `MySPI.c` 的每一个组成部分，一一对上去：**

| 环节 | 11-3 软件版（119 行，8 个函数） | 11-5 硬件版（96 行，5 个函数） | 差别 |
| --- | --- | --- | --- |
| **片选 SS** | `MySPI_W_SS()` → `GPIO_WriteBit(GPIOA, GPIO_Pin_4, …)` | `MySPI_W_SS()` → **完全相同的一行** | **没有差别**：两版片选都由软件翻 PA4 |
| **时钟 SCK** | `MySPI_W_SCK()` → `GPIO_WriteBit(GPIOA, GPIO_Pin_5, …)`；`SwapByte` 里每字节手动拉高拉低各一次 | **函数被删掉**：SCK 由**波特率发生器**按 `BR[2:0]` 自动产生 | 软件版每字节翻 SCK 两次、共 8 个脉冲全手工；硬件版 0 次 |
| **MOSI** | `MySPI_W_MOSI()` → `GPIO_WriteBit(GPIOA, GPIO_Pin_7, …)`；循环里 `0x80 >> i` 逐位写 | **函数被删掉**：`SPI_I2S_SendData()` 写一次寄存器，硬件逐位移出 | 软件版每字节写 8 次 GPIO；硬件版写 1 次寄存器 |
| **MISO** | `MySPI_R_MISO()` → `GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_6)`；循环里逐位读 | **函数被删掉**：`SPI_I2S_ReceiveData()` 读一次寄存器 | 软件版每字节读 8 次 GPIO；硬件版读 1 次寄存器 |
| **交换一个字节** | `MySPI_SwapByte()`：`for (i = 0; i < 8; i ++)`，位掩码 + `!!` 归一 + 手动采样 | `MySPI_SwapByte()`：等 TXE → `SendData` → 等 RXNE → `ReceiveData` | **本集的核心差别**：8 轮循环 ↔ 4 条语句 |
| **起始 / 终止** | `MySPI_Start()` / `MySPI_Stop()` 翻 SS | **逐字相同** | 没有差别 |
| **时钟使能** | `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE)` | 同一行 **+** `RCC_APB2PeriphClockCmd(RCC_APB2Periph_SPI1, ENABLE)` | 多开一个 SPI1 时钟 |
| **GPIO 模式** | PA4 / PA5 / PA7 = `GPIO_Mode_Out_PP`；PA6 = `GPIO_Mode_IPU` | PA4 = `GPIO_Mode_Out_PP`；**PA5 / PA7 = `GPIO_Mode_AF_PP`**；PA6 = `GPIO_Mode_IPU` | **唯一的 GPIO 差别**：SCK / MOSI 交给外设 |
| **外设初始化** | 无 | `SPI_InitTypeDef` 9 项 + `SPI_Init(SPI1, …)` + `SPI_Cmd(SPI1, ENABLE)` | 软件版没有外设可配 |
| **默认电平** | `MySPI_W_SS(1)` **和** `MySPI_W_SCK(0)` | **只有** `MySPI_W_SS(1)` | SCK 空闲电平改由 `SPI_CPOL_Low` 决定 |
| **位序** | `0x80 >> i`（B7 → B0，高位先行） | `SPI_FirstBit_MSB` | **等价** |
| **模式** | 手工实现：SCK 默认低、上升沿采样 MISO | `SPI_CPOL_Low` + `SPI_CPHA_1Edge` = 模式 0 | **等价**（官方注释「极性和相位决定选择 SPI 模式 0」） |
| **对外接口 `MySPI.h`** | `Init / Start / Stop / SwapByte` | **同一个文件（SHA-256 相同）** | **没有差别** |
| **上层 `W25Q64.c`** | 134 行 | **逐字节相同** | **没有差别** |

> [!tip] 一句话总结这张表
> 换掉的是「**谁在打拍、谁在移位**」：软件版是 **CPU 亲手翻 4 根 GPIO**，硬件版是 **SPI 外设打拍 + CPU 只读写两个寄存器**。
> 没换的是「**片选、模式、位序、分层接口**」——这四样恰好就是 `MySPI.h` 里那 4 个函数的契约，所以上层一行都不用动。

### 4.1 为什么 8 个函数变成 5 个

| 软件版函数 | 硬件版 | 去哪了 |
| --- | --- | --- |
| `MySPI_W_SS` | 保留 | 片选仍由软件模拟 |
| `MySPI_W_SCK` | **删除** | 时钟交给波特率发生器 |
| `MySPI_W_MOSI` | **删除** | MOSI 交给发送缓冲区 + 移位寄存器 |
| `MySPI_R_MISO` | **删除** | MISO 交给接收缓冲区 |
| `MySPI_Init` | 保留（内容大改） | 加了 SPI1 时钟、GPIO 模式、外设配置、`SPI_Cmd` |
| `MySPI_Start` / `MySPI_Stop` | 保留 | 逐字相同 |
| `MySPI_SwapByte` | 保留（内容大改） | 循环 → 等标志 + 读写寄存器 |

**5 = 8 − 3。** 删掉的正好是「逐位操作」那三个函数——它们干的事全被硬件接走了。

## 5 `W25Q64.c` 一个字节都没改（有实证）

这不是「看起来一样」，而是**文件内容完全相同**。对两个工程的同名文件各算一次 SHA-256：

| 文件 | 11-1 软件版工程 | 11-2 硬件版工程 | 是否相同 |
| --- | --- | --- | --- |
| `Hardware\W25Q64.c` | `EDFD2248D19A…`（4440 字节） | `EDFD2248D19A…`（4440 字节） | **相同** |
| `Hardware\W25Q64.h` | `D0C48F7AC316…`（328 字节） | `D0C48F7AC316…`（328 字节） | **相同** |
| `Hardware\W25Q64_Ins.h` | `C1295BB45B7B…`（1264 字节） | `C1295BB45B7B…`（1264 字节） | **相同** |
| `Hardware\MySPI.h` | `66B20519082C…`（166 字节） | `66B20519082C…`（166 字节） | **相同** |
| `User\main.c` | `25F447F0BC46…`（1581 字节） | `25F447F0BC46…`（1581 字节） | **相同** |
| `Hardware\MySPI.c` | `531E2EDF856E…`（4324 字节） | `6FE53D354EBE…`（3721 字节） | **不同**（这才是本集改的文件） |

**六个文件里只有 `MySPI.c` 不同。** 这就是「分层」在真实工程里的样子：`MySPI.h` 的 4 个函数就是那道分界墙。

因为 `W25Q64.c` 完全相同，11-3 第 6 节列出的指令、字节数、地址拆分、等忙逻辑在 11-5 里**一字不差地适用**：

| 函数 | 指令 | 指令后跟什么 |
| --- | --- | --- |
| `W25Q64_ReadID` | `0x9F` | 3 个 dummy，收 MID + DID 高 + DID 低 |
| `W25Q64_WriteEnable` | `0x06` | 无，发完就 Stop |
| `W25Q64_WaitBusy` | `0x05` | 反复发 dummy 读状态，判 bit0 |
| `W25Q64_PageProgram` | `0x02` | 3 个地址字节 + `Count` 个数据字节 |
| `W25Q64_SectorErase` | `0x20` | 3 个地址字节 |
| `W25Q64_ReadData` | `0x03` | 3 个地址字节 + 发 dummy 收数据 |

## 6 main.c 与现象

官方 `11-2 硬件SPI读写W25Q64\User\main.c`（与 11-3 用的 `11-1` 版本**逐字节相同**）：

```c
#include "stm32f10x.h"                  // Device header
#include "Delay.h"
#include "OLED.h"
#include "W25Q64.h"

uint8_t MID;							//定义用于存放MID号的变量
uint16_t DID;							//定义用于存放DID号的变量

uint8_t ArrayWrite[] = {0x01, 0x02, 0x03, 0x04};	//定义要写入数据的测试数组
uint8_t ArrayRead[4];								//定义要读取数据的测试数组

int main(void)
{
	/*模块初始化*/
	OLED_Init();						//OLED初始化
	W25Q64_Init();						//W25Q64初始化
	
	/*显示静态字符串*/
	OLED_ShowString(1, 1, "MID:   DID:");
	OLED_ShowString(2, 1, "W:");
	OLED_ShowString(3, 1, "R:");
	
	/*显示ID号*/
	W25Q64_ReadID(&MID, &DID);			//获取W25Q64的ID号
	OLED_ShowHexNum(1, 5, MID, 2);		//显示MID
	OLED_ShowHexNum(1, 12, DID, 4);		//显示DID
	
	/*W25Q64功能函数测试*/
	W25Q64_SectorErase(0x000000);					//扇区擦除
	W25Q64_PageProgram(0x000000, ArrayWrite, 4);	//将写入数据的测试数组写入到W25Q64中
	
	W25Q64_ReadData(0x000000, ArrayRead, 4);		//读取刚写入的测试数据到读取数据的测试数组中
	
	/*显示数据*/
	OLED_ShowHexNum(2, 3, ArrayWrite[0], 2);		//显示写入数据的测试数组
	OLED_ShowHexNum(2, 6, ArrayWrite[1], 2);
	OLED_ShowHexNum(2, 9, ArrayWrite[2], 2);
	OLED_ShowHexNum(2, 12, ArrayWrite[3], 2);
	
	OLED_ShowHexNum(3, 3, ArrayRead[0], 2);			//显示读取数据的测试数组
	OLED_ShowHexNum(3, 6, ArrayRead[1], 2);
	OLED_ShowHexNum(3, 9, ArrayRead[2], 2);
	OLED_ShowHexNum(3, 12, ArrayRead[3], 2);
	
	while (1)
	{
		
	}
}
```

**现象与 11-3 完全一样**：OLED 第 1 行显示 MID 与 DID，第 2 行 `W:` 显示 `01 02 03 04`，第 3 行 `R:` 显示 `01 02 03 04`，两行一致即读写成功。

**唯一能看出差别的地方是示波器 / 逻辑分析仪上的 SCK**：软件版的 SCK 是 CPU 一位一位翻出来的，位与位之间被循环和中断拉得疏密不均；硬件版的 SCK 由波特率发生器打拍，规整得多（课件 Slide 166「软件 / 硬件波形对比」）。

> [!note] Slide 166 的两张抓包图本页不解读
> 课件 Slide 166 是纯图页，放了两张逻辑分析仪抓包图（`image152.jpg` 与 `image145.jpeg`），**课件文本里没有任何说明文字**。本页无法从官方材料判断哪一张是软件版、哪一张是硬件版，因此不对两张图下结论，已记入「待核对」。

## 7 两版的性能差别

| | 软件 SPI（11-3） | 硬件 SPI（11-5） |
| --- | --- | --- |
| 一个字节的 CPU 动作 | 8 轮循环，每轮 1 次写 MOSI + 1 次翻 SCK + 1 次读 MISO + 1 次翻 SCK | 2 次查标志 + 1 次写寄存器 + 1 次读寄存器 |
| 每字节 GPIO 操作次数 | **32 次**（4 次 × 8 轮） | **0 次**（SCK / MOSI 由外设驱动） |
| SCK 频率 | 由 GPIO 翻转与循环开销决定，官方材料未给数值 | `72 MHz / 128 ≈ 562.5 kHz`（`SPI_BaudRatePrescaler_128`；SPI1 挂 APB2） |
| 波形 | 位间隔不均匀，容易被中断拉长 | 硬件打拍，间隔均匀 |
| 中断影响 | 任何一次中断都会把时序拉长 | 时序由硬件保证，CPU 晚一点读写寄存器不影响已经开始的传输 |

> [!note] 562.5 kHz 是本页算出来的
> 课件 Slide 161 只给了公式 `f_PCLK / (2, 4, 8, 16, 32, 64, 128, 256)`。具体数值是这样得到的：`SPI1` 挂 **APB2**（`RCC_APB2Periph_SPI1`，`stm32f10x_rcc.h` 第 508 行）→ 官方工程把系统时钟配成 72 MHz 且 APB2 不分频（`Start\system_stm32f10x.c` 的 `SetSysClockTo72()`：第 1051/1056 行 `RCC_CFGR_PLLMULL9` + HSE，第 1025 行 `RCC_CFGR_PPRE2_DIV1`；`Start\stm32f10x.h` 第 119 行 `HSE_VALUE = 8000000`）→ `72 MHz / 128 = 562.5 kHz`。

## 8 易错点

- [ ] **只删了三个函数，却忘了改 GPIO 模式** → PA5 / PA7 还是 `GPIO_Mode_Out_PP`，引脚不由 SPI 外设控制（硬件版必须是 `GPIO_Mode_AF_PP`）。
- [ ] **忘了开 SPI1 时钟** → `MySPI_Init()` 里只留了 `RCC_APB2Periph_GPIOA`，外设无时钟，标志永远不动。
- [ ] **忘了 `SPI_Cmd(SPI1, ENABLE)`** → 配置全对但外设没使能，一个字节也发不出去。
- [ ] 以为 PA4 也该配成复用 → 官方硬件版 PA4 仍是 `GPIO_Mode_Out_PP`（注释：「SS 仍由软件模拟」）。
- [ ] 把软件版 `MySPI_Init()` 末尾的 `MySPI_W_SCK(0)` 一起抄过来 → 硬件版**没有**这一行，SCK 空闲电平由 `SPI_CPOL_Low` 决定。
- [ ] `SwapByte` 里把两个 `while` 写反（先等 RXNE 再 `SendData`）→ 死等，因为不写数据就不会有时钟、也就不会有 `RXNE`。
- [ ] 改完 `MySPI.c` 顺手去"顺手优化" `W25Q64.c` → 完全没必要，官方两版的 `W25Q64.c` 是同一个文件（SHA-256 相同）。
- [ ] 以为读数据发 `0xFF` 是 W25Q64 的规定 → 那是 SPI 全双工结构决定的（11-4 第 7 节）。
- [ ] 以为硬件 SPI 就不用管片选了 → `MySPI_Start` / `MySPI_Stop` 在两版里逐字相同，都还在。
- [ ] 主循环里发现"数据没变"就怀疑 SPI 坏了 → 先确认擦除是否执行过：`0x01 0x02 0x03 0x04` 这种值在擦除后可以直接写（只 1→0），但如果上一轮写进了别的值，不擦就改不回来。

## 9 自测

1. 11-3 换到 11-5，一共改了哪个文件？哪些文件一个字节都没改？
2. 两版的 GPIO 配置在哪一脚上不同？为什么不同的恰好是这两脚？
3. 软件版 `MySPI.c` 有 8 个函数，硬件版只有 5 个，删掉的是哪三个？它们的功能去哪了？
4. 硬件版 `MySPI_Init()` 末尾只有 `MySPI_W_SS(1)`，没有 `MySPI_W_SCK(0)`，为什么可以不写？
5. 两版的 `main.c` 完全相同，为什么示波器上看到的 SCK 波形不一样？

> [!success]- 参考答案
> 1. 只改了 `Hardware\MySPI.c`。`W25Q64.c`、`W25Q64.h`、`W25Q64_Ins.h`、`MySPI.h`、`User\main.c` **五个文件 SHA-256 完全相同**（第 5 节的表）。
> 2. 差别在 **PA5（SCK）和 PA7（MOSI）**：软件版 `GPIO_Mode_Out_PP`，硬件版 `GPIO_Mode_AF_PP`。因为这两个脚在硬件版里要交给 SPI 外设驱动，属于「复用功能」；而 PA4（片选）仍由软件 GPIO 控制、PA6（MISO）本来就是输入，所以都不变。
> 3. 删掉的是 `MySPI_W_SCK`、`MySPI_W_MOSI`、`MySPI_R_MISO`。SCK 改由**波特率发生器**产生，MOSI / MISO 改由**发送缓冲区 + 移位寄存器**、**接收缓冲区**承担。
> 4. 因为 SCK 的空闲电平现在由外设按 `SPI_CPOL` 决定——本课配的是 `SPI_CPOL_Low`，空闲就是低电平，不需要软件再去摆一次。软件版没有外设可依靠，才必须手动把 SCK 停在低电平。
> 5. 因为打拍的人换了：软件版的 SCK 是 CPU 在 `for` 循环里一位一位翻 GPIO 翻出来的，位与位之间被循环开销和中断拉得疏密不均；硬件版的 SCK 是波特率发生器按 `72 MHz / 128` 自动打出来的，间隔均匀。（课件 Slide 166「软件 / 硬件波形对比」）
