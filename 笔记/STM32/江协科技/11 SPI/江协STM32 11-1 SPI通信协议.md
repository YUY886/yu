# 11-1 SPI 通信协议

> [!abstract] 这一集只解决一个问题
> **SPI 到底是怎么把一位一位的数据搬过去的？**
>
> 答：主机和从机各有一个 **8 位移位寄存器**，SCK 每打一拍，双方**同时**从对方那里收进来一位、把手里的一位推出去。所以 SPI 收和发是**同一个动作**，分不开。
>
> 下一集 [[江协STM32 11-2 W25Q64简介]] ｜ 章索引 [[江协STM32 11 SPI（章索引）]]

## 1 SPI 是什么

**SPI（Serial Peripheral Interface）** 是由 **Motorola 公司**开发的一种**通用数据总线**（课件 Slide 146 原文）。

| 属性 | 取值 | 出处 |
| --- | --- | --- |
| 同步 / 异步 | **同步** | Slide 146 |
| 双工方式 | **全双工** | Slide 146 |
| 拓扑 | 支持总线挂载多设备（**一主多从**） | Slide 146 |
| 线数 | **四根** | Slide 146 |

四根通信线（Slide 146 原文）：

| 线名 | 全称 | 方向 |
| --- | --- | --- |
| **SCK** | Serial Clock | 主机 → 从机（时钟） |
| **MOSI** | Master Output Slave Input | 主机 → 从机（数据） |
| **MISO** | Master Input Slave Output | 从机 → 主机（数据） |
| **SS** | Slave Select | 主机 → 从机（片选） |

> [!note] 「同步」和「全双工」各是什么意思
> **同步**：数据线旁边跟着一根时钟线 SCK，收发双方按同一根时钟的节拍走，不需要事先约定波特率。这一点和 I2C 一样，和 USART 的异步方式不同。
> **全双工**：MOSI 和 MISO 是**两根独立的线**，同一时刻一个方向发、另一个方向收，互不干扰。I2C 只有一根 SDA，同一时刻只能单向传输，属于半双工。

## 2 硬件电路

课件 Slide 147 原文：

- 所有 SPI 设备的 **SCK、MOSI、MISO 分别连在一起**
- 主机另外引出**多条 SS 控制线**，分别接到各从机的 SS 引脚
- **输出引脚配置为推挽输出，输入引脚配置为浮空或上拉输入**

```text
                 ┌────────────┐
        ┌─SCK───►│  从机 1    │
        ├─MOSI──►│            │
        │◄─MISO──│            │
        ├─SS1───►│            │
        │        └────────────┘
  ┌─────┴──┐     ┌────────────┐
  │  主机  ├─SS2─►│  从机 2    │
  │        ├─SS3─►│  从机 3    │
  └────────┘     └────────────┘
      SCK / MOSI / MISO 三根线所有从机共用；
      SS 各从机独占一根，主机有几条 SS 就能挂几个从机。
```

**片选线独占总线**：主机想跟谁说话，就单独把谁那根 SS 拉低。同一时刻只有一根 SS 是低的，也就只有那一个从机会去驱动 MISO 线——这就是 SPI 不需要「地址」的原因。

> [!warning] 一主多从的代价
> I2C 用「设备地址」在一根总线里点名；SPI 用「多一根 SS 线」来点名。**每多挂一个从机就多占一个主机引脚**，这是 SPI 相对 I2C 最明显的代价，也是它引脚数多（4 根起）的根源。

## 3 移位寄存器交换原理

这是整章的核心（课件 Slide 148「移位示意图」）。

主机和从机内部**各有一个 8 位移位寄存器**，中间由 MOSI、MISO 两根线连成一个环：

```text
   主机移位寄存器                          从机移位寄存器
   ┌──┬──┬──┬──┬──┬──┬──┬──┐            ┌──┬──┬──┬──┬──┬──┬──┬──┐
   │B7│B6│B5│B4│B3│B2│B1│B0│            │b7│b6│b5│b4│b3│b2│b1│b0│
   └──┴──┴──┴──┴──┴──┴──┴──┘            └──┴──┴──┴──┴──┴──┴──┴──┘
      │  ▲                                    ▲  │
      │  └──────────── MISO ──────────────────┘  │
      └────────────── MOSI ──────────────────────┘
                 每来一个 SCK 时钟脉冲：
                 两边各自左移一位，空出的位置从对面的线上补进来
```

- 主机把自己最高位（B7）推到 MOSI 上，从机把最高位（b7）推到 MISO 上；
- 一个 SCK 脉冲过后，**主机的 B7 进了从机的最低位，从机的 b7 进了主机的最低位**；
- 打 8 拍之后，两个寄存器的内容**整体换了个个儿**。

**为什么 SPI 收发是一体的**：因为收和发用的是同一套移位结构、同一根时钟。你不可能「只发不收」或者「只收不发」——每打一拍，必然是一边进一边出。所谓「发一个字节」，实际发生的动作是**交换一个字节**。

> [!tip] 这个名字上的暗示
> 官方源码里那个函数就叫 `MySPI_SwapByte()`，不叫 `SendByte()` 也不叫 `ReceiveByte()`。它返回的正是「换进来的那个字节」：
>
> ```c
> uint8_t MySPI_SwapByte(uint8_t ByteSend);   // 发一个字节进去，同时收到一个字节回来
> ```
>
> 这条特性在后面非常有用：**想读数据时，随便发一个字节（源码里发 `0xFF`）当「时钟搬运工」就行**，换回来的就是对方的数据。

## 4 四种模式：CPOL × CPHA

SPI 有 **CPOL**（时钟极性）和 **CPHA**（时钟相位）两个参数，2 × 2 = **4 种模式**（课件 Slide 150~153 逐页讲了一遍）。

- **CPOL 决定空闲状态时 SCK 是高还是低**（也就是第一个边沿是上升沿还是下降沿）；
- **CPHA 决定在第一个边沿动作还是在第二个边沿动作**。

| 模式 | CPOL | 空闲时 SCK | CPHA | 课件表述 | 库函数取值 |
| --- | --- | --- | --- | --- | --- |
| 模式 0 | 0 | **低电平** | 0 | 第一个边沿移入数据，第二个边沿移出数据 | `SPI_CPOL_Low` + `SPI_CPHA_1Edge` |
| 模式 1 | 0 | **低电平** | 1 | 第一个边沿移出数据，第二个边沿移入数据 | `SPI_CPOL_Low` + `SPI_CPHA_2Edge` |
| 模式 2 | 1 | **高电平** | 0 | 第一个边沿移入数据，第二个边沿移出数据 | `SPI_CPOL_High` + `SPI_CPHA_1Edge` |
| 模式 3 | 1 | **高电平** | 1 | 第一个边沿移出数据，第二个边沿移入数据 | `SPI_CPOL_High` + `SPI_CPHA_2Edge` |

（「课件表述」一列抄自 Slide 150~153 原文；「库函数取值」一列来自 ST 标准外设库 `stm32f10x_spi.h` 第 168~183 行的 `SPI_CPOL_Low/High`、`SPI_CPHA_1Edge/2Edge` 四个宏。）

**在哪个边沿采样、哪个边沿移出**：

- `CPHA = 0`（模式 0、2）：**第一个边沿**是采样边沿（移入），**第二个边沿**是移出边沿。数据必须在第一个边沿到来**之前**就摆到线上，所以是「先摆好、再打拍」。
- `CPHA = 1`（模式 1、3）：**第一个边沿**先把数据推出去（移出），**第二个边沿**才采样（移入）。数据是「打拍的同时摆出去」。

> [!warning] 课件 Slide 150~153 与 ST 库头文件对「移入 / 移出」的说法需要留个心眼
> 课件把 `CPHA=0` 说成「第一个边沿**移入**数据，第二个边沿**移出**数据」（见上表）。
> 同一份课件里，`CPHA=1` 又说成「第一个边沿移出、第二个边沿移入」——**两句话里的「移入 / 移出」正好互换**。
> 而本集官方软件 SPI 源码 `MySPI.c` 第 112~115 行的注释写的是：
> 「拉高 SCK，**上升沿移出数据**」「拉低 SCK，**下降沿移入数据**」。
> 这两处表述不一致，已记入下面的「待核对」。**本页只保证「引脚、时序结构、参数取值」与官方材料一致**，不对「移入 / 移出」这两个词在中英文语境下该怎么叫下定论。
> 实用判断方式：不管怎么叫，**模式 0 就是「SCK 空闲为低、上升沿时 MISO 上的数据有效」**，按这个去读时序波形不会出错。

### 4.1 本课 W25Q64 用模式几

**模式 0**，有三个独立依据：

1. 官方源码 `11-1 软件SPI读写W25Q64\Hardware\MySPI.c` 第 100 行函数头注释：「交换传输一个字节，**使用 SPI 模式 0**」；
2. 同工程 `11-2 硬件SPI读写W25Q64\Hardware\MySPI.c` 第 49~50 行：`SPI_CPOL_Low` 且 `SPI_CPHA_1Edge`，注释直接写「极性和相位决定选择 **SPI 模式 0**」；
3. 软件 SPI 的实现里 SCK 默认低电平（`MySPI_Init()` 末尾 `MySPI_W_SCK(0)`），符合模式 0 的「空闲状态时 SCK 为低电平」。

## 5 时序基本单元

课件 Slide 149~153 把 SPI 的时序拆成几个基本单元：

| 单元 | 内容 | 出处 |
| --- | --- | --- |
| **起始条件** | SS 从高电平切换到低电平 | Slide 149 |
| **终止条件** | SS 从低电平切换到高电平 | Slide 149 |
| **交换一个字节** | 8 个 SCK 脉冲，高位先行（B7 → B0） | Slide 150~153 |
| **发送指令** | 向 SS 指定的设备发送指令，例如 `0x06` | Slide 154 |
| **指定地址写** | 发送写指令 `0x02`，随后在 `Address[23:0]` 下写入 `Data` | Slide 155 |
| **指定地址读** | 发送读指令 `0x03`，随后在 `Address[23:0]` 下读取 `Data` | Slide 156 |

官方软件 SPI 源码 `MySPI.c` 把「起始 / 终止」也封装成了两个函数，和课件的表述完全对应：

```c
void MySPI_Start(void)
{
	MySPI_W_SS(0);				//拉低SS，开始时序
}

void MySPI_Stop(void)
{
	MySPI_W_SS(1);				//拉高SS，终止时序
}
```

**起始和终止只动 SS 一根线**，SCK 不用管——这一点和 I2C 的「起始 / 终止条件靠 SCL 与 SDA 的先后关系拼出来」很不一样，SPI 的起始终止简单得多。

## 6 软件 SPI 与硬件 SPI

第 11 章后面几集的分界线就在这条线上：

| 对比项 | 软件 SPI（11-1 工程的做法） | 硬件 SPI（11-2 工程的做法） |
| --- | --- | --- |
| SCK / MOSI / MISO | **纯 GPIO**，由代码一位一位翻转电平 | 由 SPI 外设硬件自动产生和采样 |
| SS | GPIO 手动拉低拉高 | **仍然由 GPIO 手动拉低拉高**（源码 `MySPI_W_SS` 注释：「SS 仍由软件模拟」） |
| GPIO 模式 | PA5、PA7 为 `GPIO_Mode_Out_PP`（推挽输出）；PA6 为 `GPIO_Mode_IPU`（上拉输入） | PA5、PA7 为 `GPIO_Mode_AF_PP`（**复用**推挽输出）；PA6 仍为 `GPIO_Mode_IPU` |
| 传输一个字节 | `for` 循环 8 次，手工摆 MOSI、拉 SCK、读 MISO | 写一次 `SPI_I2S_SendData`，等 `TXE` / `RXNE` 标志 |
| 速率 | 受 GPIO 翻转速度限制，很慢 | 由波特率发生器分频得到，可到 MHz 级 |
| CPU 占用 | 每一位都要 CPU 参与 | 硬件搬运，CPU 只读写寄存器 |
| 会不会有波形瑕疵 | 软件时序容易产生毛刺，波形不如硬件规整 | 波形规整（课件 Slide 166「软件 / 硬件波形对比」） |

课件 Slide 145 与 Slide 166 各有一页「软件 / 硬件波形对比」，分别对应软件 I2C 与软件 SPI。**第 11 章的 11-1 是软件版、11-2 是硬件版**，两集主循环代码几乎一样，差别全在 `MySPI.c` 这一层。

> [!tip] 这就是「分层」的好处
> 两集里 `W25Q64.c` 一个字都没改。换掉底层的 `MySPI.c`，上层读写 Flash 的逻辑原封不动就能跑——因为 `MySPI.h` 对外只暴露 `Init / Start / Stop / SwapByte` 四个函数。

## 7 推挽输出：SPI 为什么不像 I2C 那样需要开漏

课件 Slide 147 明确要求「输出引脚配置为**推挽输出**」，官方两个工程也是这么做的（`GPIO_Mode_Out_PP` / `GPIO_Mode_AF_PP`）。原因在于两者的**总线结构不同**：

| 对比项 | I2C | SPI |
| --- | --- | --- |
| 一根线上挂几个输出 | SDA 上所有设备都能输出，**可能冲突** | MOSI / SCK 只有主机输出，MISO 同一时刻只有被选中的从机输出 |
| 冲突怎么解决 | 必须**开漏 + 上拉电阻**，靠「线与」避免两个设备对拉 | 靠**片选**保证同一时刻只有一个设备驱动 MISO |
| 引脚配置 | 开漏输出（`GPIO_Mode_Out_OD`） | **推挽输出**（`GPIO_Mode_Out_PP` / `GPIO_Mode_AF_PP`） |
| 上升沿 | 靠上拉电阻，边沿被 RC 拖慢 | 推挽主动拉高，上升沿干脆、速度快 |

**一句话**：I2C 是「大家共用一根线、谁都能拉低」，所以只能开漏；SPI 是「每根线各管各的方向、片选保证不撞车」，所以可以放心用推挽，顺便拿到了更快的边沿。

## 8 SPI 与 I2C 对照

| 对比项 | I2C | SPI |
| --- | --- | --- |
| 线数 | **2 根**（SCL、SDA） | **4 根**（SCK、MOSI、MISO、SS） |
| 双工方式 | 半双工（一根 SDA 分时复用） | **全双工**（MOSI / MISO 各一根） |
| 同步方式 | 同步 | 同步 |
| 多从机怎么选 | **设备地址寻址**（7 位 / 10 位），挂在同一对线上 | **片选线 SS**，一从机一根，各自独占 |
| 挂多设备时代价 | 地址位宽有限，但**不额外占引脚** | **每多一个从机就多一个引脚** |
| 速率 | 标准 100 kHz、快速 400 kHz（见第 10 章课件） | 由分频器决定，可到 MHz 量级（课件 Slide 161 列出 `f_PCLK / (2,4,…,256)`） |
| 输出引脚 | 必须**开漏** + 上拉电阻 | **推挽** |
| 抗噪 | 开漏 + 上拉，边沿较缓 | 推挽边沿陡，且时钟线与数据线分离，**同速率下抗噪更好** |
| 协议开销 | 每次通信都要起始、地址、应答 | 没有地址和应答，**几乎全是有效数据**，协议开销小 |

> [!warning] 「SPI 更快」这句话要说清楚前提
> SPI 的**协议本身**没有地址位和应答位，开销确实比 I2C 小；但「SPI 一定比 I2C 快」不是无条件的——实际速率由主机分频和从机上限共同决定。本集软件 SPI 更是**用 GPIO 一位一位翻转出来的**，比硬件 I2C 还慢。**「高速」是 SPI 协议的能力上限，不是软件 SPI 的实际表现。**

本集的 W25Q64 模块就接在 STM32 的 **PA4~PA7** 这一组引脚上（官方接线图 `ground-truth\接线图\11-1 软件SPI读写W25Q64.png`）。官方源码 `MySPI.c` 中四个引脚的定义（依据，非推测）：

## 10 易错点

- [ ] 把 SPI 当成「只管发」或「只管收」→ 每一次传输都是**交换**，收和发同时发生。
- [ ] 忘记了 SS 必须先拉低 → 从机不响应，波形全对但没反应。
- [ ] 以为 SS 可以像 SCK 一样共用一根 → 每个从机一根 SS，共用就分不清在跟谁说话。
- [ ] 主从的 CPOL / CPHA 配得不一致 → 采到的位整体错位，读回来的数据看着像乱码。
- [ ] 把「高位先行」当成默认常识 → 库里有 `SPI_FirstBit_MSB` 和 `SPI_FirstBit_LSB` 两个选项，必须显式配置（本课用 MSB）。
- [ ] 输出引脚配成开漏 → 本课官方源码用的是推挽（`GPIO_Mode_Out_PP` / `GPIO_Mode_AF_PP`），照 I2C 的习惯配开漏会得到上升沿很缓的波形。
- [ ] 软件 SPI 里忘了给 `ByteReceive` 赋初值 `0x00` → 官方注释特别强调「此处必须赋初值 0x00」，因为后面只做「置 1」不做「清 0」。
- [ ] 认为「SPI 一定比 I2C 快」→ 软件 SPI 是用 GPIO 翻出来的，比硬件 I2C 慢得多。

## 11 自测

1. SPI 的四根线分别叫什么？各自的方向是什么？
2. 为什么说「SPI 的收发是一体的」？
3. 主机要挂 4 个从机，最少需要几根 IO？I2C 呢？
4. 模式 0 的 CPOL 和 CPHA 各是多少？空闲时 SCK 是什么电平？
5. SPI 为什么可以用推挽输出，而 I2C 必须用开漏？
6. 软件 SPI 和硬件 SPI 的差别在哪一层？

> [!success]- 参考答案
> 1. SCK（主机→从机，时钟）、MOSI（主机→从机，数据）、MISO（从机→主机，数据）、SS（主机→从机，片选）。
> 2. 因为收发共用同一套 8 位移位寄存器和同一根 SCK，每打一拍必然是「进一位、出一位」，动作不可分割，所以官方函数叫 `SwapByte`。
> 3. SPI 需要 3 根共用线（SCK/MOSI/MISO）+ 4 根 SS = **7 根**；I2C 只要 **2 根**（SCL/SDA）。
> 4. `CPOL = 0`、`CPHA = 0`；空闲时 SCK 为**低电平**。对应库函数 `SPI_CPOL_Low` + `SPI_CPHA_1Edge`。
> 5. I2C 的 SDA 上所有设备都可能输出，必须开漏避免冲突；SPI 靠片选保证同一时刻只有一个设备驱动 MISO，不会冲突，所以可以用推挽，边沿更陡、速度更快。
> 6. 只差在 `MySPI.c` 这一层：软件版用 GPIO 翻转，硬件版交给 SPI 外设。`MySPI.h` 的四个接口和 `W25Q64.c` 完全不变。
