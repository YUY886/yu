# 06-8 编码器接口测速

> [!abstract] 这一集只解决一个问题
> **怎么把 CNT 里的格子数变成"电机转多快、往哪边转"？**
>
> 答：**每隔固定的闸门时间 T，读一次 CNT，然后立刻清零。** 读到的数就是这段时间内转过的格数（增量 ΔCNT），带正负号，正负即方向；ΔCNT 除以 T 就是脉冲频率，再除以"每转计数值"就得到转速。
>
> 上一集 [[江协STM32 06-7 TIM编码器接口]] ｜ 章索引 [[江协STM32 06 TIM定时器（章索引）]] ｜ 下一章 [[江协STM32 07 ADC（章索引）]]

## 1 测速思路：固定闸门时间 + 计数增量

6-7 里编码器接口已经帮我们把"转了多少格"实时写进了 CNT。测速要做的只有一件事：**在固定时间点上把 CNT 抄下来，然后清零，准备下一次。**

```text
        ◄── 闸门时间 T ──►◄── 闸门时间 T ──►◄── 闸门时间 T ──►
CNT:    0 ──► 涨到 ΔCNT₁ │ 0 ──► 涨到 ΔCNT₂ │ 0 ──► 涨到 ΔCNT₃
            读走并清零  │      读走并清零  │      读走并清零
```

于是：

| 量 | 怎么算 |
| --- | --- |
| 脉冲频率 | `f = ΔCNT / T` |
| 转向 | `ΔCNT` 的**正负号** |
| 转速 | 见第 4 节的换算公式 |

**编码器测速的本质就是「测频法」**：在固定的闸门时间内数出脉冲个数，用个数除以时间得到频率。这和 6-6 测频率是同一类思路——区别在于"数脉冲"这个动作。在这一集里，数脉冲的活儿被**编码器接口硬件**全包了，软件只需要每隔一段时间取一次结果，完全不用中断逐个数。

> [!tip] 测频法 vs 测周法，怎么选
> - **测频法**（固定时间数脉冲）：信号频率越高，闸门内数到的个数越多，量化误差占比越小 → **适合高频信号**。
> - **测周法**（测一个周期的时间）：信号频率越低，测到的周期越长，量化误差占比越小 → **适合低频信号**。
>
> 编码器正常转动时脉冲很密，用测频法正合适。

## 2 为什么必须清零

两个理由，都很硬：

**理由一：CNT 是 16 位，不清零就会回绕。**

```text
CNT: 0 ──────► 65535 ──► 0 ──────► 65535 ──► 0 ...
                            ↑
                       在这里回绕，超过 65535 的信息全部丢失
```

ARR 给的是 **65536 − 1 = 65535**（满量程，官方 `Encoder.c` 写的是 `TIM_Period = 65536 - 1`），所以 CNT 只能表示 `0 ~ 65535`。连续转动时它一直在累加，迟早会绕回来。绕回来之后，你读到的值**不再是"这段时间转了多少格"**，而是"绕了几圈之后剩下的余数"——信息已经丢了。

**理由二：清零之后，每次读到的就是增量本身。**

不清零的话，想求增量得自己保存上一次的读数、再做差，还要额外处理回绕：

```text
不清零：ΔCNT = CNT_now − CNT_last      // 需要保存 CNT_last，还要判回绕
清零后：ΔCNT = CNT_now                 // 直接就是答案
```

清零把"减法"这件麻烦事交给了硬件，读一次就是一个增量。这也正是这一步的价值所在。

> [!warning] 清了零就读不到绝对位置了
> 清零意味着**放弃了累计位置信息**。所以"测位置"和"测速度"对同一次读取的要求正好相反，见第 6 节。

## 3 `Encoder_Get()`：读 CNT、清零、返回带符号增量

```c
/**
  * 函    数：获取编码器的增量值
  * 参    数：无
  * 返 回 值：自上此调用此函数后，编码器的增量值
  */
int16_t Encoder_Get(void)
{
	/*使用Temp变量作为中继，目的是返回CNT后将其清零*/
	int16_t Temp;
	Temp = TIM_GetCounter(TIM3);
	TIM_SetCounter(TIM3, 0);
	return Temp;
}
```

（这是官方 `6-8 编码器接口测速\Hardware\Encoder.c` 第 52~64 行的原文，逐字未改。注意 `TIM_GetCounter()` 本身返回 `uint16_t`，官方**没有写显式强制类型转换**，靠的是赋给 `int16_t Temp` 时的隐式转换——语义等价，但要看清楚。）

### 3.1 为什么返回类型必须是 `int16_t`，不能是 `uint16_t`

这是本集最关键的一处细节。

`TIM_GetCounter()` 的返回值类型是 `uint16_t`，取值范围 `0 ~ 65535`。**它全是非负数，根本表达不了"反转"。**

但在编码器模式下，CNT 是**可以往下数的**：正转自增，反转自减。当反转把 CNT 从 0 再减 1 时，16 位寄存器会**下溢回绕**到 65535：

```text
正转：  0 → 1 → 2 → 3 → ...            （自增，读到的就是转过的格数）
反转：  0 → 65535 → 65534 → 65533 → ... （自减，从0往下借位回绕）
```

用 `uint16_t` 看，反转时读到的是一串 65535 附近的大数——看起来像"转得飞快"，完全看不出在反转。

而把它按 **`int16_t`（补码）**重新解释，一切就对了：

| 16 位原始值 | 按 `uint16_t` 看 | 按 `int16_t` 看 |
| --- | --- | --- |
| `0x0000` | 0 | 0 |
| `0x0001` | 1 | 1 |
| `0x7FFF` | 32767 | 32767 |
| `0x8000` | 32768 | **−32768** |
| `0xFFFF` | 65535 | **−1** |
| `0xFFFE` | 65534 | **−2** |

所以代码里用 `int16_t Temp` 当中继变量，把 `TIM_GetCounter()` 的结果**隐式转换成带符号数**：正转读到正数，反转读到负数，符号天然就代表了方向。

> [!warning] `int16_t` 的量程上限
> 一个闸门时间内 `|ΔCNT|` 必须 **小于 32768**，否则符号会翻转（比如实际转了 +40000 格，显示出来是负数）。本课程的闸门 + 普通电机远达不到这个量级，但换长闸门或高线数编码器时要注意。
>
> 如果确实可能超过，就把闸门时间缩短，或者用 `uint16_t` 读数自己在外层做 32 位累加和回绕判断。

### 3.2 读取与清零之间的一点点误差

`TIM_GetCounter()` 和 `TIM_SetCounter()` 是两条独立指令，两条指令之间编码器**仍可能继续计数**，这一两个数会被算进下一次读数里。所以测速结果可能有 **±1~2 个计数**的抖动。

对测速来说这点误差完全可以忽略（分母上还有倍频数和 PPR 呢）。真要做到严格无缝，可以在读之前先关掉编码器计数、读完再开，但本课程不需要这么讲究。

## 4 从增量换算转速

### 4.1 公式

```text
ΔCNT          闸门时间内 CNT 的带符号增量（由 Encoder_Get() 得到）
倍频数         TI1 / TI2 模式 = 2，TI12 模式 = 4
PPR            编码器每转脉冲数（单相的线数，Pulses Per Revolution）
T              闸门时间，单位：秒

每转计数值  = 倍频数 × PPR
转数        = ΔCNT / (倍频数 × PPR)          [转]
转速        = 转数 / T × 60                  [转/分, r/min]
```

合并成一个式子：

```text
转速(r/min) = ΔCNT / (倍频数 × PPR) / T × 60
```

推导过程很简单，都是一步一步的单位换算：

```text
ΔCNT 格  ──除以每转格数──►  ΔCNT / (倍频数 × PPR)  转
         ──除以闸门时间──►  每秒转多少转            (转/秒)
         ──乘以 60───►      每分钟转多少转          (转/分)
```

`ΔCNT` 带符号，所以算出来的转速**也带符号**：正数正转，负数反转。

### 4.2 算例

设 4 倍频（TI12），编码器 PPR = 11，闸门时间 T = 1 s：

```text
每转计数值 = 4 × 11 = 44

例1：正转，ΔCNT = +440
     转速 = 440 / 44 / 1 × 60 = 10 × 60 = 600 r/min        （正转 600 转/分）

例2：反转，ΔCNT = −220
     转速 = -220 / 44 / 1 × 60 = -5 × 60 = -300 r/min       （反转 300 转/分）

例3：静止，ΔCNT = 0
     转速 = 0 r/min                                        （不转）
```

再验算一下例 1 的物理意义：1 秒转 10 圈，每圈 44 个计数，所以 1 秒内 CNT 涨 440，对得上。

### 4.3 常数合并，方便单片机算

闸门时间和编码器参数定下来后，分母是个常数，可以预先合并：

```text
K = 60 / (倍频数 × PPR × T)

转速(r/min) = ΔCNT × K
```

上例中 `K = 60 / (4 × 11 × 1) ≈ 1.3636`。

> [!warning] 别用整数除法把自己除成 0
> 单片机里如果写 `Speed = ΔCNT * 60 / (4 * 11 * 1)`，先乘后除没问题；但写成 `ΔCNT / 44 * 60` 在整数运算下会先丢掉小数部分。
>
> K 是个小于 1 的小数，直接 `ΔCNT * K` 用整数是算不出来的。惯用做法是**放大 1000 倍做定点运算**：
>
> ```c
> /* K × 1000 = 60 × 1000 / (4 × 11 × 1) ≈ 1364 */
> Speed_x1000 = (int32_t)ΔCNT * 1364 / 1000;       // 结果是"转速 × 1000"
> ```
>
> 注意 `ΔCNT * 1364` 会超出 16 位，**必须先把 ΔCNT 转成 `int32_t` 再乘**，否则溢出。

## 5 主程序：TIM2 定时中断产生闸门

闸门时间靠**另一个定时器**的更新中断来产生——这是 6-1 定时中断的直接复用。注意分工：

| 定时器 | 职责 |
| --- | --- |
| **TIM3** | 编码器接口，负责数格子 |
| **TIM2** | 定时中断，负责每隔一个固定时间段喊一次"该读数了" |

> [!note] 官方参数核对：闸门确实是 **1 s**
> 官方 `System\Timer.c` 写的是 `TIM_Prescaler = 7200 - 1`、`TIM_Period = 10000 - 1`。代入课件 Slide 235/239 的官方公式：
>
> ```text
> CK_CNT    = CK_PSC / (PSC + 1) = 72 MHz / 7200 = 10 kHz   （1 拍 = 0.1 ms）
> CK_CNT_OV = CK_CNT / (ARR + 1) = 10 kHz / 10000 = 1 Hz    （周期 = 1 s）
> ```
>
> 即 `(PSC + 1) × (ARR + 1) / 72 MHz = 7200 × 10000 / 72 000 000 = 1 s` ✔。本页所有涉及闸门时间的算式与算例都按 **T = 1 s** 处理。

### 5.1 Timer.c（官方 `System\Timer.c` 原文；**位于 `System\` 目录，不是 `Hardware\`**）

```c
#include "stm32f10x.h"

/**
  * 函    数：定时中断初始化
  * 参    数：无
  * 返 回 值：无
  */
void Timer_Init(void)
{
	/*开启时钟*/
	RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM2, ENABLE);			//开启TIM2的时钟
	
	/*配置时钟源*/
	TIM_InternalClockConfig(TIM2);		//选择TIM2为内部时钟，若不调用此函数，TIM默认也为内部时钟
	
	/*时基单元初始化*/
	TIM_TimeBaseInitTypeDef TIM_TimeBaseInitStructure;				//定义结构体变量
	TIM_TimeBaseInitStructure.TIM_ClockDivision = TIM_CKD_DIV1;		//时钟分频，选择不分频，此参数用于配置滤波器时钟，不影响时基单元功能
	TIM_TimeBaseInitStructure.TIM_CounterMode = TIM_CounterMode_Up;	//计数器模式，选择向上计数
	TIM_TimeBaseInitStructure.TIM_Period = 10000 - 1;				//计数周期，即ARR的值
	TIM_TimeBaseInitStructure.TIM_Prescaler = 7200 - 1;				//预分频器，即PSC的值
	TIM_TimeBaseInitStructure.TIM_RepetitionCounter = 0;			//重复计数器，高级定时器才会用到
	TIM_TimeBaseInit(TIM2, &TIM_TimeBaseInitStructure);				//将结构体变量交给TIM_TimeBaseInit，配置TIM2的时基单元	
	
	/*中断输出配置*/
	TIM_ClearFlag(TIM2, TIM_FLAG_Update);						//清除定时器更新标志位
																//TIM_TimeBaseInit函数末尾，手动产生了更新事件
																//若不清除此标志位，则开启中断后，会立刻进入一次中断
																//如果不介意此问题，则不清除此标志位也可
	
	TIM_ITConfig(TIM2, TIM_IT_Update, ENABLE);					//开启TIM2的更新中断
	
	/*NVIC中断分组*/
	NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);				//配置NVIC为分组2
																//即抢占优先级范围：0~3，响应优先级范围：0~3
																//此分组配置在整个工程中仅需调用一次
																//若有多个中断，可以把此代码放在main函数内，while循环之前
																//若调用多次配置分组的代码，则后执行的配置会覆盖先执行的配置
	
	/*NVIC配置*/
	NVIC_InitTypeDef NVIC_InitStructure;						//定义结构体变量
	NVIC_InitStructure.NVIC_IRQChannel = TIM2_IRQn;				//选择配置NVIC的TIM2线
	NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;				//指定NVIC线路使能
	NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 2;	//指定NVIC线路的抢占优先级为2
	NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;			//指定NVIC线路的响应优先级为1
	NVIC_Init(&NVIC_InitStructure);								//将结构体变量交给NVIC_Init，配置NVIC外设
	
	/*TIM使能*/
	TIM_Cmd(TIM2, ENABLE);			//使能TIM2，定时器开始运行
}
```

```c
#ifndef __TIMER_H
#define __TIMER_H

#endif
```

### 5.3 main.c（官方 `User\main.c` 原文）

```c
#include "stm32f10x.h"                  // Device header
#include "Delay.h"
#include "OLED.h"
#include "Timer.h"
#include "Encoder.h"

int16_t Speed;			//定义速度变量

int main(void)
{
	/*模块初始化*/
	OLED_Init();		//OLED初始化
	Timer_Init();		//定时器初始化
	Encoder_Init();		//编码器初始化
	
	/*显示静态字符串*/
	OLED_ShowString(1, 1, "Speed:");		//1行1列显示字符串Speed:
	
	while (1)
	{
		OLED_ShowSignedNum(1, 7, Speed, 5);	//不断刷新显示编码器测得的最新速度
	}
}

/**
  * 函    数：TIM2中断函数
  * 参    数：无
  * 返 回 值：无
  * 注意事项：此函数为中断函数，无需调用，中断触发后自动执行
  *           函数名为预留的指定名称，可以从启动文件复制
  *           请确保函数名正确，不能有任何差异，否则中断函数将不能进入
  */
void TIM2_IRQHandler(void)
{
	if (TIM_GetITStatus(TIM2, TIM_IT_Update) == SET)		//判断是否是TIM2的更新事件触发的中断
	{
		Speed = Encoder_Get();								//每隔固定时间段读取一次编码器计数增量值，即为速度值
		TIM_ClearITPendingBit(TIM2, TIM_IT_Update);			//清除TIM2更新事件的中断标志位
															//中断标志位必须清除
															//否则中断将连续不断地触发，导致主程序卡死
	}
}
```

现象：

- **正转**：`Speed` 显示**正数**，转得越快数值越大；
- **反转**：`Speed` 显示**负数**；
- **停止**：数值回到 **0**；
- 每 1 秒刷新一次，数值大小与转速成正比。

> [!tip] 本集显示的是"每秒增量"，不一定是 r/min
> 例程里 `Speed` 直接就是 `Encoder_Get()` 的返回值，单位是"**计数 / 秒**"，它和真实转速只差一个常数倍数。要显示 r/min，把它按第 4 节的公式换算一下即可。

> [!note] 想刷新快一点怎么办
> 把 TIM2 的闸门时间改短（比如 100 ms），OLED 就能每 100 ms 刷一次，看着更"跟手"。但代价是**闸门内数到的 ΔCNT 变小，量化误差（±1 个计数）占比变大，速度显示会更抖**。
>
> 这是测频法的固有取舍：**刷新率 ↔ 分辨率**，只能二选一或折中。

## 6 位置测量 vs 速度测量

同样一个 CNT，两种测量对它做的事情**正好相反**。这是最容易写错的地方：

| | 测位置（position） | 测速度（speed） |
| --- | --- | --- |
| 目的 | 转了多少格 / 转到了哪个角度 | 转得有多快 |
| 读法 | 直接读 CNT，**绝对不清零** | 每隔固定闸门时间读一次 CNT，**读完立刻清零** |
| 读到的量 | 从开机（或上次手动清零）起的**累计值** | 该段时间内的**增量 ΔCNT** |
| 结果性质 | 绝对值，掉电/复位即归零 | 相对值，只反映这一段时间 |
| 方向 | 看 CNT 的正负（相对初始位置） | 看 ΔCNT 的正负 |
| 对应代码 | `TIM_GetCounter(TIM3)` | `Encoder_Get()` |

```text
测位置：CNT 一直累加，不清零
        0 ──► 137 ──► 402 ──► 1108 ──► ...      （绝对位置）

测速度：每 T 秒读一次就清零
        0 ──► 220 │ 0 ──► -180 │ 0 ──► 430 │ ...  （每段的增量）
```

**核心区别一句话：清零会丢掉绝对位置，所以测位置绝不清零，测速度必须清零。**

### 6.1 两个都要怎么办

如果既要知道位置、又要知道速度，**只用一个 CNT 寄存器是做不到的**，因为"清零"这个动作本身就销毁了位置信息。两个办法：

**办法一：软件累加（推荐）。** 速度照常由 `Encoder_Get()` 取增量，位置在外层把增量攒起来：

```c
int32_t Position;													//累计位置，用32位防止长时间累加溢出
int16_t Speed;

void TIM2_IRQHandler(void)
{
	if (TIM_GetITStatus(TIM2, TIM_IT_Update) == SET)
	{
		Speed = Encoder_Get();										//取本段增量（读后已清零）
		Position += Speed;											//增量累加，得到累计位置
		TIM_ClearITPendingBit(TIM2, TIM_IT_Update);
	}
}
```

**办法二：不清零，用软件做差分。** 编码器接口照常累计，永不清零，位置就是 CNT 本身；速度则每个闸门时间算一次差值：

```c
int16_t Speed;
uint16_t Cnt_Last;													//上一次读到的CNT

void TIM2_IRQHandler(void)
{
	if (TIM_GetITStatus(TIM2, TIM_IT_Update) == SET)
	{
		uint16_t Cnt_Now = TIM_GetCounter(TIM3);					//本次读到的CNT（不清零）
		/* 直接相减再强转int16_t，回绕会被补码自动处理，前提是|差值| < 32768 */
		Speed = (int16_t)(Cnt_Now - Cnt_Last);						//两次读数之差就是增量
		Cnt_Last = Cnt_Now;											//保存本次读数，供下次做差
		TIM_ClearITPendingBit(TIM2, TIM_IT_Update);
	}
}
```

这样位置和速度同源，但要自己维护 `Cnt_Last`，而且**必须保证两次读数的差小于 32768**，否则符号判断照样会错。

> [!warning] `Position` 一定要用 `int32_t`
> 用办法一累加位置时，`Position` 会一直增长，16 位放不下。用 `int32_t`（需要更长量程时甚至用 `int64_t`）。

## 7 易错点

- [ ] **返回类型写成 `uint16_t`** → 反转时显示 65535 附近的数，看起来像在飞转，其实是 `−1`。必须用 `int16_t`。
- [ ] **忘了 `TIM_SetCounter(TIM3, 0)`** → CNT 一直累加，闸门时间一长就回绕，读到的数完全是错的。
- [ ] **拿来测速度却不去清零**（把测位置的读法用在了测速度上）→ 读到的是累计值，速度随时间单调增长。
- [ ] **拿来测位置却清了零** → 绝对位置每次都被抹掉，只能得到增量。
- [ ] **一次闸门内 `|ΔCNT|` 超过 32767** → `int16_t` 符号翻转，正转会显示成反转。要么缩短闸门时间，要么换 32 位自己处理。
- [ ] **整数除法顺序写错**（如 `ΔCNT / 44 * 60`）→ 小数被丢掉，低速时直接算成 0。正确做法是先乘后除，或用放大 1000 倍的定点运算。
- [ ] **`ΔCNT * 1364` 时没有先转成 `int32_t`** → 16 位乘法溢出，结果乱掉。
- [ ] **在中断里刷 OLED、做浮点运算或串口打印** → 中断执行时间过长，影响其他中断。**正确做法：中断里只读值、只计算，主循环负责显示。**
- [ ] **编码器接口和闸门定时器用了同一个定时器** → 一个定时器只能干一件事。本集是 TIM3 数格子、TIM2 计时。
- [ ] **闸门时间和显示刷新时间不一致，却按闸门时间算转速** → 换算出来的转速整体差一个倍数。
- [ ] **只算了频率，忘了除以每转计数值** → 得到的是"计数/秒"而不是"转/分"，两者差 `倍频数 × PPR` 倍。
- [ ] **编码器与 MCU 没有共地，或供电电压不匹配** → 计数乱跳，速度显示成随机数。

## 8 自测

1. 闸门时间 T 为什么不能太短，也不能太长？
2. `Encoder_Get()` 为什么必须在返回前把 CNT 清零？不清零会怎样？
3. 返回值写成 `uint16_t` 会看到什么现象？为什么？
4. 1000 线（PPR = 1000）编码器、4 倍频、闸门 1 s，读回 `ΔCNT = 12000`，转速是多少 r/min？
5. 既想知道"电机转到了哪个角度"，又想知道"转多快"，代码该怎么改？
6. 为什么测速一定要另外用一个定时器（TIM2），而不能用数格子的 TIM3？

> [!success]- 参考答案
> 1. **太短**：闸门内数到的 ΔCNT 太小，±1 个计数的量化误差占比过大，速度显示抖动严重。**太长**：刷新变慢，而且 CNT 可能在闸门内就回绕（ARR = 65536 − 1，4 倍频下几万计数/秒时几秒就绕一圈），`int16_t` 也可能溢出。
> 2. 因为要的是"这段闸门时间内的**增量**"。不清零读到的是累计值，必须自己保存上一次读数再做差，还得处理 65535→0 的回绕，麻烦且容易错。
> 3. 反转时会显示 65535、65534 附近的大数（而不是 `−1`、`−2`）。因为 CNT 从 0 往下减会下溢回绕到 65535，而 `uint16_t` 无法表达负数，只有按 `int16_t` 补码解释才是负值。
> 4. 每转计数值 = `4 × 1000 = 4000`；转数 = `12000 / 4000 = 3` 转；转速 = `3 / 1 × 60 = 180 r/min`。
> 5. 速度仍然用 `Encoder_Get()` 取增量；另外定义一个 `int32_t Position`，在中断里 `Position += Speed;` 把增量累加起来，就同时得到了累计位置。注意 `Position` 必须用 32 位。
> 6. TIM3 的计数时钟已经被编码器接口托管了，它的 CNT 只跟着编码器走，**没法再用来定时**。所以闸门时间必须交给另一个独立的定时器（本集用 TIM2）来产生。
