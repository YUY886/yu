# 06-6 输入捕获测频率与占空比

> [!abstract] 这一集把 6-5 的原理变成两个能跑的工程
> **实验一**：用输入捕获 + 从模式复位，把 6-5 讲的**测周法**跑通，读出被测信号频率。
> **实验二**：用 **PWMI 模式**（PWM Input）让一根引脚同时抓上升沿和下降沿，一个周期内**同时**拿到频率和占空比。
>
> 核心公式只有两条：`FX = FC / (CCR1 + 1)`、`Duty = (CCR2 + 1) * 100 / (CCR1 + 1)`（**官方源码 `IC.c` 的原文写法，分子分母都加 1**，来由见 1.3 节）。**两个通道共用同一个 CNT**，这是占空比能直接相除的原因。
>
> 上一集 [[江协STM32 06-5 TIM输入捕获]] ｜ 章索引 [[江协STM32 06 TIM定时器（章索引）]] ｜ 下一集 [[江协STM32 06-7 TIM编码器接口]]

## 0 实验接线与总体参数

两个实验的被测信号都是**自己产出来的一路 PWM**，用杜邦线从输出引脚接到捕获引脚，形成「自产自销」的闭环：

```text
   ┌──────────── TIM2_CH1（输出比较）────────────┐
   │  PA0 ──── PWM 输出，1 kHz / 50%             │
   └───────────────────┬─────────────────────────┘
                       │  杜邦线短接
   ┌───────────────────▼─────────────────────────┐
   │  PA6 ──── TIM3_CH1（输入捕获）              │
   │  捕获时钟 FC = 1 MHz，ARR = 65535           │
   └─────────────────────────────────────────────┘
```

| 项目 | 取值 | 理由 |
| --- | --- | --- |
| 被测信号（输出） | PA0 → **TIM2_CH1** | 官方 `PWM.c`：`GPIO_Pin_0` + `GPIO_Mode_AF_PP`，TIM2_CH1 默认映射在 PA0；引脚定义表同 |
| 被测信号参数 | `PSC = 720 - 1`、`ARR = 100 - 1`、`CCR = 50` | 官方 `PWM_Init()` 写 `TIM_Prescaler = 720 - 1`、`TIM_Period = 100 - 1`，`main.c` 写 `PWM_SetCompare1(50)` |
| 捕获通道（输入） | PA6 → **TIM3_CH1** | 官方 `IC.c`：`GPIO_Pin_6` + `GPIO_Mode_IPU`；STM32F103 既定映射 TIM3_CH1 = PA6、TIM3_CH2 = PA7 |
| 捕获时钟 | `PSC = 72 - 1` → **1 MHz** | 官方 `IC.c` 原文 `TIM_Prescaler = 72 - 1`，一个计数节拍 = **1 µs**，读数直接就是微秒数 |
| 捕获量程 | `ARR = 65536 - 1` | 官方 `IC.c` 原文 `TIM_Period = 65536 - 1`，拉满，最长可测 65535 µs ≈ 65.5 ms |

> [!warning] 定时器时钟别忘了 ×2 那条规则
> TIM2/TIM3 挂在 APB1 上，APB1 是 36 MHz，但**只要 APB 预分频系数 ≠ 1，定时器时钟就是 APB 时钟的 2 倍**，所以两者拿到的都是 **72 MHz**。看到 36 MHz 就写 `PSC = 36 - 1`，捕获时钟会变成 500 kHz，所有频率读数翻倍错的离谱。

> [!warning] 官方的「1 kHz」是标称值，不是精确值
> 官方 `main.c` 注释写 `PWM频率Freq = 72M / (PSC + 1) / 100`，官方 `PWM.c` 注释写 `频率Freq = CK_PSC / (PSC + 1) / (ARR + 1)`、`占空比Duty = CCR / (ARR + 1)`。按课件《参数计算》页的公式代入官方参数（`PSC = 720 - 1`、`ARR = 100 - 1`，即除数 720 与 100）：
>
> ```text
> 频率 = 72 MHz / 720 / 100 = 1000 Hz     ✔ 官方注释口径
> 占空比 = 50 / 100 = 50%
> ```
>
> 也就是说「1 kHz」是按 `PSC + 1 = 720`、`ARR + 1 = 100` 这对整数参数算出来的**标称值**。真实频率是 72 MHz / 720 / 100 = 1000 Hz，不存在额外误差；但**换任何别的 PSC/ARR 组合时，两个除数分别是 `PSC + 1` 和 `ARR + 1`，不要漏掉后一个**。本笔记后文凡出现「被测 1 kHz」均按这个口径。

## 1 实验一：输入捕获模式测频率

### 1.1 配置要点

官方 `IC.c` 的实际调用序列（逐字核对）：

```text
① RCC 开启 TIM3 时钟（APB1）和 GPIOA 时钟（APB2）
② GPIOA_Pin_6 配置为上拉输入 IPU —— 输入捕获的引脚是「读」的，不是复用推挽输出
③ TIM_InternalClockConfig(TIM3) —— CNT 仍由内部 72 MHz 推进
④ TIM_TimeBaseInit —— PSC = 72-1（捕获时钟 1 MHz）、ARR = 65536-1
⑤ TIM_ICInit —— 只配通道 1：TIM_Channel_1、上升沿、直连、TIM_ICPSC_DIV1、滤波 0xF
⑥ TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1) —— 把 TI1FP1 选为 TRGI
⑦ TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset) —— 触发时硬件复位 CNT
⑧ TIM_Cmd(TIM3, ENABLE)
```

> [!note] 官方源码里**没有**的调用
> `6-6 输入捕获模式测频率\Hardware\IC.c` 全文 59 行，**没有调用 `TIM_SelectMasterSlaveMode()`**（函数在库里存在，本集未使用）。⑥⑦ 两步的顺序、以及 `TIM_ICInit` 与 `TIM_SelectInputTrigger` 的先后，都以官方源码为准。

几个必须说清楚的点：

- **第 ② 步的模式**：输入捕获的引脚配置为 `GPIO_Mode_IPU`（上拉输入），**不是** `GPIO_Mode_AF_PP`（复用推挽）。只有输出比较那一边才要复用推挽。写成 AF_PP 会让引脚不听外面的信号。
- **第 ⑤ 步只配了通道 1**：实验一不需要知道高电平时间，所以只配 CH1 一个通道。
- **第 ⑥ ⑦ 步是 6-5 的核心**：`TIM_SelectInputTrigger` 选触发源，`TIM_SelectSlaveMode` 选从模式操作，两者配套。加了这两行之后，**每个上升沿硬件同时完成「锁存 CNT → 复位 CNT」**，主循环里直接读 CCR1 就是一个周期的长度。

### 1.2 `IC_GetFreq()` 的推导

`CCR1` 里是「一个信号周期内跑了多少个 1 µs 的计数节拍」，所以：

```text
捕获时钟        FC = CK_PSC / (PSC + 1) = 72 MHz / 72 = 1 MHz     （1 拍 = 1 µs）
一个周期的计数值 N = TIM_GetCapture1(TIM3)                          （CCR1）
信号周期        T  = N / FC = N µs
信号频率        FX = 1 / T = FC / N
```

**官方源码（`6-6 输入捕获模式测频率\Hardware\IC.c` 第 56~59 行 / `6-7 PWMI模式测频率占空比\Hardware\IC.c` 第 57~60 行）逐字原文：**

```c
uint32_t IC_GetFreq(void)
{
	return 1000000 / (TIM_GetCapture1(TIM3) + 1);		//测周法得到频率fx = fc / N，这里不执行+1的操作也可
}
```

即官方写的是 `FX = 1000000 / (CCR1 + 1)`，并在注释里自己说明「**这里不执行+1的操作也可**」。用本集参数（被测 1 kHz）验算：

```text
N = FC / FX = 1 000 000 / 1 000 = 1000 个节拍
官方写法得到整数结果：CCR1 + 1 = 1000 → 1 000 000 / 1000 = 1000 Hz ✔
考虑 ±1 量化误差，CCR1 实测会在 998 ~ 1000 之间轻微摆动
```

### 1.3 「+1」到底加不加：结论是加

这是本节最值得较真的一处：**捕获值到底要不要 +1？**

直接给结论：**官方配套源码 `IC.c` 写的就是 `1000000 / (TIM_GetCapture1(TIM3) + 1)`，本笔记默认跟随官方。** 下面把这个 +1 的来由推一遍，免得只是照抄。

**推导**

```text
前提：从模式 = 复位模式，触发源 = TI1FP1（上升沿）

时刻 t0：第 k 个上升沿
        ├─ 硬件把此刻的 CNT 锁存进 CCR1
        └─ 硬件把 CNT 复位为 0        ← 复位模式的作用

时刻 t0 + T：第 k+1 个上升沿
        ├─ 硬件把此刻的 CNT 锁存进 CCR1
        └─ 硬件又把 CNT 复位为 0

两个边沿之间一共经过 N 个 CK_CNT 节拍（N = T / 1 µs）。
但「捕获」和「复位」发生在同一个边沿上：t0 那一拍被复位吃掉了，
所以到 t0+T 读到的 CNT 只有 N - 1。

所以：  CCR1 = N - 1
        一个周期真正的节拍数 N = CCR1 + 1
        T    = (CCR1 + 1) × 1 µs
        FX   = 1 / T = FC / (CCR1 + 1)    ← 要加 1
```

**结论：`FX = FC / (CCR1 + 1)`。**

> [!warning] 那为什么网上还有 `FC / CCR1` 的写法？
> 因为两者只差 **1 个计数**，在低频段完全看不出区别（相对误差 `1/N`），所以不少转载把它省掉了——**老师在自己代码的注释里也写了「这里不执行+1的操作也可」**。实际差多少：
>
> | `CCR1` | 不加 1 | 加 1 | 相对差 |
> | --- | --- | --- | --- |
> | 10000（100 Hz） | 100.0 Hz | 100.0 Hz | 0.01% |
> | 1000（1 kHz） | 1001 Hz | 1000 Hz | 0.1% |
> | 100（10 kHz） | 10000 Hz | 9901 Hz | 1% |
> | 10（100 kHz） | 100000 Hz | 90909 Hz | 10% |
>
> 越往高频差得越明显——而高频本来就不该用测周法。所以这个 +1 在低频段是「写对更准」，在高频段是「反正都不准」。
>
> 另外，**加 1 还顺手规避了除零**：没接信号时 `CCR1 = 0`，`FC / 0` 是要炸的。不过代码里还是显式判断一下 `ccr == 0` 更稳妥。

> [!tip] 30 秒自己验一遍
> 让 TIM2 输出一路已知的 1 kHz PWM，捕获时钟设成 1 MHz，**看一眼 CCR1 读到的是 999 还是 1000**：
> - 读到 **999** → `999 + 1 = 1000`，正好是一个周期的节拍数，验证了 +1；
> - 读到 **1000** → 说明在这个频率点上多了一拍，属正常的 ±1 量化摆动。
>
> 这个实验比记结论有用得多。

**本笔记的取舍**：正文与代码一律按**官方 `IC.c` 原文**（**加 1**）写。官方源码里**没有**任何宏开关或条件编译，本笔记为了最小改动也不再保留上一版自造的开关。

### 1.4 `IC_GetFreq()` 实现（官方 `IC.c` 原文）

```c
/**
  * 函    数：获取输入捕获的频率
  * 参    数：无
  * 返 回 值：捕获得到的频率
  */
uint32_t IC_GetFreq(void)
{
	return 1000000 / (TIM_GetCapture1(TIM3) + 1);		//测周法得到频率fx = fc / N，这里不执行+1的操作也可
}
```

> [!warning] 官方源码没有做除零保护
> 官方函数体只有一行，**没有 `ccr == 0` 的判断**（6-6 与 6-7 两个工程都一样）。捕获时钟常数 `1000000` 是硬编码的字面量，官方**没有** `IC_CAPTURE_CLK` 这种宏；改 `PSC` 时必须手工改这个字面量。
> 本笔记上一版加的 `IC_CAPTURE_CLK` 宏与 `IC_FREQ_USE_PLUS_ONE` 开关**不是官方写法**，已删除。

## 2 实验二：PWMI 模式测频率和占空比

实验一只能拿到**周期**，想知道**高电平时间**还得再抓一次下降沿。PWMI 模式（PWM Input Mode）就是用**一根引脚 + 两个通道**同时抓两种边沿。

### 2.1 PWMI 的原理

```text
   被测 PWM：  ┌───────┐       ┌───────┐
              │       │       │       │
    ──────────┘       └───────┘       └──────
              ↑       ↑       ↑       ↑
              │       │       │       │
         CH1 上升沿   下降沿   上升沿   下降沿
         （直连）      ↑
                  CH2 下降沿（交叉）

   CC1S = 01 直连 → IC1 ← TI1FP1（上升沿）
   CC2S = 10 交叉 → IC2 ← TI1FP2（下降沿，来自同一根 PA6）
```

- **CH1**：直连（DirectTI）+ **上升沿** → 从模式复位 → CCR1 = **一个完整周期**的计数值。
- **CH2**：交叉（IndirectTI）+ **下降沿** → CCR2 = **从上升沿到下降沿**的计数值 = **高电平时间**。
- 两个通道**接在同一根引脚 PA6 上**（TI1FP1 和 TI1FP2 都源自 TI1），所以**硬件上只用一个引脚**。

### 2.2 `TIM_PWMIConfig()` 一次配两个通道

ST 的标准外设库提供了一个便捷函数：

```c
/* 只需要描述「通道 1」的配置，函数会把配对通道自动配成相反的参数：
   极性取反（上升沿 ↔ 下降沿）、信号选择取反（直连 ↔ 交叉） */
TIM_PWMIConfig(TIM3, &TIM_ICInitStructure);
```

行为总结：

| 你填的参数（TIM_Channel_1） | `TIM_PWMIConfig` 自动补的另一半（CH2） |
| --- | --- |
| `TIM_ICPolarity_Rising` | `TIM_ICPolarity_Falling` |
| `TIM_ICSelection_DirectTI` | `TIM_ICSelection_IndirectTI` |
| `TIM_ICFilter` | 同上（滤波参数相同） |
| `TIM_ICPrescaler` | 同上 |

> [!warning] 三个必须注意的地方
> 1. **标准库的实现只判断「是不是 `TIM_Channel_1`」，不是「CH1 或 CH2 二选一」**。查 `stm32f10x_tim.c` 的 `TIM_PWMIConfig()`（第 654~702 行）：只有一个 `if (TIM_ICInitStruct->TIM_Channel == TIM_Channel_1)`，命中就配「TI1 用你填的参数、TI2 用相反参数」，否则走 `else` 配「TI2 用你填的参数、TI1 用相反参数」。所以填 `TIM_Channel_2` 是**把 TI2 当主通道**，会得到与实验二相反的通道分工——不是报错，而是结果相反，不要踩。填 `TIM_Channel_3` / `TIM_Channel_4` 会掉进同一个 `else`，把 TI2/TI1 配一遍，与你想要的 CH3/CH4 完全无关。**官方填入的是 `TIM_Channel_1`。**
> 2. **`TIM_PWMIConfig()` 取代 `TIM_ICInit()`**，不要两个都调——`TIM_PWMIConfig()` 内部直接调用 `TI1_Config()` / `TI2_Config()` 完成两个通道的配置，之后再调 `TIM_ICInit()` 会把其中一个通道覆盖掉。官方 `IC.c` 里**只有 `TIM_PWMIConfig()`，没有 `TIM_ICInit()`**。
> 3. **触发源仍然要显式指定**：`TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1)` 和 `TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset)` 一样不能少。`TIM_PWMIConfig()` 只管通道，不管从模式。

### 2.3 `IC_GetFreq()` 与 `IC_GetDuty()` 的推导

```text
两个通道共用同一个 CNT、同一个捕获时钟 FC，于是：

    CCR1 = 一个完整周期内的计数值   = T       × FC
    CCR2 = 高电平时间内的计数值     = T_high  × FC

频率：  FX   = FC / (CCR1 + 1)                 （和实验一完全一样）
占空比：Duty = T_high / T = (CCR2 / FC) / (CCR1 / FC)
             = CCR2 / CCR1                    ← FC 被约掉了
             官方写法在分子分母上同时加 1：Duty = (CCR2 + 1) * 100 / (CCR1 + 1)
```

**为什么占空比可以直接 `CCR2 / CCR1`？**

- 两个计数值是**同一把尺子**量出来的：同一个 CNT、同一个 PSC、同一个捕获时钟。
- 相除时 `FC` 被约掉，所以**占空比与 PSC 取值、与捕获时钟频率完全无关**——改 PSC 只影响频率的换算常数，不影响占空比。这一点很适合用来验证代码：如果改 PSC 之后占空比读数变了，那一定是别的地方错了。

**关于 `(CCR2 + 1) * 100 / (CCR1 + 1)` 的写法**：官方 `IC.c` 的占空比函数就是分子分母**同时加 1**。两者误差**绝大部分互相抵消**（`(M+1)/(N+1)` 与 `M/N` 在 `N` 较大时几乎相等），所以**「加不加 1」对占空比几乎没有影响，主要影响频率换算**。官方注释同样写着「这里不执行+1的操作也可」。

### 2.4 实现（官方 `IC.c` 原文）

```c
/**
  * 函    数：获取输入捕获的频率
  * 参    数：无
  * 返 回 值：捕获得到的频率
  */
uint32_t IC_GetFreq(void)
{
	return 1000000 / (TIM_GetCapture1(TIM3) + 1);		//测周法得到频率fx = fc / N，这里不执行+1的操作也可
}

/**
  * 函    数：获取输入捕获的占空比
  * 参    数：无
  * 返 回 值：捕获得到的占空比
  */
uint32_t IC_GetDuty(void)
{
	return (TIM_GetCapture2(TIM3) + 1) * 100 / (TIM_GetCapture1(TIM3) + 1);	//占空比Duty = CCR2 / CCR1 * 100，这里不执行+1的操作也可
}
```

> [!warning] 注意官方写法里的运算顺序
> 官方是 `(CCR2 + 1) * 100 / (CCR1 + 1)`：**先乘 100 再除**，和本笔记上一版的建议一致。但要注意 `(CCR2 + 1) * 100` 是在 `int` 上算的——`CCR2` 最大 65535，`(65535 + 1) * 100 = 6553600`，仍在 32 位以内，**不会溢出**（若把 100 改成更大的放大倍数就要自己当心）。另外官方**没有** `period == 0` 的除零判断。

> [!tip] 除数永远放最后
> `CCR2 * 100 / CCR1` 和 `CCR2 / CCR1 * 100` 在整数运算里天差地别：后者会先做整除，`50/100 = 0`，占空比永远显示 0。C 语言的整数除法是**截断**而不是四舍五入。

## 3 PWMI 结构说明

把两个通道画在一起，能看清「共用 CNT」这件事：

```text
                  ┌────────────────────────── TIM3 ──────────────────────────┐
                  │                                                          │
    PA6 ──► TI1 ──┼─┬─►[ 滤波 ]─►[ 上升沿检测 ]──► TI1FP1 ──┬─►[ 直连 ]─►┌─────────┐
   （一根线）      │ │   ICF=0xF      CC1P=0                  │   CC1S=01 │ CCR1    │
                  │ │                                        │           │ 整周期   │
                  │ │                                        │           └────┬────┘
                  │ │                                        │                │ CC1IF
                  │ │                                        │                │
                  │ │                                        └──►[ 从模式 ]     │
                  │ │                                              TRGI=TI1FP1  │
                  │ │                                              SMS = 复位    │
                  │ │                                                   │        │
                  │ │                                                   ▼        │
                  │ │                                          CNT 每个上升沿清零   │
                  │ │                                                   ▲        │
                  │ │                                              [ PSC ]       │
                  │ │                                                   ▲        │
                  │ │                                              CK_PSC 72MHz   │
                  │ │                                                            │
                  │ └─►[ 滤波 ]─►[ 下降沿检测 ]──► TI1FP2 ──┬─►[ 交叉 ]─►┌─────────┐
                  │       ICF=0xF      CC2P=1               │   CC2S=10 │ CCR2    │
                  │                                         └───────────│ 高电平   │
                  │                                                     └────┬────┘
                  │                                                          │ CC2IF
                  └───────────────────────────────────────────────────────────────┘

   主循环读：  FX   = 1000000 / (TIM_GetCapture1(TIM3) + 1)
               Duty = (TIM_GetCapture2(TIM3) + 1) * 100 / (TIM_GetCapture1(TIM3) + 1)
```

**两个通道共用同一个 CNT 基准**，这句话是 PWMI 能成立的全部理由：

- 只有共用 CNT，`CCR2 / CCR1` 才是一把尺子量出来的两个数，相除才等于时间之比。
- 如果两个通道用两个不同的定时器、不同的 PSC，那么相除必须先各自换算成时间再相除，做不了这么简洁。
- 也正因为共用 CNT，两个通道的 `ARR` 溢出条件相同——量程问题要么一起解决，要么一起出问题。

## 5 测周法的适用范围与误差

测周法用起来爽，但它的准确度和被测频率是**反相关**的：

```text
        ΔFX / FX = 1 / CCR1        （±1 个计数带来的相对误差）

   CCR1 越大（信号越慢）→ 相对误差越小
   CCR1 越小（信号越快）→ 相对误差越大
```

以 `FC = 1 MHz`、`ARR = 65535` 为例：

| 被测信号频率 | 周期 | `CCR1` | ±1 计数引起的相对误差 | 能不能用 |
| --- | --- | --- | --- | --- |
| 10 Hz | 100 ms | 100000 | — | **超量程**，CNT 溢出 |
| 100 Hz | 10 ms | 10000 | 0.01% | 很好 |
| 1 kHz | 1 ms | 1000 | 0.1% | 好（≈中介频率） |
| 10 kHz | 100 µs | 100 | 1% | 勉强 |
| 100 kHz | 10 µs | 10 | 10% | 不能用 |
| 1 MHz | 1 µs | 1 | 100% | 完全不能用 |

三个实用结论：

1. **超量程怎么办**：被测周期必须小于 `(ARR + 1) × 一个计数节拍的时间`。`ARR` 已经拉满时，只能**加大 PSC 降低捕获时钟**——例如 `PSC = 720 - 1`（FC = 100 kHz），量程就从 65.5 ms 扩到 655 ms。**代价是分辨率变粗（10 µs/拍），而且所有换算常数要同步改**（官方 `IC.c` 里那个字面量 `1000000` 要改成 `100000`；本笔记上一版自造的 `IC_CAPTURE_CLK` 宏已删除，因为官方没有这个宏）。
2. **高频测不准怎么办**：按 6-5 的中介频率判据，`FC = 1 MHz`、闸门 `t = 1 s` 时 `FM = 1 kHz`。**1 kHz 以上就应该改走测频法**，而不是硬调测周法的 PSC——减小 PSC 会同时减小 `CCR1`，相对误差反而更大。
3. **测频法在哪学**：就在下一集。**6-7 编码器接口本质就是测频法**——它让外部脉冲直接驱动 CNT 加减，本质是「在一段固定时间里数了多少个脉冲」，和测周法正好是一对镜像。

> [!warning] 分辨率与量程是一对矛盾
> 捕获时钟 `FC` 越大：分辨率越细（好），但量程越小（短周期/低频测不了）。
> 捕获时钟 `FC` 越小：量程越大（好），但分辨率越粗（高频测不准）。
> 这个矛盾在 ADC、PWM 里也反复出现——**任何测量系统都要先明确「我要测的量程有多大、分辨率要多细」，再回头选时钟。**

## 6 易错点

- [ ] **GPIO 模式写错**：输入捕获要 `GPIO_Mode_IPU`（上拉输入），写成 `GPIO_Mode_AF_PP` 是输出比较那边的写法，引脚不会听外面的信号。
- [ ] **忘了从模式复位**（`TIM_SlaveMode_Reset`）→ CCR1 一路累加，读数一次比一次大，频率算出来一次比一次小。
- [ ] **忘了 `TIM_SelectInputTrigger()`** → 从模式没有触发源，复位永远不发生。
- [ ] **公式里的常数和 `PSC` 不一致**：官方 `IC.c` 把捕获时钟硬编码成字面量 `1000000`，它对应 `PSC = 72-1`。改成 `720-1` 就必须把它改成 `100000`。这是最容易「程序能跑但读数全错」的地方。
- [ ] **`TIM_PWMIConfig()` 填了 `TIM_Channel_3` / `TIM_Channel_4`** → 标准库实现里只判断「是不是 `TIM_Channel_1`」，填 3/4 会掉进 `else` 分支，把 TI2/TI1 配一遍，与 CH3/CH4 毫无关系。
- [ ] **`TIM_PWMIConfig()` 和 `TIM_ICInit()` 都调了** → `TIM_PWMIConfig()` 内部已配好两个通道，后调的 `TIM_ICInit()` 会覆盖其中一个。官方 `IC.c` 只调 `TIM_PWMIConfig()`。
- [ ] **占空比写成 `CCR2 / CCR1 * 100`** → 整数除法先截断，`50/100 = 0`，占空比永远显示 0。必须**先乘后除**：官方原文 `(CCR2 + 1) * 100 / (CCR1 + 1)`。
- [ ] **没接信号直接读** → `CCR1 = 0`，`1000000 / (0 + 1) = 1000000`，读数会是一个荒谬的大频率（官方**没有**除零保护，加 1 只是让除数不为 0，并不能识别「没接信号」）。
- [ ] **滤波 `ICF = 0xF` 用在很高频的信号上** → 边沿被滤掉，读数乱跳。滤波强度要跟信号频率匹配。
- [ ] **被测信号周期超过 `ARR` 量程** → CNT 溢出回绕，读数时大时小。加大 PSC 扩量程。
- [ ] **以为改 PSC 会影响占空比** → 两个通道共用同一个时钟，`CCR2/CCR1` 把时钟约掉了，占空比与 PSC 无关。反过来，这正好是个自检手段。
- [ ] **在被测信号和捕获引脚之间忘了连线** → PA0 和 PA6 必须用杜邦线短接（或直接接外部信号源），否则读到的是悬空引脚的噪声。

## 7 自测

1. 捕获时钟 `FC = 1 MHz`，`CCR1` 读到 **999**，被测频率是多少？如果按「加 1」的写法算又是多少？两者相差百分之几？
2. PWMI 模式下 CH1 和 CH2 各自被配置成什么极性、什么信号选择？为什么只接一根 PA6 就够了？
3. 占空比公式 `Duty = CCR2 / CCR1` 为什么**与 PSC 取值无关**？这个性质能用来做什么自检？
4. 把占空比计算写成 `TIM_GetCapture2(TIM3) / TIM_GetCapture1(TIM3) * 100` 会得到什么？为什么？
5. 想测 **100 kHz** 的信号，用本集的测周法配置能测准吗？应该怎么做？

> [!success]- 参考答案
> 1. 加 1（官方写法）：`1 000 000 / (999 + 1) = 1000 Hz` ✔；不加 1：`1 000 000 / 999 ≈ 1001 Hz`。两者相差 `1/1000 = 0.1%`，也就是 1 个计数的量级，和 ±1 量化误差同阶。官方 `IC.c` 用的是加 1。
> 2. CH1 配成**上升沿 + 直连**（`CC1S = 01`，取 TI1FP1），负责测整周期；CH2 被 `TIM_PWMIConfig()` 自动配成**下降沿 + 交叉**（`CC2S = 10`，取 TI1FP2），负责测高电平时间。因为 TI1FP1 和 TI1FP2 都源自同一个 TI1（即 PA6），所以一根引脚就够了。
> 3. 因为 CCR1 和 CCR2 是**同一个 CNT、同一个捕获时钟**量出来的，相除时 `FC` 被约掉：`(T_high·FC)/(T·FC) = T_high/T`。自检用法：改 PWM 的 PSC（被测信号频率变了）之后，**占空比读数应该不变**；如果变了，说明占空比的算法或通道配置有问题。
> 4. 得到 **0**。C 语言的整数除法会先算 `CCR2 / CCR1`，`50 / 100 = 0`，再乘 100 还是 0。必须**先乘后除**：官方原文 `(CCR2 + 1) * 100 / (CCR1 + 1)`。
> 5. 不能。`FC = 1 MHz` 时 100 kHz 信号的 `CCR1 = 10`，±1 计数就是 **10% 的误差**，而 `FM = 1 kHz` 说明 1 kHz 以上就该换方法了。正确做法是改用**测频法**（固定闸门时间数边沿个数），也就是 6-8 编码器接口测速那条路线（6-7 是理论集，没有工程）。
