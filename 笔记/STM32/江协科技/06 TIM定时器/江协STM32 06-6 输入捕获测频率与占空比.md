# 06-6 输入捕获测频率与占空比

> [!abstract] 这一集把 6-5 的原理变成两个能跑的工程
> **实验一**：用输入捕获 + 从模式复位，把 6-5 讲的**测周法**跑通，读出被测信号频率。
> **实验二**：用 **PWMI 模式**（PWM Input）让一根引脚同时抓上升沿和下降沿，一个周期内**同时**拿到频率和占空比。
>
> 核心公式只有两条：`FX = FC / (CCR1 + 1)`、`Duty = (CCR2 + 1) / (CCR1 + 1)`（**课程原版的加 1 写法**，来由见 1.3 节）。**两个通道共用同一个 CNT**，这是占空比能直接相除的原因。
>
> 上一集 [[江协STM32 06-5 TIM输入捕获]] ｜ 章索引 [[江协STM32 06 TIM定时器（章索引）]] ｜ 下一集 [[江协STM32 06-7 TIM编码器接口]]

## 0 实验接线与总体参数

两个实验的被测信号都是**自己产出来的一路 PWM**，用杜邦线从输出引脚接到捕获引脚，形成「自产自销」的闭环：

```text
   ┌──────────── TIM2_CH1（输出比较）────────────┐
   │  PA0 ──── PWM 输出，1 kHz / 50%             │
   └───────────────────┬─────────────────────────┘
                       │  杜邦线短接
   ┌───────────────────▼─────────────────────────┐
   │  PA6 ──── TIM3_CH1（输入捕获）              │
   │  捕获时钟 FC = 1 MHz，ARR = 65535           │
   └─────────────────────────────────────────────┘
```

| 项目 | 取值 | 理由 |
| --- | --- | --- |
| 被测信号（输出） | PA0 → **TIM2_CH1** | 6-4 用过，标准外设库里 TIM2_CH1 默认映射在 PA0 |
| 被测信号参数 | `PSC = 720 - 1`、`ARR = 100 - 1`、`CCR = 50` | `72 MHz / 720 / 100 = 1 kHz`，占空比 `50/100 = 50%` |
| 捕获通道（输入） | PA6 → **TIM3_CH1** | STM32F103 既定映射：TIM3_CH1 = PA6、TIM3_CH2 = PA7 |
| 捕获时钟 | `PSC = 72 - 1` → **1 MHz** | 一个计数节拍 = **1 µs**，读数直接就是微秒数 |
| 捕获量程 | `ARR = 65536 - 1` | 拉满，最长可测 65535 µs ≈ 65.5 ms |

> [!warning] 定时器时钟别忘了 ×2 那条规则
> TIM2/TIM3 挂在 APB1 上，APB1 是 36 MHz，但**只要 APB 预分频系数 ≠ 1，定时器时钟就是 APB 时钟的 2 倍**，所以两者拿到的都是 **72 MHz**。看到 36 MHz 就写 `PSC = 36 - 1`，捕获时钟会变成 500 kHz，所有频率读数翻倍错的离谱。

## 1 实验一：输入捕获模式测频率

### 1.1 配置要点

```text
① RCC 开启 TIM3 时钟（APB1）和 GPIOA 时钟（APB2）
② GPIOA_Pin_6 配置为上拉输入 IPU —— 输入捕获的引脚是「读」的，不是复用推挽输出
③ TIM_InternalClockConfig(TIM3) —— CNT 仍由内部 72 MHz 推进
④ TIM_TimeBaseInit —— PSC = 72-1（捕获时钟 1 MHz）、ARR = 65536-1
⑤ TIM_ICInit —— 只配通道 1：上升沿、直连、不分频、滤波 0xF
⑥ TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1) —— 把 TI1FP1 选为 TRGI
⑦ TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset) —— 触发时硬件复位 CNT
⑧ TIM_Cmd(TIM3, ENABLE)
```

几个必须说清楚的点：

- **第 ② 步的模式**：输入捕获的引脚配置为 `GPIO_Mode_IPU`（上拉输入），**不是** `GPIO_Mode_AF_PP`（复用推挽）。只有输出比较那一边才要复用推挽。写成 AF_PP 会让引脚不听外面的信号。
- **第 ⑤ 步只配了通道 1**：实验一不需要知道高电平时间，所以只配 CH1 一个通道。
- **第 ⑥ ⑦ 步是 6-5 的核心**：`TIM_SelectInputTrigger` 选触发源，`TIM_SelectSlaveMode` 选从模式操作，两者配套。加了这两行之后，**每个上升沿硬件同时完成「锁存 CNT → 复位 CNT」**，主循环里直接读 CCR1 就是一个周期的长度。

### 1.2 `IC_GetFreq()` 的推导

`CCR1` 里是「一个信号周期内跑了多少个 1 µs 的计数节拍」，所以：

```text
捕获时钟        FC = CK_PSC / (PSC + 1) = 72 MHz / 72 = 1 MHz     （1 拍 = 1 µs）
一个周期的计数值 N = TIM_GetCapture1(TIM3)                          （CCR1）
信号周期        T  = N / FC = N µs
信号频率        FX = 1 / T = FC / N = 1000000 / CCR1
```

用本集参数（被测 1 kHz）验算：

```text
N = FC / FX = 1 000 000 / 1 000 = 1000 个节拍
即 CCR1 应该读到 999（因为 FX = FC / (CCR1 + 1)，详见 1.3 节）
考虑 ±1 量化误差，实测会在 998 ~ 1000 之间轻微摆动
```

### 1.3 「+1」到底加不加：结论是加

这是本节最值得较真的一处：**捕获值到底要不要 +1？**

直接给结论：**江协原版代码写的就是 `1000000 / (TIM_GetCapture1(TIM3) + 1)`，本笔记默认跟随课程。** 下面把这个 +1 的来由推一遍，免得只是照抄。

**推导**

```text
前提：从模式 = 复位模式，触发源 = TI1FP1（上升沿）

时刻 t0：第 k 个上升沿
        ├─ 硬件把此刻的 CNT 锁存进 CCR1
        └─ 硬件把 CNT 复位为 0        ← 复位模式的作用

时刻 t0 + T：第 k+1 个上升沿
        ├─ 硬件把此刻的 CNT 锁存进 CCR1
        └─ 硬件又把 CNT 复位为 0

两个边沿之间一共经过 N 个 CK_CNT 节拍（N = T / 1 µs）。
但「捕获」和「复位」发生在同一个边沿上：t0 那一拍被复位吃掉了，
所以到 t0+T 读到的 CNT 只有 N - 1。

所以：  CCR1 = N - 1
        一个周期真正的节拍数 N = CCR1 + 1
        T    = (CCR1 + 1) × 1 µs
        FX   = 1 / T = FC / (CCR1 + 1)    ← 要加 1
```

**结论：`FX = FC / (CCR1 + 1)`。**

> [!warning] 那为什么网上还有 `FC / CCR1` 的写法？
> 因为两者只差 **1 个计数**，在低频段完全看不出区别（相对误差 `1/N`），所以不少转载把它省掉了。实际差多少：
>
> | `CCR1` | 不加 1 | 加 1 | 相对差 |
> | --- | --- | --- | --- |
> | 10000（100 Hz） | 100.0 Hz | 100.0 Hz | 0.01% |
> | 1000（1 kHz） | 1001 Hz | 1000 Hz | 0.1% |
> | 100（10 kHz） | 10000 Hz | 9901 Hz | 1% |
> | 10（100 kHz） | 100000 Hz | 90909 Hz | 10% |
>
> 越往高频差得越明显——而高频本来就不该用测周法。所以这个 +1 在低频段是「写对更准」，在高频段是「反正都不准」。
>
> 另外，**加 1 还顺手规避了除零**：没接信号时 `CCR1 = 0`，`FC / 0` 是要炸的。不过代码里还是显式判断一下 `ccr == 0` 更稳妥。

> [!tip] 30 秒自己验一遍
> 让 TIM2 输出一路已知的 1 kHz PWM，捕获时钟设成 1 MHz，**看一眼 CCR1 读到的是 999 还是 1000**：
> - 读到 **999** → `999 + 1 = 1000`，正好是一个周期的节拍数，验证了 +1；
> - 读到 **1000** → 说明在这个频率点上少算了一拍，属正常的 ±1 量化摆动。
>
> 这个实验比记结论有用得多。

**本笔记的取舍**：正文按课程写法（**加 1**）写，代码里留一个宏开关，想对照另一种写法随时可切。

### 1.4 `IC_GetFreq()` 实现

```c
/* 捕获时钟频率 FC = CK_PSC / (PSC + 1) = 72MHz / 72 = 1MHz
   注意：这个常数必须和 IC_Init() 里的 PSC 保持一致，改 PSC 就要改它 */
#define IC_CAPTURE_CLK        1000000UL

/* 频率公式是否使用 (CCR + 1) 的写法：
   1 = 课程原版写法 FX = FC / (CCR + 1)     （默认）
   0 = 简化写法   FX = FC / CCR
   两者只差 1 个计数，低频段无可见差别，详见正文 1.3 节 */
#define IC_FREQ_USE_PLUS_ONE  1

/**
  * 获取被测信号频率，单位 Hz
  * 依据：CCR1 中保存着一个完整周期内的计数节拍数
  */
uint32_t IC_GetFreq(void)
{
	uint16_t ccr = TIM_GetCapture1(TIM3);

	if (ccr == 0)          /* 还没捕获到边沿（没接信号），直接返回 0，避免除零 */
	{
		return 0;
	}

#if IC_FREQ_USE_PLUS_ONE
	return IC_CAPTURE_CLK / (ccr + 1);
#else
	return IC_CAPTURE_CLK / ccr;
#endif
}
```

## 2 实验二：PWMI 模式测频率和占空比

实验一只能拿到**周期**，想知道**高电平时间**还得再抓一次下降沿。PWMI 模式（PWM Input Mode）就是用**一根引脚 + 两个通道**同时抓两种边沿。

### 2.1 PWMI 的原理

```text
   被测 PWM：  ┌───────┐       ┌───────┐
              │       │       │       │
    ──────────┘       └───────┘       └──────
              ↑       ↑       ↑       ↑
              │       │       │       │
         CH1 上升沿   下降沿   上升沿   下降沿
         （直连）      ↑
                  CH2 下降沿（交叉）

   CC1S = 01 直连 → IC1 ← TI1FP1（上升沿）
   CC2S = 10 交叉 → IC2 ← TI1FP2（下降沿，来自同一根 PA6）
```

- **CH1**：直连（DirectTI）+ **上升沿** → 从模式复位 → CCR1 = **一个完整周期**的计数值。
- **CH2**：交叉（IndirectTI）+ **下降沿** → CCR2 = **从上升沿到下降沿**的计数值 = **高电平时间**。
- 两个通道**接在同一根引脚 PA6 上**（TI1FP1 和 TI1FP2 都源自 TI1），所以**硬件上只用一个引脚**。

### 2.2 `TIM_PWMIConfig()` 一次配两个通道

ST 的标准外设库提供了一个便捷函数：

```c
/* 只需要描述「通道 1」的配置，函数会把配对通道自动配成相反的参数：
   极性取反（上升沿 ↔ 下降沿）、信号选择取反（直连 ↔ 交叉） */
TIM_PWMIConfig(TIM3, &TIM_ICInitStructure);
```

行为总结：

| 你填的参数（TIM_Channel_1） | `TIM_PWMIConfig` 自动补的另一半（CH2） |
| --- | --- |
| `TIM_ICPolarity_Rising` | `TIM_ICPolarity_Falling` |
| `TIM_ICSelection_DirectTI` | `TIM_ICSelection_IndirectTI` |
| `TIM_ICFilter` | 同上（滤波参数相同） |
| `TIM_ICPrescaler` | 同上 |

> [!warning] 三个必须注意的地方
> 1. **通道号只能填 `TIM_Channel_1` 或 `TIM_Channel_2`**。标准库里的 `TIM_PWMIConfig()` 只实现了「CH1 ↔ CH2 配对」这一个分支，填 `TIM_Channel_3` / `TIM_Channel_4` 会走到错误的 else 分支里，配置结果不符合预期。
> 2. **`TIM_PWMIConfig()` 取代 `TIM_ICInit()`**，不要两个都调——否则后调的那个会把前一个的配置覆盖掉一半。
> 3. **触发源仍然要显式指定**：`TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1)` 和 `TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset)` 一样不能少。`TIM_PWMIConfig()` 只管通道，不管从模式。

### 2.3 `IC_GetFreq()` 与 `IC_GetDuty()` 的推导

```text
两个通道共用同一个 CNT、同一个捕获时钟 FC，于是：

    CCR1 = 一个完整周期内的计数值   = T       × FC
    CCR2 = 高电平时间内的计数值     = T_high  × FC

频率：  FX   = FC / CCR1                       （和实验一完全一样）
占空比：Duty = T_high / T = (CCR2 / FC) / (CCR1 / FC)
             = CCR2 / CCR1                    ← FC 被约掉了
```

**为什么占空比可以直接 `CCR2 / CCR1`？**

- 两个计数值是**同一把尺子**量出来的：同一个 CNT、同一个 PSC、同一个捕获时钟。
- 相除时 `FC` 被约掉，所以**占空比与 PSC 取值、与捕获时钟频率完全无关**——改 PSC 只影响频率的换算常数，不影响占空比。这一点很适合用来验证代码：如果改 PSC 之后占空比读数变了，那一定是别的地方错了。

**关于 `(CCR2 + 1) / (CCR1 + 1)` 的写法**：课程原版的占空比函数就是分子分母**同时加 1**。两者误差**绝大部分互相抵消**（`(M+1)/(N+1)` 与 `M/N` 在 `N` 较大时几乎相等），所以**「加不加 1」对占空比几乎没有影响，主要影响频率换算**。

### 2.4 实现

```c
/**
  * 获取被测信号频率，单位 Hz
  * PWMI 模式下 CH1 仍然负责测周期，所以实现和实验一相同
  */
uint32_t IC_GetFreq(void)
{
	uint16_t ccr = TIM_GetCapture1(TIM3);

	if (ccr == 0)
	{
		return 0;
	}

	return IC_CAPTURE_CLK / ccr;      /* FX = FC / CCR1 */
}

/**
  * 获取被测信号占空比，单位 %（0 ~ 100）
  * 依据：CCR2 是高电平计数值，CCR1 是整周期计数值，两者共用同一个捕获时钟
  */
uint32_t IC_GetDuty(void)
{
	uint16_t period = TIM_GetCapture1(TIM3);

	if (period == 0)
	{
		return 0;
	}

	/* Duty = CCR2 / CCR1 × 100
	   这里先乘 100 再除，避免整数除法把结果截断成 0
	   想要更高分辨率（0.01%）把 100 改成 10000 即可，但要注意不要溢出 uint32_t */
	return (uint32_t)TIM_GetCapture2(TIM3) * 100 / period;
}
```

> [!tip] 除数永远放最后
> `CCR2 * 100 / CCR1` 和 `CCR2 / CCR1 * 100` 在整数运算里天差地别：后者会先做整除，`50/100 = 0`，占空比永远显示 0。C 语言的整数除法是**截断**而不是四舍五入。

## 3 PWMI 结构说明

把两个通道画在一起，能看清「共用 CNT」这件事：

```text
                  ┌────────────────────────── TIM3 ──────────────────────────┐
                  │                                                          │
    PA6 ──► TI1 ──┼─┬─►[ 滤波 ]─►[ 上升沿检测 ]──► TI1FP1 ──┬─►[ 直连 ]─►┌─────────┐
   （一根线）      │ │   ICF=0xF      CC1P=0                  │   CC1S=01 │ CCR1    │
                  │ │                                        │           │ 整周期   │
                  │ │                                        │           └────┬────┘
                  │ │                                        │                │ CC1IF
                  │ │                                        │                │
                  │ │                                        └──►[ 从模式 ]     │
                  │ │                                              TRGI=TI1FP1  │
                  │ │                                              SMS = 复位    │
                  │ │                                                   │        │
                  │ │                                                   ▼        │
                  │ │                                          CNT 每个上升沿清零   │
                  │ │                                                   ▲        │
                  │ │                                              [ PSC ]       │
                  │ │                                                   ▲        │
                  │ │                                              CK_PSC 72MHz   │
                  │ │                                                            │
                  │ └─►[ 滤波 ]─►[ 下降沿检测 ]──► TI1FP2 ──┬─►[ 交叉 ]─►┌─────────┐
                  │       ICF=0xF      CC2P=1               │   CC2S=10 │ CCR2    │
                  │                                         └───────────│ 高电平   │
                  │                                                     └────┬────┘
                  │                                                          │ CC2IF
                  └───────────────────────────────────────────────────────────────┘

   主循环读：  FX   = FC / TIM_GetCapture1(TIM3)
               Duty = TIM_GetCapture2(TIM3) / TIM_GetCapture1(TIM3)
```

**两个通道共用同一个 CNT 基准**，这句话是 PWMI 能成立的全部理由：

- 只有共用 CNT，`CCR2 / CCR1` 才是一把尺子量出来的两个数，相除才等于时间之比。
- 如果两个通道用两个不同的定时器、不同的 PSC，那么相除必须先各自换算成时间再相除，做不了这么简洁。
- 也正因为共用 CNT，两个通道的 `ARR` 溢出条件相同——量程问题要么一起解决，要么一起出问题。

## 4 完整代码

> [!note] 文件命名
> 江协讲义里这一集的模块文件通常叫 **`IC.c` / `IC.h`**（输入捕获）和 **`PWM.c` / `PWM.h`**（产生被测信号）。本笔记按你的工程习惯把捕获模块放进 **`Timer.c` / `Timer.h`**，功能与调用完全一致。名字不影响任何结果。

### 4.1 Timer.c（输入捕获，PWMI 模式）

```c
#include "stm32f10x.h"                  // Device header

/* 捕获时钟频率 FC = CK_PSC / (PSC + 1) = 72MHz / 72 = 1MHz
   注意：这个常数必须和下面 TIM_Prescaler 保持一致 */
#define IC_CAPTURE_CLK        1000000UL

/* 频率公式是否使用 (CCR + 1) 的写法：1 = 课程原版（加，默认），0 = 简化（不加） */
#define IC_FREQ_USE_PLUS_ONE  1

/**
  * 输入捕获初始化：TIM3_CH1（PA6），PWMI 模式
  * 同时测量被测 PWM 的频率（CH1 上升沿）与占空比（CH2 下降沿）
  */
void IC_Init(void)
{
	/* ① 开启时钟：TIM3 在 APB1 上，GPIOA 在 APB2 上 */
	RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

	/* ② GPIO：输入捕获的引脚配成上拉输入（IPU），不是复用推挽输出 */
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;
	GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_6;          /* TIM3_CH1 = PA6 */
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);

	/* ③ 时基单元时钟源：CNT 仍由内部 72MHz 推进（复位模式只管清零，不管推进） */
	TIM_InternalClockConfig(TIM3);

	/* ④ 时基单元：PSC 决定捕获时钟，ARR 决定量程 */
	TIM_TimeBaseInitTypeDef TIM_TimeBaseInitStructure;
	TIM_TimeBaseInitStructure.TIM_ClockDivision     = TIM_CKD_DIV1;   /* 数字滤波采样分频 */
	TIM_TimeBaseInitStructure.TIM_CounterMode       = TIM_CounterMode_Up;
	TIM_TimeBaseInitStructure.TIM_Period            = 65536 - 1;      /* ARR 拉满，量程约 65.5ms */
	TIM_TimeBaseInitStructure.TIM_Prescaler         = 72 - 1;         /* 72MHz / 72 = 1MHz，1 拍 = 1us */
	TIM_TimeBaseInitStructure.TIM_RepetitionCounter = 0;              /* 仅高级定时器有效 */
	TIM_TimeBaseInit(TIM3, &TIM_TimeBaseInitStructure);

	/* ⑤ 输入捕获单元：只描述通道 1，配对通道由 TIM_PWMIConfig 自动补成相反配置 */
	TIM_ICInitTypeDef TIM_ICInitStructure;
	TIM_ICInitStructure.TIM_Channel     = TIM_Channel_1;               /* 只能填 1 或 2 */
	TIM_ICInitStructure.TIM_ICFilter    = 0xF;                         /* 滤波长度最大，抑制毛刺 */
	TIM_ICInitStructure.TIM_ICPolarity  = TIM_ICPolarity_Rising;       /* CH1 抓上升沿 */
	TIM_ICInitStructure.TIM_ICPrescaler = TIM_ICPSC_DIV1;              /* 不分频，每个边沿都捕获 */
	TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;    /* TI1FP1 直连到 IC1 */
	TIM_PWMIConfig(TIM3, &TIM_ICInitStructure);                        /* CH2 自动配成下降沿 + 交叉 */

	/* ⑥ 从模式触发源：把 TI1FP1（上升沿）选为 TRGI */
	TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1);

	/* ⑦ 从模式：复位模式。每个上升沿硬件自动把 CNT 清零，无需软件干预 */
	TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset);

	/* ⑧ 运行控制：不使能计数器，一切不动 */
	TIM_Cmd(TIM3, ENABLE);
}

/**
  * 获取被测信号频率，单位 Hz
  * FX = FC / CCR1，CCR1 是一个完整周期内的计数节拍数
  */
uint32_t IC_GetFreq(void)
{
	uint16_t ccr = TIM_GetCapture1(TIM3);

	if (ccr == 0)                          /* 没接信号时 CCR 保持 0，直接返回避免除零 */
	{
		return 0;
	}

#if IC_FREQ_USE_PLUS_ONE
	return IC_CAPTURE_CLK / (ccr + 1);
#else
	return IC_CAPTURE_CLK / ccr;
#endif
}

/**
  * 获取被测信号占空比，单位 %（0 ~ 100）
  * Duty = CCR2 / CCR1 × 100：高电平计数值 ÷ 整周期计数值
  */
uint32_t IC_GetDuty(void)
{
	uint16_t period = TIM_GetCapture1(TIM3);

	if (period == 0)
	{
		return 0;
	}

	/* 先乘 100 再除，避免整数除法提前把结果截断成 0 */
	return (uint32_t)TIM_GetCapture2(TIM3) * 100 / period;
}
```

### 4.3 PWM.c（产生被测信号，来自 6-4）

不做信号发生器的话，被测信号就自己产。这一份和 6-4 的 PWM 输出模块一致。

```c
#include "stm32f10x.h"                  // Device header

/**
  * PWM 输出初始化：TIM2_CH1（PA0），用于产生被测信号
  * f_PWM = 72MHz / (PSC+1) / (ARR+1)，Duty = CCR / (ARR+1)
  */
void PWM_Init(void)
{
	RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM2, ENABLE);
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

	/* PWM 输出引脚：复用推挽输出 AF_PP（和输入捕获的 IPU 正好相反） */
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_AF_PP;
	GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_0;          /* TIM2_CH1 = PA0 */
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);

	/* PWM 输出用内部时钟，这一点和 6-3/6-4 相同 */
	TIM_InternalClockConfig(TIM2);

	TIM_TimeBaseInitTypeDef TIM_TimeBaseInitStructure;
	TIM_TimeBaseInitStructure.TIM_ClockDivision     = TIM_CKD_DIV1;
	TIM_TimeBaseInitStructure.TIM_CounterMode       = TIM_CounterMode_Up;
	TIM_TimeBaseInitStructure.TIM_Period            = 100 - 1;         /* ARR */
	TIM_TimeBaseInitStructure.TIM_Prescaler         = 720 - 1;         /* PSC */
	TIM_TimeBaseInitStructure.TIM_RepetitionCounter = 0;
	TIM_TimeBaseInit(TIM2, &TIM_TimeBaseInitStructure);

	/* 输出比较单元：PWM1 模式，高电平有效 */
	TIM_OCInitTypeDef TIM_OCInitStructure;
	TIM_OCStructInit(&TIM_OCInitStructure);                 /* 先把结构体填默认值，避免野值 */
	TIM_OCInitStructure.TIM_OCMode      = TIM_OCMode_PWM1;
	TIM_OCInitStructure.TIM_OCPolarity  = TIM_OCPolarity_High;
	TIM_OCInitStructure.TIM_OutputState = TIM_OutputState_Enable;
	TIM_OCInitStructure.TIM_Pulse       = 50;               /* CCR，50/100 = 50% */
	TIM_OC1Init(TIM2, &TIM_OCInitStructure);

	TIM_Cmd(TIM2, ENABLE);
}

/**
  * 设置 PWM 占空比（改 CCR）
  */
void PWM_SetCompare1(uint16_t Compare)
{
	TIM_SetCompare1(TIM2, Compare);
}

/**
  * 设置 PWM 频率（改 PSC）
  * 注意：改 PSC 会改变被测信号频率，但【不会】影响捕获回来的占空比
  */
void PWM_SetPrescaler(uint16_t Prescaler)
{
	TIM_PrescalerConfig(TIM2, Prescaler, TIM_PSCReloadMode_Update);
}
```

## 5 测周法的适用范围与误差

测周法用起来爽，但它的准确度和被测频率是**反相关**的：

```text
        ΔFX / FX = 1 / CCR1        （±1 个计数带来的相对误差）

   CCR1 越大（信号越慢）→ 相对误差越小
   CCR1 越小（信号越快）→ 相对误差越大
```

以 `FC = 1 MHz`、`ARR = 65535` 为例：

| 被测信号频率 | 周期 | `CCR1` | ±1 计数引起的相对误差 | 能不能用 |
| --- | --- | --- | --- | --- |
| 10 Hz | 100 ms | 100000 | — | **超量程**，CNT 溢出 |
| 100 Hz | 10 ms | 10000 | 0.01% | 很好 |
| 1 kHz | 1 ms | 1000 | 0.1% | 好（≈中介频率） |
| 10 kHz | 100 µs | 100 | 1% | 勉强 |
| 100 kHz | 10 µs | 10 | 10% | 不能用 |
| 1 MHz | 1 µs | 1 | 100% | 完全不能用 |

三个实用结论：

1. **超量程怎么办**：被测周期必须小于 `(ARR + 1) × 一个计数节拍的时间`。`ARR` 已经拉满时，只能**加大 PSC 降低捕获时钟**——例如 `PSC = 720 - 1`（FC = 100 kHz），量程就从 65.5 ms 扩到 655 ms。**代价是分辨率变粗（10 µs/拍），而且所有换算常数要同步改**（`IC_CAPTURE_CLK` 从 `1000000` 改成 `100000`）。
2. **高频测不准怎么办**：按 6-5 的中介频率判据，`FC = 1 MHz`、闸门 `t = 1 s` 时 `FM = 1 kHz`。**1 kHz 以上就应该改走测频法**，而不是硬调测周法的 PSC——减小 PSC 会同时减小 `CCR1`，相对误差反而更大。
3. **测频法在哪学**：就在下一集。**6-7 编码器接口本质就是测频法**——它让外部脉冲直接驱动 CNT 加减，本质是「在一段固定时间里数了多少个脉冲」，和测周法正好是一对镜像。

> [!warning] 分辨率与量程是一对矛盾
> 捕获时钟 `FC` 越大：分辨率越细（好），但量程越小（短周期/低频测不了）。
> 捕获时钟 `FC` 越小：量程越大（好），但分辨率越粗（高频测不准）。
> 这个矛盾在 ADC、PWM 里也反复出现——**任何测量系统都要先明确「我要测的量程有多大、分辨率要多细」，再回头选时钟。**

## 6 易错点

- [ ] **GPIO 模式写错**：输入捕获要 `GPIO_Mode_IPU`（上拉输入），写成 `GPIO_Mode_AF_PP` 是输出比较那边的写法，引脚不会听外面的信号。
- [ ] **忘了从模式复位**（`TIM_SlaveMode_Reset`）→ CCR1 一路累加，读数一次比一次大，频率算出来一次比一次小。
- [ ] **忘了 `TIM_SelectInputTrigger()`** → 从模式没有触发源，复位永远不发生。
- [ ] **`IC_CAPTURE_CLK` 和 `PSC` 不一致**：`PSC = 72-1` 就必须配 `1000000`，改成 `720-1` 就必须配 `100000`。这是最容易「程序能跑但读数全错」的地方。
- [ ] **`TIM_PWMIConfig()` 填了 `TIM_Channel_3` / `TIM_Channel_4`** → 标准库里只实现了 CH1↔CH2 配对，填 3/4 会走进错误分支。
- [ ] **`TIM_PWMIConfig()` 和 `TIM_ICInit()` 都调了** → 后调的覆盖前调的一半，配置看起来对、行为不对。
- [ ] **占空比写成 `CCR2 / CCR1 * 100`** → 整数除法先截断，`50/100 = 0`，占空比永远显示 0。必须**先乘后除**：`CCR2 * 100 / CCR1`。
- [ ] **没接信号直接读** → `CCR1 = 0`，`FC / 0`。代码里要显式判断（Cortex-M3 默认除零不报错而是返回 0，问题会被掩盖到后面）。
- [ ] **滤波 `ICF = 0xF` 用在很高频的信号上** → 边沿被滤掉，读数乱跳。滤波强度要跟信号频率匹配。
- [ ] **被测信号周期超过 `ARR` 量程** → CNT 溢出回绕，读数时大时小。加大 PSC 扩量程。
- [ ] **以为改 PSC 会影响占空比** → 两个通道共用同一个时钟，`CCR2/CCR1` 把时钟约掉了，占空比与 PSC 无关。反过来，这正好是个自检手段。
- [ ] **在被测信号和捕获引脚之间忘了连线** → PA0 和 PA6 必须用杜邦线短接（或直接接外部信号源），否则读到的是悬空引脚的噪声。

## 7 自测

1. 捕获时钟 `FC = 1 MHz`，`CCR1` 读到 **999**，被测频率是多少？如果按「加 1」的写法算又是多少？两者相差百分之几？
2. PWMI 模式下 CH1 和 CH2 各自被配置成什么极性、什么信号选择？为什么只接一根 PA6 就够了？
3. 占空比公式 `Duty = CCR2 / CCR1` 为什么**与 PSC 取值无关**？这个性质能用来做什么自检？
4. 把占空比计算写成 `TIM_GetCapture2(TIM3) / TIM_GetCapture1(TIM3) * 100` 会得到什么？为什么？
5. 想测 **100 kHz** 的信号，用本集的测周法配置能测准吗？应该怎么做？

> [!success]- 参考答案
> 1. 加 1：`1 000 000 / (999 + 1) = 1000 Hz` ✔；不加 1：`1 000 000 / 999 ≈ 1001 Hz`。两者相差 `1/1000 = 0.1%`，也就是 1 个计数的量级，和 ±1 量化误差同阶。课程原版用的是加 1。
> 2. CH1 配成**上升沿 + 直连**（`CC1S = 01`，取 TI1FP1），负责测整周期；CH2 被 `TIM_PWMIConfig()` 自动配成**下降沿 + 交叉**（`CC2S = 10`，取 TI1FP2），负责测高电平时间。因为 TI1FP1 和 TI1FP2 都源自同一个 TI1（即 PA6），所以一根引脚就够了。
> 3. 因为 CCR1 和 CCR2 是**同一个 CNT、同一个捕获时钟**量出来的，相除时 `FC` 被约掉：`(T_high·FC)/(T·FC) = T_high/T`。自检用法：改 PWM 的 PSC（被测信号频率变了）之后，**占空比读数应该不变**；如果变了，说明占空比的算法或通道配置有问题。
> 4. 得到 **0**。C 语言的整数除法会先算 `CCR2 / CCR1`，`50 / 100 = 0`，再乘 100 还是 0。必须**先乘后除**：`CCR2 * 100 / CCR1`。
> 5. 不能。`FC = 1 MHz` 时 100 kHz 信号的 `CCR1 = 10`，±1 计数就是 **10% 的误差**，而 `FM = 1 kHz` 说明 1 kHz 以上就该换方法了。正确做法是改用**测频法**（固定闸门时间数边沿个数），也就是 6-7 编码器接口那条路线。
