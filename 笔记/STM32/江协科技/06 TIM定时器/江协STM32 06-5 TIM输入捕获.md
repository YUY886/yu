# 06-5 TIM 输入捕获

> [!abstract] 这一集只解决一个问题
> **怎么让硬件自己把「外部信号的时间」量出来？**
>
> 答：输入捕获通道（IC, Input Capture）在引脚出现**指定跳变**时，把当前 **CNT** 的值锁存进 **CCR**——CCR 里装的不是电平，而是**时间刻度**。再配合**主从触发模式（Master/Slave Trigger Mode）**让 CNT 在每个上升沿被硬件自动清零，于是 CCR 里剩下的就是「一个周期有几个计数节拍」。
>
> 上一集 [[江协STM32 06-4 PWM 应用]] ｜ 章索引 [[江协STM32 06 TIM定时器（章索引）]] ｜ 下一集 [[江协STM32 06-6 输入捕获测频率与占空比]]

## 1 输入捕获（IC, Input Capture）是什么

输入捕获的英文缩写是 **IC**（Input Capture）。在定时器的整体结构图里，**左边是输入捕获，右边是输出比较**（Output Compare，OC），中间夹着时基单元。

一句话定义：

> **输入捕获模式下，当通道输入引脚出现指定电平跳变（上升沿或下降沿）时，当前 CNT 的值被锁存到 CCR 中。**

由此可以测量：

| 能测什么 | 怎么来的 |
| --- | --- |
| **频率**（Frequency） | 两个上升沿之间的 CCR 就是周期对应的计数值 |
| **占空比**（Duty Cycle） | 高电平时间的 CCR ÷ 周期的 CCR |
| **脉宽 / 高电平时间**（Pulse Width） | 上升沿捕获值到下降沿捕获值之差 |
| **电平持续时间** | 任意两次跳变之间的差值 |
| **脉冲间隔** | 同上，换个边沿组合 |

几个必须记住的资源约束：

- 每个**高级定时器**和**通用定时器**都有 **4 个输入捕获通道**（CH1~CH4），可配置为 **PWMI 模式**（PWM Input）同时测频率和占空比。
- 4 个输入捕获通道和 4 个输出比较通道**共用 4 个 CCR 寄存器和 4 个通道引脚**。所以同一个定时器的同一个通道，**输入捕获和输出比较只能用其一**。
- 捕获到之后会给状态寄存器 **SR** 里的 **CCxIF** 置标志位，可以拿去触发**中断**或 **DMA**——但测周法里我们**不需要**中断，这正是这一集最漂亮的地方。

> [!tip] 和 6-3 / 6-4 对照着理解
> 输出比较是「CNT 到点了，我去动引脚」——**往外输出**。
> 输入捕获是「引脚来边沿了，我把 CNT 抄下来」——**往里记录**。
> 一个以 CNT 为基准去改变世界，一个以世界为基准去记录 CNT。CCR 在两边的角色正好反过来。

## 2 测频法与测周法

这是本集乃至整章最容易考、也最容易记混的一对概念。

### 2.1 对比表

| | **测频法**（Frequency Measurement） | **测周法**（Period Measurement） |
| --- | --- | --- |
| 做法 | 固定一个**闸门时间** `t`，数这段时间里有多少个上升沿 `n` | 在两个上升沿之间，用**标准频率** `FC` 计数得到 `n` |
| 公式 | `FX = n / t` | `FX = FC / n` |
| 适合 | **高频**信号 | **低频**信号 |
| 结果更新 | **慢**（必须等满一个闸门，常见 `t = 1 s`） | **快**（一个信号周期就出一个结果） |
| 数值表现 | 稳，**自带均值滤波**（一个闸门里平均了很多个周期） | 跳，**噪声敏感**（只靠一两个周期就下结论） |
| ±1 误差大小 | `ΔFX = 1 / t`，**与 FX 无关** | `ΔFX = FX² / FC`，**随 FX 增大急剧恶化** |
| 谁更准 | 频率 **> 中介频率** 时 | 频率 **< 中介频率** 时 |

直觉记忆：

- **测频法**是「我拿秒表卡 1 秒，数你跳了几下」。信号跳得越快，数到的个数越多，1 秒的读数误差占比越小 → 适合高频。
- **测周法**是「我用节拍器量你一个周期有多长」。信号越慢，一个周期里塞进的节拍越多，少算一拍的占比越小 → 适合低频。

### 2.2 中介频率（Mid-frequency）

两种方法的误差相等的那一点叫**中介频率**：

```text
FX = FM 时，两种方法的误差相同：

测频法：ΔFX = 1 / t                     （n 有 ±1 的不确定度）
测周法：ΔFX = FC / n²  (由 FX = FC/n 对 n 求导)
        = FC / (FC/FX)² = FX² / FC

令 1/t = FX²/FC  →  FX = √(FC / t)

    FM = √( FC / t )
```

- `FX < FM` → 用**测周法**；
- `FX > FM` → 用**测频法**。

**算一个具体数**：若标准频率 `FC = 1 MHz`、闸门时间 `t = 1 s`：

```text
FM = √(1 000 000 / 1) = 1000 Hz
```

也就是说，`FC = 1 MHz` 的测周法在 **1 kHz 附近**和「1 秒闸门 + 1 MHz 计数」的测频法打平；**1 kHz 以下测周法更准，1 kHz 以上测频法更准**。

### 2.3 ±1 误差到底从哪来

两种方法都逃不掉 **±1 的量化误差**，根源是**边沿和时钟不同步**：

**测频法的 ±1**：闸门时间 `t` 的**起点和终点**是定时器自己定的，而信号的上升沿是外面来的，两者相位随缘。所以闸门窗口的首尾各自可能「多截半个周期或少截半个周期」，数出来的 `n` 天然有 `±1` 的不确定度。误差 `ΔFX = 1/t` 与被测频率无关——这就是为什么测高频时它反而准。

**测周法的 ±1**：标准时钟 `FC` 的跳变和信号边沿也是随缘的。一个信号周期里塞进去的标准节拍数，落在 `N` 和 `N+1` 之间，CNT 只能给出整数，末尾「不够一个标准周期」的那一小段被丢弃（或多算）。误差折算到频率上是 `ΔFX = FX²/FC`——`FX` 一翻倍，误差就翻两番。

> [!warning] 结论比公式重要
> **±1 是量化误差，不是配置错误。** 去掉它的唯一办法是让被测周期里包含更多的计数节拍：要么降低被测频率（测周法用），要么改去数很多个周期（测频法用）。看到读数末位跳 1 个字，不要去查代码。

### 2.4 本课程为什么选测周法

因为输入捕获**天生就是测周法的硬件**：它记录的就是「两个边沿之间的 CNT 差值」，直接就是周期。要改成测频法，得额外加一个 1 秒闸门去数边沿个数，还得靠软件或另一个定时器配合，属于「用错了外设的强项」。

> [!note] 6-7 编码器接口其实站在测频法那一边
> 编码器接口是让**外部脉冲直接去驱动 CNT 加减**，本质上是「在一段固定时间里数了多少个脉冲」——那是**测频法**的思路。所以测周法（6-5/6-6）和测频法（6-7/6-8）在课程里是两条并列的路线，不是递进关系。

## 3 输入捕获通道的内部电路

这是本集的画面重点。从引脚进来到 CCR，一共经过四级。

```text
  定时器 TIMx
  ────────────────────────────────────────────────────────────────────────────
  PA6 ─► TI1 ─►[① 输入滤波]─►[② 边沿检测]─►[③ 信号选择]─►[④ 预分频]─►┌──────────┐
                CCMR.IC1F     CCER.CC1P     CCMR.CC1S    CCMR.IC1PSC │  CCR1    │
                采样+滤波      极性          直连/交叉/TRC  1/2/4/8    │ 锁存 CNT │
                    │             │             │            │       └────┬─────┘
                    │             │             │            └────────────┘   │
                    │             │             │                             ▼
                    │             │             └──► TI1FP1 ──────────►  CC1IF（中断 / DMA）
                    │             │                          │
                    │             └──► TI1FP2 ──┐             │
                    │                          ▼             │
                    │              ┌────────────────────┐    │
                    │              │   从模式控制器       │◄───┘
                    │              │  SMS = 复位/门控/触发│
                    │              └─────────┬──────────┘
                    │                        │ TRGI
                    │                        ▼
                    │              CNT ◄── 硬件自动清零
                    │               ▲
                    └── TI2 也有    [ PSC ] ◄── CK_PSC (72 MHz)
                        TI2FP1/FP2
  ────────────────────────────────────────────────────────────────────────────
```

### 3.1 引脚输入与异或门

- **CH1~CH4** 是输入引脚，通过**数据选择器**可以配置成「独立输入」或「异或输入」。
- **异或门（XOR）** 的用途：三相无刷电机驱动里，三个霍尔传感器（Hall Sensor）的信号接到 CH1/CH2/CH3，异或门的输出在**任意一路电平翻转时都会翻转**，用一个通道就能同时监视三个位置信号，简化电机换向检测电路。

> [!tip] 和 6-1 的对应
> 这里的「数据选择器」就是 6-1 里提到的**输入部分**。TIMx 前面还有 CH1~CH4 的引脚复用选择，属于 GPIO/AFIO 的事，不在这里展开。

### 3.2 ① 输入滤波（Input Filter）

滤波器的任务是**滤掉输入信号上的细小毛刺**，防止一个毛刺被当成一次跳变。

- 配置位置：**CCMR1/CCMR2 的 ICF 位**（库函数里对应 `TIM_ICInitStructure.TIM_ICFilter`，取值 `0x0`~`0xF`）。
- 工作原理：以某个**采样频率 `f_DTS`** 对输入信号连续采样，**连续 N 个采样点电平都相同，才允许输出翻转**。
- **采样频率** `f_DTS = CK_INT / CKD`，其中 CKD 由 `TIM_ClockDivision` 决定（`TIM_CKD_DIV1/2/4`）。
- **滤波长度** `N` 由 ICF 的取值决定（2、4、6、8……最长 8 个点，采样频率也逐档降低）。

参数逻辑一句话：

> **采样频率越低、滤波长度越长 → 抗噪越强，但边沿延迟越大。**

所以滤波不是「越大越安全」：滤波太轻，毛刺会被当成边沿；滤波太重，高频信号的边沿会被直接「滤没」。

### 3.3 ② 边沿检测（Edge Detector）

- 支持**上升沿 / 下降沿**触发，配置位置：**CCER 的 CCxP 极性位**（库函数 `TIM_ICPolarity_Rising` / `TIM_ICPolarity_Falling`）。
- 高级定时器还支持**双边沿**。
- **双路设计**：每个通道都支持**两路独立的滤波与极性选择**，输出 **TIxFP1** 和 **TIxFP2**（FP = Filtered + Polarity）。这两路可以**交叉连接**到不同的捕获单元，PWMI 模式正是靠这一点用**一根引脚**同时抓上升沿和下降沿。

### 3.4 ③ 信号选择（Input Selection）

一个多路复用器，把哪一路 TIxFP 接到哪个捕获单元：

| `CCxS` | 名字 | 含义 |
| --- | --- | --- |
| `00` | 输出 | 该通道用作**输出比较**，不是输入捕获 |
| `01` | **直连** DirectTI | ICx ← 本通道的 TIxFPx |
| `10` | **交叉** IndirectTI | ICx ← **配对通道**的 TIxFP（CH1 取 TI2，CH2 取 TI1） |
| `11` | **TRC** | ICx ← 从模式控制器的 TRC 信号 |

「直连 + 交叉」的组合就是 PWMI：`CH1` 用直连拿上升沿（测**周期**），`CH2` 用交叉拿同一根引脚上的下降沿（测**高电平时间**）。**交叉连接省下了一个引脚**，这是这个设计最实用的价值。

### 3.5 ④ 预分频（Prescaler）

- 配置位置：**CCMR 的 ICxPSC 位**（库函数 `TIM_ICPSC_DIV1/2/4/8`）。
- 作用：**每出现 1 / 2 / 4 / 8 个捕获事件才真正捕获一次**，即降低捕获事件的发生频率，避免高频信号下 CCR 频繁被覆盖。
- 一般选 **`TIM_ICPSC_DIV1`（一分频）**：来一个上升沿就捕获一次。

### 3.6 捕获事件（Capture Event）的产生

触发条件满足时硬件做两件事：

1. 把当前 **CNT** 的值**锁存**进 **CCR**；
2. 在状态寄存器 **SR** 里把 **CCxIF** 置 1。

之后 `CCxIF` 可以选择：

- **产生中断** —— CPU 进中断读 CCR（软件干预，有延迟、有开销）；
- **产生 DMA 请求** —— 批量搬运；
- **什么都不做，只让从模式控制器去用** —— 这就是主从触发模式的硬件自动化路线。

## 4 主从触发模式（Master/Slave Trigger Mode）

这是 6-5 最核心、也是全章最漂亮的硬件自动化设计。它解决的问题是：

> 测周法里，每次捕获完必须**把 CNT 清零**，否则下一次读到的就不是「一个周期的长度」而是「从开机到现在的时间」。**这件事能不能不让软件管？**

能。让**硬件自己**在每次捕获的同时清零。

### 4.1 主模式与从模式

**主从触发模式**由两部分组成：

| | **主模式**（Master） | **从模式**（Slave） |
| --- | --- | --- |
| 角色 | 定时器作为「主设备」 | 定时器作为「从设备」 |
| 接口 | 通过 **TRGO** 输出内部信号 | 通过 **TRGI** 接收信号 |
| 信号来源 / 去向 | 更新事件、比较事件、捕获事件等 | 外部引脚、其他定时器、**本定时器的 TIxFPx** |
| 典型用途 | 触发 ADC 转换、触发另一个定时器、触发 DAC | 复位 CNT、启动计数、门控计数、外部时钟 |

```text
   主模式（Master）                              从模式（Slave）
   ┌──────────────┐                             ┌──────────────┐
   │   TIMx（主）  │───── TRGO ──►(内部连线)────►│   TIMy（从）  │
   │ 更新/比较/捕获 │                             │  TRGI 收到信号 │
   └──────────────┘                             │  → 复位 CNT   │
                                                │  → 启动计数   │
   也可以自己当自己的主：                          │  → 门控计数   │
   ┌──────────────┐         TRGI                └──────────────┘
   │ TIMx：TI1FP1 │──────────────────────────────► 复位自己的 CNT
   └──────────────┘
```

### 4.2 测周法里怎么用

关键两行库函数调用：

```c
/* ① 选择从模式的触发源：把本通道的 TI1FP1 当作 TRGI */
TIM_SelectInputTrigger(TIMx, TIM_TS_TI1FP1);

/* ② 选择从模式的操作：复位模式（Reset Mode） */
TIM_SelectSlaveMode(TIMx, TIM_SlaveMode_Reset);
```

配上这两行之后，硬件在每个**上升沿**上**同时**做两件事：

```text
   上升沿到来
        │
        ├──► ① 把当前 CNT 锁存进 CCR1      （捕获）
        │
        └──► ② 把 CNT 复位为 0             （从模式：复位模式）

   于是下一次读到的 CCR1 = 上一个完整周期里的计数节拍数
```

**全程没有一行中断代码，没有一个标志位要清。** CPU 只需要在主循环里 `TIM_GetCapture1(TIMx)` 随手读一下。

> [!tip] 为什么说这是「全章最漂亮的设计」
> 6-1 里的更新事件、6-3 里的输出比较，都是「硬件产生事件」。这里更进一步：**硬件把事件直接接回自己的时基单元**，形成了一个闭环。CPU 从「必须参与的一环」降级成「偶尔围观的路人」。
> 同样的思路在 6-7 编码器接口里还会再出现一次——那里是让外部脉冲直接驱动 CNT 加减。

### 4.3 从模式的几种常用操作

| 从模式 | 库函数宏 | 触发时干什么 |
| --- | --- | --- |
| 复位模式 | `TIM_SlaveMode_Reset` | CNT 和预分频器**归零**，并产生一次更新事件 |
| 门控模式 | `TIM_SlaveMode_Gated` | 触发信号为高时 CNT 才计数 |
| 触发模式 | `TIM_SlaveMode_Trigger` | 触发信号**启动** CNT 计数 |
| 外部时钟模式 1 | `TIM_SlaveMode_External1` | 触发信号直接当 CNT 的时钟（6-2 用过） |

### 4.4 测周法的配置顺序

```text
① RCC 开启 TIM 时钟、GPIO 时钟
② GPIO 配置为上拉输入（IPU），引脚选到定时器通道对应的那个脚
③ TIM_InternalClockConfig —— 选内部时钟当 CNT 的基准
④ TIM_TimeBaseInit        —— PSC 决定捕获时钟，ARR 给足量程
⑤ TIM_ICInit              —— 配置输入捕获通道（极性、滤波、直连、预分频）
⑥ TIM_SelectInputTrigger  —— 选 TI1FP1 当触发源
⑦ TIM_SelectSlaveMode     —— 选复位模式，硬件自动清零 CNT
⑧ TIM_Cmd                 —— 启动计数器
```

注意顺序上的两个细节：

- 第 ③ 步的 `TIM_InternalClockConfig` **必须**要——复位模式管的是 CNT 什么时候**清零**，不管 CNT **由谁推进**。CNT 还是要靠内部 72 MHz 走时，否则没东西可数。
- 第 ⑥ ⑦ 步要在 `TIM_Cmd` **之前**配好，避免启动瞬间的乱触发。

## 5 输入捕获基本结构图

把前面几节串起来，就是这一集的画面主体：

```text
                 ┌───────────────────────────── TIM3 ─────────────────────────────┐
                 │                                                                 │
  被测信号 ──►PA6─┼─► TI1 ─►[ 滤波 ]─►[ 边沿检测 ]─┬─► TI1FP1 ─►[ 直连 CC1S=01 ]─┐ │
  （外部或自产）  │        ICF=0xF    CC1P=上升沿     │                            │ │
                 │                                  │                            ▼ │
                 │                                  │                    ┌────────────┐
                 │                                  │                    │ CCR1 锁存  │
                 │                                  │                    └─────┬──────┘
                 │                                  │                          │
                 │                                  │        ┌─────────────────┘
                 │                                  │        │  CC1IF（本集不用中断）
                 │                                  │        ▼
                 │                                  └──►[ 从模式控制器 ]         │
                 │                                       TRGI = TI1FP1           │
                 │                                       SMS  = 复位模式           │
                 │                                            │                    │
                 │                                            ▼                    │
                 │                            ┌───────────────────────────┐        │
                 │                            │  CNT 每个上升沿自动清零      │        │
                 │                            └─────────────┬─────────────┘        │
                 │                                          ▲                      │
                 │                                     [ PSC ]                     │
                 │                                          ▲                      │
                 │                                     CK_PSC = 72 MHz             │
                 └─────────────────────────────────────────────────────────────────┘

  主循环里读：  FX = FC / TIM_GetCapture1(TIM3)
```

**读图要点**：

- CNT 是唯一的「时间标尺」，被 PSC 降速后每个节拍有固定的时间长度。
- 上升沿这条线**分叉**：一路去捕获（记下时间），一路去从模式控制器（清零重来）。
- `CC1IF` 这条线本集**不接**。捕获事件照常产生，只是我们不打断 CPU——和 6-1 里「更新事件 ≠ 更新中断」是同一个道理。

## 6 易错点

- [ ] 把 **CCR 当成电平寄存器** → CCR 里是**时间刻度**（CNT 的快照），不是高低电平。
- [ ] 忘了配从模式复位（`TIM_SlaveMode_Reset`）→ CCR 变成「从开机到现在的时间」，读数一路涨，频率完全不对。
- [ ] 忘了 `TIM_SelectInputTrigger()` → 从模式不知道听谁的，复位永远不触发。
- [ ] 只配 `TIM_InternalClockConfig` 却以为复位模式会让 CNT 停止 → 复位模式只管清零，CNT 仍由内部时钟推进。
- [ ] **在同一个定时器的同一个通道上同时用输入捕获和输出比较** → 共用 CCR 和引脚，二者只能选其一。
- [ ] `ARR` 给得太小 → 被测周期比 `ARR + 1` 还长时 CNT 会溢出回绕，读数时大时小；测低频要**加大 PSC**（降低捕获时钟）来扩量程。
- [ ] 滤波 `ICF` 一上来就拉满 `0xF` → 高频信号的边沿被滤掉，读数莫名其妙。滤波强度要跟信号频率匹配。
- [ ] 以为捕获必须开中断 → 测周法里 `CC1IF` 完全可以不接，硬件闭环自己就能出结果。
- [ ] 把 `TIM_ICFilter` 和 6-1 的 `TIM_ClockDivision`（CKD）当成一回事 → CKD 决定滤波器的采样频率 `f_DTS`，ICF 决定滤波长度，两者配合使用但不是一个东西。

## 7 自测

1. 输入捕获触发时，锁存进 CCR 的到底是什么？它和引脚电平是什么关系？
2. 测频法和测周法各适合什么频率的信号？各自的 ±1 误差与被测频率是什么关系？
3. 标准频率 `FC = 1 MHz`、闸门时间 `t = 1 s`，中介频率 `FM` 大约是多少？被测信号 500 Hz 和 50 kHz 各该用哪种方法？
4. 测周法里为什么必须配 `TIM_SelectInputTrigger()` + `TIM_SelectSlaveMode()`？不配会怎样？
5. 每个捕获通道为什么能提供 TIxFP1 和 TIxFP2 两路信号？这样做在实际测量中省下了什么？

> [!success]- 参考答案
> 1. 锁存的是**触发那一刻的 CNT 值**，也就是一个「时间刻度」；它和引脚电平没有直接关系，只是被边沿「拍了一张 CNT 的快照」。电压多高、是高是低都不记录。
> 2. 测频法适合**高频**，误差 `ΔFX = 1/t` 与 FX 无关；测周法适合**低频**，误差 `ΔFX = FX²/FC` 随 FX 迅速变大。
> 3. `FM = √(FC/t) = √(1 000 000/1) = 1000 Hz`。500 Hz < 1000 Hz 用**测周法**；50 kHz > 1000 Hz 用**测频法**。
> 4. 这两个调用让 **TI1FP1** 作为 **TRGI** 触发**复位模式**，硬件在每个上升沿把 CNT 清零。不配的话 CNT 从不归零，CCR 里读到的是不断累加的绝对时间，算出来的「周期」一次比一次大。
> 5. 因为每个通道的滤波器和边沿检测器都输出了**两路**（TIxFP1、TIxFP2），可以交叉接到不同的捕获单元。实际测量中省下的是一个**引脚**：PWMI 模式用一根 PA6 就能同时拿到上升沿和下降沿两个时刻。
