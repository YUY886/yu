# 05-2 对射式红外传感器计次 & 旋转编码器计次

> [!abstract] 这一集只解决一个问题
> **把上一集的 EXTI 架子真接上传感器，让它替我们数数。**
> 两个实验：① 红外管被遮挡一次 → 记一个数；② 编码器正转 `+1`、反转 `−1`，还要知道**往哪边转**。
> 难点全在实验二：**A、B 两相谁先出现下降沿，就代表往哪边转**——这套「手动鉴相」到第 6 章会被 **TIM 编码器接口**整个搬进硬件，两集对着看收获最大。
>
> 上一集 [[江协STM32 05-1 EXTI外部中断]] ｜ 下一章 [[江协STM32 06 TIM定时器（章索引）]] ｜ 章索引 [[江协STM32 05 EXTI外部中断（章索引）]]

## 1 对射式红外传感器

### 1.1 结构

对射式红外传感器由一个**红外发射管**（IR LED）和一个**红外接收管**（光敏管）面对面组成，中间留一道槽：

```text
        ┌──────────────┐
        │  ●发射管      │  ← 一直发红外光
        │     ↓ 光路    │
        │   （槽）      │  ← 遮挡物从这里穿过
        │     ↓         │
        │  ○接收管      │  ← 收到光就导通
        └──────────────┘
```

模块上通常还有：比较器（把模拟量整形为数字量）、灵敏度电位器、电源指示灯、开关指示灯，以及两个输出口：

| 输出口 | 类型 | 用途 |
| --- | --- | --- |
| **DO** | 数字开关量（0 / 1） | **本课程用这个**，直接接单片机 IO |
| AO | 模拟量 | 本课程**不用**（用不了，也不需要） |

### 1.2 输出电平：和直觉相反

关键点：**没遮挡时输出低电平，遮挡时输出高电平**。

| 状态 | 接收管 | 模块 DO 输出 | 开关指示灯 |
| --- | --- | --- | --- |
| 槽中**无**遮挡 | 收到光 → 导通 | **低电平（0）** | 亮 |
| 槽中**有**遮挡 | 收不到光 → 截止 | **高电平（1）** | 灭 |

即 **DO 是「有遮挡 = 高」**，和「被挡住就报警」的直觉一致，但和「有光 = 高」相反。接线前一定要先用万用表确认一遍自己手上模块的实际极性——不同模块可能带反相输出。

> [!warning] 为什么中断要配「下降沿」
> 课程例程把 PB14 配成**上拉输入 + 下降沿触发**：引脚平时被内部上拉为高，**遮挡物离开槽口（从有遮挡→无遮挡）的一瞬间**电平由高变低，产生下降沿，触发一次中断，`Count` 加一。
>
> 也就是说：**「移开遮挡物」的那一下计一次数**。同理也可以配成上升沿（进遮挡时计数），改成 `EXTI_Trigger_Rising` 即可——**取决于你想数「进入」还是「离开」，不是绝对的**。

### 1.3 为什么适合用来计次

- 输出是**干净的数字开关量**，只有两种稳定状态，跳变次数就代表遮挡次数。
- 每次遮挡只产生**一对边沿**（进一次、出一次），不会像模拟量那样在一堆噪声里反复穿越阈值。
- 计数的对象是「事件发生次数」，CPU **完全不需要守着**——正是中断最适合的场景。

典型用途：**限位开关**、流水线计数、码盘测速、报警器触发。

> [!tip] 一个抖动细节
> 机械式遮挡（物体摩擦着经过槽口）在跳变沿上可能抖出多个边沿。课程的 `CountSensor.c` 是在中断函数里**再读一次引脚电平**做判断，相当于最朴素的软件消抖：

```c
if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_14) == 0)   // 确实是低电平才计数
{
    CountSensor_Count++;
}
```

> 更稳的做法是调模块上的灵敏度电位器，或者用后面第 6 章定时器的**输入滤波器**。

### 1.4 实验一：硬件接线

| 模块引脚 | 接到 | 说明 |
| --- | --- | --- |
| VCC | 3.3 V | 模块工作电压 3.3~5 V |
| GND | GND | **必须共地**，否则电平没有共同参考 |
| DO | PB14 | 数字输出 → 单片机输入引脚 |

对应 EXTI 的连线：**PB14 → AFIO 选择器 14 → EXTI Line14 → `EXTI15_10_IRQn`**。

### 1.5 实验一：完整代码

代码与 [[江协STM32 05-1 EXTI外部中断]] 第 7 节完全一致，这里给出便于对照的**精简注释版**。三个文件：`CountSensor.c` / `CountSensor.h` / `main.c`。

```c
/* ============================ CountSensor.c ============================ */
#include "stm32f10x.h"                  // Device header

uint16_t CountSensor_Count;

/**
  * 对射式红外传感器计次初始化：PB14 下降沿触发外部中断
  */
void CountSensor_Init(void)
{
	/* ① 开时钟：GPIO 和 AFIO 都是 APB2 外设，两个都开 */
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO,  ENABLE);

	/* ② GPIO：上拉输入。平时高，传感器把它拉低时产生下降沿 */
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;      // 上拉输入
	GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_14;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOB, &GPIO_InitStructure);

	/* ③ AFIO：把 PB14 接到 EXTI Line14 */
	GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource14);

	/* ④ EXTI：下降沿 + 中断模式 */
	EXTI_InitTypeDef EXTI_InitStructure;
	EXTI_InitStructure.EXTI_Line    = EXTI_Line14;
	EXTI_InitStructure.EXTI_LineCmd = ENABLE;
	EXTI_InitStructure.EXTI_Mode    = EXTI_Mode_Interrupt;
	EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Falling;
	EXTI_Init(&EXTI_InitStructure);

	/* ⑤ NVIC：EXTI15_10 是 10~15 号线的公共通道 */
	NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);

	NVIC_InitTypeDef NVIC_InitStructure;
	NVIC_InitStructure.NVIC_IRQChannel                   = EXTI15_10_IRQn;
	NVIC_InitStructure.NVIC_IRQChannelCmd                = ENABLE;
	NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;
	NVIC_InitStructure.NVIC_IRQChannelSubPriority        = 1;
	NVIC_Init(&NVIC_InitStructure);
}

/**
  * 供主循环读取计数值
  */
uint16_t CountSensor_Get(void)
{
	return CountSensor_Count;
}

/**
  * ⑥ 中断服务函数：名字固定
  *    10~15 号线共用这一个函数，必须先判断是哪条线
  */
void EXTI15_10_IRQHandler(void)
{
	if (EXTI_GetITStatus(EXTI_Line14) == SET)
	{
		if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_14) == 0)   // 软件消抖
		{
			CountSensor_Count++;
		}
		EXTI_ClearITPendingBit(EXTI_Line14);                  // 必须清标志
	}
}
```

```c
/* ============================ CountSensor.h ============================ */
#ifndef __COUNT_SENSOR_H
#define __COUNT_SENSOR_H

void CountSensor_Init(void);
uint16_t CountSensor_Get(void);

#endif
```

```c
/* ============================== main.c ================================ */
#include "stm32f10x.h"                  // Device header
#include "Delay.h"
#include "OLED.h"
#include "CountSensor.h"

int main(void)
{
	OLED_Init();
	CountSensor_Init();

	OLED_ShowString(1, 1, "Count:");

	while (1)
	{
		OLED_ShowNum(1, 7, CountSensor_Get(), 5);   // 只显示，计数在中断里做
	}
}
```

**现象**：手（或纸片）快速在槽口来回划过，OLED 上的 `Count` 每划过一次加一。用不透光的东西挡一下再拿开，也是加一。

## 2 旋转编码器

### 2.1 编码器是什么

**旋转编码器**（rotary encoder）：把旋转轴的**角度、方向、速度**转成电信号的装置。

| 类型 | 原理 | 特点 |
| --- | --- | --- |
| **机械触点式** | 内部触点随轴转动通断 | 便宜、有「格」的手感、**有抖动**、寿命有限；本课程用的是这种 |
| 霍尔式 | 磁铁 + 霍尔元件 | 无接触、寿命长、无抖动 |
| 光栅式 | 光电码盘 | 分辨率高、精度高、贵 |

课程用的机械编码器**无限位**、可以一直转，每转过一格内部会「咔」一下（detent）。

> [!note] 增量式 vs 绝对式
> 本课程用的是**增量式编码器**（incremental）：断电后不知道绝对位置，只知道「相对上次转了多少格、往哪边」。
>
> 另有**绝对式编码器**（absolute）：每个位置有唯一编码，上电即知道绝对角度。第 10 章的 MPU6050、（可选）AS5600 之类才涉及绝对位置的概念。

### 2.2 输出信号：A、B 两相正交方波

编码器有两个输出口 **A** 和 **B**，输出两路**频率相同、相位差 90°**（四分之一周期）的方波，这种关系叫**正交**（quadrature）：

```text
正转：A 超前 B 90°                        反转：B 超前 A 90°
    ┌───┐   ┌───┐   ┌───┐                     ┌───┐   ┌───┐   ┌───┐
A   │   │   │   │   │   │                 A   │   │   │   │   │   │
  ──┘   └───┘   └───┘   └──               ──┘   └───┘   └───┘   └──
      ┌───┐   ┌───┐   ┌───┐                     ┌───┐   ┌───┐   ┌───┐
B     │   │   │   │   │   │               B     │   │   │   │   │   │
  ────┘   └───┘   └───┘   └──             ──────┘   └───┘   └───┘   └
      ↑ A 先跳变                                ↑ B 先跳变
```

由下一节的硬件电路可以读出两个静态电平关系（课程板这款机械编码器）：

| 状态 | A 相 | B 相 |
| --- | --- | --- |
| 静止（停在格位上） | 高 | 高 |
| 转动过程中某一相接地 | 其中一相被拉到低 | 另一相仍为高 |

也就是说：**A、B 平时都被上拉电阻拉高；谁先被拉低，就说明往哪个方向转。**

- 一个完整周期里 A、B 一共产生 **4 个边沿**（A 升/降 + B 升/降）。
- 只接一相（如只有 A）能测**速度**和**位置增量**，但**测不出方向**——必须两相都有。
- **线数 PPR**（Pulses Per Revolution，每转脉冲数）指的是**单相**每转输出的脉冲个数。

### 2.3 判方向的两种思路

| 思路 | 做法 | 本章 / 第 6 章 |
| --- | --- | --- |
| **软件鉴相** | 两相各接一路 EXTI，中断里读另一相电平 | **本章 5-2**（手动） |
| **硬件鉴相** | 两相接 TIM 的 CH1/CH2，开编码器接口 | **第 6 章 6-7**（自动） |

本章用软件做，是因为**还没学定时器**；而且软件方案**逻辑最直观、调试最方便**，适合先把「正交信号怎么判方向」这件事理解透。到了 6-7，同一件事变成：

```text
5-2（软件）：边沿 → 中断 → CPU 读另一相 → 软件 +1/-1      CPU 全程参与
6-7（硬件）：边沿 → 编码器接口 → 自动判方向 → CNT 自增/自减   CPU 零参与
```

## 3 实验二：EXTI 手动鉴相计次

### 3.1 硬件接线

| 编码器引脚 | 接到 | EXTI |
| --- | --- | --- |
| VCC | 3.3 V | — |
| GND | GND | — |
| **A 相** | PB0 | Line0 → `EXTI0_IRQn` |
| **B 相** | PB1 | Line1 → `EXTI1_IRQn` |

两条线各占一个中断通道（Line0、Line1 都是独立通道，不共用），所以**要写两个中断服务函数**。

> [!warning] 顺序线是哪个引脚，不同资料说法不一
> 配套源码镜像里收录的示例用的是 `PB0 = A 相`、`PB1 = B 相`；也有公开笔记把两根线对调接线后正好得到相反的方向定义。**方向的正负号取决于接线与代码的配合**，只要现象对得上（正转数字增大）就没问题；接反了把两根线对调即可，或者交换代码里两相对应的分支。

### 3.2 判方向的代码逻辑

核心就一句：**「自己这一相出现下降沿时，去看另一相是不是低电平」**。

```text
A 相下降沿（EXTI0 触发）：
    B 相此时是低吗？→ 是 → 说明 A 先低、B 后低 → 逆时针 → Count--，方向 = 逆时针
B 相下降沿（EXTI1 触发）：
    A 相此时是低吗？→ 是 → 说明 B 先低、A 后低 → 顺时针 → Count++，方向 = 顺时针
```

为什么两个条件里都要判断「另一相也是低」？因为机械编码器转动时的**抖动**会在某一相上抖出多余的下降沿；只有「两相都是低」这个状态在正规转动中才出现，用它当条件能挡掉大部分毛刺，即**软件消抖**。

另外，同一次转动中两相的下降沿**不会同时发生**（有 90° 相位差），所以两个分支互斥，不会重复计数。

### 3.3 完整代码

```c
/* ============================== Encoder.c ============================= */
#include "stm32f10x.h"                  // Device header

int16_t Encoder_Count;      // 带符号：正转加、反转减
int16_t Encoder_Speed;      // 方向标志：0 = 逆时针，1 = 顺时针（沿用课程命名，存的是「方向」不是「速度」）

/**
  * 旋转编码器初始化：PB0 = A 相、PB1 = B 相，都配下降沿触发
  */
void Encoder_Init(void)
{
	/* ① 开时钟：GPIO + AFIO */
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO,  ENABLE);

	/* ② GPIO：两相都上拉输入，平时被拉高 */
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;               // 上拉输入
	GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_0 | GPIO_Pin_1;     // PB0 + PB1
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOB, &GPIO_InitStructure);

	/* ③ AFIO：PB0 → Line0，PB1 → Line1（两个引脚两条线，各调一次） */
	GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource0);
	GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource1);

	/* ④ EXTI：两条线一起配，都是下降沿 + 中断模式 */
	EXTI_InitTypeDef EXTI_InitStructure;
	EXTI_InitStructure.EXTI_Line    = EXTI_Line0 | EXTI_Line1;   // 多条线可以按位或
	EXTI_InitStructure.EXTI_LineCmd = ENABLE;
	EXTI_InitStructure.EXTI_Mode    = EXTI_Mode_Interrupt;
	EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Falling;
	EXTI_Init(&EXTI_InitStructure);

	/* ⑤ NVIC：Line0 走 EXTI0_IRQn，Line1 走 EXTI1_IRQn，是两个独立通道 */
	NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);

	NVIC_InitTypeDef NVIC_InitStructure;
	NVIC_InitStructure.NVIC_IRQChannelCmd                = ENABLE;
	NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;    // 抢占相同：两个中断互不打断
	NVIC_InitStructure.NVIC_IRQChannelSubPriority        = 1;
	NVIC_InitStructure.NVIC_IRQChannel                   = EXTI0_IRQn;
	NVIC_Init(&NVIC_InitStructure);

	NVIC_InitStructure.NVIC_IRQChannel            = EXTI1_IRQn;
	NVIC_InitStructure.NVIC_IRQChannelSubPriority = 2;           // 同时到达时 Line0 先响应
	NVIC_Init(&NVIC_InitStructure);
}

/**
  * 读「自上次调用以来」的增量并把计数清零
  * 主循环周期性调用即可得到这一段时间转了多少格
  */
int16_t Encoder_Get(void)
{
	int16_t Temp;
	Temp = Encoder_Count;
	Encoder_Count = 0;
	return Temp;
}

/**
  * ⑥ A 相（PB0）下降沿
  */
void EXTI0_IRQHandler(void)
{
	if (EXTI_GetITStatus(EXTI_Line0) == SET)
	{
		/* A 相下降沿时 B 相也是低 → A 先低，逆时针 */
		if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_0) == 0 &&
		    GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0)
		{
			Encoder_Count--;      // 逆时针：减
			Encoder_Speed = 0;
		}
		EXTI_ClearITPendingBit(EXTI_Line0);      // 必须清标志
	}
}

/**
  * ⑥ B 相（PB1）下降沿
  */
void EXTI1_IRQHandler(void)
{
	if (EXTI_GetITStatus(EXTI_Line1) == SET)
	{
		/* B 相下降沿时 A 相也是低 → B 先低，顺时针 */
		if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0 &&
		    GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_0) == 0)
		{
			Encoder_Count++;      // 顺时针：加
			Encoder_Speed = 1;
		}
		EXTI_ClearITPendingBit(EXTI_Line1);      // 必须清标志
	}
}
```

```c
/* ============================== Encoder.h ============================= */
#ifndef __ENCODER_H
#define __ENCODER_H

void Encoder_Init(void);
int16_t Encoder_Get(void);

#endif
```

```c
/* ============================== main.c ================================ */
#include "stm32f10x.h"                  // Device header
#include "Delay.h"
#include "OLED.h"
#include "Encoder.h"

int16_t Num;            // 累计值，带符号

int main(void)
{
	OLED_Init();
	Encoder_Init();

	OLED_ShowString(1, 1, "Num:");

	while (1)
	{
		Num += Encoder_Get();                    // 把增量累加进来
		OLED_ShowSignedNum(1, 5, Num, 5);        // 带符号显示，反转会变小
	}
}
```

> [!tip] 为什么用 `Encoder_Get()` 返回增量再累加，而不是直接读全局变量
> 直接读 `Encoder_Count` 也行，但**中断随时可能改动它**，主循环读到一半时数值可能已经变了（尤其是一次读多个字节时），还可能因为主循环跑得太快而**看不到变化**。
> 「**中断里累加、主循环取增量并清零**」是处理这类计数的标准套路；第 6 章的 [[江协STM32 06-8 编码器接口测速]] 测转速用的也是同一招（读 CNT → 清零 → 按闸门时间换算）。

**现象**：慢慢正转，`Num` 递增；反转，`Num` 递减；不转时数值保持不变（这点比按键/红外实验更能体现「中断只在事件发生时干活」）。

## 4 GPIO 中断函数表与两个必用函数

### 4.1 七个中断服务函数名

| 中断服务函数 | 管辖的线 | 对应引脚 |
| --- | --- | --- |
| `EXTI0_IRQHandler` | Line0 | Px0 |
| `EXTI1_IRQHandler` | Line1 | Px1 |
| `EXTI2_IRQHandler` | Line2 | Px2 |
| `EXTI3_IRQHandler` | Line3 | Px3 |
| `EXTI4_IRQHandler` | Line4 | Px4 |
| `EXTI9_5_IRQHandler` | Line5 ~ Line9（**5 条共用**） | Px5 ~ Px9 |
| `EXTI15_10_IRQHandler` | Line10 ~ Line15（**6 条共用**） | Px10 ~ Px15 |

两套写法可以直接照抄：

```c
/* 情况一：这条线独占一个中断通道（Line0 ~ Line4）——通道里只有这一条线，判断其实可省，但保留它更保险 */
void EXTI0_IRQHandler(void)
{
	if (EXTI_GetITStatus(EXTI_Line0) == SET)
	{
		/* 用户代码 */
		EXTI_ClearITPendingBit(EXTI_Line0);
	}
}

/* 情况二：多条线共用一个通道（Line5~9 或 Line10~15）——必须逐条判断 */
void EXTI15_10_IRQHandler(void)
{
	if (EXTI_GetITStatus(EXTI_Line14) == SET)
	{
		/* 用户代码 */
		EXTI_ClearITPendingBit(EXTI_Line14);
	}
	/* 还有别的线就继续往下写 if 分支 */
}
```

### 4.2 `EXTI_GetITStatus()` 与 `EXTI_ClearITPendingBit()`

这一对函数是**中断函数里唯一该用的**读取/清除函数：

```c
ITStatus EXTI_GetITStatus(uint32_t EXTI_Line);      // 返回 SET / RESET
void     EXTI_ClearITPendingBit(uint32_t EXTI_Line);
```

它俩和另一对「长得几乎一样」的函数，是本节最经典的坑：

| 函数 | 用在哪 | 干了什么 |
| --- | --- | --- |
| `EXTI_GetFlagStatus()` | **主程序** | 只读挂起标志位，**不管中断有没有使能** |
| `EXTI_ClearFlag()` | **主程序** | 清挂起标志位 |
| `EXTI_GetITStatus()` | **中断函数** | 读挂起位 **并且**判断该线的中断使能位 |
| `EXTI_ClearITPendingBit()` | **中断函数** | 清中断挂起位 |

> [!warning] 中断里必须清标志
> `EXTI_PR`（请求挂起寄存器）是**写 1 清零**，而且**置位后一直保持 1**，不会自动清。
>
> 中断函数里漏掉 `EXTI_ClearITPendingBit()` 的后果：CPU 退出中断函数的一瞬间，发现挂起位还是 1 → 立刻再次进入同一个中断函数 → 无限循环，**主循环彻底卡死**，表现为 OLED 不再刷新、程序像死机。
>
> 这是本章最高频的 bug，且现象极具迷惑性（看起来像「程序卡在第一次中断」）。

### 4.3 为什么用 `EXTI_GetITStatus()` 而不是直接 `if (1)`

`EXTI15_10_IRQHandler` 被 6 条线共用、`EXTI9_5_IRQHandler` 被 5 条线共用。假设 `Line10` 和 `Line14` 都配了中断：

```c
/* 错误写法一：不判断，Line10 来了也会当成 Line14 处理，还把 Line14 的标志清了 */
void EXTI15_10_IRQHandler(void)
{
	CountSensor_Count++;
	EXTI_ClearITPendingBit(EXTI_Line14);
}

/* 正确写法 */
void EXTI15_10_IRQHandler(void)
{
	if (EXTI_GetITStatus(EXTI_Line14) == SET)   // 是我这条线吗？
	{
		CountSensor_Count++;
		EXTI_ClearITPendingBit(EXTI_Line14);    // 只清自己这条
	}
	if (EXTI_GetITStatus(EXTI_Line10) == SET)   // 别的线继续判断
	{
		/* ... */
		EXTI_ClearITPendingBit(EXTI_Line10);
	}
}
```

### 4.4 中断优先级该怎么定（本集两个实验的对照）

| 实验 | 用了几路中断 | 抢占 | 响应 | 说明 |
| --- | --- | --- | --- | --- |
| 实验一 红外计次 | 1 路（`EXTI15_10_IRQn`） | 随便填 | 随便填 | 只有一个中断源，优先级无实际影响 |
| 实验二 编码器计次 | 2 路（`EXTI0_IRQn`、`EXTI1_IRQn`） | 都填 1 | 1 和 2 | **抢占必须相同**，否则两个中断会互相打断 |

> [!tip] 为什么编码器的两路中断抢占优先级要相同
> 如果 A 相中断抢占优先级高于 B 相，A 相中断函数执行到一半时来了 B 相边沿，B 会被挂起等待——本来能立刻读到的「另一相电平」在等待期间可能已经变了，判定就会出错。
>
> 抢占相同 → **互不打断、顺序执行**，每次判定用到的那一相电平都还是「刚跳变时」的值。响应优先级不同只是为了同时到达时有个确定顺序。

## 5 与第 6 章 6-7 的对照

同一个问题（编码器计数），两种解法。这张表是本章最有价值的一张表：

| | 5-2 EXTI 手动鉴相 | 6-7 TIM 编码器接口 |
| --- | --- | --- |
| 需要的知识 | 中断、EXTI、NVIC（本章） | 定时器、编码器接口（第 6 章） |
| 引脚 | 任意 GPIO（PB0 / PB1） | 必须接在 **TIMx_CH1 / CH2** 上（TIM3 默认是 PA6 / PA7） |
| 鉴相 | **软件**：中断里读另一相 | **硬件**：编码器接口自动判断 |
| 计数 | 软件变量 `Encoder_Count` | 定时器的 **CNT 寄存器** |
| 边沿利用率 | 只用了**下降沿**（2 个边沿/周期） | TI12 模式用**全部 4 个边沿**（4 倍频） |
| CPU 占用 | 每次跳变都进中断，**转速越高越忙** | **完全零占用**，只在读结果时看一眼 CNT |
| 能测的速度上限 | 受中断响应时间限制（机械编码器手转没问题） | 很高（硬件计数，几十 kHz 以上都轻松） |
| 位置 / 方向 / 速度 | 位置 ✅ 方向 ✅ 速度需要软件算 | 位置 ✅ 方向 ✅ 速度 ✅（配闸门时间读增量） |
| 抗抖动 | 靠软件「读到低电平才算」 | 可用输入滤波器（硬件滤波） |
| 典型场景 | 少量、低速、教学与调试 | **电机闭环控制**、高速测速 |

一句话总结这层衔接：**5-2 把「正交信号怎么判方向」这件事讲透了，6-7 只是把这段逻辑从软件搬进了硬件。** 先写一遍软件版，再看 6-7 的 `TIM_EncoderInterfaceConfig()`，会非常顺。

详见 [[江协STM32 06-7 TIM编码器接口]] 与 [[江协STM32 06-8 编码器接口测速]]。

## 6 易错点

- [ ] 红外模块的 **DO 极性**没先用万用表确认，把上升沿配成了下降沿 → 数出来的次数是对的，但「计数时刻」和预期相反（进遮挡 / 出遮挡）。
- [ ] 红外模块和编码器**忘了共地**（VCC 接了、GND 没接）→ 电平漂移，计数乱跳。
- [ ] `EXTI15_10_IRQHandler` 里**没判断是哪条线** → 误清其他线的标志，丢中断。
- [ ] 中断函数里漏 `EXTI_ClearITPendingBit()` → 死循环卡在中断里。
- [ ] 用了 `EXTI_GetFlagStatus()` 配 `EXTI_ClearITPendingBit()` 这种**混搭** → 判断与清除的对象不一致，行为不可预测。
- [ ] 编码器两相**放到同一个中断通道**（例如都接 PB0/PB1 却只配了 `EXTI0_IRQn`）→ Line1 的中断没人接。
- [ ] 编码器两路中断的**抢占优先级填得不一样** → 一个中断会打断另一个，方向判定出错。
- [ ] 直接在主循环读 `Encoder_Count` 累加，同时又忘了清零 → 数值飞涨；或忘了用 `int16_t` 存方向（用 `uint16_t` 反转就下溢成大正数）。
- [ ] 编码器**转得太快**时漏数：软件方案一次中断只能处理一个边沿，转速超过中断响应能力就会丢格。
- [ ] 把对射式红外传感器当**反射式**用（一个模块收发同侧）→ 收不到信号。对射式必须把遮挡物**放进槽中间**。
- [ ] 用第 3 章的**按键**思路给编码器加 `Delay_ms()` 消抖 → 中断里延时是禁忌，会把整个系统拖死。

## 7 自测

1. 对射式红外传感器在槽中「无遮挡」时 DO 输出是高还是低？课程的例程为什么要配成下降沿触发？
2. 编码器的 A、B 两相是什么关系？为什么只接一相就测不出方向？
3. 5-2 的中断函数里，A 相下降沿时为什么要判断 B 相是不是低电平？不判断会怎样？
4. `EXTI_GetITStatus()` 和 `EXTI_GetFlagStatus()` 有什么区别？分别在什么场合用？
5. 同一个编码器，5-2 的软件方案和 6-7 的编码器接口方案，各有什么优劣？为什么电机测速要用后者？

> [!success]- 参考答案
> 1. **低电平**（接收管收到光而导通，把 DO 拉低）；有遮挡时才输出高电平。配成下降沿，意味着在「遮挡物离开槽口、由遮挡变无遮挡」的那一刻计数。
> 2. A、B 是**频率相同、相位差 90° 的正交方波**。方向信息完全藏在「谁超前谁」里面，只接一相只能得到「转了多少个脉冲」，拿不到先后关系，所以**只能测速度/位置、测不出方向**。
> 3. 因为要靠「另一相此刻的电平」判断谁先跳变：A 相下降沿时 B 相还是低 → A 先低 → 逆时针。同时这个条件还兼任**软件消抖**——抖动产生的孤立下降沿往往另一相还是高电平，会被这条判断挡掉。不判断的话毛刺也会计数，且无法区分方向。
> 4. `EXTI_GetITStatus()` 除了读挂起位，**还会判断该线的中断使能位**，是给中断服务函数用的；`EXTI_GetFlagStatus()` 只读挂起位、不看使能位，适合在主程序里查询状态。清标志同理：中断里用 `EXTI_ClearITPendingBit()`，主程序里用 `EXTI_ClearFlag()`。
> 5. 软件方案**每次跳变都要进中断**、只利用下降沿（2 倍频）、转速高时来不及处理会丢数，但逻辑直观、引脚随意、易调试；硬件方案由**编码器接口自动鉴相计数**、用全部 4 个边沿（4 倍频，分辨率更高）、CPU 零参与，但**引脚必须接在 TIMx_CH1/CH2 上**。电机闭环控制转速高、采样频繁，软件方案会一直占着 CPU 甚至丢数，所以必须用硬件方案。
