# 10-3 软件 I2C 读写 MPU6050

> [!abstract] 这一集只解决一个问题
> **怎么用两根普通 GPIO，把 I2C 的时序一位一位地「敲」出来？**
>
> 答：把 I2C 拆成**引脚配置层**和**协议层**两层。引脚配置层只会三件事——写 SCL、写 SDA、读 SDA；协议层用这三个动作拼出起始、终止、收发字节、收发应答这**六个基本时序**；再由 `MPU6050.c` 用这六个时序拼出「写寄存器 / 读寄存器 / 取数据」。
>
> 上一集 [[江协STM32 10-2 MPU6050简介]] ｜ 下一集 [[江协STM32 10-4 I2C通信外设]] ｜ 章索引 [[江协STM32 10 I2C（章索引）]]

## 1 工程里的文件分工

官方工程目录 `10-1 软件I2C读写MPU6050` 里本集相关的文件：

| 文件 | 所在目录 | 职责 |
| --- | --- | --- |
| `MyI2C.c` / `MyI2C.h` | `Hardware\` | 软件模拟 I2C：引脚配置层 + 协议层 |
| `MPU6050.c` / `MPU6050.h` | `Hardware\` | 用 MyI2C 的六个时序，封装寄存器读写与数据获取 |
| `MPU6050_Reg.h` | `Hardware\` | MPU6050 寄存器地址宏 |
| `main.c` | `User\` | 初始化 + OLED 显示 |
| `OLED.c` / `OLED.h` | `Hardware\` | 沿用第 4 章（它自己内部也是软件 I2C，走 PB8/PB9） |
| `Delay.c` / `Delay.h` | `System\` | 沿用 1-3 的 SysTick 延时，`MyI2C.c` 靠它做微秒延时 |

`MyI2C.c` 被官方用两个注释块切成了两半，这就是本集的主线：

```c
/*引脚配置层*/
... MyI2C_W_SCL / MyI2C_W_SDA / MyI2C_R_SDA / MyI2C_Init ...

/*协议层*/
... MyI2C_Start / MyI2C_Stop / MyI2C_SendByte /
    MyI2C_ReceiveByte / MyI2C_SendAck / MyI2C_ReceiveAck ...
```

**协议层只认电平、不认引脚**；想换引脚，只改引脚配置层。

## 2 接线：SCL = PB10，SDA = PB11

| 信号 | 单片机引脚 | 官方源码写法 | 官方接线图 |
| --- | --- | --- | --- |
| SCL | PB10 | `GPIOB` + `GPIO_Pin_10` | 黄线，接 MPU6050 模块丝印 `SCL` |
| SDA | PB11 | `GPIOB` + `GPIO_Pin_11` | 绿线，接 MPU6050 模块丝印 `SDA` |
| 电源 | 3.3 V / GND | — | 红线接模块 `VCC`、蓝线接模块 `GND` |

MPU6050 模块在接线图上引出 8 个引脚，丝印顺序是
`INT`、`AD0`、`XCL`、`XDA`、`SDA`、`SCL`、`GND`、`VCC`。
本集只用到 `SDA`、`SCL`、`GND`、`VCC`；`AD0` 悬空，即从机地址最低位为 0。

> [!tip] 为什么软件 I2C 能自己挑引脚
> 因为时序完全由程序控制，SCL/SDA 只是两根**普通 GPIO**，接 PA0/PA1 也照样能做，只要改引脚配置层里的 `GPIOB` 和 `GPIO_Pin_x`。
> 到 10-5 换成硬件 I2C 就不能随便挑了：硬件 I2C2 的 SCL/SDA 固定复用在这两个脚上（PB10 = `I2C2_SCL`、PB11 = `I2C2_SDA`），所以 10-1 与 10-2 的接线图是同一张。

## 3 引脚配置层

### 3.1 官方原文

```c
#include "stm32f10x.h"                  // Device header
#include "Delay.h"

/*引脚配置层*/

/**
  * 函    数：I2C写SCL引脚电平
  * 参    数：BitValue 协议层传入的当前需要写入SCL的电平，范围0~1
  * 返 回 值：无
  * 注意事项：此函数需要用户实现内容，当BitValue为0时，需要置SCL为低电平，当BitValue为1时，需要置SCL为高电平
  */
void MyI2C_W_SCL(uint8_t BitValue)
{
	GPIO_WriteBit(GPIOB, GPIO_Pin_10, (BitAction)BitValue);		//根据BitValue，设置SCL引脚的电平
	Delay_us(10);												//延时10us，防止时序频率超过要求
}

/**
  * 函    数：I2C写SDA引脚电平
  * 参    数：BitValue 协议层传入的当前需要写入SDA的电平，范围0~1
  * 返 回 值：无
  * 注意事项：此函数需要用户实现内容，当BitValue为0时，需要置SDA为低电平，当BitValue为1时，需要置SDA为高电平
  */
void MyI2C_W_SDA(uint8_t BitValue)
{
	GPIO_WriteBit(GPIOB, GPIO_Pin_11, (BitAction)BitValue);		//根据BitValue，设置SDA引脚的电平，BitValue要实现非0即1的特性
	Delay_us(10);												//延时10us，防止时序频率超过要求
}

/**
  * 函    数：I2C读SDA引脚电平
  * 参    数：无
  * 返 回 值：协议层需要得到的当前SDA的电平，范围0~1
  * 注意事项：此函数需要用户实现内容，当前SDA为低电平时，返回0，当前SDA为高电平时，返回1
  */
uint8_t MyI2C_R_SDA(void)
{
	uint8_t BitValue;
	BitValue = GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_11);		//读取SDA电平
	Delay_us(10);												//延时10us，防止时序频率超过要求
	return BitValue;											//返回SDA电平
}
```

注意 `MyI2C_R_SDA` 用的是 `GPIO_ReadInputDataBit`——**开漏输出模式下，读输入数据寄存器拿到的是引脚上的真实电平**，所以读之前不用切换成输入模式。

### 3.2 GPIO 为什么必须配成开漏输出

```c
/*开启时钟*/
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);	//开启GPIOB的时钟
```

```c
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;
GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_Init(GPIOB, &GPIO_InitStructure);					//将PB10和PB11引脚初始化为开漏输出
```

- `GPIO_Mode_Out_OD` 在 `stm32f10x_gpio.h` 的 `GPIOMode_TypeDef` 里枚举值是 `0x14`。
- 课件 Slide 128 的原话：所有 I2C 设备的 SCL 连在一起、SDA 连在一起；**设备的 SCL 和 SDA 均要配置成开漏输出模式**；SCL 和 SDA 各添加一个上拉电阻，阻值一般为 **4.7 KΩ** 左右。
- 开漏的含义：引脚**只能主动拉低，不能主动拉高**。想输出高电平就「释放」引脚，由上拉电阻把线拉上去。这样多个设备同时挂在一条线上，谁拉低都不会打架——这就是 I2C 能挂多设备的硬件前提。

**上电后第一件事是把两条线都置 1（释放总线）**，官方原文最后一行就是干这个的：

```c
/*设置默认电平*/
GPIO_SetBits(GPIOB, GPIO_Pin_10 | GPIO_Pin_11);			//设置PB10和PB11引脚初始化后默认为高电平（释放总线状态）
```

I2C 的两条线在**空闲态都是高电平**（起始条件就是「SCL 高电平期间 SDA 从高变低」）。如果初始化后引脚停在低电平，等于有一根线被死死拉住，起始条件根本发不出来，后面全部时序都会错。

### 3.3 微秒延时：软件 I2C 的速率就是这么定的

`MyI2C_W_SCL`、`MyI2C_W_SDA`、`MyI2C_R_SDA` 三个函数里，每个动作后面都跟一句 `Delay_us(10)`。官方注释只有一句：

```c
Delay_us(10);		//延时10us，防止时序频率超过要求
```

`Delay_us` 来自 `1-3 Delay函数模块`，是 SysTick 轮询式延时：

```c
void Delay_us(uint32_t xus)
{
	SysTick->LOAD = 72 * xus;				//设置定时器重装值
	SysTick->VAL = 0x00;					//清空当前计数值
	SysTick->CTRL = 0x00000005;				//设置时钟源为HCLK，启动定时器
	while(!(SysTick->CTRL & 0x00010000));	//等待计数到0
	SysTick->CTRL = 0x00000004;				//关闭定时器
}
```

按官方的 10 µs 参数推算速率：

```text
发送一位的过程： W_SDA(位) → W_SCL(1) → W_SCL(0)
                  每一步内部各含 10us 延时
SCL 高电平时间 ≈ 10 us     （W_SCL(1) 内的延时）
SCL 低电平时间 ≈ 10 us     （W_SCL(0) 内的延时）
SCL 周期      ≈ 20 us   →  f_SCL ≈ 50 kHz
```

> [!warning] 50 kHz 是推算值，不是源码里的注释
> 官方 `MyI2C.c` 里**没有**写频率数字，`50 kHz` 是我按「SCL 高低各 10 µs」算出来的，算式已在上方列出，可自行验算。
> 延时越小 I2C 越快，但不能超过从机的承受能力。课件 Slide 140 里的「标准速度（高达 100 kHz）、快速（高达 400 kHz）」说的是 **STM32 硬件 I2C 外设**；**MPU6050 这一侧的 I2C 速率上限在课件与官方源码中未见**，已列入「待核对」。

## 4 协议层：六个基本时序

### 4.1 `MyI2C_Start` 起始条件

```c
/**
  * 函    数：I2C起始
  * 参    数：无
  * 返 回 值：无
  */
void MyI2C_Start(void)
{
	MyI2C_W_SDA(1);							//释放SDA，确保SDA为高电平
	MyI2C_W_SCL(1);							//释放SCL，确保SCL为高电平
	MyI2C_W_SDA(0);							//在SCL高电平期间，拉低SDA，产生起始信号
	MyI2C_W_SCL(0);							//起始后把SCL也拉低，即为了占用总线，也为了方便总线时序的拼接
}
```

为什么最后还要把 SCL 拉低？官方注释给了两个理由：

1. **占用总线**——起始条件发出后 SCL 就归主机控制；
2. **方便时序拼接**——后面的 `SendByte` 是「先摆 SDA 再抬 SCL」，如果起始结束时 SCL 停在低电平，紧接着就能直接摆第一位数据，不用再做多余动作。

### 4.2 `MyI2C_Stop` 终止条件

```c
/**
  * 函    数：I2C终止
  * 参    数：无
  * 返 回 值：无
  */
void MyI2C_Stop(void)
{
	MyI2C_W_SDA(0);							//拉低SDA，确保SDA为低电平
	MyI2C_W_SCL(1);							//释放SCL，使SCL呈现高电平
	MyI2C_W_SDA(1);							//在SCL高电平期间，释放SDA，产生终止信号
}
```

终止条件 = 「SCL 高电平期间 SDA 从低变高」。所以先把 SDA 拉低垫底，再抬 SCL，最后释放 SDA。

### 4.3 `MyI2C_SendByte` 发送一个字节

```c
/**
  * 函    数：I2C发送一个字节
  * 参    数：Byte 要发送的一个字节数据，范围：0x00~0xFF
  * 返 回 值：无
  */
void MyI2C_SendByte(uint8_t Byte)
{
	uint8_t i;
	for (i = 0; i < 8; i ++)				//循环8次，主机依次发送数据的每一位
	{
		/*两个!可以对数据进行两次逻辑取反，作用是把非0值统一转换为1，即：!!(0) = 0，!!(非0) = 1*/
		MyI2C_W_SDA(!!(Byte & (0x80 >> i)));//使用掩码的方式取出Byte的指定一位数据并写入到SDA线
		MyI2C_W_SCL(1);						//释放SCL，从机在SCL高电平期间读取SDA
		MyI2C_W_SCL(0);						//拉低SCL，主机开始发送下一位数据
	}
}
```

**官方确实用了 `!!`**，原文就是 `MyI2C_W_SDA(!!(Byte & (0x80 >> i)));`，而且专门加了一行注释解释它：

```c
/*两个!可以对数据进行两次逻辑取反，作用是把非0值统一转换为1，即：!!(0) = 0，!!(非0) = 1*/
```

三点细节：

- 掩码是 `0x80 >> i`，从**最高位**开始取，即**高位先行**（课件 Slide 130）；
- 数据是在 **SCL 低电平期间**摆到 SDA 上的，摆好后才抬 SCL，让从机在 SCL 高电平期间读（课件 Slide 130：SCL 高电平期间 SDA 不允许有数据变化）；
- `!!` 有没有都「能跑」：库函数 `GPIO_WriteBit` 内部写的是 `if (BitVal != Bit_RESET) GPIOx->BSRR = GPIO_Pin;`，非 0 值一样会把引脚置高。但 `GPIO_WriteBit` 开头有 `assert_param(IS_GPIO_BIT_ACTION(BitVal))`，而 `IS_GPIO_BIT_ACTION` 只认 `Bit_RESET` / `Bit_SET`——本工程的 `stm32f10x_conf.h` 里 `USE_FULL_ASSERT` 是注释掉的、`assert_param` 退化成空语句，所以不写 `!!` 也不会当场报错。官方写 `!!` 就是让传进去的值严格落在 0 和 1 上。

### 4.4 `MyI2C_ReceiveByte` 接收一个字节

```c
/**
  * 函    数：I2C接收一个字节
  * 参    数：无
  * 返 回 值：接收到的一个字节数据，范围：0x00~0xFF
  */
uint8_t MyI2C_ReceiveByte(void)
{
	uint8_t i, Byte = 0x00;					//定义接收的数据，并赋初值0x00，此处必须赋初值0x00，后面会用到
	MyI2C_W_SDA(1);							//接收前，主机先确保释放SDA，避免干扰从机的数据发送
	for (i = 0; i < 8; i ++)				//循环8次，主机依次接收数据的每一位
	{
		MyI2C_W_SCL(1);						//释放SCL，主机机在SCL高电平期间读取SDA
		if (MyI2C_R_SDA()){Byte |= (0x80 >> i);}	//读取SDA数据，并存储到Byte变量
													//当SDA为1时，置变量指定位为1，当SDA为0时，不做处理，指定位为默认的初值0
		MyI2C_W_SCL(0);						//拉低SCL，从机在SCL低电平期间写入SDA
	}
	return Byte;							//返回接收到的一个字节数据
}
```

为什么必须在开头 `MyI2C_W_SDA(1)`？因为**发送时 SDA 是主机驱动的，接收时 SDA 要交给从机驱动**。主机不先松手，就会和从机抢线。官方注释写得很直白：`接收前，主机先确保释放SDA，避免干扰从机的数据发送`。课件 Slide 131 也有这句：`主机在接收之前，需要释放 SDA`。

### 4.5 `MyI2C_SendAck` 发送应答

```c
/**
  * 函    数：I2C发送应答位
  * 参    数：Byte 要发送的应答位，范围：0~1，0表示应答，1表示非应答
  * 返 回 值：无
  */
void MyI2C_SendAck(uint8_t AckBit)
{
	MyI2C_W_SDA(AckBit);					//主机把应答位数据放到SDA线
	MyI2C_W_SCL(1);							//释放SCL，从机在SCL高电平期间，读取应答位
	MyI2C_W_SCL(0);							//拉低SCL，开始下一个时序模块
}
```

**0 = 应答（ACK），1 = 非应答（NACK）**（课件 Slide 132）。

### 4.6 `MyI2C_ReceiveAck` 接收应答

```c
/**
  * 函    数：I2C接收应答位
  * 参    数：无
  * 返 回 值：接收到的应答位，范围：0~1，0表示应答，1表示非应答
  */
uint8_t MyI2C_ReceiveAck(void)
{
	uint8_t AckBit;							//定义应答位变量
	MyI2C_W_SDA(1);							//接收前，主机先确保释放SDA，避免干扰从机的数据发送
	MyI2C_W_SCL(1);							//释放SCL，主机机在SCL高电平期间读取SDA
	AckBit = MyI2C_R_SDA();					//将应答位存储到变量里
	MyI2C_W_SCL(0);							//拉低SCL，开始下一个时序模块
	return AckBit;							//返回定义应答位变量
}
```

### 4.7 六个时序的动作小结

| 时序 | SDA 什么时候变 | SCL 高电平期间 SDA 的状态 | 是否有第 9 个时钟 |
| --- | --- | --- | --- |
| `Start` | SCL 高时拉低 | 从高变低 | — |
| `Stop` | SCL 高时释放 | 从低变高 | — |
| `SendByte` | SCL 低时摆位 | 保持不变，供从机读 | 否（8 位后再单独收发应答） |
| `ReceiveByte` | 由从机在 SCL 低时摆位 | 保持不变，供主机读 | 否 |
| `SendAck` | SCL 低时摆应答位 | 保持不变，供从机读 | 是（第 9 个时钟） |
| `ReceiveAck` | 由从机在 SCL 低时摆位 | 保持不变，供主机读 | 是（第 9 个时钟） |

## 5 `MyI2C_Init` 与 `MyI2C.h`

```c
/**
  * 函    数：I2C初始化
  * 参    数：无
  * 返 回 值：无
  * 注意事项：此函数需要用户实现内容，实现SCL和SDA引脚的初始化
  */
void MyI2C_Init(void)
{
	/*开启时钟*/
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);	//开启GPIOB的时钟
	
	/*GPIO初始化*/
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOB, &GPIO_InitStructure);					//将PB10和PB11引脚初始化为开漏输出
	
	/*设置默认电平*/
	GPIO_SetBits(GPIOB, GPIO_Pin_10 | GPIO_Pin_11);			//设置PB10和PB11引脚初始化后默认为高电平（释放总线状态）
}
```

## 6 MPU6050 寄存器地址

`MPU6050_Reg.h` 官方原文，本集用到的全部地址都在这里：

```c
#ifndef __MPU6050_REG_H
#define __MPU6050_REG_H

#define	MPU6050_SMPLRT_DIV		0x19
#define	MPU6050_CONFIG			0x1A
#define	MPU6050_GYRO_CONFIG		0x1B
#define	MPU6050_ACCEL_CONFIG	0x1C

#define	MPU6050_ACCEL_XOUT_H	0x3B
#define	MPU6050_ACCEL_XOUT_L	0x3C
#define	MPU6050_ACCEL_YOUT_H	0x3D
#define	MPU6050_ACCEL_YOUT_L	0x3E
#define	MPU6050_ACCEL_ZOUT_H	0x3F
#define	MPU6050_ACCEL_ZOUT_L	0x40
#define	MPU6050_TEMP_OUT_H		0x41
#define	MPU6050_TEMP_OUT_L		0x42
#define	MPU6050_GYRO_XOUT_H		0x43
#define	MPU6050_GYRO_XOUT_L		0x44
#define	MPU6050_GYRO_YOUT_H		0x45
#define	MPU6050_GYRO_YOUT_L		0x46
#define	MPU6050_GYRO_ZOUT_H		0x47
#define	MPU6050_GYRO_ZOUT_L		0x48

#define	MPU6050_PWR_MGMT_1		0x6B
#define	MPU6050_PWR_MGMT_2		0x6C
#define	MPU6050_WHO_AM_I		0x75

#endif
```

| 寄存器 | 地址 | 本集用途 |
| --- | --- | --- |
| `MPU6050_PWR_MGMT_1` | `0x6B` | 写 `0x01`：取消睡眠模式，时钟源选 X 轴陀螺仪 |
| `MPU6050_PWR_MGMT_2` | `0x6C` | 写 `0x00`：所有轴均不待机 |
| `MPU6050_SMPLRT_DIV` | `0x19` | 写 `0x09`：采样率分频 |
| `MPU6050_CONFIG` | `0x1A` | 写 `0x06`：配置 DLPF |
| `MPU6050_GYRO_CONFIG` | `0x1B` | 写 `0x18`：陀螺仪满量程 ±2000 °/s |
| `MPU6050_ACCEL_CONFIG` | `0x1C` | 写 `0x18`：加速度计满量程 ±16 g |
| `MPU6050_ACCEL_*OUT_H/L` | `0x3B` ~ `0x40` | 读加速度计 X/Y/Z 各 16 位 |
| `MPU6050_GYRO_*OUT_H/L` | `0x43` ~ `0x48` | 读陀螺仪 X/Y/Z 各 16 位 |

## 7 `MPU6050.c`：写寄存器 / 读寄存器 / 初始化 / 取数据

### 7.1 从机地址

```c
#define MPU6050_ADDRESS		0xD0		//MPU6050的I2C从机地址
```

课件 Slide 137：MPU6050 的 I2C 从机地址是 `1101000`（AD0 = 0）、`1101001`（AD0 = 1）。
`0xD0` = `1101 0000`，即 7 位地址 `1101000` 左移一位后**读写位补 0**，正好是「写」的方向。

### 7.2 `MPU6050_WriteReg` 指定地址写

```c
/**
  * 函    数：MPU6050写寄存器
  * 参    数：RegAddress 寄存器地址，范围：参考MPU6050手册的寄存器描述
  * 参    数：Data 要写入寄存器的数据，范围：0x00~0xFF
  * 返 回 值：无
  */
void MPU6050_WriteReg(uint8_t RegAddress, uint8_t Data)
{
	MyI2C_Start();						//I2C起始
	MyI2C_SendByte(MPU6050_ADDRESS);	//发送从机地址，读写位为0，表示即将写入
	MyI2C_ReceiveAck();					//接收应答
	MyI2C_SendByte(RegAddress);			//发送寄存器地址
	MyI2C_ReceiveAck();					//接收应答
	MyI2C_SendByte(Data);				//发送要写入寄存器的数据
	MyI2C_ReceiveAck();					//接收应答
	MyI2C_Stop();						//I2C终止
}
```

对应课件 Slide 133 的「指定地址写」时序：
`Start → 从机地址(写) → ACK → 寄存器地址 → ACK → 数据 → ACK → Stop`。

### 7.3 `MPU6050_ReadReg` 指定地址读

```c
/**
  * 函    数：MPU6050读寄存器
  * 参    数：RegAddress 寄存器地址，范围：参考MPU6050手册的寄存器描述
  * 返 回 值：读取寄存器的数据，范围：0x00~0xFF
  */
uint8_t MPU6050_ReadReg(uint8_t RegAddress)
{
	uint8_t Data;
	
	MyI2C_Start();						//I2C起始
	MyI2C_SendByte(MPU6050_ADDRESS);	//发送从机地址，读写位为0，表示即将写入
	MyI2C_ReceiveAck();					//接收应答
	MyI2C_SendByte(RegAddress);			//发送寄存器地址
	MyI2C_ReceiveAck();					//接收应答
	
	MyI2C_Start();						//I2C重复起始
	MyI2C_SendByte(MPU6050_ADDRESS | 0x01);	//发送从机地址，读写位为1，表示即将读取
	MyI2C_ReceiveAck();					//接收应答
	Data = MyI2C_ReceiveByte();			//接收指定寄存器的数据
	MyI2C_SendAck(1);					//发送应答，给从机非应答，终止从机的数据输出
	MyI2C_Stop();						//I2C终止
	
	return Data;
}
```

三个要点：

1. **中间那次 `MyI2C_Start()` 是「重复起始」（Repeated Start）**，官方注释写的就是「I2C重复起始」，课件 Slide 135 的「指定地址读」画的正是这个 `Sr`。它的作用是——先把「要读哪个地址」告诉从机，然后**不释放总线**、直接重新起手，把方向翻成「读」。
2. **地址最后一位决定方向**：`MPU6050_ADDRESS` 是 `0xD0`（最低位 0=写），`MPU6050_ADDRESS | 0x01` = `0xD1`（最低位 1=读）。
3. **读完一个字节要发非应答 `MyI2C_SendAck(1)`**，官方注释：`给从机非应答，终止从机的数据输出`。因为这里只读 1 个字节，主机用 NACK 告诉从机「别给了」，然后 Stop。

### 7.4 `MPU6050_Init`

```c
/**
  * 函    数：MPU6050初始化
  * 参    数：无
  * 返 回 值：无
  */
void MPU6050_Init(void)
{
	MyI2C_Init();									//先初始化底层的I2C
	
	/*MPU6050寄存器初始化，需要对照MPU6050手册的寄存器描述配置，此处仅配置了部分重要的寄存器*/
	MPU6050_WriteReg(MPU6050_PWR_MGMT_1, 0x01);		//电源管理寄存器1，取消睡眠模式，选择时钟源为X轴陀螺仪
	MPU6050_WriteReg(MPU6050_PWR_MGMT_2, 0x00);		//电源管理寄存器2，保持默认值0，所有轴均不待机
	MPU6050_WriteReg(MPU6050_SMPLRT_DIV, 0x09);		//采样率分频寄存器，配置采样率
	MPU6050_WriteReg(MPU6050_CONFIG, 0x06);			//配置寄存器，配置DLPF
	MPU6050_WriteReg(MPU6050_GYRO_CONFIG, 0x18);	//陀螺仪配置寄存器，选择满量程为±2000°/s
	MPU6050_WriteReg(MPU6050_ACCEL_CONFIG, 0x18);	//加速度计配置寄存器，选择满量程为±16g
}
```

注意第一行是 `MyI2C_Init()`——**软件 I2C 的引脚初始化是在 MPU6050 的初始化里顺带做的**，这也说明 10-5 换硬件版本时，改的就正好是这一段。

> [!note] `0x18` 为什么是这两个量程
> 官方注释直接给出了结论（±2000 °/s、±16 g）。课件 Slide 137 列出的可选量程是：加速度计 ±2 / ±4 / ±8 / ±16（g），陀螺仪 ±250 / ±500 / ±1000 / ±2000（° / sec）。
> **寄存器位与量程的对应关系（为什么写 `0x18`）在课件与官方源码中未见**，不在本页展开。

### 7.6 `MPU6050_GetData` 读六个轴

```c
/**
  * 函    数：MPU6050获取数据
  * 参    数：AccX AccY AccZ 加速度计X、Y、Z轴的数据，使用输出参数的形式返回，范围：-32768~32767
  * 参    数：GyroX GyroY GyroZ 陀螺仪X、Y、Z轴的数据，使用输出参数的形式返回，范围：-32768~32767
  * 返 回 值：无
  */
void MPU6050_GetData(int16_t *AccX, int16_t *AccY, int16_t *AccZ, 
						int16_t *GyroX, int16_t *GyroY, int16_t *GyroZ)
{
	uint8_t DataH, DataL;								//定义数据高8位和低8位的变量
	
	DataH = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_H);		//读取加速度计X轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_L);		//读取加速度计X轴的低8位数据
	*AccX = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_ACCEL_YOUT_H);		//读取加速度计Y轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_ACCEL_YOUT_L);		//读取加速度计Y轴的低8位数据
	*AccY = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_ACCEL_ZOUT_H);		//读取加速度计Z轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_ACCEL_ZOUT_L);		//读取加速度计Z轴的低8位数据
	*AccZ = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_GYRO_XOUT_H);		//读取陀螺仪X轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_GYRO_XOUT_L);		//读取陀螺仪X轴的低8位数据
	*GyroX = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_GYRO_YOUT_H);		//读取陀螺仪Y轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_GYRO_YOUT_L);		//读取陀螺仪Y轴的低8位数据
	*GyroY = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_GYRO_ZOUT_H);		//读取陀螺仪Z轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_GYRO_ZOUT_L);		//读取陀螺仪Z轴的低8位数据
	*GyroZ = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
}
```

数据拼接的处理方式：

| 步骤 | 官方写法 | 说明 |
| --- | --- | --- |
| 取高 8 位 | `DataH = MPU6050_ReadReg(..._H);` | 例如 `0x3B`（`ACCEL_XOUT_H`） |
| 取低 8 位 | `DataL = MPU6050_ReadReg(..._L);` | 例如 `0x3C`（`ACCEL_XOUT_L`） |
| 拼接 | `*AccX = (DataH << 8) \| DataL;` | 高 8 位左移 8 位后与低 8 位按位或，得到一个 16 位量 |
| 转有符号 | 赋值给 `int16_t *` 形参 | 输出参数本身就是 `int16_t *`，官方注释标明范围 `-32768~32767` |

> [!warning] 官方源码里没有换算公式
> `MPU6050_GetData` 归还的是**原始值**（官方注释：范围 `-32768~32767`），`main.c` 直接把原始值交给 `OLED_ShowSignedNum` 显示。整个工程里**没有**把原始值换算成 g 或 °/s 的代码，课件里也没有给出换算公式，所以本页不写公式。
>
> 另外，官方对「有符号数」的处理就是**把拼接结果直接赋给 `int16_t` 型输出参数**，函数注释里也只写了「数据拼接，通过输出参数返回」，没有额外讨论符号位。

## 8 `main.c` 与现象

```c
#include "stm32f10x.h"                  // Device header
#include "Delay.h"
#include "OLED.h"
#include "MPU6050.h"

uint8_t ID;								//定义用于存放ID号的变量
int16_t AX, AY, AZ, GX, GY, GZ;			//定义用于存放各个数据的变量

int main(void)
{
	/*模块初始化*/
	OLED_Init();		//OLED初始化
	MPU6050_Init();		//MPU6050初始化
	
	/*显示ID号*/
	OLED_ShowString(1, 1, "ID:");		//显示静态字符串
	ID = MPU6050_GetID();				//获取MPU6050的ID号
	OLED_ShowHexNum(1, 4, ID, 2);		//OLED显示ID号
	
	while (1)
	{
		MPU6050_GetData(&AX, &AY, &AZ, &GX, &GY, &GZ);		//获取MPU6050的数据
		OLED_ShowSignedNum(2, 1, AX, 5);					//OLED显示数据
		OLED_ShowSignedNum(3, 1, AY, 5);
		OLED_ShowSignedNum(4, 1, AZ, 5);
		OLED_ShowSignedNum(2, 8, GX, 5);
		OLED_ShowSignedNum(3, 8, GY, 5);
		OLED_ShowSignedNum(4, 8, GZ, 5);
	}
}
```

OLED 的屏幕布局（行列都从 1 开始）：

| 行 | 第 1 列起 | 第 8 列起 |
| --- | --- | --- |
| 1 | `ID:` + 2 位十六进制 ID | — |
| 2 | `AX` | `GX` |
| 3 | `AY` | `GY` |
| 4 | `AZ` | `GZ` |

现象：OLED 第 1 行显示 ID 号（正常应为 `0x68`），下面是加速度三轴与陀螺仪三轴的**原始值**，晃动传感器数值跟着变。

> [!note] 关于 ID 号的具体数值
> 官方 `main.c` 只把 `MPU6050_GetID()` 的返回值按 2 位十六进制显示，**源码与课件中都没有写死这个值应该是多少**。课件 Slide 137 只给了从机地址 `1101000`。所以「正常显示 0x68」是常见经验值，**不作为官方依据**，已列入「待核对」。

## 9 易错点

- [ ] 忘记把 SCL/SDA 配成 `GPIO_Mode_Out_OD` 开漏输出，而是配成 `GPIO_Mode_Out_PP` 推挽 → 总线上多个设备会互相「顶牛」，读回来的电平也不对。
- [ ] 初始化后忘了 `GPIO_SetBits()` 把两条线置 1（释放总线）→ 总线不是空闲态，起始条件发不出来。
- [ ] 发送时忘了 `!!`（或任何把掩码结果归一到 0/1 的手段），把 `0x80` 这类值直接传给 `GPIO_WriteBit` → 本工程因为 `USE_FULL_ASSERT` 没开而侥幸能跑，但语义上已经不合法。
- [ ] `MyI2C_ReceiveByte` 忘了 `Byte = 0x00` 初值 → 读回来的字节里混进垃圾位，越高位越容易错。
- [ ] 接收前忘了 `MyI2C_W_SDA(1)` 释放 SDA → 主机和从机抢线，数据全乱。
- [ ] `MPU6050_ReadReg` 里的第二次起始写成 `MyI2C_Stop()` + `MyI2C_Start()` → 那就变成两次独立传输，中间总线被释放，从机的地址指针可能失效；官方用的是**重复起始**。
- [ ] 读方向忘了把地址最低位置 1（`MPU6050_ADDRESS | 0x01`）→ 从机仍然按「写」来理解，读回的数据无效。
- [ ] 读完最后一个字节忘了 `MyI2C_SendAck(1)`（非应答）→ 从机会继续输出下一个字节的数据，占住 SDA，后面 `Stop` 起不来。
- [ ] 把延时 `Delay_us(10)` 一路砍小去「提速」→ 超过从机的承受能力（MPU6050 侧上限见「待核对」）；反过来把延时加得很大，只是变慢不会错。
- [ ] 以为 `MPU6050_GetData` 出来的就是「多少个 g」→ 官方给的是原始值，工程里没有换算。
- [ ] 在 `MPU6050_Init` 里自己又写了一遍 GPIO 初始化、忘了 `MyI2C_Init()` 已经在里面了 → 重复初始化，虽然不致命但容易漏掉默认电平那一步。

## 10 自测

1. `MyI2C_SendByte` 里的 `!!(Byte & (0x80 >> i))` 为什么用两个 `!`？直接写 `(Byte & (0x80 >> i))` 会怎样？
2. SCL/SDA 为什么必须配成 `GPIO_Mode_Out_OD`？课件给的硬件电路上还要求加什么元件？
3. `MyI2C_ReceiveByte` 里 `Byte` 为什么一定要先赋 `0x00`？`MyI2C_ReceiveAck` 开头为什么先写 `MyI2C_W_SDA(1)`？
4. `MPU6050_ReadReg` 中间那次 `MyI2C_Start()` 叫什么？如果改成 `MyI2C_Stop()` 再 `MyI2C_Start()` 有什么问题？
5. 官方三个引脚函数里每步都延时 10 µs，据此推算 SCL 大约是多少赫兹？改成 `Delay_us(1)` 大约变成多少？

> [!success]- 参考答案
> 1. `!!` 是两次逻辑取反，作用是把非 0 值统一转换成 1：`!!(0) = 0`，`!!(非 0) = 1`（这就是官方那一行注释的原话）。`Byte & (0x80 >> i)` 的结果是 `0x80`、`0x40`…或 `0`，直接传进 `GPIO_WriteBit` 时，本工程因为 `USE_FULL_ASSERT` 是注释掉的、`assert_param` 为空，功能上仍会把引脚置高；但 `GPIO_WriteBit` 的形参是 `BitAction` 枚举，合法值只有 `Bit_RESET` / `Bit_SET`，写 `!!` 才是语义正确的做法。
> 2. 因为 I2C 总线上可以挂多个设备，开漏输出**只能主动拉低、不能主动拉高**，高电平靠上拉电阻给出，这样谁拉低都不会冲突（课件 Slide 128 原话：设备的 SCL 和 SDA 均要配置成开漏输出模式）。课件还要求 SCL、SDA 各加一个上拉电阻，阻值一般 4.7 KΩ 左右。
> 3. `Byte` 必须初始化成 `0x00`，因为接收循环里只在「读到 1」时才 `Byte |= (0x80 >> i)`，读到 0 的那一位不做任何处理、保持初值；如果初值不是 0，这些位就会是垃圾。`MyI2C_ReceiveAck` 开头先 `MyI2C_W_SDA(1)` 是为了**释放 SDA**，把线的驱动权让给从机，避免主机和从机同时驱动同一条线。
> 4. 那叫**重复起始（Repeated Start，课件时序图里写作 `Sr`）**。它的作用是：先把「要读哪个寄存器」告诉从机，然后**不释放总线**直接重新起手，把方向翻成「读」。如果改成 `Stop` + `Start`，中间总线被释放，从机的内部地址指针可能不再指向刚才那个寄存器，读回来的就不是想要的数据了。
> 5. 每一位的 SCL 高电平时间 ≈ `Delay_us(10)`，低电平时间 ≈ `Delay_us(10)`，周期 ≈ 20 µs，所以 `f_SCL ≈ 1 / 20 us = 50 kHz`。换成 `Delay_us(1)` 后周期 ≈ 2 µs，`f_SCL ≈ 500 kHz`——已经超过 I2C 快速模式的 400 kHz，可能从机跟不上（**注意这是推算值，官方源码里没有写频率**；课件 Slide 140 的 100 kHz/400 kHz 说的是 STM32 硬件 I2C 外设）。
