# 10-1 I2C 通信协议

> [!abstract] 这一集只解决一个问题
> **只有两根线，怎么让总线上好几个设备「各说各话」而不打架？**
>
> 答：SCL 提供节拍，SDA 传数据。所有设备的 SCL 拧在一起、SDA 也拧在一起，**谁都不许主动输出高电平**（开漏），只能「拉低」或者「放手」。于是「谁说低谁说了算」——这一条同时解决了**多点并联**、**多个主机抢总线**和**时钟互相等待**三个问题。剩下的全部内容，都是在这根线上定义「什么波形算开始说话、什么波形算说完了」。
>
> 这一集是**纯理论集**，官方**没有**对应工程目录。所有时序都能在 10-3 的 `MyI2C.c` 里找到一一对应的代码，本页在必要时引用它作为「协议 → 代码」的落点。
>

## 1 I2C 是什么

课件 Slide 127 的原话：

> I2C（Inter IC Bus）是由 Philips 公司开发的一种通用数据总线
> 两根通信线：SCL（Serial Clock）、SDA（Serial Data）
> 同步，半双工
> 带数据应答
> 支持总线挂载多设备（一主多从、多主多从）

把这五句话拆开看：

| 特性 | 含义 | 后果 |
| --- | --- | --- |
| **两根通信线** | SCL 管节拍、SDA 管数据 | 省引脚，但**一次只能传 1 位**，速度上不去 |
| **同步** | 数据位靠**时钟线**对齐，不靠双方约定的波特率 | 允许从机**拉长时钟**来给自己争取时间（时钟拉伸） |
| **半双工** | 一根数据线，同一时刻只能一个方向传 | 收发必须**分时**，而且要规定「这一拍谁在驱动 SDA」 |
| **带数据应答** | 每传完一个字节，接收方回 1 位 ACK/NACK | 发送方能立刻知道对方在不在、收没收下 |
| **支持多设备** | 一主多从、多主多从 | 必须靠**地址**点名，还要能处理多主机冲突 |

> [!tip] 和 USART 的一句话对比
> USART 是**异步**的：没有时钟线，靠双方各自数够 8 位；所以它只能**点对点**（外加 RS-485 那种物理层改造）。
> I2C 是**同步**的：有时钟线，每一位都有明确的采样时刻；所以它可以挂一长串设备，代价是每传一个字节要多花 1 位应答。

### 1.1 SCL 和 SDA 分别是谁的

| 线 | 全称 | 谁产生 | 作用 |
| --- | --- | --- | --- |
| **SCL** | Serial Clock | **主机**产生（从机只能拉伸，不能主动产生） | 每一位的节拍，高电平期间被采样 |
| **SDA** | Serial Data | 发的一方驱动 | 数据位，**高位先行** |

两条线都是**双向**的：主机要读数据时，从机驱动 SDA；主机要发数据时，主机驱动 SDA。同一根线要能双向，正是它必须开漏的原因（见第 2 节）。

### 1.2 地址与读写位

总线上每个从机都有**唯一的地址**。STM32 的硬件 I2C 支持 **7 位地址**和 **10 位地址**两种模式（课件 Slide 140），本课程用的 MPU6050 是 7 位地址。

一次传输的**第一个字节**固定是「地址 + 方向」：

```text
bit7  bit6  bit5  bit4  bit3  bit2  bit1  bit0
 A6    A5    A4    A3    A2    A1    A0    R/W
 └──────────── 7 位从机地址 ────────────┘   └ 0=写 1=读
```

以本课程 MPU6050 为例，从机地址 `1101000`（课件 Slide 137），拼上读写位：

| 操作 | 第 1 个字节 | 怎么来的 |
| --- | --- | --- |
| 写 | `0xD0` = `1101 0000` | 7 位地址 `1101000` 左移 1 位，低位补 `0` |
| 读 | `0xD1` = `1101 0001` | 同上，低位补 `1` |

> [!warning] 手册上的地址和代码里的字节不是同一个数
> 手册写 `1101000`（7 位），代码写 `0xD0`（8 位）。**代码里的值 = 7 位地址 × 2**，因为第 8 位被读写方向占掉了。
> 第 4 章 OLED 的 `0x78` 也是这么来的（`0x3C` 左移一位），**同一个道理**，不要以为是两套规则。
> 也正因为如此，读的时候要 `地址 | 0x01`，而**不是** `地址 | 0x80`。

## 2 硬件电路：为什么必须开漏 + 上拉

课件 Slide 128 的原话：

> 所有 I2C 设备的 SCL 连在一起，SDA 连在一起
> 设备的 SCL 和 SDA 均要配置成**开漏输出**模式
> SCL 和 SDA 各添加一个**上拉电阻**，阻值一般为 **4.7KΩ** 左右

对应的电路长这样：

```text
                    +VDD
                     │
                   ┌─┴─┐   ┌─┴─┐
                   │ R │   │ R │      ← 上拉电阻（课件：一般 4.7 kΩ 左右）
                   └─┬─┘   └─┬─┘
   ┌───────┐         │       │
   │  CPU  │─────────┴───┬───┴────────  SDA ──┬─────┬─────┐
   │ (主机)│             │                    │     │     │
   │       │─────────────┴────────────────  SCL ─┬───┬───┬─┘
   └───────┘        （所有设备并联在同一对线上）  │   │   │
                                            ┌──┴─┐┌──┴─┐┌──┴─┐
                                            │从机1││从机2││从机3│  …… 每个从机都是 SCL + SDA
                                            └────┘└────┘└────┘
```

### 2.1 开漏输出 = 只能「拉低」或「放手」

STM32 的 GPIO 配成开漏输出后，输出级只剩一个**下拉 MOS 管**：

```text
        ┌──────────── 引脚
        │
   ┌────┴────┐
   │  MOS 管  │   ← 写 1：MOS 管截止 → 引脚「放手」，被上拉电阻拉到高
   └────┬────┘      写 0：MOS 管导通 → 引脚被强行拉到低
        │
       GND
```

所以写「1」在开漏模式下**不是输出高电平，而是松开引脚**。这一点在代码里也看得出来——官方 `MyI2C.c` 里把「写 1」直接注释成**「释放」**：

```c
/**
  * 函    数：I2C起始
  * 参    数：无
  * 返 回 值：无
  */
void MyI2C_Start(void)
{
	MyI2C_W_SDA(1);							//释放SDA，确保SDA为高电平
	MyI2C_W_SCL(1);							//释放SCL，确保SCL为高电平
	MyI2C_W_SDA(0);							//在SCL高电平期间，拉低SDA，产生起始信号
	MyI2C_W_SCL(0);							//起始后把SCL也拉低，即为了占用总线，也为了方便总线时序的拼接
}
```

### 2.2 为什么非开漏不可

三个理由，缺一不可：

**① 多点并联不能打架（线与）**

如果把两根线配成**推挽输出**，一个设备想输出高、另一个想输出低，电源和地之间就通过两个 MOS 管直接短路了——**这是会烧引脚的**。

开漏之后没有「输出高」这个动作，只有「拉低」和「放手」，于是：

- 任何一个设备拉低 → 线就是**低**
- 所有设备都放手 → 上拉电阻把线拉**高**

这就是所谓「**线与**」：总线电平 = 所有设备输出的逻辑与。冲突不再是短路，而变成一次可解释的电平。

**② 双向传输**

同一根 SDA，主机发数据时主机驱动、主机收数据时从机驱动。因为开漏下「放手」就等于「不管这根线」，所以**谁放手，线就交给别人**——不需要额外的方向控制引脚。代码里这一点体现得非常直白：接收前一定先「释放 SDA」：

```c
uint8_t MyI2C_ReceiveByte(void)
{
	uint8_t i, Byte = 0x00;					//定义接收的数据，并赋初值0x00，此处必须赋初值0x00，后面会用到
	MyI2C_W_SDA(1);							//接收前，主机先确保释放SDA，避免干扰从机的数据发送
	...
```

**③ 多主机仲裁与时钟同步（多主多从的前提）**

- **仲裁**：两个主机同时发数据时，谁发出「1」而线上却是「0」，谁就立刻知道自己输了，主动退出并转为从机。**这种比较只有在线与结构下才成立**——如果是推挽，早就短路了。STM32 硬件 I2C 里对应的就是仲裁丢失错误（RM0008 中 `SR1` 的 `ARLO` 位）。
- **时钟同步**：SCL 也是线与的。只要有一个主机把 SCL 拉低，SCL 就是低。于是**慢的主机会自动把快的主机拖慢**，双方不用事先商量速度。

> [!note] 这三点里，哪一点是官方材料写明的
> 三点原理本身都对，但**出处层次不同**，用的时候心里要有数：
> - 「设备 SCL / SDA 均要配置成开漏输出」「各加上拉电阻，一般 4.7 kΩ 左右」是**课件 Slide 128 的原话**（已直接引用，属最高依据）。
> - 「多主机能力」在 **RM0008 第 26.1 节**有明确表述：I2C 接口「provides multimaster capability, and controls all I2C bus-specific sequencing, protocol, arbitration and timing」。
> - 「线与」「总线仲裁」「时钟同步」**这三个词，课件文本、官方源码、官方接线图里都没有出现**；它们出自 I2C 总线的通用原理与 RM0008 的 arbitration 机制描述，本页按通用原理讲，**不把它们写成课件原话**。

### 2.3 上拉电阻为什么是「一般 4.7 kΩ 左右」

上拉电阻的值是两个方向的折中：

| 阻值太小 | 阻值太大 |
| --- | --- |
| 灌电流大，从机开漏管可能扛不住 | 上升沿变慢（RC 充电变慢），高速下还没升到高就该采样了 |
| 抗干扰好、边沿陡 | 抗干扰差、边沿缓 |

从机开漏管把线拉低时，电流是 `VDD / R` 直接灌进这个管子的。所以阻值不能太小；而 I2C 的上升沿完全靠这个电阻给总线电容充电，所以阻值也不能太大——**总线挂的设备越多、线越长，电容越大，上拉电阻就得越小**。

> [!note] 与总线电容有关的那个数
> MPU6050 官方产品规格书 `PS-MPU-6000A.pdf` 的 I2C 快速模式时序表里给了两条相邻的约束：
> 「Capacitive Load for each Bus Line **< 400 pF**」与「SDA and SCL Rise Time … bus cap. from 10 to 400pF … 300 ns」。
> 也就是说：**单条总线的电容上限是 400 pF**，上升时间随电容增大而变长。
> 课件与 RM0008 里**都没有**这个「400 pF」的数，本页的数字出处是 MPU6050 官方规格书，特此说明。

### 2.4 本课程模块上的实际接法

课程资料包 `模块资料.zip` → `13-MPU6050 陀螺仪加速度计\MPU6050-V1-SCH.jpg` 是这块模块的**官方原理图**：

| 元件 | 作用 |
| --- | --- |
| `R4` = **4.7 kΩ**、`R5` = **4.7 kΩ** | 分别接在 `SDA`、`SCL` 上，另一头到 `VCC_3.3V`——**模块板载上拉** |
| `R6` = **4.7 kΩ** | 接在 `AD0` 上，另一头接地（与模块丝印旁标注的「4.7 k」一致） |
| `Q2` + `C3`/`C10`/`C12` | 3.3 V LDO 与滤波电容，所以模块 `VCC` 可以接 5 V |
| `D1` | 电源指示灯 |
| `J2`（`SCL`/`SDA`）与 `J1`（`XDA`/`XCL`/`AD0`/`INT`） | 两组引出排针 |

这解释了为什么本课程**没有额外插上拉电阻**：模块板上已经带了。

> [!warning] 能查到的和查不到的
> 「模块板载 4.7 kΩ 上拉」有**官方原理图**支持（`MPU6050-V1-SCH.jpg`，R4/R5 = 4.7 k）；
> 但**课件与官方源码里没有提这件事**，视频里老师是否讲过、怎么讲的，本页无法核实。
> 另：`AD0` 上的 `R6 = 4.7 kΩ` 接地这一点，课件与 `RM-MPU-6000A.pdf` 都**没有**提，只有模块原理图上画着，本页如实标明出处。

## 3 时序基本单元

课件把 I2C 拆成 **6 个基本单元**（Slide 129~132）。这 6 个拼起来就是全部 I2C 通信。

### 3.1 起始条件（Start）

> SCL 高电平期间，SDA 从高电平切换到低电平

```text
SCL  ────────┐           ┌────────
             └───────────┘
SDA  ─────────────┐
                  └──────────────
             ↑
      这一拍 SCL 是高，SDA 却动了 → 从机判定「有人要开始说话了」
```

注意顺序：**先确保两根线都是高（总线空闲）**，再在 SCL 保持高的情况下把 SDA 拉低。官方代码正是这个顺序（见 2.1 引用的 `MyI2C_Start`）。

### 3.2 终止条件（Stop）

> SCL 高电平期间，SDA 从低电平切换到高电平

```text
SCL  ────────┐           ┌────────
             └───────────┘
SDA                     ┌──────────
        ────────────────┘
                        ↑
                 这一拍 SCL 是高，SDA 由低变高 → 从机判定「说完了，总线释放」
```

```c
/**
  * 函    数：I2C终止
  * 参    数：无
  * 返 回 值：无
  */
void MyI2C_Stop(void)
{
	MyI2C_W_SDA(0);							//拉低SDA，确保SDA为低电平
	MyI2C_W_SCL(1);							//释放SCL，使SCL呈现高电平
	MyI2C_W_SDA(1);							//在SCL高电平期间，释放SDA，产生终止信号
}
```

> [!warning] 起始 / 终止共同依赖的同一条铁律
> **只有在 SCL 高电平期间，SDA 的跳变才有「特殊含义」。**
> SCL 低电平期间 SDA 随便怎么翻都行（那是正常的数据准备）。这也正是「数据位只在 SCL 低电平期间改变」的原因——**如果不遵守，就会凭空多出一个起始或终止条件**。

### 3.3 数据有效性：SCL 高电平期间 SDA 必须稳定

课件 Slide 130 / 131 把发送和接收分开写，但其实说的是同一件事：

> 发送一个字节：SCL 低电平期间，主机将数据位依次放到 SDA 线上（**高位先行**），然后释放 SCL，从机将在 SCL 高电平期间读取数据位，所以 **SCL 高电平期间 SDA 不允许有数据变化**，依次循环上述过程 8 次，即可发送一个字节
>
> 接收一个字节：SCL 低电平期间，**从机**将数据位依次放到 SDA 线上（高位先行），然后释放 SCL，**主机**将在 SCL 高电平期间读取数据位，所以 SCL 高电平期间 SDA 不允许有数据变化，依次循环上述过程 8 次，即可接收一个字节（**主机在接收之前，需要释放 SDA**）

两条只有一个区别——**谁在驱动 SDA**：

| | 发送字节 | 接收字节 |
| --- | --- | --- |
| SCL 低电平期间谁放数据 | **主机** | **从机** |
| SCL 高电平期间谁读数据 | 从机 | 主机 |
| 主机的额外动作 | — | **读之前先释放 SDA** |

> [!tip] 一句话记住
> **数据在 SCL 低电平期间「换」，在 SCL 高电平期间「被读」。**

官方代码把这条规则实现得极为直白——`MyI2C_SendByte()` 里，先摆 SDA，再抬 SCL，再落 SCL：

```c
/**
  * 函    数：I2C发送一个字节
  * 参    数：Byte 要发送的一个字节数据，范围：0x00~0xFF
  * 返 回 值：无
  */
void MyI2C_SendByte(uint8_t Byte)
{
	uint8_t i;
	for (i = 0; i < 8; i ++)				//循环8次，主机依次发送数据的每一位
	{
		/*两个!可以对数据进行两次逻辑取反，作用是把非0值统一转换为1，即：!!(0) = 0，!!(非0) = 1*/
		MyI2C_W_SDA(!!(Byte & (0x80 >> i)));//使用掩码的方式取出Byte的指定一位数据并写入到SDA线
		MyI2C_W_SCL(1);						//释放SCL，从机在SCL高电平期间读取SDA
		MyI2C_W_SCL(0);						//拉低SCL，主机开始发送下一位数据
	}
}
```

`0x80 >> i` 就是从最高位开始取，所以是**高位先行（MSB first）**。

```c
/**
  * 函    数：I2C接收一个字节
  * 参    数：无
  * 返 回 值：接收到的一个字节数据，范围：0x00~0xFF
  */
uint8_t MyI2C_ReceiveByte(void)
{
	uint8_t i, Byte = 0x00;					//定义接收的数据，并赋初值0x00，此处必须赋初值0x00，后面会用到
	MyI2C_W_SDA(1);							//接收前，主机先确保释放SDA，避免干扰从机的数据发送
	for (i = 0; i < 8; i ++)				//循环8次，主机依次接收数据的每一位
	{
		MyI2C_W_SCL(1);						//释放SCL，主机机在SCL高电平期间读取SDA
		if (MyI2C_R_SDA()){Byte |= (0x80 >> i);}	//读取SDA数据，并存储到Byte变量
													//当SDA为1时，置变量指定位为1，当SDA为0时，不做处理，指定位为默认的初值0
		MyI2C_W_SCL(0);						//拉低SCL，从机在SCL低电平期间写入SDA
	}
	return Byte;							//返回接收到的一个字节数据
}
```

注意这里 `Byte` **必须初值 `0x00`**：代码只在读到 `1` 的时候置位，读到 `0` 时「不做处理」，靠的就是初值里的 0。

### 3.4 应答 ACK / 非应答 NACK

> **发送应答**：主机在接收完一个字节之后，在下一个时钟发送一位数据，数据 `0` 表示应答，数据 `1` 表示非应答
> **接收应答**：主机在发送完一个字节之后，在下一个时钟接收一位数据，判断从机是否应答，数据 `0` 表示应答，数据 `1` 表示非应答（主机在接收之前，需要释放 SDA）

也就是：**每 8 位数据之后必然跟着第 9 个时钟**，这一拍专门用来回答「收到了吗」。

| 场景 | 谁驱动第 9 拍 | `0` 的含义 | `1` 的含义 |
| --- | --- | --- | --- |
| 主机**发**完一个字节 | **从机** | ACK：我收到了 | NACK：我不在 / 我不收了 |
| 主机**收**完一个字节 | **主机** | ACK：继续发下一个字节 | NACK：够了，别再发了 |

```c
/**
  * 函    数：I2C发送应答位
  * 参    数：Byte 要发送的应答位，范围：0~1，0表示应答，1表示非应答
  * 返 回 值：无
  */
void MyI2C_SendAck(uint8_t AckBit)
{
	MyI2C_W_SDA(AckBit);					//主机把应答位数据放到SDA线
	MyI2C_W_SCL(1);							//释放SCL，从机在SCL高电平期间，读取应答位
	MyI2C_W_SCL(0);							//拉低SCL，开始下一个时序模块
}

/**
  * 函    数：I2C接收应答位
  * 参    数：无
  * 返 回 值：接收到的应答位，范围：0~1，0表示应答，1表示非应答
  */
uint8_t MyI2C_ReceiveAck(void)
{
	uint8_t AckBit;							//定义应答位变量
	MyI2C_W_SDA(1);							//接收前，主机先确保释放SDA，避免干扰从机的数据发送
	MyI2C_W_SCL(1);							//释放SCL，主机机在SCL高电平期间读取SDA
	AckBit = MyI2C_R_SDA();					//将应答位存储到变量里
	MyI2C_W_SCL(0);							//拉低SCL，开始下一个时序模块
	return AckBit;							//返回定义应答位变量
}
```

> [!note] 应答位用得上、也可以不用
> 第 4 章的 OLED 驱动**发了时钟但不去读 ACK**（`OLED.c` 里那两行注释写着「额外的一个时钟，不处理应答信号」），因为 SSD1306 只写不读、不需要判断。
> 本课程从 10-3 开始**要读**数据，`MyI2C_ReceiveAck()` 就必须真的去读 SDA 了——代码里它被调用了很多次，但**返回值并没有被判断**（`MPU6050.c` 里是 `MyI2C_ReceiveAck();` 独立一行，没有 `if`）。也就是说：**时序收全了，但没有做错误处理**。

## 4 一次完整传输长什么样

把基本单元串起来，**「指定地址写」**（课件 Slide 133：对于指定设备 Slave Address，在指定地址 Reg Address 下，写入指定数据 Data）的完整流程是：

```text
      ┌─起始─┐ ┌──── 第 1 个字节 ────┐ ┌应答┐ ┌──── 第 2 个字节 ────┐ ┌应答┐ ┌──── 第 3 个字节 ────┐ ┌应答┐ ┌─终止─┐
SDA ──┘      └─┤ A6 A5 A4 A3 A2 A1 A0 0 ├──────┤ R7 R6 ... ... ... R0 ├──────┤ D7 D6 ... ... ... D0 ├──────└──────
SCL ────────────────────────────────────────────────────────────────────────────────────────────────────────────
                ↑                       ↑      ↑                    ↑      ↑                    ↑
           从机地址（7 位）          读写位=0  寄存器地址           从机回  要写入的数据         从机回
                                        （写）  Reg Address          ACK                        ACK
```

每一步「谁在拉低 SDA」，可以逐拍列清楚：

| 阶段 | 谁驱动 SDA | 内容 |
| --- | --- | --- |
| 起始条件 | **主机** | SCL 高时把 SDA 拉低 |
| 第 1 个字节（地址 + 写） | **主机** | `1101000` + `0` |
| 第 1 个应答位 | **从机** | 拉低 SDA 表示「这个地址是我」 |
| 第 2 个字节（寄存器地址） | **主机** | 从机内部把地址指针指到这里 |
| 第 2 个应答位 | **从机** | 拉低表示「地址收下了」 |
| 第 3 个字节（数据） | **主机** | 写进刚才指定的寄存器 |
| 第 3 个应答位 | **从机** | 拉低表示「数据写完了」 |
| 终止条件 | **主机** | SCL 高时把 SDA 放开（低→高） |

对应到官方 `MPU6050.c`：

```c
#define MPU6050_ADDRESS		0xD0		//MPU6050的I2C从机地址

/**
  * 函    数：MPU6050写寄存器
  * 参    数：RegAddress 寄存器地址，范围：参考MPU6050手册的寄存器描述
  * 参    数：Data 要写入寄存器的数据，范围：0x00~0xFF
  * 返 回 值：无
  */
void MPU6050_WriteReg(uint8_t RegAddress, uint8_t Data)
{
	MyI2C_Start();						//I2C起始
	MyI2C_SendByte(MPU6050_ADDRESS);	//发送从机地址，读写位为0，表示即将写入
	MyI2C_ReceiveAck();					//接收应答
	MyI2C_SendByte(RegAddress);			//发送寄存器地址
	MyI2C_ReceiveAck();					//接收应答
	MyI2C_SendByte(Data);				//发送要写入寄存器的数据
	MyI2C_ReceiveAck();					//接收应答
	MyI2C_Stop();						//I2C终止
}
```

> [!warning] 「谁在拉低 SDA」是本章最容易含糊过去的一点
> 一句话概括：**主机想说话的时候拉低 SDA，其余时间放手；从机只在「应答位」和「主机读数据的数据位」这两种时刻拉低 SDA。**
> 也正因为如此，主机在**读**之前必须先放手（`MyI2C_W_SDA(1)`），否则主机把线拉低、从机想输出高，读回来的永远是 0。

## 5 四种读写时序

课件 Slide 133~135 给了三种，实际常用的是四种组合。它们的差别只在「第 1 个字节的读写位」和「谁是数据的驱动方」。

### 5.1 指定地址写（Slide 133）

```text
起始 → 地址+W → ACK → 寄存器地址 → ACK → 数据 → ACK → 终止
```

上面第 4 节已完整给出。**从机内部有一个「地址指针」，第 2 个字节就是把它搬到指定位置。**

### 5.2 当前地址读（Slide 134）

```text
起始 → 地址+R → ACK → 数据 ← NACK(主机发) → 终止
```

> 对于指定设备（Slave Address），在**当前地址指针**指示的地址下，读取从机数据（Data）

它不指定寄存器地址，直接读「地址指针现在指着的那个寄存器」。指针会在每次读写后自动 +1，所以连读很方便——**但前提是你知道指针现在在哪**。上电后指针是 0，所以一般还是配合 5.1 或 5.3 用。

### 5.3 指定地址读（Slide 135）

```text
起始 → 地址+W → ACK → 寄存器地址 → ACK ─┐
                                        │  ← 注意：这里没有「终止」，而是「重复起始」
起始 → 地址+R → ACK → 数据 ← NACK(主机发) → 终止
```

**为什么「读之前要先写一次」？**

因为从机没有「地址」这个引脚——你没法像 SPI 那样用片选之外的地址线告诉它「我要读哪个寄存器」。寄存器地址只能**通过数据线发过去**，而「发数据」这个方向就是写。所以流程必然是：

1. **先写**：把「我想读哪个寄存器」写进从机的地址指针（这一步并不写入数据）
2. **再读**：从当前指针读出数据

两次之间用**重复起始条件（Repeated Start）**衔接：不发出终止条件、不释放总线，而是再发一次起始。

```c
/**
  * 函    数：MPU6050读寄存器
  * 参    数：RegAddress 寄存器地址，范围：参考MPU6050手册的寄存器描述
  * 返 回 值：读取寄存器的数据，范围：0x00~0xFF
  */
uint8_t MPU6050_ReadReg(uint8_t RegAddress)
{
	uint8_t Data;
	
	MyI2C_Start();						//I2C起始
	MyI2C_SendByte(MPU6050_ADDRESS);	//发送从机地址，读写位为0，表示即将写入
	MyI2C_ReceiveAck();					//接收应答
	MyI2C_SendByte(RegAddress);			//发送寄存器地址
	MyI2C_ReceiveAck();					//接收应答
	
	MyI2C_Start();						//I2C重复起始
	MyI2C_SendByte(MPU6050_ADDRESS | 0x01);	//发送从机地址，读写位为1，表示即将读取
	MyI2C_ReceiveAck();					//接收应答
	Data = MyI2C_ReceiveByte();			//接收指定寄存器的数据
	MyI2C_SendAck(1);					//发送应答，给从机非应答，终止从机的数据输出
	MyI2C_Stop();						//I2C终止
	
	return Data;
}
```

> [!warning] 三个最容易错的细节
> 1. **第一次操作不能 `MyI2C_Stop()`**。如果两次之间发了终止，总线就被释放了，从机的地址指针也可能复位——必须用重复起始「一口气说下去」。
> 2. **第二次的地址要 `| 0x01`**（读），不是 `| 0x80`。
> 3. **读完最后一个字节必须发非应答**（`MyI2C_SendAck(1)`）。官方注释写得很清楚：「发送应答，给从机**非应答**，终止从机的数据输出」。如果这里发的是应答，从机会以为你还要，继续占着 SDA 往下发。

### 5.4 连续读多个字节

在 5.3 的基础上，把「读一个字节 + 发应答(0)」重复 n−1 次，最后再「读一个字节 + 发非应答(1) + 终止」：

```text
… 地址+R → ACK → 数据0 → ACK(0) → 数据1 → ACK(0) → … → 数据n → NACK(1) → 终止
```

**注意应答位正是这 8 位之后的第 9 拍**，所以「继续读」和「到此为止」完全由主机的这 1 位决定。本课程**没有用**连续读——官方 `MPU6050_GetData()` 是老老实实一字节一字节读的（`MPU6050.c` 里 12 次调用 `MPU6050_ReadReg`）。

> [!note] 关于这几种时序的命名
> 「指定地址写 / 当前地址读 / 指定地址读」这三个名字是**课件 Slide 133~135 的标题原话**，本页照搬。
> 「重复起始条件（Repeated Start）」这个词**课件文本与官方源码注释里都没有出现**——官方 `MyI2C.c` 第 40 行的注释写的是「I2C**重复起始**」，指的是同一个动作。本页用「重复起始」这一表述。

## 6 速率与总线电容

I2C 的速率不是随便定的，标准里划了档：

| 档位 | 最高速率 | 出处 |
| --- | --- | --- |
| 标准模式（Sm，Standard mode） | **100 kHz** | 课件 Slide 140；RM0008 第 26.1 节 |
| 快速模式（Fm，Fast mode） | **400 kHz** | 课件 Slide 140；RM0008 第 26.1 节 |

RM0008 第 26.1 节原文：

> It supports the standard mode (Sm, up to 100kHz) and Fm mode (Fm, up to 400 kHz).

这两档速率**同时是 I2C 器件的上限**：MPU6050 官方产品规格书 `PS-MPU-6000A.pdf` 第 9 节写着「The internal registers and memory of the MPU-6000/MPU-6050 can be accessed using either I2C at **400 kHz** or SPI at 1MHz」。

速率上不去的**物理原因**是总线电容：

- 每个挂在总线上的器件引脚都有几 pF 的输入电容，走线自身也有分布电容；
- 开漏输出的**上升沿**完全靠上拉电阻给这些电容充电（`RC` 充电），**下降沿**才是 MOS 管主动拉低（快得多）；
- 电容越大，上升越慢；速率越高，一个位周期越短，上升沿占的比例就越大，**还没升到判决门限就该采样了**。

MPU6050 官方规格书给了三条定量约束：

| 参数 | 条件 | 值 |
| --- | --- | --- |
| Capacitive Load for each Bus Line | — | **< 400 pF** |
| SDA and SCL Rise Time | bus cap. from 10 to 400 pF | **300 ns** |
| SCL Clock Frequency（快速模式） | — | **400 kHz** |

所以工程上的经验是：**挂得越多、线越长 → 电容越大 → 上拉电阻取小一些**（如 2.2 kΩ）；只用一两个模块时 4.7 kΩ 足够。

> [!warning] 别把「速率」和「软件 I2C 的延时」搞混
> 官方 `MyI2C.c` 里每个电平动作后面都跟了 `Delay_us(10)`（注释：「延时10us，防止时序频率超过要求」）。
> 一个位周期里要翻 2 次 SCL，每次动作各带 10 μs 延时，实际速率**远低于 100 kHz**。这是**故意的**——STM32 跑 72 MHz，不延时的话 GPIO 翻转速度会冲到几 MHz，远超器件上限，通信反而会失败。
> 也就是说：**软件 I2C 的「速率」是由你的延时决定的**，这是它和硬件 I2C 最大的手感差别之一。

## 7 软件 I2C 与硬件 I2C

同一个协议，两种实现方式。这张表把差别一次说清：

| 对比项 | **软件 I2C**（10-3） | **硬件 I2C**（10-4 / 10-5） |
| --- | --- | --- |
| 实现方式 | 用两个普通 GPIO 手工翻电平，程序里写清每一位 | 用芯片内部的 I2C 收发电路，寄存器配置 |
| 引脚 | **任意 GPIO**（本课程 PB10/PB11，其实接哪都行） | **固定复用**（I2C2 → PB10/PB11；I2C1 → PB6/PB7 或 PB8/PB9） |
| GPIO 模式 | `GPIO_Mode_Out_OD` | `GPIO_Mode_AF_OD` |
| CPU 占用 | **全程盯着每一位**，`for` 循环里翻 8 次 | 只在**事件**处等一下，字节收发由硬件移位完成 |
| 时序可控性 | **完全可控**，可以随手加延时、插入调试 | 由 `CCR`/`TRISE` 寄存器决定，改动要算时钟 |
| 速率 | 由延时决定，通常**远低于 100 kHz** | 可达标准 100 kHz / 快速 400 kHz |
| 稳定性 | 时序由自己保证，**出问题能一行行看波形** | 硬件状态机有超时/死锁的历史包袱，出问题不好调 |
| 代码量 | 要自己写一个 `MyI2C.c` | 工程里**没有** `MyI2C.c` 这个文件 |
| 换器件/换引脚 | 只改引脚宏和 `GPIO_Init` | 引脚不能随便改；换外设要改一堆配置 |
| 适用场景 | 学习、引脚受限、时序奇怪的器件 | 量大、要速度、要省 CPU 的正式项目 |

STM32 硬件 I2C 的能力（课件 Slide 140）：

> STM32 内部集成了硬件 I2C 收发电路，可以由硬件自动执行时钟生成、起始终止条件生成、应答位收发、数据收发等功能，减轻 CPU 的负担
> 支持多主机模型
> 支持 7 位 / 10 位地址模式
> 支持不同的通讯速度，标准速度（高达 100 kHz），快速（高达 400 kHz）
> 支持 DMA
> 兼容 SMBus 协议
> STM32F103C8T6 硬件 I2C 资源：I2C1、I2C2

> [!tip] 两者的关系：硬件 I2C 只是把「翻引脚」这一步交给了电路
> 协议本身**一模一样**——起始、地址、应答、数据、终止，一个不少。
> 差别只在于：软件 I2C 里 `MyI2C_SendByte()` 那个 8 次循环，在硬件 I2C 里被 `I2C_SendData()` 写一个寄存器替代了；而 CPU 从「盯着每一位」变成「在 EV5 / EV6 / EV7 / EV8 这几个节点上等标志位」。
> 这也解释了 10-5 的做法：**只换最底层那一层，上层 `MPU6050.c` 一个字不改。**

## 8 易错点

- [ ] SCL/SDA 配成**推挽输出** → 多设备时直接短路；单设备时也可能因为「从机想输出高、主机想输出低」而通信失败。**必须开漏 + 上拉。**
- [ ] 忘了上拉电阻（且模块板载也没有）→ 总线永远读不到高电平，起始条件都发不出去。
- [ ] 在 **SCL 高电平期间**改 SDA → 凭空多出一个起始 / 终止条件，从机直接懵。
- [ ] 发送字节时写成 `(Byte & (0x80 >> i))` 而漏了 `!!` → 传给 GPIO 的值不是 0/1，行为不可预期。官方原文是 `MyI2C_W_SDA(!!(Byte & (0x80 >> i)))`。
- [ ] 接收字节时 `Byte` 忘了初值 `0x00` → 读到 0 的那些位是随机值。
- [ ] 读数据前**没有先释放 SDA** → 主机和从机同时驱动 SDA，读回来恒为 0（或电平异常）。
- [ ] 读最后一个字节后发了**应答(0)** 而不是**非应答(1)** → 从机继续输出，SDA 被占着，紧接着的终止条件可能发不出去。
- [ ] 把从机地址当成手册上那个 7 位数直接写进 `SendByte` → 地址全错，从机不应答。**代码里用的是左移一位后的值**（MPU6050 → `0xD0`）。
- [ ] 读操作时写成 `地址 | 0x80` → 应该 `地址 | 0x01`。
- [ ] 「指定地址读」中间误用了 `MyI2C_Stop()` → 必须用**重复起始**。
- [ ] 忘了 `MyI2C_Init()` 里最后要把两根线**置为默认高电平**（官方那行注释写的是「释放总线状态」）→ 总线一上电就是低的，别人没法用。
- [ ] 软件 I2C 不加 `Delay_us` → 72 MHz 下 GPIO 翻转太快，超过器件上限，通信失败。
- [ ] 用硬件 I2C 时随手把 GPIO 配成 `GPIO_Mode_Out_OD` → 硬件 I2C 要用 **`GPIO_Mode_AF_OD`**（复用开漏）。
- [ ] 以为「软件 I2C 能接任意 GPIO」也适用于硬件 I2C → 硬件 I2C 的引脚是**固定复用**的，不能随便挑。

## 9 自测

1. I2C 为什么必须用**开漏输出 + 上拉电阻**？不用行不行？
2. 起始条件和终止条件，分别是在 SCL 为什么电平时 SDA 发生什么跳变？为什么它们必须发生在 SCL 高电平期间？
3. 传输一个字节之后为什么要跟着第 9 个时钟？这一拍谁在驱动 SDA，「0」和「1」分别表示什么？
4. 「指定地址读」为什么要**先写一次**寄存器地址？两次之间为什么不能用终止条件？
5. 主机读完最后一个字节时应该发应答还是非应答？为什么？
6. 从机地址 `1101000` 在代码里写成 `0xD0`，读的时候写 `0xD0 | 0x01`。为什么是左移一位，而不是别的？
7. 软件 I2C 与硬件 I2C 在「引脚自由度」「CPU 占用」「时序可控性」上分别有什么差别？

> [!success]- 参考答案
> 1. 必须。因为总线上所有设备的同名线都并联在一起，而同一根 SDA 需要在不同时刻由不同设备驱动。开漏输出没有「输出高」这个动作，只有「拉低」和「释放」，所以不会出现两个设备一个拉高一个拉低而短路的情况；「释放」让线交给上拉电阻（或交给别的设备）。不用开漏就无法既多点并联又双向传输。
> 2. **起始**：SCL 为**高**时 SDA 由高变低。**终止**：SCL 为**高**时 SDA 由低变高。因为一旦约定「SCL 高电平期间 SDA 不许变化」（数据有效性规则），那么**任何**在 SCL 高电平期间出现的 SDA 跳变就可以被单独赋予含义，用来区分「数据」和「控制」。反过来，如果允许在 SCL 高时改数据，就无法把起始/终止与普通数据位区分开。
> 3. 第 9 拍是**应答位**，用来让接收方告知发送方「这个字节我收到了 / 我没收到」。主机**发**完时由**从机**驱动：`0` = 应答（ACK），`1` = 非应答（NACK）。主机**收**完时由**主机**驱动：`0` = 还要继续收，`1` = 收够了。
> 4. 因为从机没有额外的地址引脚，寄存器地址只能通过数据线传送，而「传送数据」这个方向就是写。所以必须先写一次，把从机的内部地址指针搬到目标寄存器，再从当前指针读。两次之间不能用终止条件——一旦发了终止，总线释放，整个「读一个寄存器」的动作就断了，必须用**重复起始**把它连成一次事务。
> 5. 必须发**非应答（1）**。发应答等于告诉从机「继续发」，从机会继续占着 SDA 输出下一个字节，与随后要发出的终止条件冲突。
> 6. 因为一次传输的第一个字节 8 位里，**高 7 位是地址、最低位是读写方向**。手册上的 `1101000` 只有 7 位，把它放到高 7 位、低位补 0，就得到 `1101 0000` = `0xD0`；要读时把最低位置 1，得到 `1101 0001` = `0xD1`，也就是 `0xD0 | 0x01`。
> 7. **引脚自由度**：软件 I2C 可以接任意 GPIO（本课程 PB10/PB11 只是习惯选择），硬件 I2C 必须用固定复用引脚。**CPU 占用**：软件 I2C 全程在 `for` 循环里翻电平，CPU 被占满；硬件 I2C 只在事件节点等标志位，字节收发由硬件移位寄存器完成。**时序可控性**：软件 I2C 完全可控（可以随手加延时、方便调试），硬件 I2C 由 `CCR` / `TRISE` 决定，改动要按公式算时钟。
