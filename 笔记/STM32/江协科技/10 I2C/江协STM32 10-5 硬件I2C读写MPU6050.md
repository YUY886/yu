# 10-5 硬件 I2C 读写 MPU6050

> [!abstract] 这一集只解决一个问题
> **把 10-3 的软件 I2C 换成 I2C2 硬件外设，代码到底改哪几行？**
>
> 答：只改 `MPU6050.c` 一个文件。把里面的 `MyI2C_*` 六个时序调用换成 `I2C_*` 库函数加「等事件」，工程里直接**删掉 `MyI2C.c` / `MyI2C.h`**；`MPU6050.h`、`MPU6050_Reg.h`、`main.c`、`OLED.c`、`Delay.c` 一行都不用动。
> **引脚也一个都不用动**：软件版手搓的是 PB10/PB11，而硬件 I2C2 的 SCL/SDA 正好也复用在这两个脚上，所以官方 `10-1` 与 `10-2` 用的是**同一张接线图**。
>
> 上一集 [[江协STM32 10-4 I2C通信外设]] ｜ 下一章 [[江协STM32 11 SPI（章索引）]] ｜ 章索引 [[江协STM32 10 I2C（章索引）]]

## 1 两个工程差在哪

| 文件 | `10-1 软件I2C读写MPU6050` | `10-2 硬件I2C读写MPU6050` |
| --- | --- | --- |
| `Hardware\MyI2C.c` / `MyI2C.h` | **有**（软件模拟 I2C 的全部时序） | **没有**（工程里根本没这两个文件） |
| `Hardware\MPU6050.c` | 调用 `MyI2C_*` | 调用 `I2C_*` + 自己写的 `MPU6050_WaitEvent` |
| `Hardware\MPU6050.h` | — | 与软件版**逐字节相同** |
| `Hardware\MPU6050_Reg.h` | — | 与软件版**逐字节相同** |
| `User\main.c` | — | 与软件版**逐字节相同** |
| `Hardware\OLED.c` / `OLED.h` | — | 与软件版**逐字节相同** |
| `System\Delay.c` / `Delay.h` | — | 与软件版**逐字节相同** |
| I2C 引脚 | PB10 = SCL、PB11 = SDA | PB10 = SCL、PB11 = SDA（同一张接线图） |
| I2C 速率 | 靠 `Delay_us(10)` 凑（推算约 50 kHz） | `I2C_ClockSpeed = 50000`，硬件精确分频 |

> [!tip] 这个「只改一个 .c 文件」的对照关系，就是本集最值得记的东西
> 10-3 把 I2C 拆成「引脚配置层 + 协议层」，10-5 换硬件时**协议层整个被外设接管**，所以改动全部落在 `MPU6050.c` 里；上层（`main.c`）连一个字符都不用改。
> 「官方 `10-1` 与 `10-2` 共用同一张接线图」也正是「两版引脚相同」的直接证据——这是**已核实的正常结论**，不是资料缺失。

## 2 引脚：还是 PB10 / PB11（因为选的是 I2C2）

| 信号 | 单片机引脚 | 该脚的复用功能 | 官方源码写法 |
| --- | --- | --- | --- |
| SCL | PB10 | `I2C2_SCL` | `GPIOB` + `GPIO_Pin_10` |
| SDA | PB11 | `I2C2_SDA` | `GPIOB` + `GPIO_Pin_11` |

课程官方 `引脚定义_xlsx原文.txt` 里的原文：

```text
21 | PB10  | I/O  | FT  | PB10  | I2C2_SCL/USART3_TX | TIM2_CH3
22 | PB11  | I/O  | FT  | PB11  | I2C2_SDA/USART3_RX | TIM2_CH4
42 | PB6   | I/O  | FT  | PB6   | I2C1_SCL/TIM4_CH1  | USART1_TX
43 | PB7   | I/O  | FT  | PB7   | I2C1_SDA/TIM4_CH2  | USART1_RX
45 | PB8   | I/O  | FT  | PB8   | TIM4_CH3           | I2C1_SCL/CAN_RX
46 | PB9   | I/O  | FT  | PB9   | TIM4_CH4           | I2C1_SDA/CAN_TX
```

也就是说：

- **本课用的是 I2C2**，它的 SCL/SDA 就在 PB10/PB11——和软件版手搓的两个脚一模一样。
- 如果想用 **I2C1**，默认复用是 **PB6/PB7**；PB8/PB9 那一行 `I2C1_SCL` / `I2C1_SDA` 是写在**「重定义功能」**列里的，即需要重映射才有。

硬件 I2C 的引脚是**复用功能**，不像软件版那样随便挑，这也是 10-4 里讲「取舍」时列的一条。

## 3 `MPU6050.c` 完整代码（官方 `10-2` 工程原文）

```c
#include "stm32f10x.h"                  // Device header
#include "MPU6050_Reg.h"

#define MPU6050_ADDRESS		0xD0		//MPU6050的I2C从机地址

/**
  * 函    数：MPU6050等待事件
  * 参    数：同I2C_CheckEvent
  * 返 回 值：无
  */
void MPU6050_WaitEvent(I2C_TypeDef* I2Cx, uint32_t I2C_EVENT)
{
	uint32_t Timeout;
	Timeout = 10000;									//给定超时计数时间
	while (I2C_CheckEvent(I2Cx, I2C_EVENT) != SUCCESS)	//循环等待指定事件
	{
		Timeout --;										//等待时，计数值自减
		if (Timeout == 0)								//自减到0后，等待超时
		{
			/*超时的错误处理代码，可以添加到此处*/
			break;										//跳出等待，不等了
		}
	}
}

/**
  * 函    数：MPU6050写寄存器
  * 参    数：RegAddress 寄存器地址，范围：参考MPU6050手册的寄存器描述
  * 参    数：Data 要写入寄存器的数据，范围：0x00~0xFF
  * 返 回 值：无
  */
void MPU6050_WriteReg(uint8_t RegAddress, uint8_t Data)
{
	I2C_GenerateSTART(I2C2, ENABLE);										//硬件I2C生成起始条件
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT);					//等待EV5
	
	I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Transmitter);	//硬件I2C发送从机地址，方向为发送
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED);	//等待EV6
	
	I2C_SendData(I2C2, RegAddress);											//硬件I2C发送寄存器地址
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_BYTE_TRANSMITTING);			//等待EV8
	
	I2C_SendData(I2C2, Data);												//硬件I2C发送数据
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_BYTE_TRANSMITTED);				//等待EV8_2
	
	I2C_GenerateSTOP(I2C2, ENABLE);											//硬件I2C生成终止条件
}

/**
  * 函    数：MPU6050读寄存器
  * 参    数：RegAddress 寄存器地址，范围：参考MPU6050手册的寄存器描述
  * 返 回 值：读取寄存器的数据，范围：0x00~0xFF
  */
uint8_t MPU6050_ReadReg(uint8_t RegAddress)
{
	uint8_t Data;
	
	I2C_GenerateSTART(I2C2, ENABLE);										//硬件I2C生成起始条件
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT);					//等待EV5
	
	I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Transmitter);	//硬件I2C发送从机地址，方向为发送
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED);	//等待EV6
	
	I2C_SendData(I2C2, RegAddress);											//硬件I2C发送寄存器地址
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_BYTE_TRANSMITTED);				//等待EV8_2
	
	I2C_GenerateSTART(I2C2, ENABLE);										//硬件I2C生成重复起始条件
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT);					//等待EV5
	
	I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Receiver);		//硬件I2C发送从机地址，方向为接收
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED);		//等待EV6
	
	I2C_AcknowledgeConfig(I2C2, DISABLE);									//在接收最后一个字节之前提前将应答失能
	I2C_GenerateSTOP(I2C2, ENABLE);											//在接收最后一个字节之前提前申请停止条件
	
	MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_BYTE_RECEIVED);				//等待EV7
	Data = I2C_ReceiveData(I2C2);											//接收数据寄存器
	
	I2C_AcknowledgeConfig(I2C2, ENABLE);									//将应答恢复为使能，为了不影响后续可能产生的读取多字节操作
	
	return Data;
}

/**
  * 函    数：MPU6050初始化
  * 参    数：无
  * 返 回 值：无
  */
void MPU6050_Init(void)
{
	/*开启时钟*/
	RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C2, ENABLE);		//开启I2C2的时钟
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);		//开启GPIOB的时钟
	
	/*GPIO初始化*/
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_OD;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOB, &GPIO_InitStructure);					//将PB10和PB11引脚初始化为复用开漏输出
	
	/*I2C初始化*/
	I2C_InitTypeDef I2C_InitStructure;						//定义结构体变量
	I2C_InitStructure.I2C_Mode = I2C_Mode_I2C;				//模式，选择为I2C模式
	I2C_InitStructure.I2C_ClockSpeed = 50000;				//时钟速度，选择为50KHz
	I2C_InitStructure.I2C_DutyCycle = I2C_DutyCycle_2;		//时钟占空比，选择Tlow/Thigh = 2
	I2C_InitStructure.I2C_Ack = I2C_Ack_Enable;				//应答，选择使能
	I2C_InitStructure.I2C_AcknowledgedAddress = I2C_AcknowledgedAddress_7bit;	//应答地址，选择7位，从机模式下才有效
	I2C_InitStructure.I2C_OwnAddress1 = 0x00;				//自身地址，从机模式下才有效
	I2C_Init(I2C2, &I2C_InitStructure);						//将结构体变量交给I2C_Init，配置I2C2
	
	/*I2C使能*/
	I2C_Cmd(I2C2, ENABLE);									//使能I2C2，开始运行
	
	/*MPU6050寄存器初始化，需要对照MPU6050手册的寄存器描述配置，此处仅配置了部分重要的寄存器*/
	MPU6050_WriteReg(MPU6050_PWR_MGMT_1, 0x01);				//电源管理寄存器1，取消睡眠模式，选择时钟源为X轴陀螺仪
	MPU6050_WriteReg(MPU6050_PWR_MGMT_2, 0x00);				//电源管理寄存器2，保持默认值0，所有轴均不待机
	MPU6050_WriteReg(MPU6050_SMPLRT_DIV, 0x09);				//采样率分频寄存器，配置采样率
	MPU6050_WriteReg(MPU6050_CONFIG, 0x06);					//配置寄存器，配置DLPF
	MPU6050_WriteReg(MPU6050_GYRO_CONFIG, 0x18);			//陀螺仪配置寄存器，选择满量程为±2000°/s
	MPU6050_WriteReg(MPU6050_ACCEL_CONFIG, 0x18);			//加速度计配置寄存器，选择满量程为±16g
}


/**
  * 函    数：MPU6050获取ID号
  * 参    数：无
  * 返 回 值：MPU6050的ID号
  */
uint8_t MPU6050_GetID(void)
{
	return MPU6050_ReadReg(MPU6050_WHO_AM_I);		//返回WHO_AM_I寄存器的值
}

/**
  * 函    数：MPU6050获取数据
  * 参    数：AccX AccY AccZ 加速度计X、Y、Z轴的数据，使用输出参数的形式返回，范围：-32768~32767
  * 参    数：GyroX GyroY GyroZ 陀螺仪X、Y、Z轴的数据，使用输出参数的形式返回，范围：-32768~32767
  * 返 回 值：无
  */
void MPU6050_GetData(int16_t *AccX, int16_t *AccY, int16_t *AccZ, 
						int16_t *GyroX, int16_t *GyroY, int16_t *GyroZ)
{
	uint8_t DataH, DataL;								//定义数据高8位和低8位的变量
	
	DataH = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_H);		//读取加速度计X轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_L);		//读取加速度计X轴的低8位数据
	*AccX = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_ACCEL_YOUT_H);		//读取加速度计Y轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_ACCEL_YOUT_L);		//读取加速度计Y轴的低8位数据
	*AccY = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_ACCEL_ZOUT_H);		//读取加速度计Z轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_ACCEL_ZOUT_L);		//读取加速度计Z轴的低8位数据
	*AccZ = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_GYRO_XOUT_H);		//读取陀螺仪X轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_GYRO_XOUT_L);		//读取陀螺仪X轴的低8位数据
	*GyroX = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_GYRO_YOUT_H);		//读取陀螺仪Y轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_GYRO_YOUT_L);		//读取陀螺仪Y轴的低8位数据
	*GyroY = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
	
	DataH = MPU6050_ReadReg(MPU6050_GYRO_ZOUT_H);		//读取陀螺仪Z轴的高8位数据
	DataL = MPU6050_ReadReg(MPU6050_GYRO_ZOUT_L);		//读取陀螺仪Z轴的低8位数据
	*GyroZ = (DataH << 8) | DataL;						//数据拼接，通过输出参数返回
}
```

注意：硬件版的 `MPU6050.c` **没有 `#include "MyI2C.h"`**，只 include 了 `stm32f10x.h` 和 `MPU6050_Reg.h`——这是「协议层被外设接管」最直接的证据。

## 4 逐函数对照表（本集最有价值的部分）

### 4.1 六个基本时序：`MyI2C_*` ↔ `I2C_*`

| 10-3 软件版的时序 | 10-5 硬件版的对应写法 | 关键差别 |
| --- | --- | --- |
| `MyI2C_Init()` | `RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C2, ENABLE)` + `GPIO_Mode_AF_OD` + `I2C_Init()` + `I2C_Cmd(ENABLE)` | 软件版只开 GPIOB 时钟、配 `GPIO_Mode_Out_OD`、最后 `GPIO_SetBits()` 释放总线；硬件版要额外开 **APB1** 上的 I2C2 时钟、配**复用开漏**、用 `I2C_Init` 配置外设 |
| `MyI2C_Start()` | `I2C_GenerateSTART(I2C2, ENABLE)` + `MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT)` | 硬件版**多了一步等 EV5** |
| `MyI2C_Stop()` | `I2C_GenerateSTOP(I2C2, ENABLE)` | 硬件版发完就走，**没有**等事件；软件版里有 4 次 10 µs 延时 |
| `MyI2C_SendByte(Byte)` | `I2C_SendData(I2C2, Byte)` | 硬件版不单独等「一个字节发完」，而是按流程等 `EV8`（后面还有字节）或 `EV8_2`（最后一个字节） |
| `MyI2C_ReceiveByte()` | `I2C_ReceiveData(I2C2)` | 硬件版要先 `MPU6050_WaitEvent(..., I2C_EVENT_MASTER_BYTE_RECEIVED)`（EV7）才能读 |
| `MyI2C_SendAck(1)` | `I2C_AcknowledgeConfig(I2C2, DISABLE)` | 软件版是「主动摆一个 1 到 SDA」；硬件版只是**关掉应答使能**，应答位本身由硬件发 |
| `MyI2C_SendAck(0)` | `I2C_AcknowledgeConfig(I2C2, ENABLE)` | 同上 |
| `MyI2C_ReceiveAck()` | 没有对应函数——**应答结果体现在 `MPU6050_WaitEvent` 等不等得到 EV6** | 软件版能拿到 0/1 的返回值；硬件版等不到 EV6 就说明从机没应答（官方代码只做了超时跳出） |
| — | `MPU6050_WaitEvent(I2Cx, I2C_EVENT)` | **10-5 新增的辅助函数**，软件版完全没有对应物 |

> [!note] 一句话概括这条对照
> 软件版是**「我摆电平」**，硬件版是**「我下命令 + 等回执」**。软件版的 `SendByte`/`ReceiveByte`/`SendAck`/`ReceiveAck` 四个函数在硬件版里被压缩成了 `I2C_SendData`/`I2C_ReceiveData`/`I2C_AcknowledgeConfig` 三个动作，外加一个到处都要用的 `MPU6050_WaitEvent`。

### 4.2 `MPU6050_WriteReg` 逐步对照

| 步骤 | 10-3 软件版 | 10-5 硬件版 | 对应课件事件 |
| --- | --- | --- | --- |
| 起始 | `MyI2C_Start();` | `I2C_GenerateSTART(I2C2, ENABLE);` + 等 `I2C_EVENT_MASTER_MODE_SELECT` | `EV5` |
| 从机地址（写） | `MyI2C_SendByte(MPU6050_ADDRESS);` | `I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Transmitter);` | — |
| 等应答 | `MyI2C_ReceiveAck();` | 等 `I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED` | `EV6` |
| 寄存器地址 | `MyI2C_SendByte(RegAddress);` | `I2C_SendData(I2C2, RegAddress);` | — |
| 等应答 | `MyI2C_ReceiveAck();` | 等 `I2C_EVENT_MASTER_BYTE_TRANSMITTING` | `EV8` |
| 数据 | `MyI2C_SendByte(Data);` | `I2C_SendData(I2C2, Data);` | — |
| 等应答 | `MyI2C_ReceiveAck();` | 等 `I2C_EVENT_MASTER_BYTE_TRANSMITTED` | `EV8_2` |
| 终止 | `MyI2C_Stop();` | `I2C_GenerateSTOP(I2C2, ENABLE);` | — |

注意最后一步的**不对称**：寄存器地址后面等的是 `EV8`（因为后面还有数据要发），数据后面等的是 `EV8_2`（因为这是本次传输的最后一个字节，等它等于确认数据真的上了总线，这时再 `STOP` 才安全）。

### 4.3 `MPU6050_ReadReg` 逐步对照

| 步骤 | 10-3 软件版 | 10-5 硬件版 | 对应课件事件 |
| --- | --- | --- | --- |
| 起始 | `MyI2C_Start();` | `I2C_GenerateSTART(I2C2, ENABLE);` + 等 `I2C_EVENT_MASTER_MODE_SELECT` | `EV5` |
| 从机地址（写） | `MyI2C_SendByte(MPU6050_ADDRESS);` | `I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Transmitter);` | — |
| 等应答 | `MyI2C_ReceiveAck();` | 等 `I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED` | `EV6` |
| 寄存器地址 | `MyI2C_SendByte(RegAddress);` | `I2C_SendData(I2C2, RegAddress);` | — |
| 等应答 | `MyI2C_ReceiveAck();` | 等 `I2C_EVENT_MASTER_BYTE_TRANSMITTED`（**这里就是 `EV8_2`**） | `EV8_2` |
| 重复起始 | `MyI2C_Start();`（注释写「I2C重复起始」） | `I2C_GenerateSTART(I2C2, ENABLE);` + 等 `I2C_EVENT_MASTER_MODE_SELECT` | `EV5`（`Sr`） |
| 从机地址（读） | `MyI2C_SendByte(MPU6050_ADDRESS \| 0x01);` | `I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Receiver);` | — |
| 等应答 | `MyI2C_ReceiveAck();` | 等 `I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED` | `EV6` |
| 提前关应答 | — | `I2C_AcknowledgeConfig(I2C2, DISABLE);` | `EV6_1` |
| 提前申请停止 | — | `I2C_GenerateSTOP(I2C2, ENABLE);` | `EV7_1` |
| 收数据 | `Data = MyI2C_ReceiveByte();` | 等 `I2C_EVENT_MASTER_BYTE_RECEIVED` + `Data = I2C_ReceiveData(I2C2);` | `EV7` |
| 发非应答 | `MyI2C_SendAck(1);` | 由前面那步 `I2C_AcknowledgeConfig(DISABLE)` 实现 | `EV7_1` |
| 终止 | `MyI2C_Stop();` | 由前面那步 `I2C_GenerateSTOP(ENABLE)` 实现 | `EV7_1` |
| 恢复应答 | — | `I2C_AcknowledgeConfig(I2C2, ENABLE);` | — |

**顺序上的最大差别**：软件版是先 `ReceiveByte` → 再 `SendAck(1)` → 再 `Stop`；硬件版必须在**等 EV7 之前**就把「不应答」和「我要停止」交代下去（官方注释：「在接收最后一个字节之前提前将应答失能」「在接收最后一个字节之前提前申请停止条件」）。这正是 10-4 里图246 的 `EV6_1` / `EV7_1` 那两步。

### 4.4 `MPU6050_Init` 对照

| 项目 | 10-3 软件版 | 10-5 硬件版 |
| --- | --- | --- |
| 时钟 | `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);` | `RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C2, ENABLE);` + `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);` |
| GPIO 模式 | `GPIO_Mode_Out_OD`（开漏输出） | `GPIO_Mode_AF_OD`（**复用**开漏输出） |
| GPIO 速度 | `GPIO_Speed_50MHz` | `GPIO_Speed_50MHz`（相同） |
| 引脚 | `GPIO_Pin_10 \| GPIO_Pin_11` | `GPIO_Pin_10 \| GPIO_Pin_11`（**相同**） |
| 默认电平 | `GPIO_SetBits(GPIOB, GPIO_Pin_10 \| GPIO_Pin_11);` 释放总线 | **没有这一步**——总线由 I2C 外设接管 |
| 外设配置 | 无（协议层用软件实现） | `I2C_InitTypeDef` 六个成员 + `I2C_Init(I2C2, ...)` |
| 使能 | 无 | `I2C_Cmd(I2C2, ENABLE);` |
| 底层初始化调用 | `MyI2C_Init();` | 上面这些直接就写在 `MPU6050_Init` 里 |
| 之后写的 6 个寄存器 | `PWR_MGMT_1=0x01`、`PWR_MGMT_2=0x00`、`SMPLRT_DIV=0x09`、`CONFIG=0x06`、`GYRO_CONFIG=0x18`、`ACCEL_CONFIG=0x18` | **完全相同**（连注释都一样） |

`I2C_InitTypeDef` 六个成员的含义与取值（`stm32f10x_i2c.h` 里都能查到）：

| 成员 | 本集取值 | 库里的枚举/范围 | 备注 |
| --- | --- | --- | --- |
| `I2C_Mode` | `I2C_Mode_I2C` | `I2C_Mode_I2C`(`0x0000`)、`I2C_Mode_SMBusDevice`、`I2C_Mode_SMBusHost` | 不用 SMBus |
| `I2C_ClockSpeed` | `50000`（50 kHz） | 注释要求「必须低于 400 kHz」 | 硬件精确分频；软件版靠 10 µs 延时凑 |
| `I2C_DutyCycle` | `I2C_DutyCycle_2` | `I2C_DutyCycle_2`(`0xBFFF`)、`I2C_DutyCycle_16_9`(`0x4000`) | 注释写明「快速模式下的占空比」 |
| `I2C_Ack` | `I2C_Ack_Enable` | `I2C_Ack_Enable`(`0x0400`)、`I2C_Ack_Disable` | |
| `I2C_AcknowledgedAddress` | `I2C_AcknowledgedAddress_7bit` | `I2C_AcknowledgedAddress_7bit`(`0x4000`)、`_10bit`(`0xC000`) | 官方注释：从机模式下才有效 |
| `I2C_OwnAddress1` | `0x00` | 7 位或 10 位地址 | 官方注释：从机模式下才有效 |

> [!note] 关于从机地址 `0xD0` 为什么能直接传给 `I2C_Send7bitAddress`
> 这个函数名字里的「7bit」说的是**7 位地址模式**，不是「参数要传 7 位地址」。它的实现是：
> ```c
> if (I2C_Direction != I2C_Direction_Transmitter)  Address |= OAR1_ADD0_Set;   /* 0x0001 */
> else                                            Address &= OAR1_ADD0_Reset; /* 0xFFFE */
> I2Cx->DR = Address;
> ```
> `MPU6050_ADDRESS = 0xD0` 的最低位本来就是 0，所以发送方向写进 `DR` 的还是 `0xD0`，接收方向变成 `0xD1`——和软件版 `MPU6050_ADDRESS | 0x01` 的结果完全一致。两版从机地址宏都是 `0xD0`，一个字都没改。

## 5 `main.c` 与现象

`10-2` 工程的 `User\main.c` 与 `10-1` **逐字节相同**：

```c
#include "stm32f10x.h"                  // Device header
#include "Delay.h"
#include "OLED.h"
#include "MPU6050.h"

uint8_t ID;								//定义用于存放ID号的变量
int16_t AX, AY, AZ, GX, GY, GZ;			//定义用于存放各个数据的变量

int main(void)
{
	/*模块初始化*/
	OLED_Init();		//OLED初始化
	MPU6050_Init();		//MPU6050初始化
	
	/*显示ID号*/
	OLED_ShowString(1, 1, "ID:");		//显示静态字符串
	ID = MPU6050_GetID();				//获取MPU6050的ID号
	OLED_ShowHexNum(1, 4, ID, 2);		//OLED显示ID号
	
	while (1)
	{
		MPU6050_GetData(&AX, &AY, &AZ, &GX, &GY, &GZ);		//获取MPU6050的数据
		OLED_ShowSignedNum(2, 1, AX, 5);					//OLED显示数据
		OLED_ShowSignedNum(3, 1, AY, 5);
		OLED_ShowSignedNum(4, 1, AZ, 5);
		OLED_ShowSignedNum(2, 8, GX, 5);
		OLED_ShowSignedNum(3, 8, GY, 5);
		OLED_ShowSignedNum(4, 8, GZ, 5);
	}
}
```

现象：和 10-3 **完全一样**——第 1 行显示 ID，2/3/4 行的左列是加速度三轴、第 8 列起是陀螺仪三轴的原始值，晃动传感器数值跟着变。

两版在现象上的差别只能从「看不见的地方」感受：**软件版每次读一个寄存器要 CPU 空转几千个微秒（每位 10 µs），硬件版只等事件**。课件 Slide 145 专门放了两张逻辑分析仪截图做「软件/硬件波形对比」。

## 6 易错点

- [ ] 只开了 `RCC_APB2Periph_GPIOB`，忘了 `RCC_APB1Periph_I2C2` → **I2C2 挂在 APB1 上**，外设根本没时钟，怎么写都不动。
- [ ] GPIO 模式照抄软件版写成 `GPIO_Mode_Out_OD` → 硬件版必须是 `GPIO_Mode_AF_OD`（**复用**开漏输出），否则引脚不交给 I2C 外设。
- [ ] 照搬软件版那句 `GPIO_SetBits()` → 硬件版没有这一步，也不用写；总线状态由外设管。写了不致命，但说明没搞清谁在驱动引脚。
- [ ] 忘了 `I2C_Cmd(I2C2, ENABLE)` → `I2C_Init()` 只是**配置**，不使能外设就不工作。
- [ ] 发完动作不等事件就发下一个 → 硬件还没做完，数据直接丢；官方靠 `MPU6050_WaitEvent` 兜住。
- [ ] 该等 `EV8` 的地方等了 `EV8_2`、该等 `EV8_2` 的地方只等 `EV8` → `WriteReg` 里寄存器地址等 `EV8`、数据等 `EV8_2`；`ReadReg` 里发完寄存器地址立刻要重复起始，所以直接等 `EV8_2`。
- [ ] 读寄存器时把 `I2C_AcknowledgeConfig(DISABLE)`、`I2C_GenerateSTOP(ENABLE)` 挪到 `MPU6050_WaitEvent(EV7)` **之后** → 这时从机已经把下一个字节推上 SDA 了，时序收不住。
- [ ] 单字节读完后忘了 `I2C_AcknowledgeConfig(I2C2, ENABLE)` 恢复 → 后面再做多字节读取全部失败。官方注释：「为了不影响后续可能产生的读取多字节操作」。
- [ ] 用了 I2C1 的引脚 PB6/PB7（或 PB8/PB9）却写 `I2C2` / `RCC_APB1Periph_I2C2` → 引脚和外设对不上。本课是 **I2C2 + PB10/PB11**。
- [ ] 把 `I2C_ClockSpeed` 写成 `400000` 以上 → 库注释明确要求「must be set to a value lower than 400kHz」。
- [ ] 超时跳出后就当没事发生继续跑 → 官方在 `if (Timeout == 0)` 里留了空位 `/*超时的错误处理代码，可以添加到此处*/`，**官方没有写具体处理**；实际使用时应自己加上重试或报错，否则后面读到的数据是无效的。
- [ ] 以为硬件版也要改从机地址或寄存器地址 → `MPU6050_ADDRESS`、`MPU6050_Reg.h`、`MPU6050.h`、`main.c` 与软件版**完全相同**，一个字都没改。
- [ ] 以为硬件版不用管延时 → 时序延时确实不用管了，但**等待事件的超时保护必须自己管**（`MPU6050_WaitEvent` 就是为此而写）。

## 7 自测

1. 从软件版换到硬件版，工程里**删掉了哪个文件**？哪些文件**一个字都没改**？
2. 硬件版 `MPU6050_Init` 里的 GPIO 为什么是 `GPIO_Mode_AF_OD` 而不是 `GPIO_Mode_Out_OD`？为什么又不需要软件版那句 `GPIO_SetBits()`？
3. 本课用的是 I2C1 还是 I2C2？为什么引脚还是 PB10/PB11？I2C1 的默认引脚是哪两个？
4. `MPU6050_WriteReg` 里发寄存器地址后等 `EV8`、发数据后等 `EV8_2`，为什么不一样？`MPU6050_ReadReg` 里发完寄存器地址为什么直接等 `EV8_2`？
5. `MPU6050_ReadReg` 里 `I2C_AcknowledgeConfig(I2C2, DISABLE)` 和 `I2C_GenerateSTOP(I2C2, ENABLE)` 为什么要写在等 `EV7` **之前**？软件版是怎么做同一件事的？

> [!success]- 参考答案
> 1. 删掉了 `Hardware\MyI2C.c` 和 `MyI2C.h`（官方 `10-2` 工程的 `Hardware\` 下根本没有这两个文件）。`MPU6050.h`、`MPU6050_Reg.h`、`User\main.c`、`Hardware\OLED.c` / `OLED.h`、`System\Delay.c` / `Delay.h` 与软件版**逐字节相同**，一个字符都没改；改动的只有 `MPU6050.c`。
> 2. 因为硬件版要把 PB10/PB11 交给 **I2C2 外设**去驱动，所以必须是复用功能 + 开漏（`GPIO_Mode_AF_OD`）；软件版是 CPU 直接 `GPIO_WriteBit` 驱动引脚，所以用普通开漏（`GPIO_Mode_Out_OD`）。也不需要 `GPIO_SetBits()` 了——总线空闲时的电平由 I2C 外设管理，不再由 GPIO 输出寄存器决定。
> 3. 用的是 **I2C2**。因为 I2C2 的 SCL/SDA 默认就复用在这两个脚上（官方引脚定义表：`21 | PB10 | ... | I2C2_SCL/USART3_TX`、`22 | PB11 | ... | I2C2_SDA/USART3_RX`），和软件版手搓的两个脚正好重合，所以官方 `10-1` 与 `10-2` 共用同一张接线图。**I2C1 的默认引脚是 PB6（`I2C1_SCL`）和 PB7（`I2C1_SDA`）**；PB8/PB9 上也有 `I2C1_SCL`/`I2C1_SDA`，但那是写在「重定义功能」列里的，需要重映射。
> 4. 因为 `EV8`（`TxE = 1`，移位寄存器**非空**）只表示「数据已经搬进 DR、正在往外发」，后面还有字节要发，等它就能接着写下一个；`EV8_2`（`TxE = 1` 且 `BTF = 1`）表示「数据已经真的发到总线上了」，所以用在**本次传输的最后一个字节**之后，这时再 `STOP` 才安全。`MPU6050_ReadReg` 里发完寄存器地址紧跟着就是**重复起始**，也必须确认这个地址字节真的发完了，所以直接等 `EV8_2`。
> 5. 因为「应答不应答」和「什么时候发停止条件」这两个决定，必须在**接收最后一个字节的过程当中**就已经生效：图246 的 `EV6_1` 说「恰好在 `EV6` 之后（即清除了 `ADDR` 之后）要清除响应和停止条件的产生位」，`EV7_1` 说「读 DR 后设置 ACK = 0 和 STOP 请求」。如果等 `EV7` 到了、数据也读走了再去关应答，从机已经在推下一个字节了。软件版的同一件事是**读完字节后再手动做**：`Data = MyI2C_ReceiveByte(); MyI2C_SendAck(1); MyI2C_Stop();`——因为软件版整条时序都由 CPU 控制，可以「事后补」，硬件版不行，必须「提前交代」。
