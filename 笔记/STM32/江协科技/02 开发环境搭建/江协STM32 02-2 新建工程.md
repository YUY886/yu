# 02-2 新建工程

> [!abstract] 这一集只解决一个问题
> **怎么从零搭出一个"能编译、能下载、以后每集都能直接复制"的标准库工程模板？**
>
> 答：建目录 → 拷库文件 → Keil 新建工程选器件 → 建分组加文件 → **把 Options for Target 的关键设置配全** → 写 `main.c` 编译通过。
>
> 课件第 16 页给的是**六步**：① 建工程文件夹、Keil 新建工程选型号 ② 建 `Start`/`Library`/`User` 文件夹并拷固件库文件 ③ 工程里建同名称分组并添加文件 ④ `C/C++` → `Include Paths` ⑤ `C/C++` → `Define` 填 `USE_STDPERIPH_DRIVER` ⑥ `Debug` 选调试器 → `Settings` → `Flash Download` 勾 `Reset and Run`。本页在此基础上把 `Target`、`Output`、`Listing` 三项也一并说明（这三项**不是**课件要求的必做项，标注见正文）。
>

## 1 为什么要用标准外设库

标准外设库（Standard Peripheral Library，SPL，也叫固件库）是 ST 官方对寄存器的**二次封装**。同一件事两种写法：

```c
/* 直接操作寄存器：得先翻手册查"哪个寄存器哪一位" */
GPIOA->BSRR = GPIO_Pin_0;

/* 用标准库函数：函数名本身就在说明功能 */
GPIO_SetBits(GPIOA, GPIO_Pin_0);
```

两者**完全等价**，最终编译出来的机器码一样。标准库的代价是多一层函数调用，换来的是可读性和不容易写错。课程全程用标准库。

> [!tip] 三个概念别混
> **CMSIS**（Cortex Microcontroller Software Interface Standard，内核软件接口标准）管的是 **ARM 内核**那一层（`core_cm3.c/h`）；**SPL** 管的是 **ST 外设**那一层（`stm32f10x_gpio.c/h` 等）；**DFP** 是 Keil 的**器件支持包**，管的是"Keil 认不认识这颗芯片"。三者不是一回事。

## 2 工程目录结构

标准库工程的目录长这样。**源码目录是 `Start`、`Library`、`User` 三个**（课件第 16 页：「工程文件夹里建立 **Start、Library、User** 等文件夹」），`Objects` / `Listings` 是 Keil 的输出目录。后面每一集都用头文件路径去引用它们。

```text
工程根目录/
├── Start/        启动文件 + 内核文件 + 系统时钟文件（ST 提供，不改）
│   ├── startup_stm32f10x_md.s    汇编启动文件   ← 固件库 startup\arm\ 下有 8 个 .s，只拷这一个
│   ├── stm32f10x.h               外设寄存器描述（总头文件）
│   ├── system_stm32f10x.c        系统时钟配置
│   ├── system_stm32f10x.h
│   ├── core_cm3.c                Cortex-M3 内核外设访问层
│   └── core_cm3.h
├── Library/      标准外设库（ST 提供，不改）
│   ├── misc.c / misc.h           ← 也在这一层，容易漏
│   ├── stm32f10x_gpio.c / .h
│   ├── stm32f10x_rcc.c / .h
│   └── ……                        （库文件名太多，全部平铺，不分子目录）
├── User/         用户程序
│   ├── main.c                    主函数
│   ├── stm32f10x_conf.h          外设头文件"开关文件"
│   └── stm32f10x_it.c / .h       中断服务函数
├── Objects/      Keil 编译输出的目标文件（.o / .axf / .hex）
└── Listings/     .map / .lst 列表文件
```

> [!important] 这里有一处最容易照抄错的细节
> **课程工程模板里的 `Library` 是「一层平铺」，没有 `inc/` 与 `src/` 两个子目录。**
> 依据是官方工程 `2-1 STM32工程模板\` 的实际磁盘结构：`Library\` 下直接是 `misc.c`、`misc.h`、`stm32f10x_adc.c`、`stm32f10x_adc.h` …… 共 23 组 `.c/.h`（每组同名文件放在一起），**不存在 `Library\inc` 或 `Library\src`**；`Project.uvprojx` 里的 `IncludePath` 也写作 `.\Library`（而非 `..\Library\inc`）。
> 固件库压缩包里确实是 `Libraries\STM32F10x_StdPeriph_Driver\inc` 与 `...\src` **两个目录**——只要把两个目录里的文件**合并拷到工程的一个 `Library\` 文件夹**即可。
> 另外 `Objects\` 与 `Listings\` 是 Keil 的**编译输出目录**，官方模板里就有这两个文件夹，但**不是需要你手工建好、往里面放源码的目录**。`System\`、`Hardware\` 是后续章节才加的，官方 2-1 模板里**没有**。

### 2.1 每个文件是干什么的

| 目录 | 文件 | 作用 |
| --- | --- | --- |
| `Start` | `startup_stm32f10x_md.s` | 复位后第一段代码：初始化堆栈指针、中断向量表、调 `SystemInit`、跳 `main`。**汇编写的，不要改** |
| `Start` | `stm32f10x.h` | 所有外设寄存器的结构体与地址宏定义，**每个 `.c` 都要 `#include "stm32f10x.h"`** |
| `Start` | `system_stm32f10x.c/.h` | `SystemInit()`：配置系统时钟（PLL、AHB/APB 分频），把主频拉到 72 MHz |
| `Start` | `core_cm3.c/.h` | CMSIS 内核层，提供 `__enable_irq()`、`NVIC_*` 等内核相关定义 |
| `Library` | `misc.c/.h` | NVIC 与 SysTick 的高层函数（CMSIS 之外的附加封装），**和 `stm32f10x_*.c` 平铺在同一层** |
| `Library` | `stm32f10x_xxx.h/.c` | 各外设的标准库实现（GPIO、TIM、USART、ADC……），`.c` 与 `.h` 同名放在一起 |
| `User` | `main.c` | 你的主函数 |
| `User` | `stm32f10x_conf.h` | **配置/开关文件**：决定 `stm32f10x.h` 最终包含哪些外设头文件，并定义 `assert_param` |
| `User` | `stm32f10x_it.c/.h` | 中断服务函数（如 `TIM2_IRQHandler`）的集中存放处 |
| `System` | `Delay.c/.h` | 课程自定义的延时模块，本质是封装 SysTick。**官方 2-1 模板里没有这个目录**，是后续集加的 |
| `Hardware` | 自建 | 每讲一个外设就加一组 `.c/.h`，如 `LED.c/.h`、`OLED.c/.h`。**官方 2-1 模板里也没有** |
| `Objects` | 编译产物 | `.o` / `.axf` / `.hex`，由 `Output` 选项卡的 `Select Folder for Objects` 指定（官方模板为 `.\Objects\`） |
| `Listings` | 编译产物 | `.map` 内存分布、`.lst` 汇编列表，由 `Listing` 选项卡指定（官方模板为 `.\Listings\`） |

### 2.2 启动文件后缀怎么选（`ld` / `md` / `hd` / `xl` / `cl` / `vl`）

**本课程用的 STM32F103C8T6，Flash 是 64KB，选 `md`（medium density，中容量）。**

| 后缀 | 含义 | 对应产品 |
| --- | --- | --- |
| `ld` | low density，低容量 | Flash 16～32 KB |
| `md` | medium density，中容量 | Flash 64～128 KB |
| `hd` | high density，高容量 | Flash 256～512 KB |
| `xl` | extra high density，超高容量 | Flash 大于 512 KB |
| `cl` | connectivity line，互联型 | STM32F105 / F107 |
| `vl` | value line，超值型 | STM32F100 |

> [!warning] 选错启动文件会怎样
> 症状是**链接时找不到中断向量表里的某些符号**，或者程序跑飞。`md` 和 `hd` 的向量表长度不同，不能随便换。

## 3 新建工程的完整步骤

### 3.0 课程用的是哪个固件库

`STM32F10x_StdPeriph_Lib_V3.5.0`（本机课程资料包路径：`固件库\固件库\STM32F10x_StdPeriph_Lib_V3.5.0\`）。它的目录长这样：

```text
STM32F10x_StdPeriph_Lib_V3.5.0/
├── Libraries/
│   ├── CMSIS/CM3/
│   │   ├── CoreSupport/                       core_cm3.c / core_cm3.h
│   │   └── DeviceSupport/ST/STM32F10x/
│   │       ├── stm32f10x.h
│   │       ├── system_stm32f10x.c / .h
│   │       └── startup/arm/                   8 个 startup_stm32f10x_xx.s
│   └── STM32F10x_StdPeriph_Driver/
│       ├── inc/                               全部 .h
│       └── src/                               全部 .c
├── Project/STM32F10x_StdPeriph_Template/      main.c / stm32f10x_conf.h / stm32f10x_it.c / .h
└── Utilities/
```

课件第 15 页还给了「型号分类及缩写」表，**决定你该拷哪个启动文件**：

| 缩写 | 释义 | Flash 容量 | 型号 |
| --- | --- | --- | --- |
| `LD_VL` | 小容量产品超值系列 | 16~32K | STM32F100 |
| `MD_VL` | 中容量产品超值系列 | 64~128K | STM32F100 |
| `HD_VL` | 大容量产品超值系列 | 256~512K | STM32F100 |
| `LD` | 小容量产品 | 16~32K | STM32F101/102/103 |
| `MD` | 中容量产品 | 64~128K | STM32F101/102/103 |
| `HD` | 大容量产品 | 256~512K | STM32F101/102/103 |
| `XL` | 加大容量产品 | 大于 512K | STM32F101/102/103 |
| `CL` | 互联型产品 | — | STM32F105/107 |

本课程的 F103C8T6 是 64K Flash → **`MD`** → `startup_stm32f10x_md.s`。

### 3.1 第一步：建目录、拷库文件

1. 新建一个工程根目录，例如 `D:\STM32Project\Template`（**路径不要有中文和空格**）。
2. 在里面建好 `Start`、`Library`、`User` 三个源码文件夹（`System`、`Hardware` 等后续章节再加；`Objects`、`Listings` 由 Keil 在配置输出目录时生成）。
3. 从标准库包里拷文件（本机官方包为 `STM32F10x_StdPeriph_Lib_V3.5.0`，见第 3.0 节）：

| 从哪拷 | 拷什么 | 拷到哪 |
| --- | --- | --- |
| `Libraries\CMSIS\CM3\CoreSupport\` | `core_cm3.c`、`core_cm3.h` | `Start\` |
| `Libraries\CMSIS\CM3\DeviceSupport\ST\STM32F10x\startup\arm\` | `startup_stm32f10x_md.s`（该目录下有 8 个 `.s`，只拷 medium density 这一个） | `Start\` |
| `Libraries\CMSIS\CM3\DeviceSupport\ST\STM32F10x\` | `stm32f10x.h`、`system_stm32f10x.c`、`system_stm32f10x.h` | `Start\` |
| `Libraries\STM32F10x_StdPeriph_Driver\inc\` | 全部 `.h` | `Library\`（**与 src 的文件合并，不建 inc 子目录**） |
| `Libraries\STM32F10x_StdPeriph_Driver\src\` | 全部 `.c` | `Library\`（同上） |
| `Project\STM32F10x_StdPeriph_Template\` | `main.c`、`stm32f10x_conf.h`、`stm32f10x_it.c`、`stm32f10x_it.h` | `User\` |

> [!note] 关于版本号
> **本机课程官方配套的固件库就是 `STM32F10x_StdPeriph_Lib_V3.5.0`**（目录名与包内 `Release_Notes.html` 一致），官方工程 `2-1 STM32工程模板\User\stm32f10x_conf.h` 文件头也写着 `@version V3.5.0  @date 08-April-2011`。所以本课程按 **V3.5.0** 对照即可。

### 3.2 第二步：Keil 新建工程、选器件

1. 打开 Keil µVision5 → `Project` → `New µVision Project...`。
2. 保存位置选到刚建好的目录（课程放在工程根目录或 `User` 同级均可），工程名例如 `Project`。
3. 弹出 **`Select Device for Target`** 对话框：
   - 左侧展开 `STMicroelectronics` → `STM32F1 Series` → `STM32F103`；
   - 右侧选中 **`STM32F103C8`**；
   - 点 `OK`。
4. 紧接着弹出 **`Manage Run-Time Environment`**（RTE）窗口 —— **直接点 `Cancel` 关掉**。课程用的是手动拷库的标准库方式，不用 RTE 自动添加组件。

> [!warning] 选不到 STM32F103C8
> 说明 **STM32F1xx 器件支持包（DFP）没装好**，回到 [[江协STM32 02-1 软件安装]] 第 3 节处理。

### 3.3 第三步：管理工程分组、添加文件

点工具栏的 **`Manage Project Items`** 图标（或 `Project` → `Manage` → `Project Items`），在 `Groups` 栏里建分组，再往每个分组里加文件：

| 分组名 | 添加的文件 |
| --- | --- |
| `Start` | `startup_stm32f10x_md.s`、`stm32f10x.h`、`system_stm32f10x.c`、`system_stm32f10x.h`、`core_cm3.c`、`core_cm3.h` |
| `Library` | `misc.c/.h` + `Library\` 下的**全部 `stm32f10x_*.c/.h`** |
| `User` | `main.c`、`stm32f10x_conf.h`、`stm32f10x_it.c`、`stm32f10x_it.h` |

> [!important] 官方 2-1 模板里**只有三个分组**
> 依据：官方工程 `2-1 STM32工程模板\Project.uvprojx` 中只有 `<GroupName>Start</GroupName>`、`<GroupName>Library</GroupName>`、`<GroupName>User</GroupName>` 三个分组；`System`（Delay）与 `Hardware` 是**后续集**才加的（参见 `1-3 Delay函数模块`、`3-1 LED闪烁` 等工程的 `Project.uvprojx`）。
> 课件第 16 页的措辞也是「工程里对应建立 **Start、Library、User** 等**同名称**的分组」——分组名与文件夹名**一一对应**。

> [!tip] 分组名和文件夹名不必相同，但强烈建议相同
> Keil 的"分组（Group）"只是左边的树形显示，和磁盘上的目录**没有绑定关系**。但同名能让你一眼对上，改文件时不用两处找。课程的做法就是**同名**。

> [!warning] `stm32f10x.h` 要不要加进分组？
> 头文件加不加进 Keil 分组**都不影响编译**——编译真正需要的是 `Include Paths` 里有它所在的目录。课程里把 `stm32f10x.h` 一起加进 `Start` 分组只是为了方便双击打开。**别把"没加头文件"和"没加头文件路径"搞混。**

### 3.4 第四步：Options for Target 关键设置

点工具栏的**魔术棒**图标（或 `Project` → `Options for Target 'Target 1'`，快捷键 `Alt` + `F7`）打开配置对话框。

> [!note] 这一节里，哪些是课件要求的
> 课件第 16 页的六步流程只覆盖了**第 ④⑤⑥ 项**（`Include Paths`、`Define`、`Debug`）。下面的 **① `Target` 的 `Xtal`、② `Output` 的 `Create HEX File`、③ `Listing` 输出目录** 三项是**本笔记补充的**，课件里没有、官方 2-1 模板的存档也没有按"必做"来设置——请按需取舍。

#### ① Target 选项卡：晶振频率

把 **`Xtal (MHz)`** 改成 **`8.0`**。

> [!warning] 这一项是**本笔记补的**，不是课件原文要求
> 课件第 16 页的「新建工程步骤」六步里，`Target` 选项卡只出现在第①步的「Keil 中新建工程，选择型号」中，**没有要求改 `Xtal`**；官方 `Project.uvprojx` 保存的 `<Cpu>` 字段里写的是 `CLOCK(12000000)`（Keil 导出该字段的常见写法，与 `Xtal` 输入框不是同一个值），**无法据此判断课上填的是多少**。详见 `## 待核对`。

`Xtal` 填的是板子上那颗外部晶振（HSE）的实际频率。标准库工程默认按 HSE 计算 PLL 倍频参数把主频抬到 72 MHz，**填错了程序照样编译、照样下载，但时钟会不对**——延时变长/变短、串口波特率全错，而且不会报错，极难排查。

> [!warning] 8 MHz 是"对外部晶振的声明"，不是"设置主频"
> 这里填的是**板子上那颗晶振的实际频率**。STM32F103C8T6 最小系统板普遍是 8 MHz。最终的主频 72 MHz 由 PLL 倍频算出来。

#### ② Output 选项卡：生成 HEX 文件

勾选 **`Create HEX File`**。

- Keil 下载时用的是 `.axf`（带调试信息），**不需要** HEX；
- 但 **FlyMcu 串口下载只认 `.hex`**，所以这一项早晚要勾。
- 输出目录在同一个选项卡的 `Select Folder for Objects` 里设置，官方模板为 **`Objects`**。

> [!warning] 这项在官方 2-1 模板里是**没勾**的
> `2-1 STM32工程模板\Project.uvprojx` 里是 `<CreateHexFile>0</CreateHexFile>`。但课件第 16 页的「新建工程步骤」**只在 `Definition` 与 `Debug` 两处给了要求**，没有把 `Create HEX File` 列为新建工程必做项；到第 9 章要用 FlyMcu 串口下载时才需要它。所以「新建工程时就勾上」是本笔记的建议，不是课程原文要求。

#### ③ Listing 选项卡：列表文件目录

在 `Listing` 选项卡里，把 `Select Folder for Listings` 指到工程里的 **`Listings`** 目录。

官方模板的实际取值是 `<ListingPath>.\Listings\</ListingPath>`（注意官方目录名带 `s`，且与 `Objects` 是两个独立目录）。这不是必需的，但能把 `.map`（内存分布）、`.lst`（汇编列表）集中起来不污染根目录。排查"为什么变量被优化掉了""Flash 用了多少"时非常有用。

#### ④ C/C++ 选项卡：宏定义与头文件路径（最容易漏）

**a. `Define` 输入框**

```text
USE_STDPERIPH_DRIVER
```

课程在 2-2 **只填了这一个宏**。依据是官方工程 `2-1 STM32工程模板\Project.uvprojx` 的 `<Define>USE_STDPERIPH_DRIVER</Define>`——**没有** `STM32F10X_MD`（该工程第二个 `<Define>` 节点是空的）。器件容量宏见第 4.2 节。

**b. `Include Paths` 输入框**

点右侧的 `...` 按钮，把**所有含头文件的目录**逐个加进去。官方 2-1 模板里的实际内容是：

```text
.\Start
.\User
.\Library
```

> [!important] 官方模板的 `Include Paths` 只有三项，且写法值得照抄
> 依据：`2-1 STM32工程模板\Project.uvprojx` 的 `<IncludePath>.\Start;.\User;.\Library</IncludePath>`。
> 两点差别请注意：① 因为 `Library` 是**一层平铺**（没有 `inc` 子目录），所以写 `.\Library` 而不是 `..\Library\inc`；② 官方用的是 **`.\`**（相对工程文件本身所在的目录）而**不是 `..\`**。两种写法在本工程层级下等价，但**跟官方保持一致最不容易出错**。
> 后续章节加了 `System`、`Hardware` 文件夹后，再往这里追加 `.\System`、`.\Hardware`。

> [!warning] 头文件路径是最容易漏、报错又最直白的一项
> 漏了哪个目录，编译就报 `cannot open source input file "xxx.h"`。**报错里点名了哪个头文件，就去把它所在目录加进去。**
> 路径写法是用相对工程文件（`.uvprojx`）的相对路径。用 `...` 按钮浏览选择，Keil 会自动写成相对路径，比手打靠谱。

#### ⑤ Debug 选项卡：调试器与下载设置

1. `Debug` 选项卡右上角的下拉框选 **`ST-Link Debugger`**（用的是 ST-Link 就选它；用 J-Link 则选 `J-LINK / J-TRACE Cortex`）。
2. 点右侧的 **`Settings`** 按钮，弹出新窗口：
   - `Debug` 页：应能看到 `SW Device` 里识别出的芯片 ID（说明连接正常）；
   - **`Flash Download` 页**：确认 `Programming Algorithm` 里已经带上了中容量的 Flash 算法；
   - 勾选 **`Reset and Run`**。

> [!note] 官方模板里保存下来的 Flash 算法是 `STM32F10x_128`
> `2-1 STM32工程模板\Project.uvoptx` 里保存的驱动串是
> `UL2CM3(-S0 -C0 -P0 -FD20000000 -FC1000 -FN1 -FF0STM32F10x_128 -FS08000000 -FL020000 -FP0($$Device:STM32F103C8$Flash\STM32F10x_128.FLM))`，
> 即算法文件为 **`STM32F10x_128.FLM`**（Keil 里显示的条目名形如 `STM32F10x Med-density Flash` / `STM32F10x_128`，随 DFP 版本措辞略有不同），起始 `0x08000000`、长度 `0x20000`。
> **所以「必须选 128K 的那个算法」不是笔误**——中容量系列共用同一个算法文件，F103C8 的 64 KB 在它的覆盖范围内。本机官方工程使用的 DFP 是 `Keil.STM32F1xx_DFP.2.2.0`。

> [!warning] 这一项本次**没有**从官方工程文件里核实到
> `Project.uvprojx` / `.uvoptx` **不保存**「Debug 下拉框里选的是 ST-Link 还是 J-LINK」这个选择（本次导出中只有 `TargetDllName = SARMCM3.DLL` 这类通用项）。所以 `Debug` 下拉框的具体条目名以课件第 16 页「下拉列表选择对应调试器」为准，**具体选哪一个**请按你手上的下载器决定。

> [!tip] `Reset and Run` 到底解决什么
> 不勾它，每次下载完程序**不会自动运行**，要手动按板子上的复位键才跑。勾上之后，"下载完 → 芯片自动复位 → 开始执行新程序"一气呵成。
> 调试时无感，**不调试、只看现象时非常省事**。
> 课件第 16 页明确把「`Debug` → `Settings` → `Flash Download` 里勾选 `Reset and Run`」列为新建工程的最后一步，**这一条是课程原文要求**。

### 3.5 第五步：写 `main.c`，编译

**a. `stm32f10x_conf.h` —— 官方模板默认全部放开，不需要动**

打开 `User\stm32f10x_conf.h` 就能看到，ST 官方模板（V3.5.0）里 **22 个外设头文件加 `misc.h` 全部是放开状态**，被注释掉的只有 `/* #define USE_FULL_ASSERT 1 */` 那一行：

```c
#include "stm32f10x_adc.h"
#include "stm32f10x_bkp.h"
……
#include "stm32f10x_usart.h"
#include "stm32f10x_wwdg.h"
#include "misc.h" /* High level functions for NVIC and SysTick */
……
/* #define USE_FULL_ASSERT    1 */
```

> [!important] 这一节原来的说法已纠正
> 原笔记说「ST 官方模板里这些行大多是放开的，但部分简化版/裁剪版模板默认把它们注释掉了」，并把「放开 `#include`」列为新建工程的一步。
> **依据本机官方 `2-1 STM32工程模板\User\stm32f10x_conf.h` 实测：全部 23 行 `#include` 默认就是放开的，2-2 这一集根本不需要改这个文件。** 课件第 16 页的六步新建流程里也**没有**「修改 stm32f10x_conf.h」这一步。
> `stm32f10x_conf.h` 本身也确实是**从固件库 `Project\STM32F10x_StdPeriph_Template\` 拷过来的原版文件**（第 3 行文件头写着 `Project/STM32F10x_StdPeriph_Template/stm32f10x_conf.h`）。

> [!warning] 真正会遇到「类型未定义」的场景
> 如果你用的是**别处拿到的精简模板**（把用不到的 `#include` 注释掉了），那么报 `identifier "GPIO_InitTypeDef" is undefined` 时，去 `stm32f10x_conf.h` 把对应那一行放开即可。**先看清你手上那份文件的实际状态，不要凭记忆改。**

**b. 写最小可编译的 `main.c`**

```c
#include "stm32f10x.h"    // 标准库总头文件，所有 .c 的第一行都写它

int main(void)
{
	while (1)
	{
		/* 主循环 */
	}
}
```

> [!note] 官方模板里的 `main.c` 不是空的
> `2-1 STM32工程模板\User\main.c` 实际写的是**点灯 PC13 的代码**（`RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE)` → `GPIO_Init` 推挽输出 `GPIO_Pin_13` → `GPIO_ResetBits(GPIOC, GPIO_Pin_13)` → `while(1)`，注释很完整）。这说明 2-2 建好模板后，老师是**当场往 `main.c` 里写了一段 PC13 点灯**来验证工具链的，第 3 章才正式讲 GPIO。
> 所以「先写一个空 `main.c` 编译通过」是本笔记的简化写法；跟着课程做时，`main.c` 里会有点灯代码，**模板工程本身就带这份代码**。

**c. 编译**

点 `F7`（或工具栏 `Build` 图标）。看下面 `Build Output` 窗口，出现：


就说明工程模板搭好了。**这时候还没有任何功能，串口/GPIO 都还没写**——它的意义是"证明工具链是通的"。

## 4 为什么需要 `USE_STDPERIPH_DRIVER`

这是本集最值得弄懂的一个知识点。**不填这个宏会发生什么？** 报一个让人摸不着头脑的错：

```text
warning: #223-D: function "assert_param" declared implicitly
         assert_param(IS_GPIO_ALL_PERIPH(GPIOx));
```

原因是**层层条件编译**。打开 `Start\stm32f10x.h`，翻到文件末尾，有这么一段：

```c
#ifdef USE_STDPERIPH_DRIVER
  #include "stm32f10x_conf.h"
#endif
```

于是链条是这样的：

```text
main.c
  └─ #include "stm32f10x.h"
       ├─ 定义所有寄存器结构体、地址宏            ← 始终生效
       └─ #ifdef USE_STDPERIPH_DRIVER            ← 只有定义了宏才进来
            └─ #include "stm32f10x_conf.h"
                 ├─ #include "stm32f10x_gpio.h"  ← 外设函数原型
                 ├─ #include "stm32f10x_rcc.h"
                 └─ #define assert_param(...)     ← 就在这里定义！
```

**结论**：不定义 `USE_STDPERIPH_DRIVER`，`stm32f10x_conf.h` 根本不会被包含，`assert_param` 这个宏也就没定义。而标准库的每个 `stm32f10x_xxx.c` 里都大量使用 `assert_param(...)`，于是编译器认为它是个"隐式声明的函数"。

> [!tip] 一句话记住
> **`USE_STDPERIPH_DRIVER` 是"启用标准外设库"的开关，它的唯一作用是让 `stm32f10x.h` 去包含 `stm32f10x_conf.h`。**

### 4.1 `stm32f10x_conf.h` 里那 23 行 `#include` 是干什么的

把 `stm32f10x_conf.h` 比作**配电箱**：`USE_STDPERIPH_DRIVER` 是总闸，每个 `#include "stm32f10x_xxx.h"` 是一路分闸。

放开哪一路，哪个外设的函数原型就对 `main.c` 可见。好处有两个：

1. **不用在每个 `.c` 里手动包含一堆头文件**——只要包含了 `stm32f10x.h`，就等于包含了所有已放开的外设头文件。
2. **可以把不用的外设注释掉**，减少编译时间。

> [!important] 课程里**不需要**动这个文件
> ST 官方模板（V3.5.0）把这 23 行**全部放开**了，`Project\STM32F10x_StdPeriph_Template\stm32f10x_conf.h` 原样拷到 `User\` 即可。课件第 16 页的六步流程里也**没有**「修改 stm32f10x_conf.h」这一步。

> [!warning] 什么时候才会遇到「忘记放开」
> 只有在你用**别处的精简模板**（有人把用不到的 `#include` 注释掉了）时，编译 `main.c` 才会报 `identifier "GPIO_InitTypeDef" is undefined`（或 `GPIO_SetBits` 未声明）。**明明 `Library` 里的文件都加了，却说不认识类型**——第一反应就该去看 `stm32f10x_conf.h` 里这一行是不是被注释着。

### 4.2 `USE_STDPERIPH_DRIVER` vs `STM32F10X_MD`

| 宏 | 作用 | 课程 2-2 是否要求 |
| --- | --- | --- |
| `USE_STDPERIPH_DRIVER` | 决定 `stm32f10x.h` 是否包含 `stm32f10x_conf.h` | **要求填**（课件第 16 页原文；官方 `Project.uvprojx` 里也只填了它） |
| `STM32F10X_MD` 等容量宏 | 决定 `stm32f10x.h` 里启用哪一套寄存器定义（中/大/小容量）| **官方模板的 `Define` 里没有填** |

> [!danger] 原笔记这里写错了一处，必须纠正
> 原笔记说：「`stm32f10x.h` 文件开头有一段兜底逻辑：如果一个容量宏都没定义，它会默认按 `STM32F10X_MD`（中容量）处理。」
> **这是错的。** 实测官方 `2-1 STM32工程模板\Start\stm32f10x.h` 第 95~97 行：
> ```c
> #if !defined (STM32F10X_LD) && !defined (STM32F10X_LD_VL) && !defined (STM32F10X_MD) && !defined (STM32F10X_MD_VL) && !defined (STM32F10X_HD) && !defined (STM32F10X_HD_VL) && !defined (STM32F10X_XL) && !defined (STM32F10X_CL)
>  #error "Please select first the target STM32f10x device used in your application (in stm32f10x.h file)"
> #endif
> ```
> 它是**直接 `#error` 报错**，**没有**「默认按 MD 处理」这种兜底。
> 至于官方工程只填了 `USE_STDPERIPH_DRIVER` 却能编译通过——那说明 `STM32F10X_MD` 这个宏是由 **Keil 的器件支持包（DFP）在编译时自动提供**的，不是模板里手填的。具体机制本次未能验证（本机未安装 Keil，无法打开 `Keil.STM32F1xx_DFP.2.2.0` 的器件头文件确认），**已列入待核对**。
> 结论：**照课程做就只填 `USE_STDPERIPH_DRIVER`**；若你的环境报上面那句 `#error`，再把 `STM32F10X_MD` 补进 `Define`。

## 5 编译下载流程与常见报错

### 5.1 正常流程

```text
① F7 编译        → Build Output 显示 0 Error(s), 0 Warning(s)
② F8 下载        → 若勾了 Reset and Run，芯片自动复位并运行新程序
③ Ctrl+F5 调试    → 进调试模式，可设断点、看变量、看寄存器
```

### 5.2 常见报错对照表

| 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `cannot open source input file "stm32f10x.h"` | `Include Paths` 里没有 `Start` 目录 | 在 `C/C++` → `Include Paths` 加上 `.\Start` |
| `cannot open source input file "stm32f10x_gpio.h"` | 没加 `Library` 路径 | 加上 `.\Library` |
| `#error "Please select first the target STM32F10x device used in your application"` | 一个器件容量宏都没定义（`stm32f10x.h` 第 95 行直接 `#error`，没有兜底） | 在 `C/C++` → `Define` 补上 `STM32F10X_MD`（官方模板靠 DFP 自动提供，仅在你手动换环境时才会遇到） |
| `warning: #223-D: function "assert_param" declared implicitly` | **没定义 `USE_STDPERIPH_DRIVER`** | 在 `C/C++` → `Define` 填上 |
| `identifier "uint32_t" is undefined`（在 `core_cm3.h` 里） | `core_cm3.h` 里缺 `#include <stdint.h>`（部分旧版本库的已知问题） | 在 `core_cm3.h` 相应位置补上 `#include <stdint.h>` |
| `identifier "GPIO_InitTypeDef" is undefined` | `stm32f10x_conf.h` 里 `#include "stm32f10x_gpio.h"` 被注释着（**官方模板默认是放开的，只有精简模板才会这样**） | 取消注释 |
| `Undefined symbol SystemInit` | 没把 `system_stm32f10x.c` 加进工程 | 在 `Manage Project Items` 里补加 |
| `Undefined symbol main` | `main.c` 没加进 `User` 分组 | 补加 `main.c` |
| 中断服务函数进不去 | `stm32f10x_it.c` 没加进工程，或函数名与向量表对不上 | 检查文件是否添加、函数名是否完全一致 |
| 下载报 `No ST-LINK detected` / 找不到设备 | 驱动、线、USB 口问题 | 回到 [[江协STM32 02-1 软件安装]] 第 4 节 |
| 下载报 Flash 算法相关错误 | `Flash Download` 里没选对 `Programming Algorithm` | 选 `STM32F10x Med-density Flash` / `STM32F10x_128`（官方模板保存的就是后者） |
| 下载成功但程序不跑 | 没勾 `Reset and Run`，或 BOOT0 跳线帽不在 0 | 勾上 `Reset and Run`；检查跳线帽并复位 |

> [!warning] `assert_param` 未定义与"头文件找不到"是两回事
> - 报 **`cannot open source input file`** → 是**路径问题**，去 `Include Paths` 加目录。
> - 报 **`assert_param declared implicitly`** → 是**宏问题**，去 `Define` 加 `USE_STDPERIPH_DRIVER`。
>
> 把这两类分开，排查速度会快很多。

## 6 易错点

- [ ] 建工程时选了器件，却在 `Manage Run-Time Environment` 里点了 OK 而不是 Cancel → 工程里混进 RTE 组件，头文件路径变得混乱。
- [ ] **启动文件后缀选错**：F103C8 是 64KB Flash，必须用 `startup_stm32f10x_md.s`（`md` = 中容量）。
- [ ] 只把文件加进了 Keil 分组，却**没加 `Include Paths`** → 照样报 `cannot open source input file`。**分组 ≠ 路径**。
- [ ] 只加了 `Include Paths`，却**没把 `.c` 文件加进分组** → 链接时报 `Undefined symbol`。
- [ ] **`Define` 里忘填 `USE_STDPERIPH_DRIVER`** → `assert_param` 未定义。
- [ ] 在**精简模板**上把 `stm32f10x_conf.h` 里的 `#include "stm32f10x_gpio.h"` 留着注释 → 类型/函数未定义（**官方模板默认全放开，照课程做不会遇到**）。
- [ ] `Target` 里 `Xtal` 保持默认值没改成 `8.0` → 时钟不对，延时和波特率全错，**而且不报错**。
- [ ] 没勾 `Create HEX File` → 用 FlyMcu 时找不到可下载文件（**官方 2-1 模板本身也没勾**，第 9 章之前不影响）。
- [ ] 没勾 `Reset and Run` → 下载完不跑，误以为下载失败。
- [ ] `Debug` 里没选 `ST-Link Debugger` → 下载按钮点不动或报找不到设备。
- [ ] 把固件库的 `inc/` 与 `src/` **照原样搬成两个子目录**（`Library\inc`、`Library\src`）→ 与官方模板的 `.\Library` 一层平铺不一致，头文件路径写法也跟着错。
- [ ] `Library` 分组里**漏掉 `misc.c`** → `NVIC_PriorityGroupConfig()`、`SysTick_Config()` 这些链接时报 `Undefined symbol`。
- [ ] 把 `main.c` 的 `int main(void)` 写成 `void main(void)` → 启动文件跳转后行为不确定。
- [ ] 工程路径含**中文或空格** → 各种玄学编译失败。
- [ ] 直接改 `Start` / `Library` 里的 ST 官方文件 → 后期想换库版本时无法对照。**这些文件只读不改**（`core_cm3.h` 补 `stdint.h` 是已知例外）。

## 7 自测

1. `Start`、`Library`、`User` 三个目录里的文件来源和职责分别是什么？
2. 为什么 F103C8T6 要用 `startup_stm32f10x_md.s`，而不是 `hd` 或 `ld`？
3. 在 `C/C++` → `Define` 里填 `USE_STDPERIPH_DRIVER` 到底改变了什么？请说出完整的包含链条。
4. 编译报 `cannot open source input file "stm32f10x_gpio.h"`，和报 `function "assert_param" declared implicitly`，分别该去改哪个设置？
5. `Target` 选项卡里的 `Xtal (MHz)` 填错会有报错吗？会造成什么后果？

> [!success]- 参考答案
> 1. `Start` 放 ST 官方的**启动文件、内核文件（`core_cm3.c/h`）和系统时钟文件**，负责复位后到 `main` 之间的初始化；`Library` 放 **ST 官方的标准外设库**（`misc.c/h` 与 `stm32f10x_*.c/h` **平铺在同一层**，不是 inc/src 两个子目录），提供各外设的库函数；`User` 放**用户自己的程序**（`main.c`、`stm32f10x_conf.h`、`stm32f10x_it.c/h`）。前两个只读不改，第三个随便改。
> 2. 因为 STM32F103C8T6 的 Flash 是 **64 KB**，属于**中容量（medium density）**产品，对应后缀 `md`。`ld` 是低容量（16～32 KB），`hd` 是高容量（256～512 KB），向量表长度不同，选错会导致链接报错或程序跑飞。
> 3. 它让 `stm32f10x.h` 末尾的 `#ifdef USE_STDPERIPH_DRIVER` 成立，从而 `#include "stm32f10x_conf.h"`。完整链条：`main.c` → `#include "stm32f10x.h"` → （宏已定义）`#include "stm32f10x_conf.h"` → 各外设头文件 `#include "stm32f10x_gpio.h"` 等 + `#define assert_param(...)`。不定义这个宏，`stm32f10x_conf.h` 不会被包含，`assert_param` 就没有定义。
> 4. 前者是**路径问题**——去 `C/C++` → `Include Paths` 把 `.\Library` 加进去；后者是**宏问题**——去 `C/C++` → `Define` 把 `USE_STDPERIPH_DRIVER` 填上。
> 5. **不会有任何报错。** `Xtal` 的值被 `system_stm32f10x.c` 用来计算 PLL 参数，填错会让实际主频不是 72 MHz。后果是系统时钟错误，导致**延时时间不对、串口波特率不对、定时器周期不对**，但编译和下载全都正常，属于最难排查的一类问题。
