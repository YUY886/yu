# 02-1 软件安装

> [!abstract] 这一集只解决一个问题
> **怎么把"写代码 → 编译 → 下载 → 调试"这条链路上所有软件装齐，并让电脑真的认得出硬件？**
>
> 答：装 **Keil5 MDK**（编译器/IDE）→ 装 **STM32F1xx DFP**（让 Keil 认识 F103 这颗芯片）→ 装 **ST-Link 驱动**（SWD 下载器）和 **CH340 驱动**（USB 转串口）→ 再用 **STLINK Utility / FlyMcu** 作为 Keil 之外的备用下载手段。
>
> 章索引 [[江协STM32 02 开发环境搭建（章索引）]] ｜ 下一集 [[江协STM32 02-2 新建工程]]

## 1 安装清单与顺序

软件装错顺序的代价很小，但**漏装器件支持包**的代价很大——Keil 能打开，却选不到 `STM32F103C8`。建议按这个顺序来：

```text
① Keil5 MDK（MDK-ARM）          编译器 + IDE，一切的地基
② STM32F1xx DFP（器件支持包）    让 Keil 的器件库能识别 STM32F103C8
③ ST-Link 驱动                  让电脑认得出 SWD 下载器
④ USB 转串口驱动（CH340 等）     让电脑认得出串口，多出一个 COM 口
⑤ STLINK Utility                可选，ST-Link 配套下载/选项字节工具
⑥ FlyMcu                        可选，串口下载工具（没有 ST-Link 时的替代）
```

> [!tip] 一条判据
> 装完任何一步，都用**设备管理器**验证一次。装驱动不算成功，**设备管理器里出现正确的设备且没有黄色感叹号**才算成功。

## 2 Keil5 MDK 的下载与安装

### 2.1 先分清两个 Keil

| 名称 | 全称 | 编什么 | 说明 |
| --- | --- | --- | --- |
| Keil MDK-ARM | MDK-ARM（µVision5） | ARM Cortex-M 系列 | **本课程用这个** |
| Keil C51 | C51（µVision） | 8051 系列 | 学 51 单片机用的，和上面**不是同一个软件** |

两个可以装在同一台电脑上（安装目录要分开），但课程只需要 **MDK-ARM**。

### 2.2 安装步骤

1. 到课程资料包（江协科技官网 <https://jiangxiekeji.com> 提供）里找到 `MDK` 安装包，双击运行。
2. 一路 `Next`，中间会出现许可协议页，勾选同意后继续。
3. **改安装路径**：默认在 `C:\Keil_v5`，可以改到其他盘，但——
   - **路径里不要有中文、空格、特殊符号**。这类路径是后面 "找不到文件""编译报错" 的常见根源。
   - 建议形如 `D:\Keil_v5`。
4. 安装过程中会弹出安装 **Pack 支持包**的提示（有的版本是自动弹出 Pack Installer），可以先关掉，后面单独处理。
5. 装完勾选 `Finish`，会顺带弹出 **Pack Installer**。

> [!warning] 安装路径是范围最广的坑
> 很多"下载失败""找不到头文件""编译报 stop"最后查出来都是路径里有中文。装之前先把路径定好，比装完再迁移省事得多。

### 2.3 激活 / License（可选，但早晚要做）

- `File` → `License Management` 可以查看当前授权状态。
- 未激活的 MDK 是 **Lite/Evaluation 版**，编译有 **32 KB 代码大小限制**。前期点灯、定时器这类小程序够用；程序一大就会报代码超限。
- 激活需要注册码（课程资料包或官方渠道提供），填好后重启 Keil。

> [!warning] 授权与"编译超限"
> 如果编译时报的是代码容量超限、而不是语法错误，先怀疑授权，不要怀疑代码。

## 3 器件支持包 DFP（Device Family Pack）

### 3.1 它是干什么的

Keil 本身只是一个通用编译器，**它凭什么知道 STM32F103C8 有多少 Flash、寄存器地址在哪、启动文件长什么样？** 答案就是器件支持包（Device Family Pack，DFP）。对应 F103 的包名是：

```text
Keil.STM32F1xx_DFP
```

**没装这个包，新建工程选器件时根本找不到 STM32F103C8。**

### 3.2 在线安装

1. 打开 Keil，点工具栏上的 **Pack Installer** 图标（绿色小盒子）。
2. 左侧 `Devices` 树里展开 `STMicroelectronics` → `STM32F1 Series` → `STM32F103`。
3. 右侧 `Packs` 标签页里找到 `Keil::STM32F1xx_DFP`，点 `Install`。
4. 等待下载安装完成，`Install` 变成 `Up to date`（或显示版本号）即可。
5. 关掉 Pack Installer，回到 Keil，新建工程时就能搜到 `STM32F103C8` 了。

> [!note] 在线安装为什么经常失败
> Pack 服务器在国外，下载慢或超时很常见。这不是操作错，直接走下面的离线安装。

### 3.3 离线安装（推荐，尤其在网络不好时）

1. 从课程资料包或 Keil 官网下载 **`.pack` 文件**（形如 `Keil.STM32F1xx_DFP.x.x.x.pack`）。
2. **方法 A**：直接双击这个 `.pack` 文件，Keil 会自动导入。
3. **方法 B**：Keil 菜单 `Pack Installer` → `File` → `Import`，选择 `.pack` 文件。
4. 安装完成后同样能在新建工程的器件列表里搜到 `STM32F103C8`。
5. 也可以手动放到 Keil 安装目录下的 `ARM\PACK\Keil\STM32F1xx_DFP\` 目录里（版本号目录名）。

### 3.4 验证

新建工程 → 选器件时，在搜索框输入 `STM32F103C8`，能出现 **`STM32F103C8`（64KB Flash）** 这个条目，就说明 DFP 装好了。

## 4 ST-Link 驱动安装

ST-Link 是 SWD 下载调试器，**Keil 要能通过它把程序写进芯片、也要能通过它单步调试**，所以驱动必须装。

### 4.1 安装步骤

1. 把 ST-Link 插到电脑 USB 口。
2. 到课程资料包里找到 ST-Link 驱动（安装包名一般含 `ST-Link`、`STLink` 或 `dpinst`）：
   - 若是 `dpinst_x86.exe` / `dpinst_amd64.exe`，直接双击运行，一路下一步。
   - 若是 `ST-Link_V2` 驱动目录，也可以右键 `stlink_winusb.inf` → **安装**。
3. 打开 **设备管理器**（`Win` + `X` → 设备管理器），确认：
   - 出现 `STMicroelectronics STLink dongle`（或在"通用串行总线设备"下）。
   - **没有黄色感叹号**。

> [!tip] 如果一次插上没反应
> 换一个 USB 口（优先插主板后面的 USB 口，不要用前面板或 USB Hub），拔掉重插，再装一次驱动。劣质数据线也会导致只供电不通信。

### 4.2 ST-Link 固件

ST-Link 本身也有固件版本。如果 Keil 或 STLINK Utility 提示固件过旧，可以通过 **STLINK Utility 的 `ST-LINK` → `Firmware update`** 升级（见第 6 节）。**用着没问题就不必升级。**

## 5 USB 转串口驱动（CH340）

### 5.1 为什么需要

课程后面要讲 USART 串口通信，需要一块 **USB 转串口模块**（常见芯片：CH340、CP2102）。它把 USB 转成 TTL 串口，接到 STM32 的 `PA9(TX)` / `PA10(RX)` 上。

**电脑要认得出这个模块，必须装对应的驱动。** 最常见的是 **CH340 驱动**。

### 5.2 安装步骤

1. 把 USB 转串口模块插到电脑 USB 口。
2. 如果没装驱动，设备管理器里会看到一个**带黄色感叹号**的未知设备（或显示为 `USB2.0-Serial` 但异常）。
3. 运行 CH340 驱动安装程序（`CH341SER.EXE` 之类），点 `安装` / `INSTALL`，等待提示"驱动安装成功"。
4. **拔掉再重新插一次**模块。
5. 打开设备管理器 → 展开 **`端口（COM 和 LPT）`**，应该能看到：

```text
端口 (COM 和 LPT)
└── USB-SERIAL CH340 (COM3)     ← 括号里的 COM 号就是要填进软件的那个
```

> [!warning] 端口号是动态的
> `COM3` 只是举例，实际可能是 `COM4`、`COM7` 等。**换 USB 口之后 COM 号通常会变**，用 FlyMcu / 串口助手前要重新看一眼设备管理器。

## 6 两个下载工具：STLINK Utility 与 FlyMcu

这两个是课程里单独介绍的小工具。它们**都能下载程序**，但走的通路完全不同。

### 6.1 对比

| | STLINK Utility | FlyMcu |
| --- | --- | --- |
| 通路 | ST-Link 调试器（SWD） | USB 转串口 → **USART1** |
| 硬件要求 | 一块 ST-Link | 一块 USB 转串口模块 + 能改 BOOT0 的跳线帽 |
| 支持的文件 | `.hex` 和 `.bin` | **只支持 `.hex`** |
| 选项字节 | 可**单独**读写、单独 `Apply` | 只能随下载一起写 |
| 需要安装吗 | 需要，是安装包 | 绿色软件，双击即用 |
| 类比 | Keil 内置下载的独立版 | 51 单片机的 STC-ISP |

> [!tip] 怎么选
> **有 ST-Link 就用 ST-Link**（Keil 里直接下载，最省事）。FlyMcu 是**没有 ST-Link 时的替代方案**，也是理解"串口下载 / BootLoader"原理的好教具。

### 6.2 STLINK Utility 的安装与用法

**安装**：双击安装包 → `Next` → 同意许可 → 选安装路径（同样避免中文）→ 中途会提示**安装 ST-Link 驱动**，点"是" → `Finish`。桌面会出现图标。

**下载流程**：

1. 只用 ST-Link 连接，串口线可以不接。
2. 跳线帽恢复成正常启动（BOOT0 = 0），按一下复位。
3. 打开 STLINK Utility，点 **连接**（`Target` → `Connect`，或工具栏连接图标）。
4. 连接成功后界面会显示器件信息，下面的大框显示从 `0x08000000` 开始的 Flash 数据。
5. 点**打开文件**按钮，选择 `.hex` 或 `.bin`。
6. 点 **`Program` / `Start`** 开始下载。
7. 其他按钮：**擦除**（Erase）、**断开连接**（Disconnect）、**保存**（Save，可存成 `.hex` 或 `.bin`）。
8. **选项字节**：`Target` → `Option Bytes`，改完直接 `Apply` —— 这一点比 FlyMcu 强，被读保护锁住时可以在这里单独解锁。

> [!warning] 读保护会锁死下载
> 如果选项字节里的**读保护**被设成阻止读出，再回 Keil 下载就会失败。要回到 STLINK Utility（或 FlyMcu）的选项字节页**取消读保护**。注意：**取消读保护会同时清空芯片里的程序**。

### 6.3 FlyMcu 串口下载的完整流程

FlyMcu 是绿色软件，直接运行，不需要安装。

**前置条件**：

- 硬件要能保证 **USART1** 和电脑串口通信。**STM32F103 的串口下载只适配 USART1，接在其他 USART 上不行。**
- 工程里要**勾选生成 HEX 文件**（`Options for Target` → `Output` → `Create HEX File`），编译后在 `Objects`（或 `Listing`）目录里找到 `.hex`。

**步骤**：

```text
① 打开 FlyMcu
② 点「搜索串口」→ Port 下拉框选设备管理器里看到的那个 COM 号
③ 波特率保持默认 115200（不要超过 115200）
④ 点「...」按钮选择刚生成的 .hex 文件
⑤ 改跳线帽：把配置 BOOT0 的跳线帽插到「BOOT0 = 1」的位置
⑥ 按一下复位键        ← 关键！STM32 只在复位瞬间读取 BOOT 引脚
⑦ 点「开始编程」，等待下载完成
⑧ 跳线帽换回 BOOT0 = 0，再按一次复位，程序开始运行
```

**为什么必须改跳线帽？** 前面第 7 节讲原理。这里先记住：**不改跳线帽就点"开始编程"，软件会一直卡住不动。**

> [!tip] 少拔一次跳线帽的缓招
> 勾上 FlyMcu 的 **「编程后执行」**，下载完软件会直接从 `0x08000000` 跳转运行主程序，可以省掉"换回跳线帽"这一步。
> 但要注意：**必须同时去掉「编程到 FLASH 时写选项字节」的勾**，否则会提示执行失败。
> 代价是——这个跳转是**一次性的**，按一下复位就又回到 BootLoader 了。适合"在 BootLoader 里连续下载调试，最后再换回来"的用法。

**串口下载的其他常用功能**（了解即可）：

| 功能 | 说明 |
| --- | --- |
| **读 Flash** | 把芯片里的程序读出来。**只能存成 `.bin`**（无地址信息的原始数据） |
| **清除芯片** | 擦除主程序区，之后全是 `FF` |
| **读器件信息** | 读出芯片序列号等。注意 F103C8T6 标称 64KB，这里常读出 256KB，属正常现象 |
| **选项字节** | 读保护 / 写保护 / 硬件参数 / 用户参数四大块 |

> [!warning] FlyMcu 的选项字节有个死循环陷阱
> FlyMcu 不能单独写选项字节，只能"随下载一起写"。如果先把某些页设了**写保护**，再下载就会因为写不进保护区而失败；下载失败就再也改不了选项字节，**形成死循环**。
> 遇到这种情况换 **STLINK Utility** 单独 `Apply` 选项字节即可解决。

## 7 串口下载的原理（为什么必须动跳线帽）

这一节解释第 6.3 节里的"怪操作"。

**问题**：程序在 Flash 里跑着，它怎么把自己换掉？就像机器人给自己换电池——拆掉旧电池的瞬间，它就动不了了。

**答案**：需要一个小机器人。ST 公司在 ROM 区**最后一小块**里预先烧好了一段程序：

```text
系统存储器（System Memory）  地址 0x1FFF F000 起
└── BootLoader（自举程序）   只干一件事：不断接收 USART1 的数据，刷新到主 Flash
```

> [!success] 这几个地址已核对
> 课件「存储器映像」页原文（各项间原有竖线分隔）：`ROM` / `0x0800 0000` / `程序存储器 Flash` / `存储 C 语言编译后的程序代码`；`0x1FFF F000` / `系统存储器` / `存储 BootLoader，用于串口下载`；`0x1FFF F800` / `选项字节` / `存储一些独立于程序代码的配置参数`；`RAM` / `0x2000 0000` / `运行内存 SRAM` / `存储运行过程中的临时变量`。地址与用途与下文完全一致。

主程序区在 `0x08000000`。串口下载就是：**让 CPU 从 `0x1FFF F000` 开始跑 BootLoader，BootLoader 把收到的数据写进 `0x08000000`。**

那么"从哪儿开始跑"由谁决定？——**BOOT 引脚**。STM32 复位后会采样 BOOT 引脚的值：

| BOOT0 | BOOT1 | 启动区域 | 地址 | 干什么用 |
| --- | --- | --- | --- | --- |
| 0 | x | 主闪存（Main Flash） | `0x08000000` | **正常运行你的程序** |
| 1 | 0 | 系统存储器（System Memory） | `0x1FFF F000` | 跑 BootLoader，用于串口下载 |
| 1 | 1 | 内置 SRAM | `0x20000000` | 调试用，课程不用 |

> [!warning] 为什么改完跳线帽一定要按复位
> 依据课程课件「启动配置」页引用的官方参考手册原文：**「在系统复位后，SYSCLK 的第 4 个上升沿，BOOT 引脚的值将被锁存。」** 也就是说程序运行中途改跳线帽完全无效，**必须复位一次**让它重新采样。

> [!tip] 一键下载电路
> 每次拔插跳线帽很烦。串口模块除了 TXD/RXD，还有 **RTS 和 DTR** 两个流控引脚（不用流控时可以当普通 GPIO 用）。用两个三极管搭一个电路，让 RTS/DTR 去控制 BOOT0 和 RST，就能实现"点一下软件自动进 BootLoader"。
> 这正是 FlyMcu 下方那个"DTR 低电平复位 / RTS 高电平进 BootLoader"下拉框的用处——**没有一键下载电路时，这个下拉框选什么都无所谓。**

## 8 汉化与主题（可选）

- **界面语言**：Keil µVision5 默认英文。课程演示多为英文界面，**建议保持英文**，因为网上所有报错信息、菜单名对照的都是英文版。
- 若确实需要中文，第三方汉化包通常是把 Keil 安装目录下的资源文件替换掉，**升级或重装 Keil 后汉化会失效**，且可能让菜单名与教程对不上，反而增加沟通成本。
- **编辑器主题**：`Edit` → `Configuration` → `Colors & Fonts` 可以改配色；中文注释乱码则改 `Edit` → `Configuration` → `Editor` 里的 **Encoding**（见下）。

> [!note] 中文注释乱码
> 如果注释显示成乱码，把 `Edit` → `Configuration` → `Editor` → `Encoding` 改成 **`UTF-8`** 或 **`GB2312`**（两者与你的文件实际编码一致即可）。这是一个"改一次管很久"的设置。

## 9 常见报错与排查

| 现象 | 可能原因 | 排查动作 |
| --- | --- | --- |
| 新建工程时搜不到 `STM32F103C8` | 没装 `Keil.STM32F1xx_DFP` | 打开 Pack Installer 检查是否 Install 成功；或离线双击 `.pack` |
| 编译报代码容量超限 | Keil 未激活（Lite 版 32KB 限制） | `File` → `License Management` 检查授权 |
| 编译报 `cannot open source input file ...` | 头文件路径没加 / 路径含中文 | 检查 `C/C++` → `Include Paths`，检查安装与工程路径 |
| 下载时提示找不到设备 / `No ST-LINK detected` | ST-Link 驱动没装好，或线/口有问题 | 设备管理器看有没有黄色感叹号；换 USB 口和数据线 |
| 设备管理器里找不到 COM 口 | USB 转串口驱动没装 | 装 CH340 驱动，拔插一次模块 |
| FlyMcu 点"开始编程"后一直卡住 | 没进 BootLoader | 跳线帽切到 BOOT0 = 1，**按复位** |
| 串口下载失败 | 串口线没接在 **USART1** 上 | 检查接线是否为 PA9/PA10 |
| FlyMcu 下载 `.bin` 报错 | FlyMcu 只接受 `.hex` | 改用 `.hex`，或换 STLINK Utility |
| Keil 下载失败，但芯片之前下载过 | 选项字节被设了读保护 | 用 STLINK Utility 取消读保护（注意会清空程序） |
| 装完 Keil 打开就是 "Evaluation Version" | 未激活 | 正常现象，按 2.3 节激活 |

## 10 易错点

- [ ] 装了 Keil 但没装 **器件支持包 DFP** → 选器件时找不到 F103C8，误以为是 Keil 装坏了。
- [ ] 把 **Keil C51** 当成 MDK-ARM 装 → 完全没有 STM32 器件可选。
- [ ] 安装路径带**中文或空格** → 后面各种莫名其妙的编译/下载失败。
- [ ] 以为"驱动装好了" → 实际要在 **设备管理器**里看到设备且**没有黄色感叹号**才算数。
- [ ] 把 ST-Link 驱动和 USB 转串口驱动搞混 → 一个是 SWD 下载，一个是 COM 口通信，**两个都要装**。
- [ ] FlyMcu 里选的 COM 号不是 USB 转串口那个口 → **换 USB 口后 COM 号会变**，要重新确认。
- [ ] 串口下载接在 USART2/USART3 → **F103 的串口下载只认 USART1**。
- [ ] 改了 BOOT0 跳线帽但**没按复位** → 芯片不会重新采样引脚，下载照样卡住。
- [ ] 忘了在 `Options for Target` → `Output` 勾 **Create HEX File** → FlyMcu 找不到可下载的文件。
- [ ] 在 FlyMcu 里勾了"编程后执行"却还勾着"写选项字节" → 提示执行失败。
- [ ] 用 FlyMcu 设置写保护后下载失败，越救越死 → 换 **STLINK Utility** 单独 Apply 选项字节。

## 11 自测

1. 为什么装完 Keil5 MDK 之后，新建工程里还是找不到 `STM32F103C8`？
2. ST-Link 驱动和 CH340 驱动分别解决什么问题？能不能只装一个？
3. 用 FlyMcu 串口下载时，为什么改了 BOOT0 跳线帽之后**还必须按一下复位**？
4. FlyMcu 和 STLINK Utility 在"支持的文件类型"和"选项字节"上各有什么差别？
5. 有人把 BOOT0 跳到 1 下载完程序，跳回 0 却没按复位，发现 LED 还是不亮。为什么？

> [!success]- 参考答案
> 1. 因为 Keil 只是通用编译器，要在它的器件库里看到具体型号，必须额外安装**器件支持包** `Keil.STM32F1xx_DFP`（在线 Pack Installer 或离线双击 `.pack`）。
> 2. ST-Link 驱动让电脑认得出 **SWD 下载调试器**（Keil 下载、在线调试都靠它）；CH340 驱动让电脑认得出 **USB 转串口模块**（多出一个 COM 口，串口通信和 FlyMcu 串口下载靠它）。**不能只装一个**，它们是两条独立的通路。
> 3. STM32 只在**复位后 SYSCLK 的第 4 个上升沿**采样并锁定 BOOT 引脚。程序运行中途改跳线帽不生效，必须复位让它重新采样，才能从 `0x1FFF F000` 的系统存储器启动 BootLoader。
> 4. FlyMcu **只支持 `.hex`**（读出来却只能存 `.bin`，且 `.bin` 下不回去）；STLINK Utility **`.hex` 和 `.bin` 都支持**。选项字节方面，FlyMcu 只能**随下载一起写**，STLINK Utility 可以**单独读、单独 `Apply`**，所以被写保护锁住时只能靠 STLINK Utility 解锁。
> 5. 因为改跳线帽后没复位，芯片仍在跑 BootLoader（BootLoader 只是等串口数据，不会执行刚下载的 LED 程序）。**必须按复位**，让它重新采样 BOOT0 = 0，才会从 `0x08000000` 启动新程序。
