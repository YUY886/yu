# 09-3 串口发送 & 串口发送+接收

> [!abstract] 这一集只解决两个问题
> **① 怎么让单片机通过串口把数据发给电脑？② 怎么把电脑发来的数据收进单片机？**
> 
> 答：发送靠 `USART_SendData()` 往数据寄存器里丢一个字节，硬件自动生成数据帧时序从 **PA9（USART1_TX）** 发出去；接收靠 **PA10（USART1_RX）** 收进来的字节触发 **RXNE 中断**，在 `USART1_IRQHandler` 里把数据取出并置标志位，主循环再消费这个标志位。
> 
> 本集对应两个官方工程：**9-1 串口发送**（只有发送）和 **9-2 串口发送+接收**（发送 + 接收）。两个工程的 `Serial.c` **内容不同**，本页分别照原文列出。
> 
> 上一集 [[江协STM32 09-2 USART串口外设]] ｜ 下一集 [[江协STM32 09-4 USART串口数据包]] ｜ 章索引 [[江协STM32 09 USART串口（章索引）]]

## 1 硬件接线：TX 与 RX 必须交叉

串口是**全双工、异步、单端、点对点**的通信接口（课件 Slide 108）：

| 名称 | 引脚 | 双工 | 时钟 | 电平 | 设备 |
| --- | --- | --- | --- | --- | --- |
| **USART** | TX、RX | 全双工 | 异步 | 单端 | 点对点 |

官方接线图 `9-1 串口发送.png` / `9-2 串口发送+接收.png` 画的是 **STM32 最小系统板 + USB 转串口模块**：

| 单片机引脚 | 引脚号 | 接到模块的哪一脚 | 说明 |
| --- | --- | --- | --- |
| **PA9**（USART1_TX） | 30 | 模块 **RXD** | 单片机发 → 模块收 |
| **PA10**（USART1_RX） | 31 | 模块 **TXD** | 模块发 → 单片机收 |
| GND | — | 模块 **GND** | 共地，必接 |
| — | — | 模块 **VCC / 3V3** | 由 3.3V 供电 |

> [!warning] 交叉接线是硬规定
> 课件 Slide 110 原文：**「TX 与 RX 要交叉连接」**。A 机的 TX 接 B 机的 RX，否则双方都在「说」、没人「听」。
> 
> 另外两条同页规定：**「当只需单向的数据传输时，可以只接一根通信线」**（本集 9-1 就是单向发送）；**「当电平标准不一致时，需要加电平转换芯片」**——这里用的 USB 转串口模块内部已经做了转换，单片机侧就是 TTL 电平（Slide 111：`+3.3V` 或 `+5V` 表示 1，`0V` 表示 0）。

引脚定义（`ground-truth\引脚定义_xlsx原文.txt`，第 32~33 行）：

| 引脚号 | 引脚名称 | 类型 | I/O 口电平(FT) | 主功能 | 默认复用功能 | 重定义功能 |
| --- | --- | --- | --- | --- | --- | --- |
| 30 | PA9 | I/O | FT | PA9 | USART1_TX/TIM1_CH2 |  |
| 31 | PA10 | I/O | FT | PA10 | USART1_RX/TIM1_CH3 |  |

> [!note] 关于接线图
> `9-1 串口发送.png` 与 `9-2 串口发送+接收.png` 是**同一张图**——两个实验的串口接线完全相同，课程作者就复用了同一张接线图，**这是正常情况，不是错误**。本页引脚一律**以官方源码 `Serial.c` 为准**，接线图只作旁证。

> [!tip] 为什么发送脚配「复用推挽」、接收脚配「上拉输入」
> - **PA9 是输出**：串口波形由 USART 外设产生，所以 GPIO 必须配成**复用推挽输出 `GPIO_Mode_AF_PP`**——只有复用模式下输出数据寄存器的控制权才交给片上外设（这条和 6-3 里 PWM 引脚的要求是同一个道理）。
> - **PA10 是输入**：配成**上拉输入 `GPIO_Mode_IPU`**。空闲时串口线是高电平，上拉保证没有信号时引脚停在稳定的高电平，不会因为悬空乱触发。

## 2 本集用的串口参数：9600、8 位数据、1 位停止、无校验

课件 Slide 112 定义了几个参数：**波特率（串口通信的速率）、起始位（固定低电平）、数据位（低位先行）、校验位、停止位（固定高电平）**；Slide 113 给出一组时序示例，本集用的那一组就是 **`0x55`，9600，8 位数据，1 位停止，无校验**。

| 参数 | 本集取值 | 库函数成员 | 取值 |
| --- | --- | --- | --- |
| 波特率 | **9600** | `USART_BaudRate` | `9600`（数值，不是枚举） |
| 字长 | 8 位 | `USART_WordLength` | `USART_WordLength_8b` |
| 停止位 | 1 位 | `USART_StopBits` | `USART_StopBits_1` |
| 奇偶校验 | 无 | `USART_Parity` | `USART_Parity_No` |
| 硬件流控制 | 不用 | `USART_HardwareFlowControl` | `USART_HardwareFlowControl_None` |
| 模式 | 9-1 只发 / 9-2 收发 | `USART_Mode` | `USART_Mode_Tx` / `USART_Mode_Tx \| USART_Mode_Rx` |

**波特率是怎么算出来的**：课件 Slide 121 给出 `波特率 = f_PCLK2/1 / (16 * DIV)`，波特率由波特率寄存器 `BRR` 里的 `DIV` 确定。USART1 挂在 **APB2**（官方源码用 `RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE)` 开时钟），`PCLK2 = 72 MHz`，所以：

```text
DIV = 72 000 000 / (16 × 9600) = 468.75
整数部分 468，小数部分按库函数头文件给出的 (468.75 − 468) × 16 + 0.5 = 12.5 → 12
BRR = 468 × 16 + 12 = 7500 = 0x1D4C
```

> [!note] 上面这段是「按公式推算」，不是源码原话
> `USART_BaudRate` 只需要填 `9600` 这个**数值**，剩下的分频计算由库函数 `USART_Init()` 自动完成——结构体成员注释里写着 `IntegerDivider = ((PCLKx) / (16 * USART_InitStruct->USART_BaudRate))`、`FractionalDivider = ((IntegerDivider - ((u32) IntegerDivider)) * 16) + 0.5`（`stm32f10x_usart.h` 第 52~55 行）。本页据此算了一遍 `0x1D4C` 作为验算，源码里并没有这个数。

## 3 发送版串口初始化：`Serial_Init()`（9-1 工程原文）

配置顺序与 6-1 的定时器一致：**开时钟 → 配 GPIO → 配外设 → 使能外设**。

| 步骤 | 干什么 | 官方源码行 |
| --- | --- | --- |
| ① | 开 USART1 和 GPIOA 时钟 | 第 13、14 行 |
| ② | PA9 配复用推挽输出 | 第 18~21 行 |
| ③ | 填 `USART_InitTypeDef` 并调用 `USART_Init` | 第 24~31 行 |
| ④ | `USART_Cmd(USART1, ENABLE)` 让串口开始运行 | 第 34 行 |

```c
#include "stm32f10x.h"                  // Device header
#include <stdio.h>
#include <stdarg.h>

/**
  * 函    数：串口初始化
  * 参    数：无
  * 返 回 值：无
  */
void Serial_Init(void)
{
	/*开启时钟*/
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE);	//开启USART1的时钟
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);	//开启GPIOA的时钟
	
	/*GPIO初始化*/
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_9;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);					//将PA9引脚初始化为复用推挽输出
	
	/*USART初始化*/
	USART_InitTypeDef USART_InitStructure;					//定义结构体变量
	USART_InitStructure.USART_BaudRate = 9600;				//波特率
	USART_InitStructure.USART_HardwareFlowControl = USART_HardwareFlowControl_None;	//硬件流控制，不需要
	USART_InitStructure.USART_Mode = USART_Mode_Tx;			//模式，选择为发送模式
	USART_InitStructure.USART_Parity = USART_Parity_No;		//奇偶校验，不需要
	USART_InitStructure.USART_StopBits = USART_StopBits_1;	//停止位，选择1位
	USART_InitStructure.USART_WordLength = USART_WordLength_8b;		//字长，选择8位
	USART_Init(USART1, &USART_InitStructure);				//将结构体变量交给USART_Init，配置USART1
	
	/*USART使能*/
	USART_Cmd(USART1, ENABLE);								//使能USART1，串口开始运行
}
```

> [!warning] 9-1 的 `Serial_Init()` 只有 PA9、只有 Tx
> 这个工程**只发不收**，所以：**没有** PA10 的上拉输入配置、**没有** `USART_ITConfig()`、**没有** NVIC 配置，`USART_Mode` 也只写 `USART_Mode_Tx`。到 9-2 才把这几项补上（见第 7 节）。两边**不要混抄**。

## 4 发送函数族

### 4.1 `Serial_SendByte()`：发送一个字节

```c
/**
  * 函    数：串口发送一个字节
  * 参    数：Byte 要发送的一个字节
  * 返 回 值：无
  */
void Serial_SendByte(uint8_t Byte)
{
	USART_SendData(USART1, Byte);		//将字节数据写入数据寄存器，写入后USART自动生成时序波形
	while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);	//等待发送完成
	/*下次写入数据寄存器会自动清除发送完成标志位，故此循环后，无需清除标志位*/
}
```

三个要点：

1. **`USART_SendData(USART1, Byte)`** 只是把字节写进**发送数据寄存器 TDR**，波形的生成是硬件自动完成的（课件 Slide 114：「可根据数据寄存器的一个字节数据自动生成数据帧时序，从 TX 引脚发送出去」）。
2. **必须等 `USART_FLAG_TXE`**：刚写完数据寄存器时，数据还没被搬进发送移位寄存器，此时再写会覆盖上一个字节。官方注释把这一步叫「**等待发送完成**」，并在注释里明确「**下次写入数据寄存器会自动清除发送完成标志位，故此循环后，无需清除标志位**」。
3. **只发一个字节也是阻塞的**：这个 `while` 会一直转到标志位置位才返回。

> [!note] TXE 的确切位含义未从官方材料取得
> 标准库头文件只给了 `#define USART_FLAG_TXE ((uint16_t)0x0080)`（`stm32f10x_usart.h` 第 323 行），**没有给出这个标志的中文含义**。本页只复述官方源码注释的两句话（「等待发送完成」「下次写入数据寄存器会自动清除」），不替它下位级定义。位级定义需查《STM32F10xxx 参考手册》，已记入「待核对」。

### 4.2 `Serial_SendArray()`：发送一个数组

```c
/**
  * 函    数：串口发送一个数组
  * 参    数：Array 要发送数组的首地址
  * 参    数：Length 要发送数组的长度
  * 返 回 值：无
  */
void Serial_SendArray(uint8_t *Array, uint16_t Length)
{
	uint16_t i;
	for (i = 0; i < Length; i ++)		//遍历数组
	{
		Serial_SendByte(Array[i]);		//依次调用Serial_SendByte发送每个字节数据
	}
}
```

**数组是「按原样发」的**：`0x42` 发出去就是 `0x42`，不会做任何编码——这正是 09-4 要讲的 **HEX 模式**。

### 4.3 `Serial_SendString()`：发送一个字符串

```c
/**
  * 函    数：串口发送一个字符串
  * 参    数：String 要发送字符串的首地址
  * 返 回 值：无
  */
void Serial_SendString(char *String)
{
	uint8_t i;
	for (i = 0; String[i] != '\0'; i ++)//遍历字符数组（字符串），遇到字符串结束标志位后停止
	{
		Serial_SendByte(String[i]);		//依次调用Serial_SendByte发送每个字节数据
	}
}
```

以 `'\0'` 为结束标志，逐个字节发。**注意循环变量是 `uint8_t`，字符串最长只能到 255 个字符**（官方源码就是这么写的，改动前请确认）。

### 4.4 `Serial_Pow()`：内部用的次方函数

```c
/**
  * 函    数：次方函数（内部使用）
  * 返 回 值：返回值等于X的Y次方
  */
uint32_t Serial_Pow(uint32_t X, uint32_t Y)
{
	uint32_t Result = 1;	//设置结果初值为1
	while (Y --)			//执行Y次
	{
		Result *= X;		//将X累乘到结果
	}
	return Result;
}
```

### 4.5 `Serial_SendNumber()`：发送数字

```c
/**
  * 函    数：串口发送数字
  * 参    数：Number 要发送的数字，范围：0~4294967295
  * 参    数：Length 要发送数字的长度，范围：0~10
  * 返 回 值：无
  */
void Serial_SendNumber(uint32_t Number, uint8_t Length)
{
	uint8_t i;
	for (i = 0; i < Length; i ++)		//根据数字长度遍历数字的每一位
	{
		Serial_SendByte(Number / Serial_Pow(10, Length - i - 1) % 10 + '0');	//依次调用Serial_SendByte发送每位数字
	}
}
```

逐位拆分的过程（以 `Number = 111`、`Length = 3` 为例）：

| `i` | `Length - i - 1` | `Serial_Pow(10, n)` | `Number / 10ⁿ` | `% 10` | `+ '0'` | 发出的字符 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 2 | 100 | 1 | 1 | `'1'` | `1` |
| 1 | 1 | 10 | 11 | 1 | `'1'` | `1` |
| 2 | 0 | 1 | 111 | 1 | `'1'` | `1` |

- **`+ '0'`** 是把 0~9 的数值变成 ASCII 字符（`'0'` 的编码是 `0x30`）。这一步就是课件 Slide 122 里说的「**编码**」——所以 `Serial_SendNumber(111, 3)` 在串口助手的**文本模式**下看到 `111`，而在 **HEX 模式**下看到的是 `31 31 31`。
- `Length` 是**要显示几位**，不是数字的位数：`Serial_SendNumber(1, 3)` 发出去的是 `001`。
- `Length` 范围 0~10 来自官方注释（`uint32_t` 十进制最多 10 位）。
- `Length = 0` 时 `Length - i - 1` 里的 `Length` 是 `uint8_t`，会先整型提升成 `int` 参与运算，所以 `0 - 0 - 1 = -1` 不会变成 255；但循环条件 `i < 0` 一开始就不成立，**一个字节都不会发**。

## 5 printf 的三条路：重定向 `fputc` 与 `Serial_Printf`

官方 `main.c` 里用注释列出了**三种实现 printf 效果的方法**（原文照抄）：

```c
//	/*下述3种方法可实现printf的效果*/
//	
//	/*方法1：直接重定向printf，但printf函数只有一个，此方法不能在多处使用*/
//	printf("\r\nNum2=%d", 222);			//串口发送printf打印的格式化字符串
//										//需要重定向fputc函数，并在工程选项里勾选Use MicroLIB
//	
//	/*方法2：使用sprintf打印到字符数组，再用串口发送字符数组，此方法打印到字符数组，之后想怎么处理都可以，可在多处使用*/
//	char String[100];					//定义字符数组
//	sprintf(String, "\r\nNum3=%d", 333);//使用sprintf，把格式化字符串打印到字符数组
//	Serial_SendString(String);			//串口发送字符数组（字符串）
//	
//	/*方法3：将sprintf函数封装起来，实现专用的printf，此方法就是把方法2封装起来，更加简洁实用，可在多处使用*/
//	Serial_Printf("\r\nNum4=%d", 444);	//串口打印字符串，使用自己封装的函数实现printf的效果
//	Serial_Printf("\r\n");
```

### 5.1 三种方法的取舍

| 方法 | 做法 | 官方注释给出的评价 |
| --- | --- | --- |
| 1 重定向 `printf` | 自己写 `fputc`，让 `printf` 的输出走串口 | 「**printf 函数只有一个，此方法不能在多处使用**」——一个工程里 `printf` 只能对应一个出口，想同时往两个串口/屏幕输出就不行了 |
| 2 `sprintf` 到字符数组 | 先格式化进 `String[]`，再 `Serial_SendString` | 「打印到字符数组，之后想怎么处理都可以，**可在多处使用**」 |
| 3 封装 `Serial_Printf` | 把方法 2 包成一个带可变参数的函数 | 「就是把方法 2 封装起来，**更加简洁实用，可在多处使用**」 |

### 5.2 `fputc` 重定向（方法 1）

```c
/**
  * 函    数：使用printf需要重定向的底层函数
  * 参    数：保持原始格式即可，无需变动
  * 返 回 值：保持原始格式即可，无需变动
  */
int fputc(int ch, FILE *f)
{
	Serial_SendByte(ch);			//将printf的底层重定向到自己的发送字节函数
	return ch;
}
```

`fputc` 是 C 标准库里 `printf` 最终输出一个字符时调用的**底层函数**。把它改写成「往串口发一个字节」，`printf` 的输出就整体改道到串口了。函数名、参数、返回值都必须按上面这个格式写（官方注释：「**保持原始格式即可，无需变动**」）。

### 5.3 Use MicroLIB：官方源码明确要求勾选

- **要求本身有官方出处**：官方 `main.c` 第 27 行注释原文——「**需要重定向 fputc 函数，并在工程选项里勾选 Use MicroLIB**」。
- **官方工程确实勾了**：`9-1 串口发送\Project.uvprojx` 里 `<useUlib>1</useUlib>`（Keil 的「Use MicroLIB」选项），值为 1。

> [!warning] 「为什么要勾 Use MicroLIB」——官方材料只给了结论，没给原因
> 官方源码注释和课件 Slide 108~126 **都没有说明原因**。本页按核对原则**不把常见解释写成肯定句**：可以确定的是「不勾 Use MicroLIB 时用重定向后的 `printf` 会出问题」，而具体机理（与 ARM 标准库、半主机 semihosting 相关）**未见于本课程的官方材料**，需自行查阅 ARM 编译器文档。已记入「待核对」。
> 
> 想避开这个坑，直接用**方法 2 / 方法 3**——它们不依赖 `printf`，也就不依赖 Use MicroLIB 这个选项。

### 5.4 `Serial_Printf()`：用 `vsprintf` 自己造一个

```c
/**
  * 函    数：自己封装的prinf函数
  * 参    数：format 格式化字符串
  * 参    数：... 可变的参数列表
  * 返 回 值：无
  */
void Serial_Printf(char *format, ...)
{
	char String[100];				//定义字符数组
	va_list arg;					//定义可变参数列表数据类型的变量arg
	va_start(arg, format);			//从format开始，接收参数列表到arg变量
	vsprintf(String, format, arg);	//使用vsprintf打印格式化字符串和参数列表到字符数组中
	va_end(arg);					//结束变量arg
	Serial_SendString(String);		//串口发送字符数组（字符串）
}
```

四个东西各管什么：

| 名字 | 出处 | 作用 |
| --- | --- | --- |
| `...` | C 语言可变参数语法 | 让函数能接任意个参数 |
| `va_list arg` | `<stdarg.h>` | 「可变参数列表」类型的变量，装着 `...` 里收进来的那些参数 |
| `va_start(arg, format)` | `<stdarg.h>` | 从 `format` 后面开始，把参数列表收到 `arg` 里 |
| `vsprintf(String, format, arg)` | `<stdio.h>` | `sprintf` 的「参数已经打包好」版本：按 `format` 把 `arg` 格式化成字符串写进 `String` |
| `va_end(arg)` | `<stdarg.h>` | 结束使用 `arg` |
| `Serial_SendString(String)` | 本文件 | 把拼好的字符串发出去 |

`String[100]` 是**固定 100 字节的栈上缓冲区**，格式化结果超过 99 个字符就会**越界**（官方源码没有做长度检查）。

### 7.1 接收版 `Serial_Init()`（9-2 原文）

```c
uint8_t Serial_RxData;		//定义串口接收的数据变量
uint8_t Serial_RxFlag;		//定义串口接收的标志位变量

/**
  * 函    数：串口初始化
  * 参    数：无
  * 返 回 值：无
  */
void Serial_Init(void)
{
	/*开启时钟*/
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE);	//开启USART1的时钟
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);	//开启GPIOA的时钟
	
	/*GPIO初始化*/
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_9;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);					//将PA9引脚初始化为复用推挽输出
	
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10;
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
	GPIO_Init(GPIOA, &GPIO_InitStructure);					//将PA10引脚初始化为上拉输入
	
	/*USART初始化*/
	USART_InitTypeDef USART_InitStructure;					//定义结构体变量
	USART_InitStructure.USART_BaudRate = 9600;				//波特率
	USART_InitStructure.USART_HardwareFlowControl = USART_HardwareFlowControl_None;	//硬件流控制，不需要
	USART_InitStructure.USART_Mode = USART_Mode_Tx | USART_Mode_Rx;	//模式，发送模式和接收模式均选择
	USART_InitStructure.USART_Parity = USART_Parity_No;		//奇偶校验，不需要
	USART_InitStructure.USART_StopBits = USART_StopBits_1;	//停止位，选择1位
	USART_InitStructure.USART_WordLength = USART_WordLength_8b;		//字长，选择8位
	USART_Init(USART1, &USART_InitStructure);				//将结构体变量交给USART_Init，配置USART1
	
	/*中断输出配置*/
	USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);			//开启串口接收数据的中断
	
	/*NVIC中断分组*/
	NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);			//配置NVIC为分组2
	
	/*NVIC配置*/
	NVIC_InitTypeDef NVIC_InitStructure;					//定义结构体变量
	NVIC_InitStructure.NVIC_IRQChannel = USART1_IRQn;		//选择配置NVIC的USART1线
	NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;			//指定NVIC线路使能
	NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;		//指定NVIC线路的抢占优先级为1
	NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;		//指定NVIC线路的响应优先级为1
	NVIC_Init(&NVIC_InitStructure);							//将结构体变量交给NVIC_Init，配置NVIC外设
	
	/*USART使能*/
	USART_Cmd(USART1, ENABLE);								//使能USART1，串口开始运行
}
```

`USART1_IRQn` 在 `stm32f10x.h` 里定义为 `37`（注释：`USART1 global Interrupt`）。

> [!note] 为什么两级都要配（和 6-1 一模一样的道理）
> - `USART_ITConfig(USART1, USART_IT_RXNE, ENABLE)` 管的是**外设内部**这一级：把「接收数据寄存器非空（RXNE）事件」接到中断输出线上。
> - `NVIC_Init()` 管的是**内核**这一级：让 NVIC 通道 `USART1_IRQn` 能真正打断 CPU。
> 
> 少配任何一级，`USART1_IRQHandler` 都不会被调用。

### 7.2 中断服务函数：收到就存、存了就置标志

```c
/**
  * 函    数：USART1中断函数
  * 参    数：无
  * 返 回 值：无
  * 注意事项：此函数为中断函数，无需调用，中断触发后自动执行
  *           函数名为预留的指定名称，可以从启动文件复制
  *           请确保函数名正确，不能有任何差异，否则中断函数将不能进入
  */
void USART1_IRQHandler(void)
{
	if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET)		//判断是否是USART1的接收事件触发的中断
	{
		Serial_RxData = USART_ReceiveData(USART1);				//读取数据寄存器，存放在接收的数据变量
		Serial_RxFlag = 1;										//置接收标志位变量为1
		USART_ClearITPendingBit(USART1, USART_IT_RXNE);			//清除USART1的RXNE标志位
																//读取数据寄存器会自动清除此标志位
																//如果已经读取了数据寄存器，也可以不执行此代码
	}
}
```

逐句对应到「一次接收到底发生了什么」：

1. **`USART_GetITStatus(USART1, USART_IT_RXNE) == SET`**：先确认这次进中断是不是「收到了一个字节」触发的。USART 的中断源不止一个，中断服务函数可能被别的事件叫醒，所以必须判断。
2. **`USART_ReceiveData(USART1)`**：把接收数据寄存器 RDR 里的字节读出来（返回值 `uint16_t`，赋给 `uint8_t` 变量，只取低 8 位）。**读 RDR 这个动作本身就会清除 RXNE 标志**——这正是官方注释那句「读取数据寄存器会自动清除此标志位」的含义。
3. **`Serial_RxFlag = 1`**：只置一个标志位就退出中断——这是「**中断里少干活，主循环干重活**」的标准做法（和 6-1 定时中断里只 `Num++` 是一个思路）。
4. **`USART_ClearITPendingBit(USART1, USART_IT_RXNE)`**：官方注释给出的是「可以不清」的写法——「如果已经读取了数据寄存器，也可以不执行此代码」。但**写了也不会错**，本工程留着这一行。

### 7.3 `Serial_GetRxFlag()` / `Serial_GetRxData()`

```c
/**
  * 函    数：获取串口接收标志位
  * 参    数：无
  * 返 回 值：串口接收标志位，范围：0~1，接收到数据后，标志位置1，读取后标志位自动清零
  */
uint8_t Serial_GetRxFlag(void)
{
	if (Serial_RxFlag == 1)			//如果标志位为1
	{
		Serial_RxFlag = 0;
		return 1;					//则返回1，并自动清零标志位
	}
	return 0;						//如果标志位为0，则返回0
}

/**
  * 函    数：获取串口接收的数据
  * 参    数：无
  * 返 回 值：接收的数据，范围：0~255
  */
uint8_t Serial_GetRxData(void)
{
	return Serial_RxData;			//返回接收的数据变量
}
```

关键设计：**标志位是「读一次就自动清零」的**（读走 1 的同时把 `Serial_RxFlag` 清 0），所以主循环里 `if (Serial_GetRxFlag() == 1)` 每个字节只会被处理**一次**，不会重复处理。

`Serial.h` 里只导出这两个**函数**，`Serial_RxData` / `Serial_RxFlag` 这两个变量本身**没有** `extern` 出去：

```c
uint8_t Serial_GetRxFlag(void);
uint8_t Serial_GetRxData(void);
```

### 7.4 9-2 的 `main.c`：主循环消费标志位

```c
#include "stm32f10x.h"                  // Device header
#include "Delay.h"
#include "OLED.h"
#include "Serial.h"

uint8_t RxData;			//定义用于接收串口数据的变量

int main(void)
{
	/*模块初始化*/
	OLED_Init();		//OLED初始化
	
	/*显示静态字符串*/
	OLED_ShowString(1, 1, "RxData:");
	
	/*串口初始化*/
	Serial_Init();		//串口初始化
	
	while (1)
	{
		if (Serial_GetRxFlag() == 1)			//检查串口接收数据的标志位
		{
			RxData = Serial_GetRxData();		//获取串口接收的数据
			Serial_SendByte(RxData);			//串口将收到的数据回传回去，用于测试
			OLED_ShowHexNum(1, 8, RxData, 2);	//显示串口接收的数据
		}
	}
}
```

**数据流是一条完整的闭环**：

```text
电脑发 1 字节 ──► PA10 ──► RXNE 事件 ──► USART1_IRQHandler
                                              │ 存进 Serial_RxData
                                              │ Serial_RxFlag = 1
                                              ▼
主循环 while(1) ──► Serial_GetRxFlag() == 1 ──► 取数据
                                              ├──► Serial_SendByte 原样回传（PA9）
                                              └──► OLED_ShowHexNum 显示
```

**现象**：用串口助手发任意一个字节，OLED 第 1 行第 8 列会以两位十六进制显示收到的字节，同时串口助手收到同一个字节（回环测试）。

> [!tip] 「回传」是串口调试里最常用的自检手段
> 收到了就发回去，能一次性验证**发**和**收**两条路都通。如果 OLED 显示了但串口助手没收到，说明发送部分有问题；如果串口助手发了但 OLED 不动，说明接收部分（或中断、或接线）有问题。

## 易错点

- [ ] 忘记开 **GPIOA 时钟**（只开了 USART1）→ GPIO 配置无效，串口一声不响。
- [ ] PA9 配成 `GPIO_Mode_Out_PP` 而不是 **`GPIO_Mode_AF_PP`** → 引脚控制权还在输出数据寄存器手里，硬件发不出波形。
- [ ] 只配了 `USART_ITConfig()` 却没配 **NVIC** → 死活不进 `USART1_IRQHandler`。
- [ ] 中断服务函数名写错（比如 `USART1_IRQHandlerr`）→ 编译能过，但永远进不去；官方注释特别提醒「**请确保函数名正确，不能有任何差异**」（函数名可从启动文件复制）。
- [ ] 在 `Serial_SendByte()` 里**漏掉 `while (USART_GetFlagStatus(..., USART_FLAG_TXE) == RESET)`** → 连续发包时数据被覆盖，串口助手收到的字节缺斤少两。
- [ ] 收完数据在中断里做耗时操作（`Delay`、打印、刷 OLED）→ 拖慢甚至丢掉后续字节。**中断里只置标志位，主循环干活。**
- [ ] 抄了 9-2 的 `Serial_Init()` 到只发不收的场合，却忘了 `USART_Mode` 里的 `USART_Mode_Rx` → 只配了中断没收数据，或者反过来收了却不发。
- [ ] 把 `USART_Mode_Tx` 和 `USART_Mode_Rx` 当成互斥的两个值 → 它们是**位定义**（`0x0008` / `0x0004`），收发都要就 `|` 起来。
- [ ] `Serial_SendNumber(111, 3)` 看到 `111` 以为是「数字 111」→ 发出去的是三个 **ASCII 字符** `31 31 31`，文本模式才显示成 `111`。
- [ ] 用重定向的 `printf` 时**忘了在工程选项里勾 Use MicroLIB** → 官方源码注释明确要求必须勾。
- [ ] `Serial_Printf` 的 `String[100]` 格式化超过 99 字符 → **栈溢出**，官方源码没有长度检查。
- [ ] 串口助手**波特率/数据位/停止位/校验**和代码里不一致 → 收到一堆乱码（比如把 9600 看成 4800）。
- [ ] TX/RX 没有交叉、或者忘了**共地** → 完全收不到数据。

## 自测

1. 本集里单片机用哪两个引脚做串口？分别配成什么 GPIO 模式？为什么这么配？
2. `Serial_SendByte()` 里为什么要 `while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);`？这个标志需要手动清除吗？
3. 官方注释说重定向 `printf` 的方法「不能在多处使用」，指的是什么？有什么替代办法？
4. 接收一个字节的完整链路是什么？从 PA10 收到数据到主循环拿到数据，中间经过了哪几步？
5. 为什么 `Serial_GetRxFlag()` 要在返回 1 的同时把 `Serial_RxFlag` 清 0？

> [!success]- 参考答案
> 1. **PA9（USART1_TX）配 `GPIO_Mode_AF_PP` 复用推挽输出**——波形由 USART 外设产生，复用模式下引脚控制权才交给片上外设；**PA10（USART1_RX）配 `GPIO_Mode_IPU` 上拉输入**——空闲时串口线是高电平，上拉避免悬空乱触发。
> 2. 刚写入数据寄存器时数据还没被硬件搬走，此时再写会覆盖上一字节，所以要等 TXE 置位（官方注释叫「等待发送完成」）。**不需要手动清**——官方注释写明「下次写入数据寄存器会自动清除发送完成标志位」。
> 3. 一个工程里 `printf` 只有一个出口，重定向后就固定绑在某个串口上，想同时在多处输出就不行。替代办法是官方注释里的方法 2（`sprintf` 到字符数组再 `Serial_SendString`）和方法 3（把方法 2 封装成 `Serial_Printf`），它们「可在多处使用」。
> 4. PA10 收到一帧数据 → 数据进接收数据寄存器 RDR、硬件置 RXNE → `USART_ITConfig` 已使能的 RXNE 中断请求送到 NVIC → NVIC 通道 `USART1_IRQn` 已使能，CPU 跳进 `USART1_IRQHandler` → 判断 `USART_GetITStatus(USART1, USART_IT_RXNE) == SET` → `USART_ReceiveData` 读出数据存进 `Serial_RxData`、读 RDR 自动清 RXNE → `Serial_RxFlag = 1` → 退出中断 → 主循环 `Serial_GetRxFlag() == 1` 成立，`Serial_GetRxData()` 取走数据。
> 5. 因为「收到一个字节」这个事件只应该被主循环处理**一次**。标志位读走即清零，才不会同一个字节被反复处理；同时也保证主循环能区分「有新数据」和「没数据」。
