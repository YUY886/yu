# 09-1 USART 串口协议

> [!abstract] 这一集只解决一个问题
> **两根线、一堆约定俗成的规矩，怎么把 0 和 1 一位一位地送过去？**
>
> 答：约定好**电平标准**（多高的电压算 1）、**一帧的格式**（起始位 / 数据位 / 校验位 / 停止位）、**速率**（波特率），收发双方都照这个规矩来，数据就能一位一位地对上。
>
> 这一集**没有代码、没有外设**，全是后面几集要反复用到的名词。
>
> 章索引 [[江协STM32 09 USART串口（章索引）]] ｜ 下一集 [[江协STM32 09-2 USART串口外设]]

## 1 通信接口总览

课件先用一张表把 STM32 上常见的五种通信接口摆在一起（Slide 108）：

| 名称 | 引脚 | 双工 | 时钟 | 电平 | 设备 |
| --- | --- | --- | --- | --- | --- |
| **USART** | TX、RX | 全双工 | 异步 | 单端 | 点对点 |
| **I2C** | SCL、SDA | 半双工 | 同步 | 单端 | 多设备 |
| **SPI** | SCLK、MOSI、MISO、CS | 全双工 | 同步 | 单端 | 多设备 |
| **CAN** | CAN_H、CAN_L | 半双工 | 异步 | 差分 | 多设备 |
| **USB** | DP、DM | 半双工 | 异步 | 差分 | 点对点 |

> [!info] 通信的目的与通信协议
> - **通信的目的**：将一个设备的数据传送到另一个设备，扩展硬件系统。
> - **通信协议**：制定通信的规则，通信双方按照协议规则进行数据收发。（Slide 108）
>
> 串口为什么用得这么多——**成本低、容易使用、通信线路简单**，可实现两个设备的互相通信；单片机的串口可以使单片机与单片机、单片机与电脑、单片机与各式各样的模块互相通信（Slide 109）。

### 1.1 串行 vs 并行

这一对概念课件没有展开，但它是「串口」这个名字的来历，值得先分清：

| | 串行 | 并行 |
| --- | --- | --- |
| 数据线 | 1 根（数据一位一位排队走） | N 根（N 位同时走） |
| 速度 | 单根线上慢，但可以靠提高时钟补救 | 单次搬得多 |
| 线数与成本 | 少，省钱省引脚 | 多，引脚和 PCB 都吃紧 |
| 抗干扰 / 距离 | 线少、易屏蔽，能拉远 | 线多、各位到达时间不一致，远了容易错 |

串口、I2C、SPI、CAN、USB **全都是串行**。STM32 的引脚一共就 48 个，用并行总线是不现实的。

### 1.2 单工 / 半双工 / 全双工

| 方式 | 数据方向 | 需要几根线 |
| --- | --- | --- |
| **单工** | 只能 A → B，不能反向 | 1 根 |
| **半双工** | 能双向，但**同一时刻只能一个方向**（轮流说） | 1 根（加收发切换逻辑） |
| **全双工** | 两个方向**同时**收发 | 2 根（一根发、一根收） |

USART 是**全双工**，所以它至少有两根线：TX（发送）和 RX（接收）。

### 1.3 同步 vs 异步

| | 同步 | 异步 |
| --- | --- | --- |
| 时钟 | 有一根额外的时钟线（如 SPI 的 SCLK、I2C 的 SCL） | **没有时钟线** |
| 靠什么对齐 | 数据跟着时钟边沿走，谁也不用猜 | 双方**事先约定同一个波特率**，各自用自己的时钟采样 |
| 一帧里还要带什么 | 不带起止标记 | 必须带**起始位 / 停止位**来界定一帧 |
| 典型代表 | I2C、SPI、USART 的同步模式 | USART 的异步模式（最常用）、CAN、USB |

USART 的名字就藏在这里：**U**niversal **S**ynchronous/**A**synchronous **R**eceiver/**T**ransmitter——**通用同步/异步收发器**（Slide 114）。名字带「同步」，但本课程全程用的是它的**异步**模式，所以没有时钟线，只有 TX 和 RX。

## 2 硬件电路

课件 Slide 110 给出串口硬件电路的三条规则：

```text
        设备1                              设备2
      ┌───────┐                          ┌───────┐
      │   VCC ├──────────────────────────┤ VCC   │
      │       │                          │       │
      │    TX ├──────────────────────────┤ RX    │
      │    RX ├──────────────────────────┤ TX    │
      │       │                          │       │
      │   GND ├──────────────────────────┤ GND   │
      └───────┘                          └───────┘
```

| 规则 | 说明 |
| --- | --- |
| ① **TX 与 RX 要交叉连接** | 我的「发」接你的「收」，我的「收」接你的「发」 |
| ② 单向传输时可以只接一根线 | 只需要 A 发给 B，那就只连 A 的 TX 到 B 的 RX |
| ③ **电平标准不一致时要加电平转换芯片** | 两边规定的电压含义不同，直连会读错甚至烧口 |

> [!warning] 为什么不能 TX 接 TX
> 一个引脚在「发」的时候是**输出**，在「收」的时候是**输入**。如果两个设备的 TX 接在一起，那就是**两个输出对顶**：一方想拉高、另一方想拉低，结果是这条线上出现一个不高不低的电平（甚至大电流），两边的接收端都读不到东西。所以必须交叉——让一方的输出永远对着另一方的输入。
>
> **共地同理不能省**：电压是相对的，两边的 GND 不连在一起，双方对「几伏算高电平」就没有共同参照。

## 3 电平标准：0 和 1 到底是多少伏

**电平标准是数据 1 和数据 0 的表达方式，是传输线缆中人为规定的电压与数据的对应关系。**（Slide 111）

串口常用的三种：

| 标准 | 表示 1 | 表示 0 | 特点 |
| --- | --- | --- | --- |
| **TTL 电平** | +3.3V 或 +5V | 0V | 芯片引脚直接出来就是它，单端信号，板内短距离 |
| **RS-232** | −3 ~ −15V | +3 ~ +15V | 单端信号，**负逻辑**，电压摆幅大，抗干扰好、传得远 |
| **RS-485** | 两线压差 +2 ~ +6V | 两线压差 −2 ~ −6V | **差分信号**，靠两根线的电压差判断，共模干扰被抵消，可接很多设备、传很远 |

> [!warning] 三种标准不能直接对接
> **TTL ↔ RS-232 必须加电平转换芯片**（而且注意 RS-232 是负逻辑，光降压是不够的）。
>
> 「TTL 串口」（本课程用的）和「电脑上的 9 针串口」（RS-232）**不是一回事**。电脑主机后面那个 DB9 是 RS-232，电压能到 ±15V，直接连到 STM32 的 PA9 上会把引脚打坏——所以课程里用的是「**USB 转串口模块**」，模块里面已经把 USB 转成 TTL 串口了。
>
> 本课程软件安装那一页也把 `USB 转串口驱动` 和 `STLINK 驱动` 分开列出（Slide 14），说明串口这条通道是**独立的一个模块**，不是 STLINK 顺带提供的。

## 4 一帧数据里有什么

课件 Slide 112 把串口参数及时序一次讲完：

| 组成部分 | 含义 | 电平 |
| --- | --- | --- |
| **波特率** | 串口通信的速率 | — |
| **起始位** | 标志一个数据帧的开始 | **固定为低电平** |
| **数据位** | 数据帧的有效载荷，1 为高电平，0 为低电平，**低位先行** | 高 / 低 |
| **校验位** | 用于数据验证，根据数据位计算得来 | 高 / 低 |
| **停止位** | 用于数据帧间隔 | **固定为高电平** |

### 4.1 时序（无校验、8 位数据、1 位停止）

```text
        起始位   D0   D1   D2   D3   D4   D5   D6   D7   停止位
空闲 ──┐      ┌────┬────┬────┬────┬────┬────┬────┬────┐      ┌── 空闲
  (1)  │      │    │    │    │    │    │    │    │    │      │   (1)
       └──────┘    └────┘    └────┘    └────┘    └────┘      └────
        └──────────────────── 10 个位时间 ────────────────────┘
```

- **空闲**时线是**高电平**，所以起始位的那个**下降沿**就是接收方「一帧来了」的信号。
- 停止位是**高电平**，所以一帧结束时线自动回到空闲态，天然为下一帧的下降沿做准备——中间哪怕隔多久都没关系，这正是**异步**能工作的原因。

### 4.2 低位先行（LSB first）

课件写得很明确：**低位先行**。也就是先发 `D0`，最后发 `D7`。

这一条有两个旁证：

- 课件 Slide 113 的时序演示里，`0x55` 被拿来当示例。`0x55 = 0101 0101B`——它的 8 个位**从 D0 到 D7 正好是 1、0、1、0、1、0、1、0**，方波最规整，是示波器上看时序最好看的数。
- 官方参考手册《STM32F10xxx 参考手册》图 249「字长设置」里，帧结构画的是 `起始位 | 位0 | 位1 | ... | 位7 | 停止位`——紧跟起始位的那个位就是**位 0**，同样是低位先行。

> [!tip] 与 SPI 对照记
> **串口低位先行，SPI 高位先行**（见 [[江协STM32 11-1 SPI通信协议]] 里「B7 B6 … B0」的画法）。这两个记反了，收到的是「位序完全颠倒」的数据，最难查。

### 4.3 可配置的位数（来自课件与库函数）

课件 Slide 114 给出 USART 的可配置范围：

| 项目 | 可选值 |
| --- | --- |
| 数据位长度 | **8 / 9** |
| 停止位长度 | **0.5 / 1 / 1.5 / 2** |
| 校验位 | **无校验 / 奇校验 / 偶校验** |

这几组取值在标准库里一一对应（`stm32f10x_usart.h`）：

```c
#define USART_WordLength_8b    ((uint16_t)0x0000)
#define USART_WordLength_9b    ((uint16_t)0x1000)   /* 数据位只能 8 或 9 */

#define USART_StopBits_1       ((uint16_t)0x0000)
#define USART_StopBits_0_5     ((uint16_t)0x1000)
#define USART_StopBits_2       ((uint16_t)0x2000)
#define USART_StopBits_1_5     ((uint16_t)0x3000)   /* 停止位四档 */

#define USART_Parity_No        ((uint16_t)0x0000)
#define USART_Parity_Even      ((uint16_t)0x0400)
#define USART_Parity_Odd       ((uint16_t)0x0600)   /* 校验位三档 */
```

> [!note] 0.5 / 1.5 个停止位是给谁的
> 官方参考手册图 250「配置停止位」把 0.5 / 1 / 1.5 / 2 四种都画了出来。0.5 和 1.5 在**异步串口**里很少用，主要是配合**智能卡**等同步/半同步协议。本课程只用 1 位停止位。

### 4.4 校验位是怎么算出来的

校验位是**根据数据位计算得来**的（Slide 112），规则只有一句话：

| 方式 | 规则 | 效果 |
| --- | --- | --- |
| **偶校验**（Even） | 补上校验位后，整个「数据位 + 校验位」里 **1 的个数为偶数** | — |
| **奇校验**（Odd） | 补上校验位后，整个「数据位 + 校验位」里 **1 的个数为奇数** | — |
| 无校验 | 不发校验位 | 少一位，效率最高 |

举例，数据位是 `1011 0011`：

```text
数一下 1 的个数：1+0+1+1+0+0+1+1 = 5 个（奇数）
偶校验 → 校验位补 1，补完 6 个 1（偶数）
奇校验 → 校验位补 0，补完 5 个 1（奇数）
```

> [!warning] 校验位只能「发现」奇数个错，不能纠正
> 偶数个位同时翻转，奇偶性不变，校验位查不出来。所以校验位是**弱保护**，不是可靠传输的保证。（课件只写了「用于数据验证」，未展开强弱，此处按标准库头文件与参考手册的机制说明。）

还有一个容易忽略的细节，标准库头文件里写得很清楚：

> When parity is enabled, the computed parity is inserted at the MSB position of the transmitted data (9th bit when the word length is set to 9 data bits; 8th bit when the word length is set to 8 data bits).

也就是**开了校验位之后，校验位占用的是「最高位」的位置**：字长选 9 位时它是第 9 位，字长选 8 位时它是第 8 位。所以「8 位数据 + 1 位校验」实际上一帧里数据只有 7 位。**要么用 8 位数据不校验，要么用 9 位字长加校验**，才能凑够 8 位有效数据。

## 5 波特率与位时间

**波特率：串口通信的速率。**（Slide 112）单位是 **bps（bit per second）**，也就是**每秒传多少个位**。

异步串口没有时钟线，双方能对上，全靠事先约定同一个波特率。

### 5.1 位时间

```text
一个位的时间 T_bit = 1 / 波特率
```

| 波特率 | 一个位的时间 | 备注 |
| --- | --- | --- |
| 4800 | 1 / 4800 ≈ **208.33 μs** | 课件 Slide 113 里有一个 4800 的对照例子 |
| 9600 | 1 / 9600 ≈ **104.17 μs** | 课件 Slide 113 的默认演示速率、本课程两个工程的取值 |
| 115200 | 1 / 115200 ≈ **8.68 μs** | 常用高速档；**课件与本课程源码中未见此值**，此处仅作为背景知识列出 |

### 5.2 一帧占多长时间

一帧的位数 = `1（起始位） + 数据位 + 校验位 + 停止位`。

本课程用的配置是「8 位数据、无校验、1 位停止」：

```text
一帧 = 1 + 8 + 0 + 1 = 10 位
一帧时间 = 10 / 9600 ≈ 1.042 ms
```

反过来说，一秒钟最多能发 `9600 / 10 = 960` 个字节。

### 5.3 波特率误差为什么会累积

接收方靠**自己的时钟**去采样，它并不知道发送方真正什么时候开始。做法是：侦测到起始位的下降沿后，以采样时钟为单位数节拍，在**每一位的中间**取样。

于是误差会**逐位累积**：

```text
发送方发的第 1 位 → 接收方采在中间    ✔
如果接收方时钟比发送方快，采样的时刻会越来越早
如果接收方时钟比发送方慢，采样的时刻会越来越晚
```

> [!warning] 允许的误差不是 ±3%，而是由「采样窗口」决定的
> **课件、官方源码、本课程接线图里都没有给出「波特率误差 ±3%」这个数字**，本页不把它当结论写。
>
> 按官方参考手册的采样机制自己推：接收方在每一位的第 `8 / 9 / 10` 个采样节拍里取多数值，也就是允许采样点偏离位中心约 **2/16 = 12.5% 个位时间**。一帧有 10 位，误差是**累积**的，用最后一位来卡：
>
> ```text
> 允许的波特率误差 ≈ 12.5% / 9 ≈ 1.4%
> ```
>
> 留一倍余量的话，**「±3% 以内」确实是一个安全的工程经验值**，但它的来源是工程经验，不是本课程官方材料。相关条目已放进下面的「待核对」。

### 5.4 本课程用 9600 的误差有多大

F103 上 USART1 挂 **APB2**，本课程主频 72 MHz，所以 `PCLK2 = 72 MHz`。

标准库 `USART_Init()` 的换算是（`stm32f10x_usart.c`，16 倍过采样分支）：

```c
integerdivider = ((25 * apbclock) / (4 * (USART_InitStruct->USART_BaudRate)));
tmpreg = (integerdivider / 100) << 4;
fractionaldivider = integerdivider - (100 * (tmpreg >> 4));
```

也就是先算 `25 × PCLK / (4 × 波特率)`，再把这个数除以 100 取整当**整数部分**、余数当**小数部分**。等价于：

```text
USARTDIV = PCLK / (16 × 波特率)
DIV_Mantissa = USARTDIV 的整数部分
DIV_Fraction = USARTDIV 的小数部分 × 16（四舍五入）
```

代入 9600：

```text
USARTDIV = 72 000 000 / (16 × 9600) = 468.75
```

`468.75` 的 `.75` 正好是 `12/16`，小数部分**能被 1/16 的刻度整除**，所以写进 `BRR` 的整数部分和小数部分都精确，没有取整误差：

```text
DIV_Mantissa = 468 = 0x1D4      DIV_Fraction = 12 = 0xC
BRR = (468 << 4) | 12 = 0x1D4C
```

> [!tip] 9600 是「好波特率」
> 因为 `72 MHz / 16 = 4.5 MHz`，`4.5 MHz / 9600 = 468.75` 恰好落在 1/16 的格点上。有些波特率算出来除不尽（比如某些非标准速率），就只能近似，那时候累计误差才需要认真算。

## 6 数据模式：HEX 与文本

课件 Slide 122 用 `0x41` 举例说明两种「看数据」的方式：

| 模式 | 别名 | 显示方式 |
| --- | --- | --- |
| **HEX 模式** | 十六进制模式 / 二进制模式 | 以**原始数据**的形式显示 |
| **文本模式** | 字符模式 | 以**原始数据编码后的形式**显示 |

```text
发送方            接收方
 0x41 ──────────► 0x41        HEX 模式：直接看字节的十六进制值
 'A'  ──编码──► 0x41 ──译码──► 'A'   文本模式：把字节当成字符编码来看
```

关键点：**串口线上跑的永远只是 0 和 1，所谓 HEX / 文本只是上位机软件的显示方式。**`0x41` 和 `'A'` 在线上是**完全相同**的一串电平。这条到 9-4、9-5 讲数据包时会有大用。

## 7 易错点

- [ ] **TX 接 TX**：两个输出对顶。必须 TX-RX 交叉。
- [ ] **忘了共地**：两边的「高电平」没有共同参照，收到的全是乱码。
- [ ] **把 TTL 串口和 RS-232 当成一回事**：电脑 DB9 是 ±15V 的负逻辑，直连 STM32 会打坏引脚，必须经 USB 转串口模块。
- [ ] **以为串口有「高位先行」**：串口是**低位先行**（`D0` 先出），和 SPI 相反。
- [ ] **以为空闲电平是低**：空闲是**高**电平；正是靠起始位那个下降沿起帧。
- [ ] **开了校验位却还按 8 位数据算**：校验位占的是最高位位置，8 位字长 + 校验 = 只有 7 位有效数据。
- [ ] **两边波特率不一致**：字节会收到「错位」的效果，看起来像随机数，而不是干脆收不到。
- [ ] **把「波特率」当成「字节率」**：9600 波特率配 8N1 时，一秒钟只有 960 个字节。
- [ ] **以为校验位能纠错**：只能发现奇数个位错，偶数个位错查不出来。
- [ ] **以为 HEX / 文本模式影响线上电平**：线上是同一串 0/1，区别只在上位机怎么显示。

## 8 自测

1. 串口线上空闲时是高电平还是低电平？接收方靠什么判断「一帧开始了」？
2. 波特率 9600、8 位数据、无校验、1 位停止时，发一个字节需要多长时间？
3. 数据位是 `0101 0101`，用偶校验时校验位应该是几？
4. 为什么两个设备的 TX 不能接在一起？
5. USART 的名字里「同步/异步」指的是什么？本课程用的是哪一种？
6. `PCLK2 = 72 MHz`、波特率 9600，`USARTDIV` 是多少？小数部分能不能精确表示？

> [!success]- 参考答案
> 1. 空闲是**高**电平。接收方靠**起始位的下降沿**（高 → 低）判断一帧开始。
> 2. 一帧 10 位（1 起始 + 8 数据 + 1 停止），`10 / 9600 ≈ 1.042 ms`。
> 3. `0101 0101` 里有 4 个 1，已经是偶数，所以校验位补 **0**（保持偶数个 1）。
> 4. 因为发的时候引脚是输出。两个输出对顶，一方拉高一方拉低，线上会出现无效电平，双方都收不到正确数据。
> 5. 「同步」是有额外时钟线、数据跟着时钟走；「异步」是没有时钟线、双方靠事先约定的波特率对齐。USART 同步异步都支持，本课程用的是**异步**模式（所以只有 TX / RX 两根线）。
> 6. `USARTDIV = 72 000 000 / (16 × 9600) = 468.75`。小数部分 `0.75 = 12/16`，**能精确表示**，`BRR` 写 `(468 << 4) | 12`。
