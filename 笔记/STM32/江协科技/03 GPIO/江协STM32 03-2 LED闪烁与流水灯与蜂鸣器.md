# 03-2 LED 闪烁 & LED 流水灯 & 蜂鸣器

> [!abstract] 这一集只解决一个问题
> **知道怎么输出电平了，怎么让它"动起来"？**
>
> 答：加一个**软件延时**（`Delay_ms()`），再按顺序改电平——LED 就闪、就跑，蜂鸣器就叫。这一集没有新外设，全部是在 3-1 的函数上做组合。
>
> 顺手要记住两件事：**LED 是低电平点亮还是高电平点亮**取决于硬件接法；**有源和无源蜂鸣器驱动方式完全不同**。
>
> 上一集 [[江协STM32 03-1 GPIO输出]] ｜ 下一集 [[江协STM32 03-3 GPIO输入]] ｜ 章索引 [[江协STM32 03 GPIO（章索引）]]

## 1 LED 硬件电路

### 1.1 LED 是什么

**LED（Light Emitting Diode，发光二极管）**：**正向通电点亮，反向通电不亮**。所以它是一个有极性的器件，接反了不亮（也不会烧，但就是没反应）。

**怎么认正负极**：

| 判断方式 | 正极（+，阳极 Anode） | 负极（−，阴极 Cathode） |
| --- | --- | --- |
| 看引脚长短 | **长脚** | **短脚** |
| 看内部电极 | 较小的那一半 | 较大的那一半 |
| 看电路符号 | 三角形平的那一侧 | 三角形尖端 + 横杠那一侧 |

### 1.2 限流电阻

LED 两端必须串一个**限流电阻**：

- **防止电流过大烧毁 LED**。LED 正向导通后压降基本固定，不加电阻时电流只受电源内阻限制，很容易超额定值。
- **调节亮度**。觉得太亮就增大阻值，太暗就减小阻值。

> [!warning] 限流电阻阻值不在可获取资料中
> 官方接线图 3-1 / 3-2 里 **LED 与 GPIO 之间画有限流电阻（面包板上那两只立式元件）**，确认「必须串限流电阻」这一点；但**具体阻值在官方源码、接线图、课件文本里都查不到**，见 `## 待核对`。

### 1.3 低电平点亮（灌电流） vs 高电平点亮（拉电流）

用 GPIO 驱动 LED 有两种接法：

| | 低电平点亮 | 高电平点亮 |
| --- | --- | --- |
| 接法 | LED 正极 → 3.3V，负极 → 限流电阻 → 引脚（PA0） | LED 负极 → GND，正极 → 限流电阻 → 引脚（PA0） |
| 引脚输出低 | LED 两端有 3.3V 压差，**正向导通 → 亮** | LED 两端都是 0V，无电流 → 灭 |
| 引脚输出高 | LED 两端都是 3.3V，无电流 → 灭 | LED 两端有 3.3V 压差，**正向导通 → 亮** |
| 电流方向 | 电流由 3.3V **灌入**引脚（sink / 灌电流） | 电流由引脚**流出**到 GND（source / 拉电流） |

**为什么单片机电路里更常用低电平点亮**：很多单片机和芯片是"**高电平弱驱动、低电平强驱动**"的规则，这样可以在一定程度上避免高低电平互相"打架"。3-1 里也讲过，推挽输出高低都有驱动能力，所以两种接法本来都能用；但**如果某个引脚的拉电流能力弱，就只能用低电平驱动**。

实战中两种接法都要会：

- 写代码时先看硬件图，**低电平点亮就用 `GPIO_ResetBits()`，高电平点亮就用 `GPIO_SetBits()`**。
- 3-1 里那个实测（开漏模式下"正极接引脚"点不亮、"负极接引脚"能亮）说明的正是这件事：**开漏只有低电平有驱动能力，所以只能配低电平点亮的接法**。

> [!note] 本集代码用的是低电平点亮
> 流水灯里的 `GPIO_Write(GPIOA, ~0x0001)` 这种"取反"写法，前提就是**低电平点亮**——取反是为了让目标引脚为 0（亮），其他引脚为 1（灭）。如果你的板子是高电平点亮，所有取反都要去掉。

## 2 蜂鸣器硬件电路

### 2.1 有源 vs 无源蜂鸣器

| | 有源蜂鸣器 | 无源蜂鸣器 |
| --- | --- | --- |
| 内部振荡源 | **有**，自带振荡电路 | **没有** |
| 驱动方式 | 接上**直流电压**就能持续发声 | 必须由控制器提供**振荡脉冲**（方波）才能发声 |
| 发声频率 | **固定**，由内部振荡源决定 | **可调**，改脉冲频率就能发出不同音调 |
| 能否演奏音乐 | 不能 | **能**（这正是后面 PWM 章节做音乐喷泉/电子琴的原理） |
| 控制难度 | 低，写 0/1 即可 | 需要用定时器 PWM 输出方波 |

一句话记：**有源"自己会响"，无源"要你给它打拍子"**。

> [!warning] 不要望文生义
> "有源 / 无源"里的**源**指的是**振荡源**，不是"电源"。有源蜂鸣器照样需要外部供电，只是不需要外部提供振荡信号。

### 2.2 为什么要用三极管驱动

蜂鸣器的工作电流通常比 LED 大得多，**直接用 IO 口驱动会让 STM32 负担过重**（甚至超过引脚的最大灌/拉电流）。所以用一个**三极管开关**电路，由 GPIO 控制三极管的通断，让三极管去承担蜂鸣器的电流。

两种接法：

| | PNP 三极管 | NPN 三极管 |
| --- | --- | --- |
| 接在电源侧还是地侧 | **接在上边**（靠 VCC 一侧） | **接在下边**（靠 GND 一侧） |
| 基极给低电平 | **导通**，蜂鸣器响 | 截止，不响 |
| 基极给高电平 | 截止，不响 | **导通**，蜂鸣器响 |
| 对应 GPIO 控制逻辑 | 低电平响（与低电平点亮的 LED 一致） | 高电平响 |

> [!tip] 为什么 PNP 接上、NPN 接下
> 三极管导通需要在**发射极和基极之间**建立一定的开启电压。如果把负载接在发射极一侧，发射极电位会被负载抬高，基极就可能建立不起足够的 VBE，导致三极管无法正常导通。所以 **PNP 放上边、NPN 放下边**。

> [!note] 本集现象
> 课程例程中**低电平让蜂鸣器鸣叫、高电平停止**（官方 `3-3 蜂鸣器\User\main.c` 第 24~26 行注释），与「低电平触发的驱动电路」一致。接线图 3-3 里用的是成品三脚模块（VCC/GND/I-O），**模块内部的具体三极管型号与接法未在可获取资料中给出**，故本节只作一般性电路讲解，不对模块内部下定论。

## 3 Delay 延时模块

### 3.1 为什么需要软件延时

LED 闪烁的本质是"**切换电平 → 等一会儿 → 再切换**"。切换电平 3-1 已经会了，缺的就是"等一会儿"。

软件延时（也叫**忙等待 / 空循环延时**）：让 CPU 干等一段时间。它的原理可以是数空循环，也可以像课程这样**用 SysTick 定时器计时**——精度更好，且不占用其他定时器资源。

> [!warning] 软件延时是阻塞的
> 延时期间 **CPU 什么都干不了**。等以后学了定时器中断（第 6 章），周期性任务就应该改用硬件定时器，而不是在主循环里 `Delay_ms()`。

### 3.2 SysTick 是什么

**SysTick（System Tick Timer，系统滴答定时器）** 是 Cortex-M3 **内核**里的一个 24 位递减计数器。关键特性：

- **24 位**，所以最大计数值是 `2^24 − 1 = 16777215`。
- **递减计数**：从 `LOAD` 往下数到 0。
- 计数到 0 时，`CTRL` 寄存器的 **COUNTFLAG（第 16 位）**会被硬件置 1，用它就能判断"时间到了"。
- 属于内核外设，所以**不需要开 RCC 时钟**（这点和 GPIO 不同）。

SysTick 三个寄存器（`stm32f10x.h` 里通过 `SysTick` 结构体访问）：

| 寄存器 | 作用 |
| --- | --- |
| `SysTick->LOAD` | 重装载值：从多少开始往下数 |
| `SysTick->VAL` | 当前计数值，写它可清零 |
| `SysTick->CTRL` | 控制寄存器：使能、时钟源选择、COUNTFLAG |

`CTRL` 关键位（按位解读代码里那两个魔数）：

```text
0x00000005 = 0b101
             bit2 = 1  → 时钟源选 HCLK（不分频，即 72MHz）
             bit1 = 0  → 计数到 0 不产生中断（用轮询就够，不需要中断）
             bit0 = 1  → 使能定时器，开始计数

0x00000004 = 0b100
             bit2 = 1  → 保持时钟源选择
             bit0 = 0  → 关闭定时器

0x00010000 → bit16 = COUNTFLAG，计数到 0 时硬件置 1
```

### 3.3 `Delay_us` 的原理

要在 72MHz 下延时 `xus` 微秒：

```text
需要的计数值 = 72 × xus      （1 微秒 = 72 个时钟周期）
```

所以 `SysTick->LOAD = 72 * xus;` 即可。流程是：

```text
① 装载 LOAD = 72 * xus
② 清零 VAL
③ CTRL = 5（选 HCLK、使能、不开中断）→ 开始递减
④ 轮询 CTRL 的 COUNTFLAG，等待计数到 0
⑤ CTRL = 4 → 关闭定时器（省电，也避免干扰后续调用）
```

**为什么 `Delay_us` 的上限是 233015**：

```text
LOAD 是 24 位，最大 = 2^24 − 1 = 16777215
xus_max = 16777215 / 72 ≈ 233015.5  →  取 233015
```

超过这个值写进 `LOAD` 就会被截断，延时严重偏短。

### 3.4 完整代码

`Delay.h`：

```c
#ifndef __DELAY_H
#define __DELAY_H

void Delay_us(uint32_t us);
void Delay_ms(uint32_t ms);
void Delay_s(uint32_t s);

#endif
```

`Delay.c`：

```c
#include "stm32f10x.h"

/**
  * @brief  微秒级延时
  * @param  xus 延时时长，范围：0~233015
  * @retval 无
  * @note   用内核的 SysTick 计数器实现；24 位 LOAD 决定了 xus 不能无限大
  */
void Delay_us(uint32_t xus)
{
	SysTick->LOAD = 72 * xus;               // 设置重装值：1us = 72 个 72MHz 时钟周期
	SysTick->VAL = 0x00;                    // 清空当前计数值，保证从 LOAD 开始数
	SysTick->CTRL = 0x00000005;             // 选 HCLK 为时钟源、使能定时器（bit2=1, bit0=1）
	while (!(SysTick->CTRL & 0x00010000));  // 轮询 COUNTFLAG（bit16），等待计数到 0
	SysTick->CTRL = 0x00000004;             // 关闭定时器（bit0=0），避免影响下一次调用
}

/**
  * @brief  毫秒级延时
  * @param  xms 延时时长，范围：0~4294967295
  * @retval 无
  * @note   靠反复调用 Delay_us(1000) 累加，所以每次 1ms 都有一点点轮询开销
  */
void Delay_ms(uint32_t xms)
{
	while (xms--)
	{
		Delay_us(1000);
	}
}

/**
  * @brief  秒级延时
  * @param  xs 延时时长，范围：0~4294967295
  * @retval 无
  */
void Delay_s(uint32_t xs)
{
	while (xs--)
	{
		Delay_ms(1000);
	}
}
```

### 3.5 使用要点

- 把 `Delay.c` / `Delay.h` 放进工程的 `System` 分组，并把该文件夹加进**头文件搜索路径**，否则 `#include "Delay.h"` 会找不到。
- `Delay_us()` 单次上限约 **233ms**，`Delay_ms()` 靠循环调它来突破这个限制。
- **`Delay` 依赖主频是 72MHz**。`72 * xus` 这个系数就是照着 72MHz 写的；如果改主频（比如跑 36MHz 或超频），延时就会整体偏长或偏短，必须同步改系数。

> [!warning] 软件延时没有"绝对准确"
> 轮询本身、函数调用本身都要花时间，而且调 `Delay_ms(1)` 一千次并不精确等于调 `Delay_us(1000)` 一次。做严格计时请用硬件定时器，软件延时只适合点灯这类对人眼足够快的场合。

## 4 实验一：LED 闪烁

**目标**：LED 亮 500ms、灭 500ms，反复循环。

### 4.1 硬件

LED 串限流电阻接到 **PA0**，按**低电平点亮**接法（LED 阳极接 3.3V、阴极经限流电阻接 PA0）。

### 4.2 工程结构

```text
项目/
├── Start/     启动文件、内核文件
├── Library/   ST 标准外设库
├── System/    Delay.c、Delay.h
└── User/      main.c
```

### 4.3 完整代码（含三种写法）

```c
#include "stm32f10x.h"   // Device header
#include "Delay.h"

int main(void)
{
	/* 开启时钟：GPIO 挂在 APB2 上 */
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

	/* GPIO 初始化：PA0 推挽输出 */
	GPIO_InitTypeDef GPIO_InitStructure;                      // 定义结构体变量

	GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;         // 推挽输出：高低电平都有驱动能力
	GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_0;               // 第 0 号引脚，即 PA0
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;         // 输出速度 50MHz

	GPIO_Init(GPIOA, &GPIO_InitStructure);                    // 写入配置，完成 GPIOA 初始化

	/* 主循环：反复执行 */
	while (1)
	{
		/* ===== 方法 1：GPIO_ResetBits 置低，GPIO_SetBits 置高（最常用） ===== */
		GPIO_ResetBits(GPIOA, GPIO_Pin_0);       // PA0 输出低电平 → LED 亮
		Delay_ms(500);                           // 延时 500ms
		GPIO_SetBits(GPIOA, GPIO_Pin_0);         // PA0 输出高电平 → LED 灭
		Delay_ms(500);                           // 延时 500ms

		/* ===== 方法 2：GPIO_WriteBit + Bit_RESET / Bit_SET ===== */
		GPIO_WriteBit(GPIOA, GPIO_Pin_0, Bit_RESET);   // PA0 = 0
		Delay_ms(500);
		GPIO_WriteBit(GPIOA, GPIO_Pin_0, Bit_SET);     // PA0 = 1
		Delay_ms(500);

		/* ===== 方法 3：GPIO_WriteBit + 数据 0/1，需强转为 BitAction 枚举 ===== */
		GPIO_WriteBit(GPIOA, GPIO_Pin_0, (BitAction)0);  // PA0 = 0
		Delay_ms(500);
		GPIO_WriteBit(GPIOA, GPIO_Pin_0, (BitAction)1);  // PA0 = 1
		Delay_ms(500);
	}
}
```

> [!note] 三种方法为什么效果一样
> 三种写法的区别只在**参数形式**，底层最终都是去写 BSRR / BRR（见 3-1 第 3.5 节）。方法 3 之所以要 `(BitAction)` 强转，是因为 C 语言的 `0` / `1` 是 `int` 类型，而形参要求的是 `BitAction` 枚举类型，直接传会报警告。官方 `3-1 LED闪烁\User\main.c` 第 26~42 行就是这三种写法原样排列，方法与顺序完全一致。

## 5 实验二：LED 流水灯

**目标**：多个 LED 依次点亮，形成"流水"效果。

### 5.1 硬件

LED 分别接 **PA0 ~ PA7**，每个都串限流电阻，**低电平点亮**。

> [!note] 8 个 LED，引脚就是 PA0 ~ PA7
> 官方接线图 `3-2 LED流水灯.png` 上画了 **8 只 LED**，阴极分别经限流电阻接微控制器板的 **PA0 ~ PA7**、阳极统一接正电源轨（故为低电平点亮）；官方源码 `3-2 LED流水灯\User\main.c` 把 `GPIOA` 全部引脚配成推挽输出，再依次把 PA0 ~ PA7 拉低。**接线图与源码互相印证，8 路引脚已确认。**

> [!tip] 下一集 LED 换引脚了，别被绕晕
> 本集是**把代码直接写在 `main.c` 里**，用 `GPIO_Write()` 操作 **PA0 ~ PA7** 一整组引脚——流水灯要的就是"一组同时可控"。
>
> 到了 [[江协STM32 03-4 按键控制LED与光敏传感器]]，老师会把 LED、蜂鸣器**封装成独立模块**（`LED.c/h`、`Buzzer.c/h`），并且改用开发板上那两个 **PA1 / PA2** 的 LED 来做按键实验（已核对官方 `3-4 按键控制LED\Hardware\LED.c`：`GPIO_Pin_1 | GPIO_Pin_2`）。
>
> 两集引脚不同**不是前后矛盾**，而是需求差别：流水灯要 8 路，按键实验只要 2 路。

### 5.2 思路

- 一次性把 PA0 ~ PA7 全配成推挽输出，用 `GPIO_Pin_All`（或按位或 `GPIO_Pin_0 | ... | GPIO_Pin_7`）。
- 用 `GPIO_Write()` **整体写 16 位输出**：只让目标引脚为 0（亮），其余全为 1（灭）。
- 因为"低电平亮"，所以目标位要**按位取反**：想亮 PA0 就写 `~0x0001`。

```text
目标：只亮 PA0
0x0001 = 0000 0000 0000 0001
~0x0001= 1111 1111 1111 1110   ← 只有第 0 位是 0，PA0 亮，其余全灭
```

### 5.3 完整代码

```c
#include "stm32f10x.h"   // Device header
#include "Delay.h"

int main(void)
{
	/* 开启时钟 */
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

	/* GPIO 初始化：把 GPIOA 所有引脚都配成推挽输出 */
	GPIO_InitTypeDef GPIO_InitStructure;

	GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;      // 推挽输出
	GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_All;          // 全部 16 个引脚
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;

	GPIO_Init(GPIOA, &GPIO_InitStructure);

	/* 主循环：依次点亮 PA0 ~ PA7 */
	while (1)
	{
		GPIO_Write(GPIOA, ~0x0001);   // 0000 0000 0000 0001 取反 → 只有 PA0 为低电平，亮
		Delay_ms(100);
		GPIO_Write(GPIOA, ~0x0002);   // 0000 0000 0000 0010 取反 → 只有 PA1 为低电平，亮
		Delay_ms(100);
		GPIO_Write(GPIOA, ~0x0004);   // 0000 0000 0000 0100 取反 → 只有 PA2 为低电平，亮
		Delay_ms(100);
		GPIO_Write(GPIOA, ~0x0008);   // 0000 0000 0000 1000 取反 → 只有 PA3 为低电平，亮
		Delay_ms(100);
		GPIO_Write(GPIOA, ~0x0010);   // 0000 0000 0001 0000 取反 → 只有 PA4 为低电平，亮
		Delay_ms(100);
		GPIO_Write(GPIOA, ~0x0020);   // 0000 0000 0010 0000 取反 → 只有 PA5 为低电平，亮
		Delay_ms(100);
		GPIO_Write(GPIOA, ~0x0040);   // 0000 0000 0100 0000 取反 → 只有 PA6 为低电平，亮
		Delay_ms(100);
		GPIO_Write(GPIOA, ~0x0080);   // 0000 0000 1000 0000 取反 → 只有 PA7 为低电平，亮
		Delay_ms(100);
	}
}
```

### 5.4 想写得更"聪明"一点

上面那 8 行是展开写法（课程为了看清规律而展开）。等价的可读写法：

```c
/* 用循环 + 移位，效果完全一样 */
while (1)
{
	for (uint8_t i = 0; i < 8; i++)
	{
		GPIO_Write(GPIOA, ~(0x0001 << i));   // 第 i 位为 0，其余为 1
		Delay_ms(100);
	}
}
```

### 5.5 常见"跑偏"现象

| 现象 | 原因 |
| --- | --- |
| 8 个灯一起亮，不流水 | 用了 `GPIO_SetBits` / `GPIO_ResetBits` 而不是整体写，只开关了一个灯 |
| 只有 1 个灯亮着不动 | 忘了写 `Delay_ms()`，切换太快肉眼看不见 |
| 亮灭完全反了 | 板子是**高电平点亮**，把 `~` 去掉即可 |
| 只亮了前几个 | 引脚没全配成输出，或某几个 LED 硬件没接 |

## 6 实验三：蜂鸣器鸣叫

**目标**：让蜂鸣器发出"滴——滴——"两短一长的声音。

### 6.1 硬件

蜂鸣器模块的信号脚接 **PB12**，模块**内部自带振荡电路与驱动三极管**，**低电平鸣叫、高电平停止**。

> [!note] 用的是「有源蜂鸣器」
> 课程官方资料包 `模块资料.zip` 里，对应模块的文件夹名就是 **`3-有源蜂鸣器`**（内含 `有源蜂鸣器模块原理图.png`、`有源蜂鸣器模块实物图.png`），故本实验用的是**有源蜂鸣器**。官方接线图 `3-3 蜂鸣器.png` 中，该模块是 **VCC / GND / I-O 三脚模块**——**驱动电路做在模块内部**，不是拿分立三极管在面包板上搭的；模块的 I/O 脚接微控制器板 **PB12**（与官方 `3-3 蜂鸣器\User\main.c` 的 `GPIOB` + `GPIO_Pin_12` 一致）。**模块内部具体用哪种三极管、什么参数，官方资料中未见**，见 `## 待核对`。

### 6.2 完整代码

```c
#include "stm32f10x.h"   // Device header
#include "Delay.h"

int main(void)
{
	/* 开启时钟：注意这次是 GPIOB */
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);

	/* GPIO 初始化：PB12 推挽输出 */
	GPIO_InitTypeDef GPIO_InitStructure;

	GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;      // 推挽输出
	GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_12;           // 第 12 号引脚，即 PB12
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;

	GPIO_Init(GPIOB, &GPIO_InitStructure);                 // 注意参数是 GPIOB

	/* 主循环：两短一长 */
	while (1)
	{
		GPIO_ResetBits(GPIOB, GPIO_Pin_12);   // PB12 输出低电平 → 蜂鸣器鸣叫
		Delay_ms(100);                        // 响 100ms
		GPIO_SetBits(GPIOB, GPIO_Pin_12);     // PB12 输出高电平 → 蜂鸣器停止
		Delay_ms(100);                        // 停 100ms

		GPIO_ResetBits(GPIOB, GPIO_Pin_12);   // 第二声短鸣
		Delay_ms(100);
		GPIO_SetBits(GPIOB, GPIO_Pin_12);
		Delay_ms(700);                        // 停 700ms，形成"滴-滴——"的节奏
	}
}
```

### 6.3 为什么只有"滴"没有"音调"

本实验的现象**只能控制"响 / 不响"和"响多久"，改不了音调**，这与**有源蜂鸣器**的特征一致：内部自带振荡源，发声频率固定。课程官方资料包 `模块资料.zip` 中的模块文件夹名即为 **`3-有源蜂鸣器`**，与现象吻合。

想让它唱出不同音高，必须换成**无源蜂鸣器**，并用**定时器输出 PWM 方波**去驱动它——那正是第 6 章 TIM 输出比较的内容。

## 7 易错点

- [ ] LED 接反（长脚当负极）→ 死活不亮，还以为代码错了。
- [ ] 忘了串限流电阻 → LED 过流发烫甚至烧掉。
- [ ] 没搞清板子是低电平点亮还是高电平点亮 → 流水灯亮灭完全反。
- [ ] 蜂鸣器实验忘了把 `RCC_APB2Periph_GPIOA` 改成 `RCC_APB2Periph_GPIOB` → PB12 无输出。
- [ ] `GPIO_Init()` 第一个参数写 `GPIOA` 但引脚用的 `GPIO_Pin_12`，或反过来 → 配错端口。
- [ ] 在流动灯里混用 `GPIO_SetBits()` 和 `GPIO_Write()` → 前者只动一位，会残留上一个灯。
- [ ] 用 `GPIO_Write()` 时忘了 `~` 取反 → 变成"一个灯灭、其余全亮"，看着像坏了一个。
- [ ] `Delay.c` / `Delay.h` 没加进头文件搜索路径 → 编译报 `cannot open source input file "Delay.h"`。
- [ ] 改了系统主频却没改 `Delay_us()` 里的 `72` 系数 → 所有延时整体偏长或偏短。
- [ ] `Delay_us()` 传超过 233015 的值 → 24 位 LOAD 溢出截断，延时严重偏短。
- [ ] 在有源蜂鸣器上试图用延时改音调 → 徒劳，有源蜂鸣器频率固定。
- [ ] 主循环里大量使用 `Delay_ms()` 做"多任务" → 各任务相互拖慢，后面应改用定时器中断。

## 8 自测

1. LED 怎么用肉眼分辨正负极？为什么必须串限流电阻？
2. "低电平点亮"和"高电平点亮"，电流方向分别是什么？为什么单片机电路更常用低电平点亮？
3. 有源蜂鸣器和无源蜂鸣器的本质区别是什么？想让它发出不同音调该用哪种？
4. `Delay_us()` 里 `SysTick->LOAD = 72 * xus` 的 `72` 是怎么来的？为什么 `xus` 最大只能到约 233015？
5. 流水灯代码 `GPIO_Write(GPIOA, ~0x0004)` 中，为什么必须取反？如果板子是高电平点亮，这行应该怎么写？

> [!success]- 参考答案
> 1. **引脚长的为正极、短的为负极**（也可看内部电极：较小的一半是正极）。因为 LED 正向导通后压降基本固定，不加限流电阻时电流只受电源内阻限制，很容易超过额定值而烧毁 LED；电阻同时还能调节亮度。
> 2. 低电平点亮时电流从 3.3V 经 LED 灌入引脚（**灌电流 / sink**）；高电平点亮时电流从引脚流出经 LED 到 GND（**拉电流 / source**）。因为很多单片机和芯片是"高电平弱驱动、低电平强驱动"，用低电平驱动既能获得更强的驱动能力，也能在一定程度上避免高低电平互相打架。
> 3. 有源蜂鸣器**内部自带振荡源**，接直流电压就能以**固定频率**持续发声，程序只能控制响/不响；无源蜂鸣器**没有振荡源**，必须由控制器提供**振荡脉冲**（方波）才能发声，改脉冲频率就能改音调。要发出不同音调必须用**无源蜂鸣器**，并用定时器输出 PWM 驱动。
> 4. 因为 SysTick 的时钟源选了 HCLK，而系统主频是 **72MHz**，所以 1 微秒等于 72 个时钟周期，延时 `xus` 微秒就需要计 `72 × xus` 个数。SysTick 的 `LOAD` 只有 **24 位**，最大 `2^24 − 1 = 16777215`，所以 `xus ≤ 16777215 / 72 ≈ 233015`，再大就会被截断。
> 5. 因为本实验是**低电平点亮**，而 `GPIO_Write()` 是整体写 16 位输出寄存器，**写 0 才亮**。`0x0004` 只有第 2 位是 1，取反后变成只有第 2 位是 0、其余全 1，这样才只有 PA2 亮而其他灯灭。如果板子是高电平点亮，应去掉取反，直接写 `GPIO_Write(GPIOA, 0x0004);`。
