# 03-3 GPIO 输入

> [!abstract] 这一集解决两个问题
> **① 引脚怎么把外部电平读进来？② 按键这种机械触点为什么不能直接读？**
>
> 答：把引脚配成**上拉输入 / 下拉输入 / 浮空输入 / 模拟输入**之一 → 输入电平经**施密特触发器（Schmitt trigger）**整形后写进**输入数据寄存器 IDR** → 用 `GPIO_ReadInputDataBit()` 读出 0/1。下接按键（按键一端接 GND）**必须配上拉输入**，否则松手时引脚悬空、电平不确定；机械按键按下/松手瞬间有 **5~10 ms 抖动**，用**延时 20 ms 后二次确认**的软件消抖解决。
>

## 1 从「输出」到「输入」：GPIO 的 8 种模式输入占 4 种

3-1、3-2 用的是**输出**模式（点灯、响蜂鸣器）。这一集把方向反过来：引脚只做**观察者**，读外部给的电平。

STM32F103 的每个 GPIO 引脚一共 8 种工作模式，按方向一刀切开：

| 方向 | 模式 | 标准库枚举 | 内部电路要点 |
| --- | --- | --- | --- |
| **输入** | 上拉输入 | `GPIO_Mode_IPU` | 施密特触发器 + 内部**上拉**电阻 |
| **输入** | 下拉输入 | `GPIO_Mode_IPD` | 施密特触发器 + 内部**下拉**电阻 |
| **输入** | 浮空输入 | `GPIO_Mode_IN_FLOATING` | 只经施密特触发器，引脚不接上下拉 |
| **输入** | 模拟输入 | `GPIO_Mode_AIN` | **施密特触发器关闭**，引脚直连 ADC |
| 输出 | 推挽输出 | `GPIO_Mode_Out_PP` | 3-1 讲的，能真正输出高低电平 |
| 输出 | 开漏输出 | `GPIO_Mode_Out_OD` | 只能拉低，高电平靠外部上拉 |
| 输出 | 复用推挽 | `GPIO_Mode_AF_PP` | 交给片上外设（USART、SPI 等）控制 |
| 输出 | 复用开漏 | `GPIO_Mode_AF_OD` | 同上，开漏形式，I2C 常用 |

> [!tip] 记忆口诀
> **输入 4 种按「悬空时谁来定电平」区分**：内部上拉定高、内部下拉定低、外部定（浮空）、不定（模拟，因为压根不读数字量）。

## 2 四种输入模式怎么选

| 模式 | 悬空/松开时引脚电平 | 典型用途 | 什么时候用 |
| --- | --- | --- | --- |
| **上拉输入** `GPIO_Mode_IPU` | 内部上拉到**高电平** | 下接按键（按键另一端接 GND） | 按键默认高、按下变低，最常用 |
| **下拉输入** `GPIO_Mode_IPD` | 内部下拉到**低电平** | 上接按键（按键另一端接 VCC） | 按键默认低、按下变高 |
| **浮空输入** `GPIO_Mode_IN_FLOATING` | **不确定**，随外部和干扰飘 | 外部电路已经有上下拉电阻；USART/I2C 等外设的接收脚 | 只有当引脚一定不会悬空时才用 |
| **模拟输入** `GPIO_Mode_AIN` | 不适用 | ADC 采样（后面 ADC 章节） | 引脚要送模拟电压给 ADC 时 |

关于「上拉」两个字要建立正确直觉：**它是弱上拉**。F103 数据手册给出的内部上拉/下拉电阻典型值约 **40 kΩ**（范围约 30~50 kΩ），只够给悬空引脚定一个默认电平，一旦按键把引脚直接短到 GND，这点弱电流立刻被拉走，引脚就是干净的低电平。

> [!warning] 模拟输入会关掉施密特触发器
> 数字输入模式下，引脚电压先过**施密特触发器**整形成干净的高低电平，再写进输入数据寄存器；配成**模拟输入**时这条数字通路被断开，引脚直接接到 ADC。所以模拟输入模式下读 IDR 没有意义，也**不能**指望它帮你整形。

## 3 按键的硬件接法：为什么按键必须配上拉

按键本质就是一个**机械开关**：按下导通，松手断开。它只有两种接法。

### 3.1 下接按键（推荐，课程用的就是这种）

```text
       3.3V
        │
        │  内部弱上拉（约 40 kΩ，GPIO_Mode_IPU 打开）
        │
GPIO ───┴───┬──── 引脚电平
            │
          [ 按键 ]
            │
           GND
```

- 松手：开关断开，引脚只挂着内部上拉 → 读到 **1（高电平）**
- 按下：引脚被直接短到 GND → 读到 **0（低电平）**

**所以「下接按键 + 上拉输入」时，按下读到的是低电平（0）。**

### 3.2 为什么不能配成浮空输入

浮空输入时引脚**什么都不接**，相当于一根悬空的天线：

- 松手瞬间引脚电平**不确定**，可能读到 1，也可能读到 0，甚至同一块板子同一秒读两次结果都不一样；
- 悬空引脚容易受工频、手指触摸、旁边走线的干扰而乱跳，程序表现是「没按按键，LED 自己乱闪」。

所以按键接 GND 时，**必须**让引脚在松手时有一个确定的默认电平，这就是配上拉输入的原因。

### 3.3 上接按键（了解即可）

按键另一端接 VCC 时，逻辑反过来：松手时引脚需要**默认低电平** → 必须配**下拉输入** `GPIO_Mode_IPD`，按下读到 **1**。

| 接法 | 按键另一端接 | 必须配的模式 | 松手读值 | 按下读值 |
| --- | --- | --- | --- | --- |
| 下接按键 | GND | **上拉输入** `GPIO_Mode_IPU` | 1 | **0** |
| 上接按键 | VCC | **下拉输入** `GPIO_Mode_IPD` | 0 | **1** |

> [!note] 外部上拉电阻的版本
> 如果板上已经在按键处焊了外部上拉电阻，那么引脚配**浮空输入**或**上拉输入**都可以——因为「松手时是什么电平」已经由外部电阻决定了。课程板用的是「按键一端接 GND、靠单片机内部上拉」的下接方式。

### 3.4 输入模式的初始化写法

```c
#include "stm32f10x.h"                  // Device header

/**
  * 按键 GPIO 初始化：PB1 下接按键，配成上拉输入
  */
void Key_GPIO_Config(void)
{
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);   // ① 开 GPIOB 时钟（GPIO 挂 APB2）

	GPIO_InitTypeDef GPIO_InitStructure;                    // ② 定义初始化结构体
	GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;          // 上拉输入：松手=1，按下=0
	GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_1;             // ③ 选中 PB1
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;       // 输入模式下此参数无意义，照模板写即可
	GPIO_Init(GPIOB, &GPIO_InitStructure);                  // ④ 写入配置

	/* 之后读按键：GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0 即代表按下 */
}
```

和输出模式的四步**完全一样**，只是 `GPIO_Mode` 换成输入模式、不需要再 `GPIO_SetBits()` 设默认电平（默认电平由内部上下拉决定）。

## 4 按键抖动与消抖

### 4.1 抖动是什么

按键内部是**机械弹簧片**。按下和松手的瞬间，弹簧片不会干脆利落地接触/断开，而是在几毫秒内反复碰撞、弹开，产生一连串的电平毛刺：

```text
理想按下：        1 1 1 1 0 0 0 0 0          （一次干净的下降沿）
真实按下：        1 1 1 0 1 0 0 1 0 0 0      （↓↓ 中间一串抖动）
                       └─ 抖动区 ─┘
松手时同样有一串抖动：0 0 1 0 1 1 0 1 1 1 1
```

抖动时间的量级是**毫秒级**，常见说法是 **5~10 ms**（具体随按键型号、按压力度变化）。

它带来的后果：主循环一秒钟跑几十万圈，**一次按下会被读到很多次**，于是在 3-4 里表现为「按一下，LED 切换了好几次」，在计数场景里表现为「按一下加了好几个数」。

### 4.2 硬件消抖

在按键两端并一个小电容，利用 **RC 低通滤波**把抖动毛刺滤平，再靠 GPIO 内部的施密特触发器整形成干净方波。

- 优点：软件完全不用管，读到的就是干净电平。
- 缺点：多一个元件、增加成本；电容取值不当会让响应变迟钝（连按变慢）。

> [!note] 具体参数
> 课程只讲到「电容滤波 + 施密特触发器」这个思路，没有给出推荐的电容容值；实际取值要看按键与电路，本页不编造具体数值，见 `## 待核对`。

### 4.3 软件消抖：延时 20 ms 后二次确认

思路：**第一次读到的低电平不算数，等抖动期过去再确认一次**。

```c
if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0)     // 第一次读到低电平
{
	Delay_ms(20);                                      // 延时 20 ms > 抖动时间，跳过抖动区
	if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0) // 二次确认：仍然是低电平，才认定真的按下了
	{
		/* 这里才是「一次有效按下」 */
	}
	/* 如果二次确认时已经变回高电平，说明刚才是抖动，直接丢弃 */
}
```

`Delay_ms(20)` 这个 20 ms 是课程的取值，比 5~10 ms 的抖动期留了足够余量。

实际课程里把它写成了「延时 20 ms → 等松手 → 再延时 20 ms」的形式，把「消抖」和「等松手」合并在一起：

```c
uint8_t Key_GetNum(void)
{
	uint8_t KeyNum = 0;                                        // 默认 0：没有按键按下

	if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0)         // 第一次读到低，疑似按下
	{
		Delay_ms(20);                                          // 延时消抖，跳过抖动区
		while (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0);  // 二次确认：一直按住不放才继续（顺带等松手）
		Delay_ms(20);                                          // 松手瞬间同样有抖动，再躲一次
		KeyNum = 1;                                            // 消抖通过，判定为一次有效按下
	}

	return KeyNum;                                             // 返回键码，0 表示无按键
}
```

> [!warning] 消抖的两种写法别混
> - **「延时 + 二次判断」**：只保证「这一次是真按下」，**按住不放会一直被判定为按下**（适合「按住就亮」的场景）。
> - **「延时 + 等松手」**：保证「一次按下只产生一次事件」，代价是**函数会卡住直到松手**（阻塞），适合「按一下切换一次」的场景。

## 5 读取 GPIO 的四个库函数

标准库 `stm32f10x_gpio.h` 里读取用的函数一共四个，名字只差 `Bit` 和 `Input/Output`：

| 函数 | 读的是哪个寄存器 | 返回值 | 典型用途 |
| --- | --- | --- | --- |
| `GPIO_ReadInputDataBit(GPIOx, GPIO_Pin_x)` | **输入数据寄存器 IDR** 的某一位 | 0 / 1 | 读按键、读传感器 DO |
| `GPIO_ReadInputData(GPIOx)` | **整个输入数据寄存器 IDR** | 16 位 | 一次读一组引脚 |
| `GPIO_ReadOutputDataBit(GPIOx, GPIO_Pin_x)` | **输出数据寄存器 ODR** 的某一位 | 0 / 1 | 输出模式下查自己刚写了什么、做状态翻转 |
| `GPIO_ReadOutputData(GPIOx)` | **整个输出数据寄存器 ODR** | 16 位 | 同上，整组读 |

一句话区分：

- **`Input` 系列** → 读「**引脚上现在真实的电平**」，不管是谁造成的（按键、外部芯片、还是自己输出的）。
- **`Output` 系列** → 读「**CPU 刚才写进 ODR 的值**」，是程序自己的输出记录，不是引脚的测量值。

```c
/* 读引脚电平（按键、传感器）：用 Input 系列 */
if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0)
{
	/* 按键按下 */
}

/* 想知道自己刚才把 PA1 输出成了什么：用 Output 系列 */
if (GPIO_ReadOutputDataBit(GPIOA, GPIO_Pin_1) == 0)
{
	/* 说明之前写的是低电平 */
}
```

> [!warning] 读输出寄存器 ≠ 读引脚电平
> `GPIO_ReadOutputDataBit()` 读回来的是 CPU 自己写进 ODR 的值。在**开漏输出 + 外部上拉**、或引脚被外部电路强行拉低时，ODR 里的值和引脚上真实的电平**可能不一致**。要测引脚真实电平，只能用 `GPIO_ReadInput*` 系列。
>
> 所以在输入场景（按键、传感器）里用 `GPIO_ReadInputDataBit()`；`GPIO_ReadOutputDataBit()` 是给**输出**场景回看自己输出状态用的（3-4 的 `LEDx_Turn()` 就靠它做状态翻转）。

## 6 本集附带的 C 语言知识

3-3 讲 GPIO 输入之前，先补了一轮「看懂库函数所必需的 C 语言」，因为库函数全靠这些语法组织：

| 知识点 | 关键字 | 用途 | 例子 |
| --- | --- | --- | --- |
| 数据类型 | `stdint.h` | 明确位宽，避免不同平台 `int` 长度不一致 | `uint8_t` = `unsigned char`，`int16_t` = `short` |
| 宏定义 | `#define` | **字符串替换**，可替换数字、代码片段 | `#define ABC 12345` |
| typedef | `typedef` | 只能给**类型**换名，更安全 | `typedef unsigned char uint8_t;` |
| 结构体 | `struct` | 把不同类型的数据打包在一起 | `GPIO_InitTypeDef` 就是结构体 |
| 枚举 | `enum` | 取值受限的整型 / 宏定义的集合 | `enum {FALSE = 0, TRUE = 1} EnumName;` |

```c
/* 结构体的典型用法：先 typedef 换名，再定义变量，再用「.」取成员 */
typedef struct {
	char  x;
	int   y;
	float z;
} struct_t;					// 用 typedef 给结构体类型换个短名字

struct_t c;					// 用新类型名定义结构体变量
c.x = 'a';					// 「.」引出成员并赋值
c.y = 66;

/* 如果用结构体指针访问，则用「->」 */
struct_t *p = &c;
p->x = 'a';
```

这就是为什么库函数长这样——**结构体负责打包参数，传地址进去**：

```c
GPIO_InitTypeDef GPIO_InitStructure;                 // 定义结构体变量
GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_IPU;       // 打包装箱
GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_1;
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_Init(GPIOB, &GPIO_InitStructure);               // 取地址传参，库函数内部拆箱写寄存器
```

> [!tip] 宏定义 vs typedef
> **宏定义是「替换」，typedef 是「换名」**。宏定义范围更宽（可以替换任何文本），typedef 只能作用于类型，所以更安全。

## 7 易错点

- [ ] 按键一端接 GND 却把引脚配成**浮空输入** → 松手时引脚悬空，读数随机、随干扰乱跳，表现为「没按也触发」。
- [ ] 忘了 `RCC_APB2PeriphClockCmd()` 开 GPIO 时钟就直接 `GPIO_Init()` → 外设没时钟，配置全部无效。
- [ ] 在输入模式下纠结 `GPIO_Speed` → 速度只对**输出**模式有效，输入模式照模板写 `GPIO_Speed_50MHz` 即可。
- [ ] 以为「上拉输入」是引脚强力输出高电平 → 它是**弱上拉**，按键一按就被短到 GND，读到低电平。
- [ ] 消抖只延时、不做二次确认 → 抖动仍可能被读成多次按下；反之只做二次确认不延时也不行。
- [ ] 用 `GPIO_ReadOutputDataBit()` 去读按键 → 那读的是输出数据寄存器，不是引脚电平，必须用 `GPIO_ReadInputDataBit()`。
- [ ] 模拟输入模式下还指望施密特触发器帮忙整形 → 模拟输入会旁路施密特触发器，数字通路被断开。
- [ ] 把阻塞式按键函数（含 `while` 等松手）放进中断服务函数 → 中断里长时间等待会卡死整个系统。
- [ ] 把「4 种输入模式」当成「全部 8 种模式」→ 另外 4 种是输出模式（推挽/开漏/复用推挽/复用开漏）。

## 8 自测

1. 按键一端接引脚、另一端接 GND，引脚应该配成哪种输入模式？为什么不能用浮空输入？
2. 上拉输入和下拉输入在「按键松开」时分别读到什么值？这个默认电平是谁提供的？
3. 机械按键的抖动大约是什么量级？软件消抖为什么必须「延时 + 二次确认」两步，只延时行不行？
4. 要读引脚 PB13 当前的输入电平用哪个函数？想回看自己刚往 PA1 输出了什么又该用哪个函数？这个函数读的是寄存器还是引脚？
5. 模拟输入模式与浮空输入模式在内部电路上的关键区别是什么？各自适合什么场合？

> [!success]- 参考答案
> 1. **上拉输入** `GPIO_Mode_IPU`。因为按键松开时开关断开，浮空输入会让引脚悬空、电平不确定且易受干扰；上拉输入让松手时读到稳定的高电平，按下时被短到 GND 读到低电平。
> 2. 上拉输入松手读到 **1**，下拉输入松手读到 **0**。这个默认电平由芯片**内部**的上拉/下拉电阻提供（F103 典型约 40 kΩ 的弱上拉/下拉）。
> 3. 抖动是**毫秒级**，常见 5~10 ms。只延时不做二次确认，无法判断延时结束后按键是否真的还按着（可能是干扰毛刺）；只做二次确认不延时，两次读到的可能都还在抖动区内。两步合起来才算「一次有效按下」。
> 4. 读引脚用电平 `GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13)`；回看自己的输出用 `GPIO_ReadOutputDataBit(GPIOA, GPIO_Pin_1)`，它读的是**输出数据寄存器 ODR**（CPU 写进去的值），不是引脚上真实的电平。
> 5. **模拟输入会关闭施密特触发器**，引脚直连 ADC，根本不做数字量化；浮空输入的施密特触发器是开着的，但引脚没有内部上下拉，靠外部电路定电平。模拟输入用于 ADC 采样，浮空输入用于外部已有上下拉或外设接收脚的场合。
